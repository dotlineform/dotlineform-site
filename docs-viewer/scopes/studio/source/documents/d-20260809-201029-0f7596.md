# CPB-1 — Catalogue Projection Boundary Cutover Delivery

## Status And Purpose

CPB-1.4 completed on 2026-08-09 and the delivery is parked before CPB-1.5 implementation approval. CPB-1 removes accidental cross-layer consumers left around the public Catalogue aggregate indexes: Studio reads only canonical or Studio-owned Catalogue projections, selected public routes read exact focused records, and Recent and Catalogue Search each own their generated runtime projection.

CPB-1.1 removed the five draft Works and one stale draft-Series payload from the tracked public artifact before the wider ownership cutover.

## Complete Outcome

Studio reads canonical Catalogue source or Studio-owned lookup/service projections only. It never reads `site/` as source or as a local application read model.

The public Catalogue has these runtime boundaries:

| route | owned runtime data |
| --- | --- |
| `/series/` | one lean Series list index containing only fields needed to render, sort, and route Series cards |
| `/series/?series=<series_id>` | the exact Series payload, including its canonically ordered lightweight Work members |
| `/works/?work=<work_id>` | the exact Work payload plus the exact relevant Series payload when Series navigation is available |
| `/work-details/?detail=<detail_uid>` | the exact parent Work payload |
| `/recent/` | the Recent index, including each entry's resolved public destination |
| `/catalogue/search/` | the Catalogue Search index |
| bare `/works/` | redirect to `/series/` |

`site/assets/data/works_index.json` and its generator, configuration, route, test, and documentation obligations retire after their last consumer is removed. The `/works/` shell remains because exact Work routes use it. All public Work and Series projections contain published records only.

## Accepted Ownership Rules

- Canonical Works, Series, status, membership, ordering, and primary-Work meaning remain owned by canonical Catalogue source.
- Studio browser routes consume Studio-owned reads. A generated public artifact does not become a Studio authority because it is convenient or already present.
- A public list index contains only cross-record list context. A selected route reads the exact selected-record payload rather than reconstructing that record from global indexes.
- An exact Series payload owns the Series fields needed by its selected page and one lightweight ordered member-Work projection. It does not require every rich Work payload.
- Recent owns the destination frozen for each Recent entry. Catalogue Search generation reads canonical source and emits its own flat public projection; the public Search browser reads only that projection.
- Record identity, membership, ordering, and destinations are exact. There is no title, filename, route, first-record, or public-index fallback.
- Each consumer cuts over directly. CPB-1 adds no compatibility alias, dual reader, generic projection registry, or second canonical source.

Implementation should begin at the existing ownership seams and narrow the exact changed set during CPB-1.0:

- public Catalogue serializers, build planning, generated-record cleanup, field-to-artifact impact, and required-file validation;
- the Series, Work, Work Detail, Recent, and Catalogue Search route modules;
- the Catalogue Search builder and Recent projection builder; and
- [Catalogue Architecture](/docs/?scope=studio&doc=d-20260401-000000-a11bf3), [Catalogue Indexes And Payloads](/docs/?scope=studio&doc=d-20260519-202931-b05d27), [Public Catalogue Data Flow](/docs/?scope=studio&doc=d-20260331-000000-33a9c5), [Catalogue Search Policy](/docs/?scope=studio&doc=d-20260331-154730-885d0f), and [Catalogue Drafts](/docs/?scope=studio&doc=d-20260418-000000-16bf7e) as the likely durable documentation owners.

This is an inspection route, not a frozen file inventory.

#### CPB-1.0 Sanity Record

The ownership fit is confirmed. Canonical Work and Series source plus the existing Studio Catalogue read API and lookup builders can replace every Studio public-artifact read. The existing Catalogue index/record builders, cleanup owner, route modules, Recent builder, Search builder, field registry, projection audit, and required-file configuration cover the public cutover without a new store, registry, or compatibility layer.

| consumer | current read | accepted final read |
| --- | --- | --- |
| `/series/` | Series aggregate | lean Series list index |
| selected Series | Series aggregate + Works aggregate + exact Series | exact Series only |
| selected Work | exact Work + Series aggregate | exact Work + exact relevant Series |
| Work Detail | exact parent Work | unchanged |
| Recent | Recent + Series aggregate | Recent only |

| bare `/works/` | Works aggregate + Series aggregate | redirect to `/series/` |
| Studio Works and tag surfaces | public aggregates and, for Series Tag Editor media, exact public Work | canonical maps or existing Studio lookup/service reads only |

Containment evidence is exact: canonical source has five draft Works (`00373`–`00377`), all five appear in `works_index.json` and have exact public Work payloads. Canonical source has four draft Series; the Series aggregate already excludes them, but `site/assets/series/index/002.json` is stale. The Works aggregate and exact Work generator currently accept draft and published records, while exact Series generation skips drafts without removing stale files. `catalogue_generation_indexes.py` and `generate_work_pages.py` remain the generation owners; `catalogue_cleanup.py` is the existing exact-artifact cleanup seam.

The frozen public shapes and route rules are:

- lean Series-list rows contain `series_id`, `title`, `year`, `year_display`, `primary_work_id`, and `single_work_id` only; `single_work_id` is present only when the Series has exactly one published member;
- exact Series payloads retain their focused metadata/prose and add published member Works shaped as `work_id`, `title`, `year`, and `year_display`, ordered by canonical Series `sort_fields` with `work_id` as the deterministic tie-break;
- a selected Work honors a query-Series context only when that exact `series` ID appears in the Work's canonical `series_ids` and the exact Series member projection contains the Work. Independently, the first canonical `series_ids` entry remains the primary Series link. A missing query uses only that exact primary Series; a valid non-primary query may read both exact Series payloads because they serve different current links; an invalid query does not fall back as navigation context; and no aggregate is read;
- Recent entries own an `href`: Work entries route to the exact Work with `from=recent`; Series entries route to their sole published Work when there is exactly one, otherwise to the selected Series with `from=recent`; and
- `/works/` without a non-empty `work` parameter replaces the location with `/series/` and discards retired list query state. Exact Work and Work Detail URLs do not change.

The delivery remains broad but separable at its existing checkpoints. CPB-1.1 is limited to published-only aggregate/exact generation, stale exact cleanup, the bare-Works redirect, and retirement of the Works-list module. Its proposed production/config files are `catalogue_generation_indexes.py`, `generate_work_pages.py`, `catalogue_cleanup.py`, `work-page.js`, `site/works/index.html`, `site-tools.json`, and deletion of `works-index.js`; focused evidence belongs in `test_catalogue_generation_indexes.py`, `test_catalogue_cleanup.py`, and `public_route_simplification.py`. The estimate is about 100–160 production/config lines and 70–120 test lines, plus deletion of the 376-line list module and six stale exact JSON files. Later checkpoints own Studio read cutover, exact public route shapes, Recent/Search ownership, Works-aggregate retirement, audit/field-planning transfer, and durable documentation transfer.

Main risks are stale exact payloads surviving a scoped build, Series member order diverging between canonical and public/Studio projections, multi-Series Work navigation silently changing target, Search retaining a hidden public-output input, and validation or field-impact logic continuing to require the retired aggregate. Stop and re-scope if implementation needs public draft preview, URL changes, another canonical store, a generic projection framework, a replacement flat Works report, content comparison, or a compatibility/dual-read period.

CPB-1.0 is complete. No product code has changed, and CPB-1.1 has not started.

## Boundaries

CPB-1 does not change canonical Catalogue schema, Catalogue editing workflows, Series membership or primary-Work meaning, public Work/Series URL shapes, Work Detail ownership, Search ranking or interaction design, Recent snapshot meaning, Catalogue media publication, or the visual design of Series and Work pages. It creates no replacement flat Works report. A future need for that report belongs in a separate Docs Viewer delivery rather than restoring a public aggregate and route.

CPB-1 is active and parked at the completed CPB-1.4 review gate. Explicit approval is required before CPB-1.5 product implementation.
