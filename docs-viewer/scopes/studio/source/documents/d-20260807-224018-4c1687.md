# SSP-7.1a — Publishable Contract Cutover Evidence

## Outcome

SSP-7.1a is complete. The legacy cross-scope visibility field is replaced by one public-scope-only `publishable` contract, **Edit metadata** no longer exposes publication state, configured sources and projections are migrated, and the existing scope-wide **Publish** remains the only public mutation. This checkpoint stops before SSP-7.1b; it adds no **Set Publishable…** action or mutation endpoint.

## Contract Proved

- Only an exact parent or child collection with a configured public projection accepts `publishable`.
- Omission means included in the next Publish; canonical writes store only `publishable: false` for exclusion.
- Local and local-external sources, projections, package records, runtime state, and indexes omit the field without a discovery replacement.
- Legacy `viewable` source, metadata, import, and returned-package input and `include_non_viewable` package input fail closed. There is no alias or dual reader.
- A false parent excludes its descendants from the public tree, search, Recent, by-ID, reference, and location projection without rewriting descendant source.
- Publish-capable Manage rows retain the **Excluded from next Publish** icon; public reader payloads carry no publishability metadata.
- Create, ordinary Import, and Copy use the included default. Overwrite preserves an existing public gate unless an accepted returned record explicitly changes it.

## Migration And Projection Evidence

The coordinated migration covered 577 configured repository and external-local Markdown sources. Explicit true declarations normalized to omission, five public false declarations became `publishable: false`, and the reviewed local false declaration was removed without replacement. A final all-scope migration dry-run reported zero remaining source files across Studio, Library, Analysis and its Tags/Works collections, Moments, Notes, Processing, Dotlineform, and Projects.

Every configured private docs and search projection was regenerated. Live scans found no publishability keys in Studio, Processing, Notes, or Dotlineform local projections; publish-capable private projections contained false-only keys; and public site docs/search assets contained none. The five excluded Analysis parent/Tags/Works by-ID files were absent from the public site projection.

The existing Publish owner applied one required Analysis `index-tree.json` change and removed four stale Finder metadata files from Library and Moments public projection roots. Final Publish previews for Library, Analysis, and Moments each reported zero changed, zero removed, and `up_to_date: true`. Catalogue document-URL follow-through completed unchanged and non-stale.
