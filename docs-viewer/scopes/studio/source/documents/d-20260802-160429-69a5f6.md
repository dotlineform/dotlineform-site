# Authoring Directives Concept And Examples

## Purpose

Some presentation and publication decisions are deliberate authoring choices rather than facts a runtime can infer. An Authoring Directive records that choice next to the affected Markdown block as an ordinary namespaced HTML comment.

The shipped consumer is Content Detail table eligibility. A consumer acts only when it recognises the exact comment form and can associate it with the expected next table. Everything else is ignored and the Markdown renders normally. This is deliberately narrower than a validated Markdown extension language.

The current Source convenience offers only the maintained `table-detail` form. The original `table-publish` Source action was retired on 2026-08-04 after its TE-6 consumer stopped. Existing authored `table-publish` comments retain the same harmless ordinary-comment behavior as any unsupported directive.

## Illustrative Source

The maintained source shape is:

```markdown
<!-- dotlineform:table-detail -->

| Project | Folder | Series |
| --- | --- | --- |
| Nerve | projects/nerve | Series 105 |
```

The comment applies only when the next non-blank source block is the expected Markdown table. Intervening prose, another comment, a fence, or another block leaves it inert. Existing table-publication comments remain ordinary authored text; their `id` value is not a DOM ID, URL fragment, or Content Detail table identity.

Working and exported Markdown retain the comment and table. Rendered HTML may also retain the ordinary invisible comment; comment removal is not a contract. The shipped table-detail consumer adds a narrow marker only to a table associated with the exact `table-detail` form. The stopped `table-publish` form remains inert and its table stays semantic HTML.

## Recognition And Harmless No-Op

Recognition belongs to each consumer rather than a central directive subsystem:

- comments outside the exact `dotlineform:` namespace remain ordinary comments and are never interpreted;
- a malformed, unknown, misplaced, duplicated, or unsupported `dotlineform:` comment is ignored without failing the build;
- the underlying Markdown table remains ordinary semantic HTML whenever no consumer acts;
- the table-detail consumer recognises only its maintained comment and projects `data-docs-content-detail="table"` onto the associated semantic table;
- the Content Detail adapter queries that projected marker and never parses source comments or decides whether an unmarked table is large;
- the stopped table-publication form remains ordinary source text and its table remains semantic HTML; and
- no consumer needs to report comments it does not understand.

The `dotlineform:` namespace prevents accidental collisions but does not make a comment valid or mandatory. A document can move through scopes that have no consumer for it; the comment remains source text and the table remains usable.

## Table Authoring Outcomes

| authored state | current result |
| --- | --- |
| ordinary Markdown table | semantic HTML table with no Content Detail control |
| table with `table-detail` directive | semantic HTML table carrying the narrow Content Detail eligibility marker |
| table with `table-publish format=svg` directive | semantic HTML table; the TE-6 consumer is stopped |

The shipped enhanced route is explicit and opt-in. Removing `table-detail` removes the detail control on the next build. `table-publish` and misspelled or unsupported comments retain ordinary semantic table rendering.

Dedicated table documents use ordinary rendered-document entry and the explicit table-detail control. The TE-5 document-default proposal is stopped.

## Copy, Move, And Source Authoring

Copy and Move preserve the comment because they preserve canonical Markdown. A target consumer may recognise it or ignore it independently. No transfer workflow generates SVG or rewrites the comment.

[TE-1 — Directive Insertion](/docs/?scope=studio&doc=d-20260802-163320-9015b0) adds one **Directives** control to the existing Manage Source main-view toolbar. It uses an Actions-style menu to list the maintained table-detail source snippet and inserts its predefined bytes at the captured insertion point. It is a typing shortcut, not the owner of directive recognition or validity.

The sole command inserts the complete `<!-- dotlineform:table-detail -->` form. The retired Table to SVG action is preserved only in the stopped TE-6 decision record, while existing authored comments remain harmless ordinary source. The menu does not guess an ID, open a modal, save, rebuild, report a success message, locate a target table, or detect an existing directive. Removal and correction remain ordinary source editing.

The UI is only a source-writing convenience. Save/Rebuild lets the shipped table-detail consumer recognise its exact form and retains other snippets as ordinary comments. The implementation reuses the Source adapter’s revision-bound capture and `setRangeText` editing seam.

## No-Op And Safety Contract

- unknown, malformed, misplaced, unsupported, or unassociated comments are ignored;
- the stopped `table-publish` form produces an ordinary semantic table; and
- an unmarked table is never converted because of width, row count, title, scope, or previous artifacts.

## Not In Scope

- executable directives, templates, macros, conditions, includes, variables, or arbitrary build commands;
- a central directive grammar, validator, capability registry, or diagnostics system merely because two bounded table consumers recognise adjacent comments;
- runtime comment scanning in public or Manage JavaScript;
- automatic conversion based on table size or viewport;
- changing canonical Markdown into an image reference;
- table editing, sorting, filtering, pagination, or SVG interaction beyond browser navigation and zoom;
- using a successfully projected SVG table as an accessible equivalent of semantic HTML without an explicit alternative-text/summary contract; or
- adding options, progress controls, or conversion decisions to Publish.

The initial Source action does not validate directive meaning, edit attributes after insertion, remove directives, offer a directive-management modal, infer or locate a target table, detect duplicates, or expose unshipped directive ideas.
