# DSI-2 — Scope-Level Sub-Scope Search Delivery

## Status

DSI-2.1 is complete and parked for review. The three affected working scope indexes now contain their exact eligible sub-scope documents. The tracked Analysis public index and document-location projection remain unchanged pending a separate explicit Publish decision. DSI-2.2 browser navigation and presentation are not approved or started.

The current system includes eligible sub-scope documents in the parent Search index while continuing to exclude them from parent Index and Recent. Those navigation products remain separate unless another delivery explicitly changes them.

## Settled Product Boundary

The main Docs Viewer search represents the complete visible documentation experience for its active parent scope. One scope-level index should therefore contain:

- eligible ordinary parent documents; and
- eligible documents from each registered sub-scope placed by an eligible `docs_subscope` report host in that scope.

All records participate in one query and one relevance order. Corpus statistics used by [Docs Viewer Search Relevance](/docs/?scope=studio&doc=d-20260813-223337-e6c261) cover the same combined scope corpus.

The title search inside a sub-scope report remains a quick filter over that report's current list. It does not become a second full-text engine. DSI-2 does not generate independent sub-scope search indexes or merge separately queried indexes in the browser.

## Identity, Navigation, And Presentation

A sub-scope search record retains exact semantic identity `{scope, sub_scope, doc_id}`. Its report-host placement is also explicit so the browser can open the document through the correct active route. Titles, filenames, currently selected reports, and displayed UI state must not be used to infer any part of the target.

The same Analysis search projection is consumed by local Manage and public `/analysis/`, which require different route bases. Ordinary document-to-document links already use the shared active-route resolver, including exact `subdoc` and fragment preservation; DSI-2 does not introduce another link-resolution system. Search data must carry the structured parent report-host plus child target needed by that existing resolver rather than treating one stored public or Manage `href` as universal. The resolver then constructs the canonical parent report URL for the active route and preserves the exact child as `subdoc`.

Sub-scope result context should follow the existing compact metadata pattern. Beneath the document title, display update date plus the configured collection/report title, for example `2026-07-27 • Concepts`. Keep exact `sub_scope`, report-host identity, and configured collection title as separate data; do not overload `parent_title` or make collection context searchable merely because it is displayed.

## Membership And Publication

Include only a registered sub-scope with one unambiguous eligible report-host placement. Include only child documents present in the corresponding eligible collection product. Stop rather than guess if placement, collection identity, or document identity is ambiguous.

For public Analysis, the combined index must derive membership from the same accepted public report hosts, public manifests, and public by-ID projections used by the existing document-location boundary. It must not expose vocabulary from unpublished, non-publishable, Manage-only, hidden, orphaned, or unplaced child documents. Local and external-local scopes use their corresponding working collection products without weakening exact identity.

The parent report host remains an ordinary parent result in its own right. Child content is indexed once under its exact sub-scope identity. Collection membership neither boosts nor penalises relevance.

## Build And Rebuild Direction

Every eligible parent and child document uses the same configured `title`, `heading`, `body`, and `code` extraction and tokenizer policy when its scope adopts full text. Structural collection fields remain display and navigation metadata only.

The combined posting lists remain one atomic scope artifact. A search-relevant sub-scope source or membership change must rebuild the complete parent-scope search index, while its document-payload build may remain collection-targeted. The current sub-scope write path reports search mode `none`; DSI-2 must replace that behavior without broadening document rebuilding.
