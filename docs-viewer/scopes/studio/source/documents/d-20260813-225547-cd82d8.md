# DSI-2 — Scope-Level Sub-Scope Search Delivery

## Status

Proposed shared Docs Viewer search capability. No implementation is approved. DSI-2.0 may confirm the exact composition, navigation, publication, and rebuild seams, then must stop for review before production code, generated schemas, or browser presentation change.

The current system deliberately excludes sub-scope documents from parent Index, Recent, and Search. This delivery supersedes that decision for Search only. Parent Index and Recent remain separate unless another delivery explicitly changes them.

## Settled Product Boundary

The main Docs Viewer search represents the complete visible documentation experience for its active parent scope. One scope-level index should therefore contain:

- eligible ordinary parent documents; and
- eligible documents from each registered sub-scope placed by an eligible `docs_subscope` report host in that scope.

All records participate in one query and one relevance order. Corpus statistics used by [Docs Viewer Search Relevance](/docs/?scope=studio&doc=d-20260813-223337-e6c261) cover the same combined scope corpus.

The title search inside a sub-scope report remains a quick filter over that report's current list. It does not become a second full-text engine. DSI-2 does not generate independent sub-scope search indexes or merge separately queried indexes in the browser.

## Identity, Navigation, And Presentation

A sub-scope search record retains exact semantic identity `{scope, sub_scope, doc_id}`. Its report-host placement is also explicit so the browser can open the document through the correct active route. Titles, filenames, currently selected reports, and displayed UI state must not be used to infer any part of the target.

The same Analysis search projection is consumed by local Manage and public `/analysis/`, which require different route bases. Ordinary document-to-document links already use the shared active-route resolver, including exact `subdoc` and fragment preservation; DSI-2 does not introduce another link-resolution system. Search data must carry the structured parent report-host plus child target needed by that existing resolver rather than treating one stored public or Manage `href` as universal. The resolver then constructs the canonical parent report URL for the active route and preserves the exact child as `subdoc`.

Sub-scope result context should follow the existing compact metadata pattern. Beneath the document title, display update date plus the configured collection/report title, for example `2026-07-27 • Concepts`. Keep exact `sub_scope`, report-host identity, and configured collection title as separate data; do not overload `parent_title` or make collection context searchable merely because it is displayed.

## Membership And Publication

Include only a registered sub-scope with one unambiguous eligible report-host placement. Include only child documents present in the corresponding eligible collection product. Stop rather than guess if placement, collection identity, or document identity is ambiguous.

For public Analysis, the combined index must derive membership from the same accepted public report hosts, public manifests, and public by-ID projections used by the existing document-location boundary. It must not expose vocabulary from unpublished, non-publishable, Manage-only, hidden, orphaned, or unplaced child documents. Local and external-local scopes use their corresponding working collection products without weakening exact identity.

The parent report host remains an ordinary parent result in its own right. Child content is indexed once under its exact sub-scope identity. Collection membership neither boosts nor penalises relevance.

## Build And Rebuild Direction

Every eligible parent and child document uses the same configured `title`, `heading`, `body`, and `code` extraction and tokenizer policy when its scope adopts full text. Structural collection fields remain display and navigation metadata only.

The combined posting lists remain one atomic scope artifact. A search-relevant sub-scope source or membership change must rebuild the complete parent-scope search index, while its document-payload build may remain collection-targeted. The current sub-scope write path reports search mode `none`; DSI-2 must replace that behavior without broadening document rebuilding.

## Delivery Steps

### DSI-2.0 — Composition And Route Readiness

- [ ] Confirm the exact parent and sub-scope source/projection membership owners for repository, public, and external-local scopes.
- [ ] Reuse the existing exact document-location/report-host association and active-route URL resolver used by ordinary document-to-document links; do not create a second route mechanism or title-based or selected-report inference.
- [ ] Confirm the smallest additive search-record target needed to preserve `{scope, sub_scope, doc_id}` plus one unambiguous report-host placement across Manage and public routes.
- [ ] Inspect actual ID uniqueness across parent and child collections; stop rather than assume `doc_id` alone is scope-wide unique.
- [ ] Identify the watcher and write-service changes required for a sub-scope change to rebuild only the atomic parent search artifact.
- [ ] Measure current and proposed Analysis parent/sub-scope record counts and raw payload shape without changing the generated or public index.
- [ ] Present exact proposed files and a rough production/test diff estimate.

**Gate:** Review membership, structured navigation target, schema compatibility, rebuild ownership, public exclusion evidence, payload estimate, and proposed files before implementation.

### DSI-2.1 — Combined Scope Index

- [ ] Extend the shared builder to emit one deterministic scope corpus containing eligible parent and visibly hosted sub-scope documents.
- [ ] Retain exact collection identity, route placement, configured display context, and one result per exact document target.
- [ ] Apply the same field extraction and tokenizer to parent and child content without a scope-name or sub-scope-name branch.
- [ ] Make search-relevant child writes and membership changes rebuild the complete parent-scope index.
- [ ] Prove excluded child documents contribute neither identities nor terms, especially in the public Analysis projection.

**Gate:** Present generated contract, combined-corpus counts, exact exclusion evidence, rebuild behavior, payload delta, and non-Analysis scope comparison. Stop before browser presentation.

### DSI-2.2 — Exact Result Navigation And Context

- [ ] Make the shared search result path pass the structured parent report-host plus child target to the existing active-route resolver for parent and child results.
- [ ] Preserve ordinary parent navigation and query/history behavior.
- [ ] Show configured collection/report context beneath child titles using the existing compact result metadata pattern.
- [ ] Leave visual and interaction acceptance to the user; do not add or run a browser check unless explicitly requested.

**Gate:** Stop for direct user feedback on mixed parent/child results and public versus Manage navigation before code review.

### DSI-2.3 — Code Review And Closeout

- [ ] Review builder, membership, publication, schema, routing, write/rebuild, result presentation, tests, documentation, and generated projections.
- [ ] Check specifically for hidden vocabulary leakage, ambiguous placement, inferred identity, parent-route regressions, stale child postings, duplicated search artifacts, and collection-based rank drift.
- [ ] Transfer settled behavior to durable Search and Search Index documents while retaining delivery evidence here.
- [ ] Run only the focused accepted checks and stop for explicit closeout approval.

**Gate:** Present review findings, resolutions, final scope, and remaining limitations. Stop for explicit closeout approval.

## Boundaries

DSI-2 changes Search corpus composition only. It does not merge sub-scope documents into the parent tree or Recent list, replace report-local title filtering, add cross-scope search, create independent child indexes, change relevance scoring, change Catalogue Search, or publish Analysis full text before its separate adoption gate.
