# Resolver Tokens Architecture (Retired)

## Status

Resolver Tokens were retired on 2026-08-05 before implementation. No resolver token syntax, parser, definition registry, collection result policy, relationship expansion, resolver-derived semantic usage, or document-build refresh dependency was shipped.

The proposal was replaced by [SSP-3 — Insert Subject Link Delivery](/docs/?scope=studio&doc=d-20260802-174340-2fe9f4). That action reads the current exact document subject once and inserts one ordinary authored reference: an existing Work/Series Semantic Token or an existing local Folder link. Inserted source is a snapshot and is not reinterpreted when front matter changes.

The decision also confirms two separate meanings:

- subject front matter states what a document is about and remains the authority for [SSP-5](/docs/?scope=studio&doc=d-20260802-195805-94a5be) public Work/Series document metadata; and
- Semantic Token occurrences state what a document mentions and remain relationship-analysis evidence rather than public aboutness.

Project State remains an independently useful live report. Its persisted folder lookup was implemented only for the proposed resolver consumer and now has no product consumer; [SSP-2](/docs/?scope=studio&doc=d-20260801-133318-15e8fa) schedules its bounded removal before reclose.

This retained record preserves the retirement decision. Git history retains the superseded detailed design.
