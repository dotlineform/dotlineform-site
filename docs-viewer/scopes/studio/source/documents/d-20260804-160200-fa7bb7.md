# Tag Document Linking

## Purpose

Tag Document Linking owns the relationship between independently authored Tag documents, canonical Tag Registry identity, an optional primary override of the automatic document order, and Tag Semantic Token destinations. It is a Tag authoring and reference feature rather than part of Sub-Scope Publishing or the folder-centred Project State workflow.

The feature restores the bounded Tag-document direction: documents declare exact canonical `tag_id`; a private derived association answers which documents describe each Tag in one stable exact-target order; the Tag Registry editor displays that association read-only and may store one optional `primary_document` override; and Tag Semantic Tokens use the valid selected primary or otherwise the first current association in that same deterministic order.

It also owns the Tag-specific authoring surface needed to keep the app-level **Edit metadata** modal document-agnostic. Configured Tag-document fields appear read-only in Info and edit through a focused Tag-owned modal selected by the resolved sub-scope contribution rather than a literal Analysis Tags name check.

## Current Implementation Baseline — 11 August 2026

SSC-1, TDL-0, TDL-1, and TDL-2 are shipped. Analysis Tags registers `tag_fields(group, tag_id)`, passive exact-target Info projection, the focused revision-safe modal, normalized declaration states, a private deterministic `docs_tag_associations_v1` product, and source-revalidated Studio Tag Delete/Demote guards. Tag Registry presents the complete ordered association read-only and owns only one optional replace-only primary override. The second Semantic Tokens family supplies exact canonical/alias Tag discovery, guarded Source insertion, immutable-identity Info editing, deterministic primary-or-first build resolution, ordinary usage/report rows, and read-only Broken Links diagnosis. Exact relative Analysis destinations retain their parent-plus-subdocument identity in Manage and public output. Report Blocks own the Analysis Tags host presentation, placed child documents remain intentionally absent from the parent index/recent/search products, and public eligibility is `publishable`; none of those boundaries alter the exact Tag-document ownership described here.

The reviewed cutover produced `tag_registry_v6` with 247 canonical Tags, zero legacy `doc_url` rows, and no migrated primary overrides. It added exact declarations to 245 documents and validated 245 matching derived associations; four documents remain deliberately unassociated. The sole unresolved `bird-nerve` legacy URL remains migration evidence rather than invented membership. Studio now displays current associations as read-only pills and may replace one optional current primary, while stale primary identity remains visibly unavailable.

The former Library public scope was retired after this plan was written. Its stale document-location allowlist entry made the Tag Registry's one shared lookup reject before any Analysis records could resolve, so every row appeared unavailable. The TDL-0.0 prerequisite repair makes the public producer, browser provider, Registry consumer, and URL validation Analysis-only; it does not change the feature model or start TDL-0.1.

Private authoring associations and public linkability are separate products. Exact `{scope, sub_scope, doc_id}` identity remains usable for authoring and diagnosis even when no public-safe URL exists; public links are optional derived location descriptors and never replace exact identity.

## Complete Feature Outcome

An `analysis/tags` document may declare one optional canonical `tag_id` alongside its existing group metadata. The declaration is explicit scalar identity and never inferred from title, group, body, route, selected row, or Registry state. Several documents may declare the same Tag. Missing, malformed, stale, unpublished, or unavailable relationships remain bounded document or association states and do not synchronize lifecycle.

Document `group` moves out of **Edit metadata** into the registered Tag-document authoring modal before `tag_id` is added there. Info displays both fields read-only when supported. Document group remains independent from Tag Registry group after its create-time seed; neither editor synchronizes or repairs the other.

A private `tag_id -> documents[]` association projects exact Docs Viewer targets in stable ascending `{scope, sub_scope, doc_id}` order and current public-safe locations where available. Document front matter owns membership and the derived association owner owns this canonical order. The Tag Registry editor displays the complete current association list in that order but cannot add, remove, or reorder its documents; only editing or deleting document source changes membership. Tag Registry owns one optional exact `primary_document` using `{scope, sub_scope, doc_id}` whose runtime role is to override the automatic first-document destination.

The only destructive integrity guard follows document-owned membership: Studio may delete a Tag only when current canonical document declarations produce no associations; otherwise **Delete Tag** lists the exact blocking documents and writes neither owner. Current, empty, or stale `primary_document` state does not affect that decision. Docs Viewer may delete a document or change or clear its `tag_id` without consulting primary selection, then rebuilds the association product without mutating Tag Registry. If that removes the selected primary, the stored identity becomes **Unavailable document** and Semantic Tokens use the automatic first-current-document rule. Neither owner cascades, silently repairs, or selects a replacement.

The migration from `tag_registry_v5.doc_url[]` derives exact document declarations, reports unresolvable entries, validates the resulting association set, preserves the first exact target as `primary_document` only when it remains one of several current documents, and then retires the former Registry membership field. A Tag Semantic Token records canonical `tag_id`; at build time it uses an exact current selected primary when one exists, otherwise the first current association in canonical order. The chosen document must have a workable public-safe location; an unusable chosen destination does not cause a scan for another association.

## Boundary

Tag Document Linking owns Tag document field authoring, ordered derived Tag associations, optional Registry primary overrides, the bounded migration, Tag Semantic Token authoring/resolution, and their reports and diagnosis. Docs Viewer remains canonical for document source and lifecycle; Tag Registry remains canonical for Tag identity, group, aliases, and the optional override.

The feature does not participate in `dotlineform/projects`, Project State, folder/Work/Series authoring subjects, collection-aware editorial copy, public Work/Series reverse lookup, or catalogue-document coverage reporting. It does not create Tag documents automatically, synchronize Registry descriptions with documents, infer replacement primaries, cascade deletes, or add a public Tag application.

## Delivery Discipline

The feature-level boundary is settled by separating Tag authoring and reference behavior from Sub-Scope Publishing. Each delivery `.0` step confirms current implementation fit, broad owners, blast radius, deliverables, risks, and stop conditions without reopening that separation or freezing an exact file plan. Focused evidence and an independent code/diff review remain required at every implementation checkpoint.
