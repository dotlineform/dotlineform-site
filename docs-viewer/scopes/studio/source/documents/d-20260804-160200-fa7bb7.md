# Tag Document Linking

## Purpose

Tag Document Linking owns the relationship between independently authored Tag documents, canonical Tag Registry identity, one explicit primary document, and Tag Semantic Token destinations. It is a Tag authoring and reference feature rather than part of Sub-Scope Publishing or the folder-centred Project State workflow.

The feature restores the bounded Tag-document direction: documents declare exact canonical `tag_id`; a private derived association answers which documents describe each Tag; Tag Registry retains canonical identity, group, aliases, and one optional `primary_document`; and Tag Semantic Tokens resolve only that explicit primary when it is usable.

It also owns the Tag-specific authoring surface needed to keep the app-level **Edit metadata** modal document-agnostic. Configured Tag-document fields appear read-only in Info and edit through a focused Tag-owned modal selected by the resolved sub-scope contribution rather than a literal Analysis Tags name check. [SSC-1](/docs/?scope=studio&doc=d-20260804-172012-5d91bf) established that shared contribution as the single `sub_scope_customisation` workflow; this feature adds Tag-owned fields to it rather than defining another registry.

## Current Implementation Baseline — 11 August 2026

SSC-1 and the Projects assignable-field reference are shipped, but Analysis Tags currently registers its document groups, private manifest, and browser only: it has not yet registered the metadata aspect or `tag_fields` assignable group required by TDL-0. Report Blocks now own the Analysis Tags host presentation, placed child documents remain intentionally absent from the parent index/recent/search products, and public eligibility is `publishable`; none of those changes alter the exact Tag-document ownership described here.

The current `tag_registry_v5` snapshot has 247 canonical Tags, 246 stored document URLs, and one deliberately unlinked Tag (`aaa`). The Analysis public location projection resolves 245 of those URLs; `bird-nerve` retains one stale source target and must remain **Unavailable document** rather than being inferred or repaired. There are 249 managed Tag documents and 248 public Tag documents. These counts are baseline evidence for migration planning, not a persistent schema invariant.

The former Library public scope was retired after this plan was written. Its stale document-location allowlist entry made the Tag Registry's one shared lookup reject before any Analysis records could resolve, so every row appeared unavailable. The TDL-0.0 prerequisite repair makes the public producer, browser provider, Registry consumer, and URL validation Analysis-only; it does not change the feature model or start TDL-0.1.

Private authoring associations and public linkability are separate products. Exact `{scope, sub_scope, doc_id}` identity remains usable for authoring and diagnosis even when no public-safe URL exists; public links are optional derived location descriptors and never replace exact identity.

## Complete Feature Outcome

An `analysis/tags` document may declare one optional canonical `tag_id` alongside its existing group metadata. The declaration is explicit scalar identity and never inferred from title, group, body, route, selected row, or Registry state. Several documents may declare the same Tag. Missing, malformed, stale, unpublished, or unavailable relationships remain bounded document or association states and do not synchronize lifecycle.

Document `group` moves out of **Edit metadata** into the registered Tag-document authoring modal before `tag_id` is added there. Info displays both fields read-only when supported. Document group remains independent from Tag Registry group after its create-time seed; neither editor synchronizes or repairs the other.

A private `tag_id -> documents[]` association projects exact Docs Viewer targets and current public-safe locations where available. Document front matter owns membership. Tag Registry owns one optional exact `primary_document` using `{scope, sub_scope, doc_id}` and no longer owns the complete membership list. A stale stored primary remains visible as **Unavailable document** until the user explicitly clears or replaces it.

The migration from `tag_registry_v5.doc_url[]` derives exact document declarations, preserves the first exact target as `primary_document`, reports unresolvable entries, validates the resulting association set, and then retires the former Registry membership field. A Tag Semantic Token records canonical `tag_id` and resolves at build time to the current usable explicit primary without fallback to another associated document.

## Boundary

Tag Document Linking owns Tag document field authoring, derived Tag associations, Registry primary selection, the bounded migration, Tag Semantic Token authoring/resolution, and their reports and diagnosis. Docs Viewer remains canonical for document source and lifecycle; Tag Registry remains canonical for Tag identity, group, aliases, and primary selection.

The feature does not participate in `dotlineform/projects`, Project State, folder/Work/Series authoring subjects, collection-aware editorial copy, public Work/Series reverse lookup, or catalogue-document coverage reporting. It does not create Tag documents automatically, synchronize Registry descriptions with documents, infer replacement primaries, cascade deletes, or add a public Tag application.

## Delivery Discipline

The feature-level boundary is settled by separating Tag authoring and reference behavior from Sub-Scope Publishing. Each delivery `.0` step confirms current implementation fit, broad owners, blast radius, deliverables, risks, and stop conditions without reopening that separation or freezing an exact file plan. Focused evidence and an independent code/diff review remain required at every implementation checkpoint.
