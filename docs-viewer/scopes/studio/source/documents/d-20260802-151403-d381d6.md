# TE-3 — Managed Table Tools

## Status And Purpose

Active at the **TE-3.0 scope-review** checkpoint, after the completed [TE-2 — Table Detail View](/docs/?scope=studio&doc=d-20260802-162149-3ba013). TE-3 extends the shipped public-safe `content-detail` main view and lightweight static Markdown table presentation with bounded Manage-owned tools.

TE-3 adds table tools only through the Manage composition. It extends the same registered view, main-panel layout, exact table target, semantic table renderer, and `main-view` toolbar. It does not create a managed table viewer beside the public one.

## Complete Outcome

When the active Content Detail target is a Markdown table on a Manage route, the table supports pointer and keyboard-accessible column resizing with session-local **Reset widths**. The existing main-view toolbar also offers an icon-only **Copy table** button using a code-owned inline SVG of two overlapping rectangles. It follows the normal toolbar icon-button presentation and retains **Copy table** as its accessible label and tooltip; it does not display that text in the toolbar.

The public table view remains the static TE-2 presentation. No source, table identity, column widths, or exported file is persisted. **Copy table** reads only the accepted semantic table presentation and writes plain-text tab-separated rows to the clipboard for direct spreadsheet paste. It includes header cells, separates cells with tabs and rows with line feeds, normalizes cell-internal whitespace and line breaks to spaces, preserves empty cells, and uses visible text such as link labels. It emits no successful-action status message.

## Current Seams And Scope Guard

The likely blast radius is the Manage contribution boundary for the shared table adapter, session-local resize state and CSS, main-view controls, a pure semantic-table-to-TSV serializer, and clipboard invocation. The public TE-2 composition remains static.

If implementation requires a second view, renderer fork, source parser, stable table registry, persisted widths, or a public dependency on Manage code, stop for review and split the result.

## TE-3.0 Sanity Note

Completed on 2026-08-03. TE-2 is closed, the feature parent names TE-3 as the next delivery, and the exact table target, semantic clone, expanded layout, toolbar, Back restoration, and cleanup lifecycle are shipped, so the scheduling and platform dependencies are satisfied.

The result fits the current ownership model. The shared table adapter owns the accepted table clone and its presentation lifecycle; the generic Content Detail view owns the expanded shell, active presentation, and view controls; and the existing Manage entrypoint already composes view definitions, control renderers, control handlers, and error/status behavior without entering the public import graph. TE-3 needs one bounded optional seam that exposes active table-presentation commands to the Manage composition. That seam remains presentation-owned and app-neutral, while the resize and clipboard tools remain Manage-owned. Public continues to compose the same static TE-2 adapter and view.

Resizable geometry remains transient component state on the accepted clone. The focused table adapter may add presentation-owned column geometry and focusable header-boundary handles, while pointer and keyboard input update only the active presentation. **Reset widths** returns that presentation to TE-2's natural sizing and `36ch` default maximum. Back, navigation, target replacement, and disposal release handles, listeners, and widths through the existing presentation lifecycle.

**Copy table** serializes the active semantic table rather than Markdown or report data. The pure result includes headers, preserves empty positions, uses visible text such as link labels, normalizes cell-internal whitespace to spaces, separates cells with tabs and rows with line feeds, and is written only from the explicit action. The toolbar contribution is an icon-only button with the normal icon-button treatment, a code-owned overlapping-rectangles SVG, and **Copy table** as its accessible label and tooltip. Success remains quiet and failure uses the existing error surface; downloaded files remain outside the delivery.

The broad blast radius is the optional presentation-command seam, Manage table-tool composition, transient column geometry and resize interaction, main-view Reset/copy controls, the pure TSV serializer, clipboard invocation, cleanup, and focused public-import isolation. Manage acceptance uses representative laptop/desktop widths, keyboard access, zoom, and bounded overflow. The public route retains its own narrow-layout acceptance; a resized local Manage viewport is not public-mobile evidence.

The main risks are tool state escaping the active target, widths or listeners surviving lifecycle changes, inaccessible resize handles, cell extraction that loses table shape, clipboard authority entering public code, and control state outliving the presentation. Exact presentation commands, adapter-owned geometry, lifecycle cleanup, semantic-table serialization, explicit Manage composition, and public import-boundary evidence bound those risks. If implementation needs a parallel renderer/view, persistent or document-owned widths, public tool branches, stable table identity, downloaded artifacts, or a general spreadsheet/export framework, stop and split before widening TE-3.

## Not In Scope

- a second table view or Manage-specific table renderer;
- downloaded CSV/TSV or other export files, file pickers, or server-side export;
- public promotion of resizing or **Copy table**;
- persisted widths, stable table IDs, saved presets, or cross-session settings;
- freezing more than the first column or user-selected frozen columns;
- sorting, filtering, grouping, row selection/actions, editing, formulas, charts, or virtualization;
- parsing Markdown source to recover links or formatting; or
- diagram presentation, which belongs to TE-4.
