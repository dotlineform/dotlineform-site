# iSH Docs Viewer Startup Script

**Date:** 21 August 2026

## Purpose

The current iPad/iSH proof requires several manual startup steps:

```sh
. /root/venvs/dotlineform/bin/activate
cd /root/src/dotlineform-site

set -a
. ./.env.local
set +a

python3 docs-viewer/services/docs_viewer_service.py
```

A small device-local launcher removes this repetition while the `.env.local` startup-order issue is still unresolved.

The launcher should:

1. confirm that the iCloud-backed `dotlineform` mount is available;
2. confirm that the iSH Python virtual environment exists;
3. enter the repository;
4. export `.env.local` into the process environment;
5. start Docs Viewer using the virtual environment's Python directly.

## Create the launcher

```sh
mkdir -p /root/bin

cat > /root/bin/dlf-docs <<'EOF'
#!/bin/sh
set -e

REPO=/root/src/dotlineform-site
PYTHON=/root/venvs/dotlineform/bin/python3
MOUNT=/mnt/dotlineform

if [ ! -d "$MOUNT/docs-viewer" ]; then
    echo "dotlineform mount is unavailable: $MOUNT"
    echo "Remount with: mount -t ios . $MOUNT"
    exit 1
fi

if [ ! -x "$PYTHON" ]; then
    echo "dotlineform Python environment not found: $PYTHON"
    exit 1
fi

cd "$REPO"

if [ ! -f .env.local ]; then
    echo ".env.local not found"
    exit 1
fi

# Temporary workaround until Docs Viewer loads .env.local early enough.
set -a
. ./.env.local
set +a

echo "Starting Docs Viewer..."
exec "$PYTHON" docs-viewer/services/docs_viewer_service.py
EOF

chmod +x /root/bin/dlf-docs
```

Run it with:

```sh
/root/bin/dlf-docs
```

## Add `/root/bin` to PATH

Add once:

```sh
echo 'export PATH="/root/bin:$PATH"' >> ~/.profile
. ~/.profile
```

Thereafter:

```sh
dlf-docs
```

is enough to start Docs Viewer.

## Why call the venv Python directly?

The launcher does not need:

```sh
. /root/venvs/dotlineform/bin/activate
```

Activation is mostly a convenience for an interactive shell. For a launcher it is simpler and more deterministic to call:

```sh
/root/venvs/dotlineform/bin/python3
```

directly.

## Mount check

The external iCloud project tree is mounted at:

```text
/mnt/dotlineform
```

with the expected shape:

```text
/mnt/dotlineform/
├── docs-viewer/
├── data-sharing/
└── projects/
```

If the mount is missing, the launcher exits and tells you to run:

```sh
mount -t ios . /mnt/dotlineform
```

and select the real `dotlineform` folder again.

The script deliberately does **not** remount automatically, because that would unexpectedly invoke the iPadOS folder picker from a startup command.

## Temporary `.env.local` workaround

The iSH clone contains:

```text
/root/src/dotlineform-site/.env.local
```

with values such as:

```sh
DOTLINEFORM_PROJECTS_BASE_DIR=/mnt/dotlineform
DOCS_VIEWER_MANAGEMENT_ENABLED=1
DOCS_VIEWER_REVIEW_ENABLED=1
```

Starting the service directly currently fails unless these values have already entered `os.environ`, because some external workspace configuration is resolved during imports before Docs Viewer applies `.env.local`.

The launcher therefore does:

```sh
set -a
. ./.env.local
set +a
```

Once the repository startup-order issue is fixed, this block can be removed.

## Expected startup

Running:

```sh
dlf-docs
```

should eventually produce output similar to:

```text
Docs Viewer service: http://127.0.0.1:8776/docs/
Docs Viewer management: enabled
Docs Review: enabled
Docs Viewer generated reads: enabled
```

Safari:

```text
http://127.0.0.1:8776/health
http://127.0.0.1:8776/docs/
```

## Check health from a second iSH window

```sh
wget -qO- http://127.0.0.1:8776/health
```

Check for the process:

```sh
ps | grep '[d]ocs_viewer_service.py'
```

## Recover a stale server

One lifecycle test produced a state where the Python process still existed but port `8776` was no longer listening.

If:

```sh
wget -qO- http://127.0.0.1:8776/health
```

returns `Connection refused`, check:

```sh
ps | grep '[d]ocs_viewer_service.py'
```

Optionally confirm that the port is free:

```sh
python3 -c "import socket; s=socket.socket(); s.bind(('127.0.0.1',8776)); print('port 8776 is free'); s.close()"
```

If the process exists but the port is free, kill the stale process:

```sh
kill <PID>
```

Then restart with:

```sh
dlf-docs
```

## Possible future `dlf` command

The launcher could later become part of a wider CLI:

```sh
dlf docs
dlf health
dlf import ...
dlf rebuild ...
dlf package-export ...
dlf package-return ...
```

That would fit the emerging iPad architecture:

```text
Docs Viewer = rich interactive UI
CLI         = deterministic one-shot operations
Shortcuts   = native iPad entry points / Share Sheet integration
```

For now, keep `dlf-docs` device-local. The `.env.local` workaround is temporary and the final iPad startup contract is still being established.

The immediate goal is simply:

> **one reliable command to restore the Docs Viewer working environment after reopening iSH.**
