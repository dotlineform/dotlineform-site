# SDM-1 — Studio Documentation Rationalisation

## Complete Result

The Studio documentation has one reviewed current-state baseline: retained documents have clear durable purposes and correct parents, the Studio entry page routes to the useful current owners, redundant or stale manual material has an explicit approved disposition, and affected links remain exact.

This is a documentation delivery. It changes no Studio or Docs Viewer production behavior.

## Why Now

Full-text search will make the complete Studio corpus more visible. Improving retrieval before reviewing the corpus would rank duplicated, stale, or poorly owned material more effectively without making that material more trustworthy.

The current Studio subtree contains 39 documents. Thirty-one are direct Studio children, only 15 of those are linked from the Studio entry page, and several cross-application documents elsewhere contain substantial Studio authority. Those counts identify review pressure; they do not determine the outcome.

## Scope

Review:

- [Studio](/docs/?scope=studio&doc=d-20260423-000000-d015e6), its 38 descendants, and every current entry-page link
- plausible Studio-owned durable documents parented elsewhere
- short, low-inbound, overlapping, verification-only, or manually duplicated documents revealed by the inventory
- inbound and outbound document links affected by any proposed reparent, consolidation, Notes transfer, or retirement
- the boundary between durable current state, active Roadmap planning, and completed history

Classify each reviewed document as one of:

- retain unchanged
- update in place
- reparent with the same `doc_id`
- consolidate into a named durable owner
- propose transfer to external Notes
- propose retirement

Classification is a proposal until the review gate is accepted. Reparenting is not inferred from code-path frequency, and consolidation, Notes transfer, and retirement are never applied without exact approval.

## Current Authority To Inspect

- Studio source documents under `docs-viewer/scopes/studio/source/documents/`
- `parent_id` and the generated Studio index tree for navigation ownership
- [Studio Overview](/docs/?scope=studio&doc=d-20260715-084611-ae9636) and [Studio](/docs/?scope=studio&doc=d-20260423-000000-d015e6) for the current entry model
- current code, configuration, and focused tests only where a document's claimed authority needs verification
- ordinary rendered document links for exact inbound-link impact

No production or test file is part of the expected rationalisation diff.

## SDM-1.0 — Inventory And Decision Gate

Produce a concise review table containing:

- exact `doc_id`, title, current parent, and durable purpose
- inbound-link and entry-page visibility signals
- proposed classification and destination where applicable
- exact source documents and links that an accepted change would touch
- explicit production and test files, expected to remain **none**

Pay particular attention to:

- duplicated current-state explanations split across short documents
- verification records presented as durable architecture
- manually copied registry, route, endpoint, or report inventories
- documents whose parent implies the wrong owner
- completed feature history that no longer helps current Roadmap navigation
- useful low-level reference material that should remain searchable even when it is not linked from the Studio entry page

**Review stop:** present the complete proposed table, expected source-document set, and rough documentation diff before editing any pre-existing document in the SDM-1 application set, changing a parent, moving material to Notes, consolidating content, or retiring a document.
