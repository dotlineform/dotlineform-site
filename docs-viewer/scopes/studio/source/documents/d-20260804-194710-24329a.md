# SSP-0.1 — Exact Subject Info Checkpoint Evidence

## Outcome

The local Manage Info view now receives the validated active sub-scope detail target and its explicit read projection. Projects supplies one passive **Subject** row with **None** or **Folder** plus the portable folder path. The exact `{scope, sub_scope, doc_id}` target replaces the parent report only while its matching detail state is active, including for source-target consumers.

The Projects definition declares the server-owned `authoring_subject` assignable field group over `folder_path`. Its manage browser descriptor projects only the group ID; public configuration omits the private customisation. Info records assignment eligibility as projected state without adding a control, modal, write service, or Markdown parsing in this stage.

## Evidence

- Projects customisation and builder tests prove the typed field group, manage descriptor, and public omission.
- Sub-scope report module smoke proves exact detail record and target propagation, Projects Folder/None projection, and Analysis Tags retaining no subject projection.
- Metadata Info module smoke proves exact target and source target, wrong-target and list fallback, passive rendering, Projects eligibility, and public isolation.
- Manage/public target boundary tests pass against an isolated Projects workspace.
- Explicit JavaScript lint, the Projects sub-scope dry-run/write build, router module smoke, Python compilation, and `git diff --check` pass.

## Independent Review

The reviewed path keeps contribution-specific subject meaning in the Projects customisation and uses only normalized report state in shared Info code. Availability is derived from the declared group ID rather than a collection-name branch. Shared public modules reject the managed projection unless the app kind is Manage, and the public browser configuration receives no private capability.

SSP-0.2 remains unstarted. It owns the visible **Assign subject** action, None/Folder modal, revision-safe mutation, folder normalizer reuse, and removal of `folder_path` from **Edit metadata**.
