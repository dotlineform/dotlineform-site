# Target Lookup

```
docs-viewer/data/generated/semantic-tokens/target-lookup.json

```

## Purpose

The **Add catalogue token** and **Add Catalogue image** search modals are its main UI consumers, but it has a broader purpose.

`target-lookup.json` is the shared manage-side projection of targets currently usable by Semantic Tokens:

- **Add catalogue token** searches current text-link targets across Works and Series.
- **Add Catalogue image** searches only those same rows carrying a valid `image` projection.
- The Info view reads it for the existing target’s Title, link, and metadata.
- The document builder requires an exact row with a workable `href` before rendering a text occurrence as a link, and also requires `image.src` before rendering a visual occurrence.
- Docs Broken Links uses it to distinguish missing targets, missing destinations, and visual targets missing an image projection.

The Semantic Tokens report does **not** read it directly; it reads the generated usage index.

**the target lookup describes what can be linked; the usage index records what has been linked in documents.**

## Row Contract

The current file is `docs_semantic_token_target_lookup_v2`. Every row retains the existing semantic identity, title, destination, and compact metadata. An optional image projection adds only one browser-safe field:

```json
{
  "family": "catalogue",
  "target_type": "work",
  "target_id": "00638",
  "title": "3 symbols",
  "href": "/works/?work=00638",
  "meta": ["2007", "3 symbols"],
  "image": {
    "src": "https://media.dotlineform.com/works/img/00638-primary-1600.webp?v=1"
  }
}
```

`image.src` is either root-relative or HTTPS. The projection contains no canonical record, local filesystem path, provider credential, source filename, media version field, dimensions, or unrelated media metadata.

For a published Work, the builder emits the configured public 1600-pixel primary WebP URL only when the Work has complete current media data.

For a published Series, the builder copies the image projection from only the exact published Work named by `primary_work_id`, and only when that Work belongs to the Series. The row remains a Series target with its Series destination. Missing media, an absent or invalid primary Work, or invalid Series membership removes only `image`; it does not infer another member or remove an otherwise valid text target.

A visual occurrence whose exact row later lacks `image` remains literal source, contributes no resolved usage occurrence, and is reported by Docs Broken Links as `missing_image`. Text occurrences for the same row continue to use its title and destination normally.

## Build

`target-lookup.json` is built by SemanticTargetLookupBuilder, exposed through:

```bash
python docs-viewer/build/build_semantic_target_lookup.py --write
```

The Catalogue JSON build runs this as its “Build Semantic Target Lookup” step,
and Catalogue Work/Series save-and-build workflows refresh it automatically.
Docs scope builds only read the lookup.

The input flow is:

```text
Semantic-token registry
    + canonical Works
    + canonical Series
    -> SemanticTargetLookupBuilder
    -> target-lookup.json
```

Specifically:

- **registry.json** (`docs-viewer/config/semantic-tokens/registry.json`) declares the `catalogue` family, target types, ID normalization, and lookup adapters. It controls the shape, but does not contain target records.
- Works come from `studio/data/canonical/catalogue/works.json`.
- Series come from `studio/data/canonical/catalogue/series.json`.

The builder includes only `published` records with a valid normalized ID, Title, and generated destination. Work metadata includes its date and first Series title.

Destinations are generated by the builder:

- Work → `/works/?work=<id>`
- Series → `/series/?series=<id>`
