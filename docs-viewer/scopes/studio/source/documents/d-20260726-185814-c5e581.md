# Target Lookup

```
docs-viewer/data/generated/semantic-tokens/target-lookup.json

```

## Purpose

The **Add catalogue token** search modal is its main UI consumer, but it has a broader purpose.

`target-lookup.json` is the shared manage-side projection of targets currently usable by Semantic Tokens:

- The Add modal searches it across Works, Series, and Moments.
- The Info view reads it for the existing target’s Title, link, and metadata.
- The document builder requires an exact row with a workable `href` before rendering a token as a link and adding it to the usage index.
- Docs Broken Links uses it to distinguish missing targets from targets lacking a destination.

The Semantic Tokens report does **not** read it directly; it reads the generated usage index.

**the target lookup describes what can be linked; the usage index records what has been linked in documents.**

## Build

`target-lookup.json` is built by SemanticTargetLookupBuilder, exposed through:

```bash
python docs-viewer/build/build_semantic_target_lookup.py --write
```

The Catalogue JSON build runs this as its “Build Semantic Target Lookup” step,
and Catalogue Work/Series save-and-build workflows refresh it automatically.
After a successful written Moments document build, the Docs build orchestration
also refreshes it. Other Docs scope builds only read the lookup.

That Moments follow-through keeps the shared lookup current. It does not rebuild
other scopes containing Moment tokens; their rendered links and usage indexes
refresh on their next document build.

The input flow is:

```text
Semantic-token registry
    + canonical Works
    + canonical Series
    + built Moments documents
    -> SemanticTargetLookupBuilder
    -> target-lookup.json
```

Specifically:

- **registry.json** (`docs-viewer/config/semantic-tokens/registry.json`) declares the `catalogue` family, target types, ID normalization, and lookup adapters. It controls the shape, but does not contain target records.
- Works come from `studio/data/canonical/catalogue/works.json`.
- Series come from `studio/data/canonical/catalogue/series.json`.
- Moments come from:
  - `docs-viewer/scopes/moments/published/documents/index-tree.json`
  - `docs-viewer/scopes/moments/published/documents/by-id/<doc_id>.json`

For Work and Series, the builder includes only `published` records with a valid normalized ID, Title, and generated destination. Work metadata includes its date and first Series title. Moment identity and Title come from the index tree; its by-ID payload supplies date metadata.

Destinations are generated by the builder:

- Work → `/works/?work=<id>`
- Series → `/series/?series=<id>`
- Moment → `/moments/?doc=<doc_id>`
