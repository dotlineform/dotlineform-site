# Catalogue Token Delivery

## Complete Result

Deliver Catalogue as the first complete semantic-token family:

- combined Work, Series, and Moment discovery;
- accepted catalogue-token syntax and family/target data contracts;
- **Add catalogue token** toolbar action and required-data modal;
- caret recognition, exact-range highlighting, Catalogue Info view, update, and
  removal;
- builder parsing and manage-only usage-index generation;
- migration of the active Work occurrence into the Catalogue family;
- semantic-token diagnosis and repair through the existing manage-only **Docs
  Broken Links** report.

This delivery proves that an author can begin with ambiguous text, compare
different catalogue entity types, choose the best association, and then maintain
the occurrence without changing its identity. It does not add Tag, asset, image,
file, or another token family.

CT-P1 implementation is complete and stopped at its UI review gate. It adds
manage-only local source-buffer creation behavior. P2 recognition, projection,
usage data, and maintenance behavior have not started.

## Delivery Rule

Deliver the smallest complete vertical capability that replaces the existing
Work token and leaves an additive path for later fields and token families.
This delivery does not need to predict the final registry, every projection, or
the next refactor.

Work, Series, and Moment share one minimal Catalogue lookup shape. The active
`3 symbols` Work occurrence is the migration and completion specimen. Richer
type-specific fields are added only when a later UI or consumer requires them.

## CT-P0 Scope And Impact

The versioned contract fixture at
`docs-viewer/tests/fixtures/semantic_tokens_catalogue_v1.json` is the exact P0
authority. It records the grammar, Catalogue definition, resolved and broken
specimens, ambiguous `nerve` discovery rows, and minimum lookup, usage, and
broken-link shapes. The fixture is test input, not runtime configuration.

This checkpoint prevents Python/browser grammar drift and gives the later UI,
builder, usage, and audit work one additive contract. The main risk is freezing
syntax before tactile UI review; P1 therefore remains a separate review gate.
There is no public, write-service, security, semantic-token generated-output, or
production runtime change in P0. Routine Studio document and search projections
may update from these source-document edits.

production behavior. Stop for review after P0 and do not start P1 until the

### P1 Scope And Impact

The manage source editor now contributes `source-add-catalogue-token` through a
generic main-view control handler and projects its enabled state through a
generic source-action id list. The Catalogue-owned modal captures the source
range before focus moves, adapts the existing generated Work, Series, and Moment
lookup, validates a current result and required Title at confirmation, and
guarded-replaces only the captured local range.

The lookup rows now carry the P0-required workable `href`. This remains the
pilot `semantic-references` generated artifact until the accepted P2/P3
replacement and cleanup; P1 does not add a semantic-token registry, parser,
builder projection, usage index, report, public payload, or write endpoint.
The former manage-only Info-panel picker and its immediate select-to-insert
composition are removed. Ordinary metadata information remains the source-mode
Info-panel default until P2 adds caret-driven Catalogue information.

### P1 UI Review Gate

Automated behavior is green, but the P1 gate remains open for manual tactile
review of the live manage route: ambiguous `nerve` comparison, visible target
distinction, selection prefilling, insertion and cancellation feel, keyboard
use, modal fit, and narrow layout. Do not begin P2 until that review is accepted.

Individual result rows remain outside the tab order. The Results list is one tab
stop between Search and Title; while it is focused, Up/Down moves and reveals the
active result and Enter commits it. The list deliberately suppresses the shared
modal focus border for every list focus state, not only `:focus-visible`; the
moving active-row highlight carries the interaction state without clipped or
doubled scroller edges. Border-box sizing still keeps result content within the
scroller. Committing any result by click or Enter refreshes Title from that
result; the author can then edit the occurrence Title. The modal confirmation
label is **Add**. The source-toolbar action uses 📍 so the conventional link icon
remains available for a future generic link action. This interaction remains at
the P1 gate for user re-review.
