# Scope Media Management

## Purpose

Begin scope media management with one truthful read-only answer to one question: which documents, if any, reference each ready-media or registered build-source file currently present in a selected Docs Viewer scope?

The first report is deliberately a live media-to-document inventory. It includes every existing ready-media file and registered build-source file, including files with no document references. A document reference whose ready-media file does not exist is not a Docs Media row; that belongs to a separate future **Media Broken Links** report. Recorded-original evidence, byte totals, broader health states, and media actions are not part of this first outcome.

## Feature Documents

- [Docs Media Report Concept](/docs/?scope=studio&doc=d-20260720-100017-e094d8) — the exact live-file row, separate Type and File name columns, Project State-format list, document-link, scope-selection, refresh, search, and sorting contract.
- [Docs Media Report Delivery](/docs/?scope=studio&doc=d-20260720-100017-7e52de) — DMR-1 exact live rows are complete and parked for review before the local report route and UI.

## Boundary

- Scope configuration remains the ownership and managed-location authority.
- The live provider-neutral listing of configured ready-media and registered build-source locations plus exact document-media references are the only first-report data inputs.
- The report is local, read-only, hosted in the Dotlineform scope, and may inspect any configured parent scope selected from its dropdown.
- The surface reuses the [Project State](/docs/?scope=dotlineform&doc=d-20260805-155400-4c341f) list format with separate Type, File name, and Documents columns plus a scope selector, refresh pill, and search across file names and document titles.
- Every exact ready-media or build-source file remains visible when no document references it; its Documents cell is blank.
- Referenced identities absent from the live managed-file listing are excluded. Missing-reference diagnosis belongs to the separate future Media Broken Links report, which is not designed or started here.
- The first report does not join retained-original source evidence.
- Storage-provider details and absolute paths remain server-side.
- The report does not hash, continuously verify, repair, mutate, delete, republish, or roll back media files.

DMR-1 has delivered the focused server-side exact-row read model. Report registration, the local route, host document, UI, and runtime product remain unstarted pending DMR-2 approval.
