## Writes, Plans, And Transactions

All listed paths are mounted below `/analytics/api`. `OPTIONS` mirrors every
POST path.

| endpoint | contract |
| --- | --- |
| `POST /save-tags` | save or remove one Series or Work assignment row from `series_id`, optional `work_id`, `keep_work`, and normalized weighted `tags` |
| `POST /import-tag-assignments-preview` | validate an offline-session assignment payload and report applicable, conflict, invalid, and missing Series rows without writing |
| `POST /import-tag-assignments` | apply the previously represented assignment import using explicit per-Series conflict resolutions |
| `POST /import-tag-registry` | add or merge sanitized canonical tag rows; also supplies the one-tag create path |
| `POST /import-tag-aliases` | add or merge sanitized alias rows; also supplies the one-alias create path |
| `POST /delete-tag-alias` | delete one confirmed alias |
| `POST /mutate-tag-alias-preview`, `POST /mutate-tag-alias` | preview then apply alias key, description, or target edits |
| `POST /promote-tag-alias-preview`, `POST /promote-tag-alias` | preview then apply alias promotion into a canonical tag |
| `POST /demote-tag-preview`, `POST /demote-tag` | preview then apply canonical-tag demotion, including alias and assignment rewrites |
| `POST /mutate-tag-preview`, `POST /mutate-tag` | preview then apply canonical edit, rename/rewrite when explicitly allowed, or delete |

Registry and alias import confirmation is browser-owned; those imports do not
have separate HTTP preview endpoints. Direct write failure preserves the
current manual-patch fallback for registry and alias create/import/edit/delete.
Series Tag Editor direct write failure switches to its offline-session path.

The retained Python boundary is:

- `tag_source_paths.py`: source and public Series-index paths;
- `tag_source_model.py`: IDs, groups, weights, aliases, import limits, payload
  loading, and assignment-session validation;
- `tag_assignment_service.py`: Series-first assignment save and import
  preview/apply planning;
- `tag_registry_mutations.py`, `tag_alias_mutations.py`, and
  `tag_promotion_mutations.py`: registry, alias, promote/demote, and dependent
  reference plans;
- `tag_write_transactions.py`: single-file atomic replacement and multi-file
  staging, replacement, and rollback;
- `tag_activity.py`: write-only activity attachment;
- `tag_routes.py`: the 14 POST paths;
- `tag_write_api/`: HTTP request/result adapters.

## Tag Policy

Retained tag policy currently lives in
`analytics-app/app/frontend/config/analytics-config.json`:

- ordered and coverage groups: `subject`, `domain`, `form`, `theme`;
- completeness denominator `4`, tag bonus maximum `0.25`, bonus cap at `6`
  total tags, score cap `1.0`;
- red when total tags equal `0` or unknown tags are greater than `0`;
- amber when groups present are at most `1`, total tags are below `3`, or both
  `form` and `theme` are absent;
- green as fallback.

Allowed canonical groups remain registry policy in `tag-registry.json`, with
the Python model fallback matching the same four groups. The route registry,
shell paths, public data paths, media settings, and Analytics host/runtime
projection are not tag policy and must not move into the focused Studio tag
config.

## Activity And Offline Session

The activity contract currently registers 13 write actions:

- Series Tags: `import-series-tag-assignments`;
- Series Tag Editor: `save-series-tags`;
- Tag Registry: `import-tag-registry`, `create-tag`, `edit-tag`, `delete-tag`,
  and `demote-registry-tag`;
- Tag Aliases: `import-tag-aliases`, `create-tag-alias`, `edit-tag-alias`,
  `delete-tag-alias`, `promote-tag-alias`, and `demote-aliases-tag`.

All use script purpose `save-tag-data`, skip no-change activity, and attach only
on non-dry-run write paths. The browser supplies page, action, route, control,
correlation, and record identity. The service derives tag or alias record
groups where present and writes through the unified Studio activity owner.

The Series Tag Editor reuses one initiating activity context across a save that
may issue a Series request plus multiple Work requests. Preserve that behavior
when the API moves.

The offline assignment contract is:

- local-storage key `dotlineform.studio.tagAssignmentsOffline.v1`;
- envelope version `tag_assignments_offline_v1`;
- top-level `updated_at_utc` and `series` map;
- each staged Series entry stores `base_series_updated_at_utc`,
  `base_row_snapshot`, `staged_row`, and `staged_at_utc`;
- Series rows contain weighted `tags` and optional Work rows with weighted
  `tags`; tag rows preserve optional alias context.

The Series Tags route owns export, copy, download, clear, preview, explicit
conflict resolution, apply, and removal of only successfully imported matching
session entries.

canonical Series row exists; it does not project tag rows into public Series or
Work JSON. This is the current basis for expecting unchanged public catalogue
artifacts during the ownership move.

## Package Boundary

No live Analytics source, route, API, frontend module, or tag service imports a
tag-package or document-package subsystem. Analytics server tests retain
negative assertions that Data Sharing and document-package paths are not
composed.

Integrated document packages remain separately owned under
`docs-viewer/services/docs_document_packages/` and
`docs-viewer/runtime/js/packages/`. They share no runtime or source authority
with the tag cutover and do not move with it.

The Data Sharing selectors still present in `analytics.css` are retirement
residue, not evidence of a package dependency.
