# SSP-7 — Document Lineage And Publication State Delivery

[SSP-7.1a — Publishable Contract Cutover Evidence](/docs/?scope=studio&doc=d-20260807-224018-4c1687) completes that clean cut, [SSP-7.1b — Set Publishable Evidence](/docs/?scope=studio&doc=d-20260807-235046-5c0d8a) adds the exact-selection publication gate, [SSP-7.2 — Lineage And New/Replace Copy Evidence](/docs/?scope=studio&doc=d-20260808-110434-7b4c2d) proves the private exact A-to-B table plus explicit Copy choice, [SSP-7.3 — Successful Publish Reconciliation Evidence](/docs/?scope=studio&doc=d-20260808-131132-c93e41) proves the small post-Publish public-URL update, and [SSP-7.4 — Projects Publication Stage Evidence](/docs/?scope=studio&doc=d-20260808-134503-a4caeb) records the Projects-only report presentation. SSP-7 is now stopped at the SSP-7.4 review gate before broad verification and transfer:

```text
A — Working document in dotlineform/projects
  -> 🟠 Pre-publish B in analysis/works (local)
       -> 🟢 Published B on the public site
```

A and B remain separate canonical documents. The public JSON is a projection of B and retains B's identity; it is not a third canonical document. SSP-7 does not compare content, present a diff, merge changes, synchronize A and B, or decide automatically whether a later Copy should create or replace.

## Complete Outcome

One private persisted table records exact working-source, editorial-target, and current public-projection evidence. Its row grain is one exact A-to-B relationship. A may have zero, one, or several B rows, but every additional B is created deliberately.

Before lineage work, SSP-7 performs one coordinated clean-cut from the legacy `viewable` field to `publishable`. The new field exists only for a parent or child collection that participates in an owning public scope's Publish projection. Omission means publishable; `publishable: false` means exclude that document, and for parent trees its descendants, from the next scope Publish. Legacy `viewable` is removed from source, private projections, requests, packages, reports, configuration, and runtime state without an alias or dual reader.

The shared Docs management UI removes the legacy **non-viewable** control from **Edit metadata** and adds checkbox-aware **Set Publishable…** only to exact publish-capable parent Index and default sub-scope selection surfaces. It operates on every exact checked document and offers **Include in next Publish** or **Exclude from next Publish** with the selected count, **OK**, and **Cancel**. Local and local-external scopes have neither the field nor the action. If their pre-cutover audit reveals a real need to suppress local search or discovery, that becomes a separately reviewed `discoverable` contract rather than a hidden continuation of publication state. The existing scope-wide **Publish** remains unchanged and is still the sole public mutation.

When **Copy to…** targets a lineage-enabled configured workflow:

- if no eligible B exists, **New** creates a fresh B and adds one table row;
- if one or more B rows already exist, the author chooses **New** or **Replace**;
- **New** creates another independent B with a fresh `doc_id` and another row; and
- **Replace** requires selection of one exact existing B belonging to A, preserves B's identity and publication gate, replaces its source through the target's ordinary transformation, and updates that row's copy evidence.

Replace is an explicit destructive choice with preview and confirmation, but no content comparison or merge. It preserves B's `doc_id`, filename, `added_date`, exact collection placement, and current `publishable` value; it replaces the authoring content and transferable metadata, advances `last_updated`, rebuilds the exact target collection, and never publishes automatically.

The existing scope-wide **Publish** operation remains the only public mutation authority. After successful Publish, it checks exact configured editorial B public by-ID files and records `{public_url}` or clears `publication` in the small private row list. It adds no second Publish workflow, receipt extension, timestamp, generation hash, or special recovery protocol.

## Persisted Table Contract

The delivery owns one schema-versioned private product at `docs-viewer/data/canonical/document-publication-lineage.json`. Its exact top-level contract and one illustrative row are:

```json
{
  "schema_version": "docs_document_publication_lineage_v1",
  "rows": [
    {
      "source": {
        "scope": "dotlineform",
        "sub_scope": "projects",
        "doc_id": "A"
      },
      "editorial": {
        "scope": "analysis",
        "sub_scope": "works",
        "doc_id": "B"
      },
      "created_at": "2026-08-05T22:00:00Z",
      "last_copied_at": "2026-08-05T22:00:00Z",
      "publication": {
        "public_url": "/analysis/?doc=d-20260807-082735-54d9d5&subdoc=B"
      }
    }
  ]
}
```

Exact `{scope, sub_scope, doc_id}` identities are the only join keys. `publication` is `null` when B has no current public projection and otherwise contains only its exact public URL. The table never infers lineage from subject, title, filename, body, dates, selected row, current route, or public URL. It stores no copied body, content comparison, diff, merge base, semantic relationship, public timestamp/history, generation digest, or public Folder data.

The table is current operational evidence rather than report presentation. Copy and Publish own its writes through their confirmed mutation boundaries. The Projects report is its only presentation consumer. Rows remain zero-to-many by source and unique by exact source/editorial pair. If B later becomes unavailable, the row remains exact historical lineage and the report presents the target as unavailable without fallback or automatic repair.

## Publication And Publishability Meaning

`publishable` is the canonical inclusion gate for the next scope Publish. **Set Publishable…** changes this source-owned gate for exact checked documents in an exact publish-capable collection without publishing. It is not proof that B is currently present on the site. Current publication is established only by the successful public projection recorded by Publish.

Local and local-external scopes have no Publish projection, so `publishable` has no meaning there. Their documents remain ordinary locally generated and discoverable Manage documents. SSP-7.1 audits and removes legacy local `viewable` values without translating them. Any intentional local discovery suppression is a stop-and-review signal for a distinct `discoverable` contract; it is not inferred from the old field.

The Projects report deliberately glosses over this eligibility detail and uses three simple stages:

- **Working** — A exists in `dotlineform/projects` and has no B lineage target;
- **🟠 Pre-publish** — B exists locally in `analysis/works` and has no current public projection; and
- **🟢 Published** — B has a current public-site projection.

A B with `publishable: false` remains **🟢 Published** while its prior public projection still exists. After the next successful scope Publish removes that projection, it becomes **🟠 Pre-publish**. A newly copied, included, or excluded editorial B without a public projection is likewise **🟠 Pre-publish**; Projects does not expose the finer eligibility distinction.

No stored generic `stage` field becomes canonical truth. The browser derives Working, 🟠 Pre-publish, 🟢 Published, and unavailable presentation from exact lineage and current publication evidence.

## Report And Icon Ownership

The normal `dotlineform/projects` report uses the table to show publication progress beside working document A:

- **Working** when A has no B;
- **🟠 Pre-publish** beside each current B without a public projection; and
- **🟢 Published** beside each B with a current public projection.

If A has B rows in more than one stage, both distinct cues may appear. Accessible labels and focused detail expose every exact B target and current stage without collapsing zero-to-many lineage into an inferred primary document.

The Projects report is the only publication-stage presentation surface. Its existing Folder, Work, and Series row icons are removed because Project State already owns that subject-route presentation. The `analysis/works` Manage report adds no publication-stage cue; its existing exclusion icon remains sufficient whenever `publishable: false` and retains the accessible meaning **Excluded from next Publish**. Projects does not need `publishable` in its stage projection. Local scopes show no publication-exclusion icon. Project State document icons remain unchanged: they show the Folder, Work, or Series subject route through which a document entered a Project State row, not publication progress.

## Delivery Discipline

SSP-7 first replaces the ambiguous viewability contract with public-scope publishability and exposes that gate through shared exact-selection management. It then extends the existing configured Copy and scope Publish owners rather than creating a second transfer or publication workflow. The persisted table is justified because A-to-B identity cannot be reconstructed after Copy from subject, title, or public output. It is not a general provenance graph, activity log, document-version store, or report snapshot.

SSP-7.0 is a short scope-and-spec sanity gate. It confirms the current one-document metadata mutation, parent and sub-scope selection owners, Copy mapping/result, opt-in customisation boundary, exact replacement transformation, Publish changed/removed inventory, table ownership, and report seams before implementation. Each later step ends with focused evidence and an independent diff review.

## Not In Scope

- content comparison, diff, merge, three-way merge, or selective updates;
- automatic synchronization or propagation after A or B changes;
- automatically choosing New or Replace;
- replacing a B that is not an exact selected lineage target of A;
- treating subject identity, title, filename, URL, or similarity as lineage;
- one-to-one source cardinality or an inferred primary B;
- automatic publishability changes or publication during Copy/Replace;
- a local `discoverable` replacement or any other local visibility policy without a separate reviewed contract;
- a new per-document Publish action or change to scope-wide Publish authority;
- public exposure of A identity or the private table;
- document version history, rollback, audit-event history, or a general provenance graph;
- Project State subject placement or icons; or
- SSP-5 Work/Series `doc_url[]`, which remains derived from final published subject front matter.
