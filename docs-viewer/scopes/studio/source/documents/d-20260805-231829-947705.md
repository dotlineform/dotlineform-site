# SSP-7 — Document Lineage And Publication State Delivery

## Status And Purpose

Proposed after [SSP-4 — Collection-Aware Document Copy Delivery](/docs/?scope=studio&doc=d-20260801-233534-239eab) supplies exact configured collection Copy and `analysis/works`. SSP-7 adds the missing durable workflow relationship and status projection:

```text
A — Working document in dotlineform/projects
  -> 🟠 Pre-publish B in analysis/works (local)
       -> 🟢 Published B on the public site
```

A and B remain separate canonical documents. The public JSON is a projection of B and retains B's identity; it is not a third canonical document. SSP-7 does not compare content, present a diff, merge changes, synchronize A and B, or decide automatically whether a later Copy should create or replace.

## Complete Outcome

One private persisted table records exact working-source, editorial-target, and current public-projection evidence. Its row grain is one exact A-to-B relationship. A may have zero, one, or several B rows, but every additional B is created deliberately.

Before lineage work, the shared Docs management UI moves the existing `viewable` mutation out of **Edit metadata** and into a checkbox-aware **Set Publishable…** action. The action is available from the parent Index and default sub-scope selection surfaces, operates on every exact checked document, and offers **Include in next Publish** or **Exclude from next Publish** with the selected count, **OK**, and **Cancel**. It updates local source and generated management projections only; the existing scope-wide **Publish** remains unchanged and is still the sole public mutation.

When **Copy to…** targets a lineage-enabled configured workflow:

- if no eligible B exists, **New** creates a fresh B and adds one table row;
- if one or more B rows already exist, the author chooses **New** or **Replace**;
- **New** creates another independent B with a fresh `doc_id` and another row; and
- **Replace** requires selection of one exact existing B belonging to A, preserves B's identity and publication gate, replaces its source through the target's ordinary transformation, and updates that row's copy evidence.

Replace is an explicit destructive choice with preview and confirmation, but no content comparison or merge. It preserves B's `doc_id`, filename, `added_date`, exact collection placement, and current `viewable` value; it replaces the authoring content and transferable metadata, advances `last_updated`, rebuilds the exact target collection, and never publishes automatically.

The existing scope-wide **Publish** operation remains the only public mutation authority. After successful Publish, it reconciles the affected table rows with the exact public B projections, recording or clearing current public URL, publication time, and publication generation. A failed Copy or Publish never advances the table beyond the canonical/public operation it describes.

## Persisted Table Contract

The delivery owns one schema-versioned private product, provisionally `docs_document_publication_lineage_v1`. SSP-7.0 freezes its exact path and field names. An illustrative row is:

```json
{
  "source": {
    "scope": "dotlineform",
    "sub_scope": "projects",
    "doc_id": "A"
  },
  "editorial": {
    "scope": "analysis",
    "sub_scope": "works",
    "doc_id": "B"
  },
  "created_at": "2026-08-05T22:00:00Z",
  "last_copied_at": "2026-08-05T22:00:00Z",
  "publication": {
    "public_url": "/analysis/?doc=B",
    "published_at": "2026-08-05T22:30:00Z",
    "generation": "..."
  }
}
```

Exact `{scope, sub_scope, doc_id}` identities are the only join keys. The table never infers lineage from subject, title, filename, body, dates, selected row, current route, or public URL. It stores no copied body, content comparison, diff, merge base, semantic relationship, or public Folder data.

The table is current operational evidence rather than report presentation. Copy and Publish own its writes through their confirmed mutation boundaries. Projects and Analysis reports are read-only consumers. Rows remain zero-to-many by source and unique by exact source/editorial pair. If B later becomes unavailable, the row remains exact historical lineage and the report presents the target as unavailable without fallback or automatic repair.

## Publication And Viewability Meaning

`viewable` remains the canonical inclusion gate for the next scope Publish. **Set Publishable…** changes this local gate for the exact checked documents without publishing. It is not proof that B is currently present on the site. Current publication is established only by the successful public projection recorded by Publish.

The Projects report deliberately glosses over this eligibility detail and uses three simple stages:

- **Working** — A exists in `dotlineform/projects` and has no B lineage target;
- **🟠 Pre-publish** — B exists locally in `analysis/works` and has no current public projection; and
- **🟢 Published** — B has a current public-site projection.

A B with `viewable: false` remains **🟢 Published** while its prior public projection still exists. After the next successful scope Publish removes that projection, it becomes **🟠 Pre-publish**. A newly copied, included, or excluded local B without a public projection is likewise **🟠 Pre-publish**; Projects does not expose the finer eligibility distinction.

No stored generic `stage` field becomes canonical truth. The browser derives Working, 🟠 Pre-publish, 🟢 Published, and unavailable presentation from exact lineage and current publication evidence.

## Report And Icon Ownership

The normal `dotlineform/projects` report uses the table to show publication progress beside working document A:

- **Working** when A has no B;
- **🟠 Pre-publish** beside each current B without a public projection; and
- **🟢 Published** beside each B with a current public projection.

If A has B rows in more than one stage, both distinct cues may appear. Accessible labels and focused detail expose every exact B target and current stage without collapsing zero-to-many lineage into an inferred primary document.

The `analysis/works` Manage report may show B's actual publication cue separately from the existing non-viewable icon, which remains visible whenever `viewable: false`. Projects does not need `viewable` in its stage projection. Project State document icons remain unchanged: they show the Folder, Work, or Series subject route through which a document entered a Project State row, not publication progress.

## Delivery Discipline

SSP-7 first makes the existing viewability gate explicit through shared exact-selection management, then extends the existing configured Copy and scope Publish owners rather than creating a second transfer or publication workflow. The persisted table is justified because A-to-B identity cannot be reconstructed after Copy from subject, title, or public output. It is not a general provenance graph, activity log, document-version store, or report snapshot.

SSP-7.0 is a short scope-and-spec sanity gate. It confirms the current one-document metadata mutation, parent and sub-scope selection owners, Copy mapping/result, opt-in customisation boundary, exact replacement transformation, Publish changed/removed inventory, table ownership, and report seams before implementation. Each later step ends with focused evidence and an independent diff review.

- [ ] Sanity-check the current `viewable` mutation and generated follow-through, exact parent and sub-scope selection owners, exact A-to-B mapping already present during Copy planning/apply, configured source/destination capability boundary, target-safe replacement rules, current scope-wide Publish preview/apply, public document inventory, and Projects/Analysis report composition.
- [ ] Freeze the table's exact owner, path, schema, atomic-write and recovery boundary, zero-to-many cardinality, unavailable-target retention, and public-isolation rules.
- [ ] Confirm the deliverables: checkbox-aware **Set Publishable…**, explicit New/Replace choice, one persisted exact lineage table, Publish reconciliation, simple Working / 🟠 Pre-publish / 🟢 Published stages, focused evidence, and concise durable owner updates.
- [ ] Stop for review if the result requires content comparison, merge, synchronization, automatic choice, title/subject inference, a generic provenance graph, a second Publish workflow, or replacement of arbitrary documents outside exact lineage rows.

**Checkpoint:** a concise sanity note confirms the SSP-4 dependency, exact selection and viewability owners, table authority, destructive Replace boundary, Publish ordering, report row grain, risks, and stop condition. Stop before implementation approval.

### SSP-7.1 — Set Publishable

- [ ] Show the exact checked-document count and one required option group containing **Include in next Publish** and **Exclude from next Publish**, followed by **OK** and **Cancel**.
- [ ] Add one focused atomic batch mutation that validates every checked document regardless of its current value, removes explicit `viewable: false` for Include, writes `viewable: false` for Exclude, leaves already-matching documents unchanged, and rebuilds the exact parent scope or sub-scope once.
- [ ] Retain the existing non-viewable icon in the Index and sub-scope report whenever current `viewable` is false. Do not invoke or alter scope-wide **Publish**.

**Checkpoint:** focused service and pure browser evidence covers parent and sub-scope targets, one and several checked documents, mixed current values, all-no-op sets, stale or unavailable targets, atomic failure containment, exact rebuild ownership, modal copy, retained icons, and unchanged scope-wide Publish. Independent review confirms no second publication workflow, per-document Publish, selection fallback, or parallel viewability field was introduced. Stop before SSP-7.2.

### SSP-7.2 — Persist Lineage And Add New/Replace Copy

- [ ] Add the schema-versioned private table and one validated, atomically written row per exact A-to-B relationship.
- [ ] Make lineage-enabled Copy planning return the exact existing B choices for A and require explicit **New** or **Replace** when a choice exists.
- [ ] Keep **New** on the existing fresh-identity transformation and add the exact replacement transformation that preserves B identity, placement, `added_date`, and `viewable` while replacing content and transferable metadata.
- [ ] Bind Replace to one selected current table row, exact target digest, target collection, and confirmed receipt; never fall back to another B or overwrite an unrelated document.
- [ ] Update `created_at` only for New and `last_copied_at` for New or Replace after the coordinated target mutation succeeds.

**Checkpoint:** focused planner/apply evidence passes for no existing B, one B, several B rows, New, exact Replace, stale target, unavailable B, failure containment, source stability, target rebuild, and table agreement. Independent review confirms no diff, merge, sync, inference, or generic overwrite path was introduced. Stop before SSP-7.3.

### SSP-7.3 — Reconcile Successful Publish

- [ ] Extend the existing scope-wide Publish plan/receipt with the exact lineage rows affected by added, changed, retained, and removed public B projections.
- [ ] After successful public apply, record current public URL, publication time, and generation for published B rows and clear current publication evidence for removed B rows.
- [ ] Preserve the distinction between a current public projection and B's current `viewable` gate; Replace never updates public evidence and Publish never rewrites A or B.
- [ ] Define and verify the contained failure boundary so the table never claims a public generation that did not commit and any post-public table failure remains explicit and recoverable from exact current public evidence.

**Checkpoint:** focused Publish preview/apply evidence proves first publication, republish after Replace, retained public B, removal after `viewable: false`, unavailable B, exact generation agreement, failure containment, and public isolation. Stop before SSP-7.4.

### SSP-7.4 — Show Publication Stages In Reports

- [ ] Project exact lineage/publication rows into the normal Projects report and render **Working**, **🟠 Pre-publish**, and **🟢 Published** without changing the report's document identity or selection owner.
- [ ] Resolve every displayed B title and Manage link through the current exact document-location owner; show unavailable targets explicitly and never copy presentation into table identity.
- [ ] Keep `viewable` out of the Projects stage projection: a local B without public evidence is **🟠 Pre-publish**, while a B with current public evidence is **🟢 Published** until a later successful Publish removes that evidence.

**Checkpoint:** focused pure projection and service/module evidence covers zero, one, several, mixed-stage, Working, 🟠 Pre-publish, 🟢 Published, unavailable, and changed-viewability-before-Publish rows. Manual review confirms the coloured cues are quickly distinguishable and remain separate from the Analysis non-viewable and Project State subject icons. Stop before SSP-7.5.

### SSP-7.5 — Verify And Transfer

- [ ] Run focused Set Publishable, Copy, Replace, table, Publish, report, location, public-isolation, lint, whitespace, and generated-projection checks.
- [ ] Verify the full configured path: create A, New-copy B, Publish B, Replace B from A without publishing, and Publish again while retaining A/B identities and one exact lineage row.
- [ ] Verify that excluding a currently published B leaves it **🟢 Published** until scope Publish removes the public projection, after which it becomes **🟠 Pre-publish** while retaining B and its lineage row.
- [ ] Prove another New creates a distinct B and second row only after explicit selection.
- [ ] Perform the independent final code/delivery review and transfer stable table, Copy, Publish, and report contracts to their durable owners.

## Not In Scope

- content comparison, diff, merge, three-way merge, or selective updates;
- automatic synchronization or propagation after A or B changes;
- automatically choosing New or Replace;
- replacing a B that is not an exact selected lineage target of A;
- treating subject identity, title, filename, URL, or similarity as lineage;
- one-to-one source cardinality or an inferred primary B;
- automatic viewability changes or publication during Copy/Replace;
- a new per-document Publish action or change to scope-wide Publish authority;
- public exposure of A identity or the private table;
- document version history, rollback, audit-event history, or a general provenance graph;
- Project State subject placement or icons; or
- SSP-5 Work/Series `doc_url[]`, which remains derived from final published subject front matter.

## Completion Evidence

- Every displayed stage traces through one exact persisted A-to-B row and current successful Publish evidence.
- **Set Publishable…** owns exact checked-document viewability changes without publishing, and Edit metadata no longer presents the field.
- New always creates a fresh B; Replace always preserves one explicitly selected B identity and current `viewable` gate.
- A and B remain independently editable; later changes trigger no automatic propagation.
- Publish alone establishes or removes current public evidence, and public JSON remains a projection of B.
- The Projects report distinguishes Working, 🟠 Pre-publish, 🟢 Published, mixed, and unavailable states without exposing viewability details or inferring identity.
- Analysis retains its non-viewable icon separately from actual publication presentation.
- Project State subject icons, semantic-token usage, SSP-5 public metadata, and public runtime remain independent.

[Sub-Scope Publishing](/docs/?scope=studio&doc=d-20260802-194357-4d857b) owns sequencing. Shared Docs management owns **Set Publishable…** and the stored `viewable` gate; SSP-4 owns the base exact-collection New-copy workflow; SSP-7 owns persisted lineage, exact Replace, Publish reconciliation, and publication-stage presentation.
