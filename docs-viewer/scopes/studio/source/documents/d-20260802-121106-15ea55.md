# SSP-6 — Project Media Audit Delivery

## Status And Purpose

Proposed after SSP-2 proves the existing local Docs Viewer report-host mechanism with a server-run report. The current `var/studio/reports/project-state.md` is useful, but it is an image audit rather than the folder-centred Project State model.

SSP-6 preserves that capability under the accurate name **Project Media Audit** and is the only delivery that retires the current `/studio/project-state/` route, report/open APIs, activity contract, generator placement, and static Markdown output.

## Complete Outcome

One ordinary local Docs Viewer report-host document runs the existing project media audit and renders its current result through the established report module and service seams. It retains the useful inventory of source folders, source images, catalogue primary-image references, unrepresented images and folders, missing source files, and incomplete Work media fields without saving generated report Markdown.

The new audit is read-only. It does not modify Works, files, Project documents, Project State rows, or resolver data. Once accepted parity is demonstrated, the misleading Studio Project State name and duplicate static output are removed.

## Boundary With Project State

Project State owns:

- scanned-real-folder rows with independent `documents[]` and `works[] -> series memberships[]` joins;
- the live Folder/Docs/Works-by-Series report;
- the folder-keyed resolver lookup; and
- targeted relationship follow-through.

Project Media Audit owns:

- image-extension and folder/image scan policy;
- comparison with canonical Work `project_folder`, optional `project_subfolder`, and `project_filename` evidence;
- image-level exception sections and counts; and
- retirement of the current Studio report workflow.

Neither output is an input to the other.

## Delivery Discipline

SSP-6 should migrate the existing proven audit rather than redesigning it inside Project State. SSP-6.0 is a short scope-and-spec sanity gate over the current Studio workflow, existing local Docs Viewer report-host mechanism, parity target, and retirement boundary. It confirms broad owners, blast radius, deliverables, risks, and stop conditions without freezing exact files, fixtures, estimates, or implementation. Each implementation stage ends with focused evidence and an independent code/diff review before the next stage begins.

A generic audit framework, repair workflow, automatic deletion action, continuous watcher, or new media registry is scope creep and requires separate approval.

## Delivery Steps

### SSP-6.0 — Confirm Scope And Delivery

- [ ] Sanity-check parity-preserving Project Media Audit migration against the current Studio report behavior and the existing local report-host mechanism exercised by SSP-2; resolve only contradictions that would change the retained audit outcome.
- [ ] Confirm the broad blast radius across the current route/API/activity/generator/output, shared image-extension policy, audit scan/result behavior, report registry/loader/service, live Run/Refresh, failure presentation, and old-workflow retirement.
- [ ] Confirm the deliverables: one accurately named live local audit, demonstrated parity, contained current-run failure, complete old-workflow retirement after acceptance, focused evidence, and concise durable owner updates.
- [ ] Stop for review if the result requires audit redesign, Project State relationship changes, a generic audit framework, repair/deletion workflow, watcher, media registry, or another boundary excluded above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, SSP-2 dependency, broad owners, blast radius, deliverables, parity risks, local-only boundary, and stop condition. Stop before implementation approval.

### SSP-6.1 — Publish Project Media Audit

- [ ] Move reusable image-extension policy to a neutral owner if the trace confirms another catalogue consumer.
- [ ] Rehome the audit producer without changing canonical catalogue readers or folder containment.
- [ ] Register and validate one ordinary local Docs Viewer report-host document and focused audit module through the existing registry, loader, and service seams.
- [ ] Run the audit through live report execution with explicit Run/Refresh and a contained error on failure; do not persist generated Markdown or prior report presentation.
- [ ] Verify real and fixture output against the current report before retirement.

**Checkpoint:** focused audit, containment, report-host/loader/service, live-run failure, and real/fixture parity evidence passes. An independent code/diff review confirms canonical catalogue readers, Project State relationships, and the existing Studio workflow retain their current values until retirement is approved. Stop before SSP-6.2.

### SSP-6.2 — Retire The Studio Project State Workflow

- [ ] Remove or reroute the Studio page, report/open endpoints, frontend, activity contract, old generator entry point, and obsolete focused tests.
- [ ] Remove `var/studio/reports/project-state.md` only after the accepted Docs Viewer audit contains the required evidence.
- [ ] Update durable report, catalogue, and Projects documentation to the new owner and name.
- [ ] Run focused audit, containment, report-host/loader/service, live failure, lint, and whitespace checks.
- [ ] Perform the independent final code/delivery review, reconcile parity and retirement claims with exact evidence and omissions, and record any bounded follow-up trigger.

## Not In Scope

- Project State folder rows, `works[]`, `series[]`, or resolver lookups;
- changing Work media metadata;
- deciding that an unrepresented or missing file should be imported, moved, renamed, or deleted;
- Work-detail auditing beyond the current explicit exclusions; or
- public audit output.

## Completion Evidence

- The live Project Media Audit accounts for every retained current summary and exception class.
- Real-data comparison records any accepted differences from the final `var/studio/reports/project-state.md` generation.
- A failed audit run shows a contained current error without retained browser presentation.
- Studio has no remaining Project State page, report/open API, activity entry, generator entry point, or static Markdown output.
- Project State report and resolver fixtures remain unchanged by the audit migration.
