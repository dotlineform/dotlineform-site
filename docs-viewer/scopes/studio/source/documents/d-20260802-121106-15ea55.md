# SSP-6 — Uncataloged And Missing Source Files Reports Delivery

## Status And Purpose

Proposed after SSP-2 proves the existing local Docs Viewer report-host mechanism with a server-run report. The current `var/studio/reports/project-state.md` mixes several image-audit sections under the misleading Project State name. SSP-6 retains only its two useful reconciliation questions and gives each an independently useful local report.

The retained reports are **Uncataloged Files** and **Missing Source Files**. They run from separate ordinary local parent/report-host documents because one starts from real files and the other starts from canonical Works. [SSP-6.0 — Uncataloged And Missing Source Files Sanity Note](/docs/?scope=studio&doc=d-20260807-161305-326ba1) confirms the corrected contracts and bounded implementation fit. [SSP-6.1 — Uncataloged Files Report Evidence](/docs/?scope=studio&doc=d-20260807-163925-a460e9) records the accepted first report. SSP-6 is parked after SSP-6.1, before explicit SSP-6.2 approval. SSP-6 remains the only delivery that may retire the current `/studio/project-state/` route, report/open APIs, activity contract, generator placement, and static Markdown output after both replacements are accepted.

## Complete Outcome

Two ordinary local Docs Viewer parent documents host two separate read-only reports through the established report registry, loader, service, and module seams. **Uncataloged Files** lists ordinary files of every extension found directly inside exact existing Work source directories but not used as a canonical Work primary source. **Missing Source Files** lists Works whose exact canonical source path does not resolve to a file. Neither report saves generated Markdown or retained browser presentation.

The reports do not modify Works, files, Project documents, or Project State rows. They do not retain the old report's source-folder, unrepresented-folder, catalogue-folder, incomplete-field, or summary sections merely for parity. Once both focused outcomes and their accepted omissions are demonstrated, the misleading Studio Project State workflow and duplicate static output are removed.

Each report result consists only of its specified table columns and rows. It has no aggregate counts, file-type or folder totals, scan/catalogue totals, generation timestamp, path/environment summary, statistical warnings, prose recap, or other result metadata on the page or in generated Markdown. An empty result uses the report host's ordinary empty state, and a failed run uses its contained error state.

## Report Contracts

### Uncataloged Files

The producer derives each represented source directory from a complete canonical Work declaration: `project_folder` plus optional `project_subfolder`. It scans the direct ordinary files in every distinct existing represented directory, regardless of extension. Directories, hidden/system entries, and known Work-detail directory trees remain excluded. Recursive discovery outside those exact represented directories is a separate scope decision rather than an implicit scan-mode switch.

A file is catalogued when it is the same resolved existing filesystem object as a complete canonical Work source path. Comparison must not rely on raw path-string equality: Finder/macOS may expose canonically equivalent Unicode spellings with different code-point sequences. The report preserves the actual discovered filename for display and activation while treating filesystem-equivalent names as the same file.

Each row contains **Folder** and **File name**. Folder is the actual represented directory relative to the `projects/` source root, including an applicable `project_subfolder`; for example, `wa/ink`. File name preserves the actual filesystem name. Activating it sends the existing encoded base-relative target, including the required `projects/` prefix, to `/docs/open-local-target`; the service revalidates containment and uses Finder reveal (`open -R`) so the file is selected without being opened. No absolute local path enters the browser payload or generated Docs.

### Missing Source Files

The producer independently constructs every complete canonical Work source path from `project_folder`, optional `project_subfolder`, and `project_filename`, then tests that exact resolved path with file semantics. It does not infer absence from a top-level candidate scan or set subtraction. This makes nested references such as `wa/ink/...` ordinary exact checks rather than false missing rows and avoids Unicode-form false positives such as visually identical `moiré` filenames.

Each missing row contains **Work ID**, **Work title**, and **Expected source path**. Work ID links to the exact Local Studio editor route `/studio/catalogue-work/?work=<five-digit-id>`. Expected source path is the base-relative combination of the three canonical path fields rather than `project_filename` alone. A missing file has no Finder action.

## Boundary With Project State

Project State owns:

- scanned-real-folder rows with independent `documents[]` and `works[] -> series memberships[]` joins;
- the live Folder/Docs/Works-by-Series report;
- exact Folder/Work/Series subject tracing into scanned rows; and
- the ephemeral Folder/Series browser projections and clipboard transforms.

SSP-6 owns:

- represented source-directory and ordinary-file scan policy for Uncataloged Files;
- exact canonical Work source-path checks for Missing Source Files;
- local-only row presentation and exact Finder/Studio activation targets; and
- retirement of the current Studio report workflow.

Neither output is an input to the other.

## Delivery Discipline

SSP-6 should reuse the old workflow's canonical catalogue reader, contained Projects root, and useful comparison evidence without preserving its report shape or incorrect classifications. The old producer subtracts raw path strings from a direct top-level image scan; that is not a parity oracle for optional subfolders, all file types, or filesystem-equivalent Unicode names. SSP-6.0 is a short scope-and-spec sanity gate over the corrected two-report contracts, current Studio retirement target, and existing local Docs Viewer report-host mechanism. It confirms broad owners, blast radius, deliverables, risks, and stop conditions without freezing exact files, fixtures, estimates, or implementation. Each implementation stage ends with focused evidence and an independent code/diff review before the next stage begins.

A generic audit framework, shared mode-driven report, repair workflow, automatic deletion action, continuous watcher, or new file/media registry is scope creep and requires separate approval. The two producers may reuse only narrow catalogue-path, containment, and local-target seams.

## Not In Scope

- Project State folder rows, `works[]`, `series[]`, document placement, or legacy lookup cleanup;
- changing Work media metadata or canonical source-path text;
- deciding that an uncataloged or missing file should be imported, moved, renamed, or deleted;
- source folders not represented by a complete Work source directory;
- recursive project-tree inventory or Work-detail auditing beyond the explicit exclusions;
- aggregate counts, scan summaries, generated report Markdown, or other result metadata;
- preserving old summary, folder-only, or incomplete-field sections; or
- public report output.
