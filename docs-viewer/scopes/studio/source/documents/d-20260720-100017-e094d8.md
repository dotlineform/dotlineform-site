# Docs Media Report Concept

## Purpose

Give authors one simple local report showing every ready-media and registered build-source file currently present in one selected Docs Viewer scope and the exact parent or sub-scope documents, if any, that reference it.

The report is named **Docs Media** and is hosted by one manage-only report document in the Dotlineform scope. It defaults to Dotlineform data but can inspect another configured parent scope through one dropdown. Its presentation uses the same list-backed report format as [Project State](/docs/?scope=dotlineform&doc=d-20260805-155400-4c341f).

## Exact Row Contract

One row represents one distinct exact media identity:

```text
selected scope + media type + media identity
```

The row set comes only from the live provider-neutral listing of the selected scope's configured ready-media and registered build-source locations. For external-local or repository storage that means the files currently beneath those configured roots; for R2 it means the objects currently beneath the configured prefixes. The report uses both ready-media and build-source inventory items, but not a persisted media table, manifest, `media-source-evidence.json`, or missing-reference rows. An existing file therefore remains one row when no document references it.

Each row collects the distinct exact documents that reference that listed identity. Repeated occurrences in one document are deduplicated, while several documents become several links in the same Documents cell. A referenced identity absent from the live file listing does not create a row. A build-source row does not inherit the documents referencing its derived ready-media output merely because the names match; without an exact direct reference its Documents cell remains blank. The server resolves exact parent and sub-scope document identity, title, Manage URL, media or build type, identity, role-specific local activation target, and any exact document references; the browser does not infer them from labels or the current report context.

## Three-Column Surface

```text
┌ Docs Media ────────────────────────────────────────────────────┐
│ Scope [Dotlineform ▾]  [↻]  [Search…                        ×] │
├─────────┬────────────────────────────┬──────────────────────────┤
│ Type ▲  │ File name                 │ Documents                │
│ files   │ attachment-01.pdf         │ nerve (abattoir)         │
│ img     │ image-01.webp             │ nerve (abattoir)         │
│ img     │ image-02.webp             │                          │
│ mermaid │ diagram-01.mmd            │                          │
└─────────┴────────────────────────────┴──────────────────────────┘
```

This is the Project State list pattern: a report toolbar, sortable header buttons, list rows, and stacked links within a cell. It does not adopt Project State's grouping or copy controls. All three column headers are sortable. The default order is Type ascending and then File name ascending, preserving the order of the previous combined media path. Type sorting uses the exact configured media-type id with File name as its tie-breaker. File name sorting uses the exact relative identity with Type as its tie-breaker. Within each Documents cell, links are ordered by document title and then exact target. Documents sorting compares that ordered title set, places unreferenced rows after referenced rows in ascending order, and uses Type plus File name as its deterministic tie-breaker. Selecting the active column reverses its direction; selecting another column starts ascending. Scope and sort state use the existing report query-state vocabulary so reload and copy-link preserve the current view.

### Type

Type displays the exact configured ready-media type or build-source type, such as `img`, `svg`, `html`, `files`, or `mermaid`. It comes from the inventory's canonical `media_type` field and is not inferred from the file extension. Therefore `build-source/mermaid/diagram-01.mmd` displays Type `mermaid`, not `build-source` or `mmd`. The cell is plain text.

### File name

File name displays the exact relative identity without the ready-media type or `build-source/<type>` prefix, for example `example.webp`, `attachment.pdf`, `diagram-01.mmd`, or `sub-folder/example.webp`. It comes from the inventory's canonical `identity` field; the browser does not split or reconstruct identity from a combined display label. A build source is a registered workspace file, while a ready-media file is the managed artifact and a retained original plus optional source evidence remain separate concerns.

The File name label is a local action that reveals this configured target in Finder:

```text
ready media:  docs-viewer/media/<scope>/<type>/<identity>
build source: docs-viewer/media/<scope>/build-source/<type>/<identity>
```

The server supplies the exact role-specific target; the browser never reconstructs it from Type and File name. The existing confined local-target service owns activation and uses Finder's reveal-file behavior. The browser receives only a Projects-relative target, never the absolute external workspace path. If a listed file is removed between report loading and activation, the action may report it unavailable and the next report load omits its row.

### Documents

The cell contains one link for every exact document that references the listed identity. A parent document keeps its exact `{scope, doc}` target. A sub-scope document keeps its exact parent report-host `doc` plus `subdoc`; the report never substitutes a title, filename, selected row, or current host document as identity. Repeated titles remain separate links when their exact targets differ. An existing ready-media or build-source file with no direct references has a blank Documents cell.

## Scope Selection

The dropdown lists configured parent scopes and defaults to `dotlineform`. Changing it loads that scope's exact live ready-media and build-source listing plus parent and sub-scope references and persists the selection as `report_scope`. A scope with no listed files shows a contained empty state, regardless of missing references. An unavailable external workspace or read service produces one report-level unavailable state rather than stale rows or a fallback location.

## Refresh And Search

The toolbar contains a Project State-style refresh pill. Activating it reruns the selected scope's live ready-media and build-source listing plus the current document-reference join, then reapplies the current search and sort state. It does not mutate or build media.

The Project State-style search field and clear control filter the loaded rows immediately. Matching is a case-insensitive substring search across each displayed File name value and every document title in that row; Type is not a search field. A row remains visible when either searched field matches. No matches produce one contained search-empty state distinct from a scope with no listed files.

## Report Host Direction

The existing report-backed document host provides manage-only composition, scope-prefixed state, the Project State list/table presentation vocabulary, the local report service, and the safe Finder activation seam. The shipped Docs Media report reuses those owners through one focused read model and report module; it does not generalize the report framework or create a dashboard.

## Boundaries

- No public report surface.
- No missing-reference rows, broken-link diagnosis, or Media Broken Links report in this outcome.
- No aggregate counts, byte totals, additional filters, selected-detail panel, grouping control, or copy controls.
- No retained-original or Media Sources evidence join.
- No inferred build-source-to-derived-output relationship or projection of a derived output's document references onto its source row.
- No provider choice, public-projection state, publication-health state, or media registry.
- No inferred identity, fuzzy lookup, filename fallback, source-tree scan, or historical backfill.
- No hash, content comparison, folder monitoring, thumbnail, OCR, archive expansion, cache, or background index.
- No replace, rename, relink, delete, repair, publish, move, rollback, or recovery action.
- No generic report plugin, schema-driven dashboard, or parallel local-file activation path.
