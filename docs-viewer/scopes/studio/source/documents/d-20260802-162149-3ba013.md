# TE-2 — Table Detail View

## Status And Purpose

Proposed as **TE-2**, after [TE-1 — Directive Insertion](/docs/?scope=studio&doc=d-20260802-163320-9015b0). It combines source eligibility and its first useful consumer into one complete outcome: an author marks a Markdown table with the maintained comment, and public or Manage readers can open that exact table in the shared static Content Detail View.

[Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns exact-comment, next-table, source-preservation, and harmless no-op behavior. [Content Detail View Concept And Architecture](/docs/?scope=studio&doc=d-20260802-150246-bb3f88) owns the shared view, exact-target, expanded-layout, toolbar, public-composition, and static-presentation boundaries implemented here.

## Complete Outcome

The initial source form is:

```markdown
<!-- dotlineform:table-detail -->

| Project | Folder | Series |
| --- | --- | --- |
| Nerve | projects/nerve | Series 105 |
```

The build recognises only the maintained comment when its next non-blank source block is a Markdown table and projects `data-docs-content-detail="table"` onto that semantic table. Canonical Markdown and Markdown export retain the comment and table. Other comments and unassociated forms remain ordinary source and ordinary rendered output.

Every projected table in a public or Manage rendered document receives a subtle **Open table** control. Invoking it supplies the exact table target from the current document mount to the registered `content-detail` main view. The existing main panel expands, the existing `main-view` toolbar supplies **Back to document** and a presentation label, and the table receives natural column sizing, a sticky header row, a sticky first column, and one bounded horizontal/vertical viewport. Leaving restores the prior rendered-document and panel context.

The document-level `viewer_content_detail: table` hint remains TE-5-owned. It later projects the same eligibility marker for its sole table without requiring a redundant comment. TE-2 does not add managed resizing, CSV, automatic entry, SVG publication, or table identity in the URL.

## Current Seams And Scope Guard

The likely blast radius is the Markdown build path that associates comments with tables and projects rendered payloads, plus the shared main-view/panel lifecycle, an exact Markdown-table target adapter, static table CSS, and public/Manage composition.

If implementation requires a central directive parser, browser comment parser, Markdown AST replacement, new shell, toolbar host, global view registry, route model, persistent table identity, or Manage dependencies in the public composition, stop for review and split the result.

## Delivery Steps

### TE-2.0 — Confirm Scope And Delivery

- [ ] Sanity-check the exact comment-to-static-view outcome against the current Markdown build, rendered-document mount, hosted-view, panel-layout, and app-composition model; resolve only contradictions that would change the result.
- [ ] Confirm the broad blast radius across source association, payload projection, shared view/layout lifecycle, exact table targeting, static presentation, and public/Manage composition.
- [ ] Confirm the deliverables: exact recognition and projection, shared view entry/restoration, bounded static table presentation, focused evidence for the changed contracts, and concise durable owner updates.
- [ ] Stop for review if the result crosses the scope guard above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, broad owners, deliverables, and stop condition. Stop before implementation approval.

### TE-2.1 — Recognise And Project Eligibility

- [ ] Recognise only the exact maintained comment without interpreting ordinary HTML comments or classifying malformed lookalikes.
- [ ] Associate it with one immediately following source Markdown table through maintained rendering/source-position seams rather than matching rendered HTML.
- [ ] Project only `data-docs-content-detail="table"` onto the associated semantic table while preserving canonical Markdown, export, table cell HTML, links, alignment, headings, captions, and ordinary fallback behavior.
- [ ] Support the same marker independently for the later TE-5 document-default case without implementing automatic entry here.

### TE-2.2 — Add The Shared Static Table View

- [ ] Register one public-safe `content-detail` main hosted view through the existing view registry and explicit public/Manage composition.
- [ ] Extend hosted-view requests with a bounded immutable target context, expanded-main panel projection, existing-toolbar Back/label controls, restoration, and lifecycle cleanup.
- [ ] Decorate only eligible tables in the accepted rendered-document mount and supply the exact target without reselecting from title, headers, URL, displayed row, or another table.
- [ ] Present the accepted semantic table in one bounded two-axis viewport with natural widths, sticky header and first column, correct intersection layering, and ordinary link/text behavior.
- [ ] Release transient target, scroll, and event state on Back, navigation, mount replacement, or view disposal.

### TE-2.3 — Verify And Transfer

- [ ] Run the smallest focused checks that prove exact source association, marker projection, view/layout lifecycle, exact target use, and public/Manage composition through the production owners changed.
- [ ] Manually review one representative wide/long table in public and Manage desktop readers, plus the public narrow case, covering entry, scrolling, sticky intersections, Back, and navigation.
- [ ] Inspect representative generated output only when the projection changed or its freshness is uncertain; let expected watcher output stand and add broader checks only for a concrete failure they can catch.
- [ ] Update only the durable authoring, payload, panel, toolbar, or table-presentation owners whose shipped contract changed.

## Not In Scope

- resizing columns, Reset, Copy as CSV, clipboard behavior, or persisted widths, owned by TE-3;
- diagram migration into the shared view, owned by TE-4;
- default initial presentation for a dedicated table document, owned by TE-5;
- table-to-SVG preparation or public substitution, owned by TE-6;
- automatic eligibility based on table geometry, content, headings, row count, or viewport;
- dynamic report/component tables, `docs_subscope` surfaces, search results, Recent, or Review composition;
- stable table IDs, fragments, direct table-detail URLs, persisted viewer state, sorting, filtering, selection, editing, formulas, charts, virtualization, clipboard, or download export; or
- a generic directive registry, diagnostics system, browser source parser, modal table application, second toolbar, or parallel view model.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns sequencing. TE-2 supplies the complete public-safe table-detail foundation consumed independently by TE-3, TE-4, and TE-5.
