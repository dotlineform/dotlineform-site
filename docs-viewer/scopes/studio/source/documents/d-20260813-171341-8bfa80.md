# DSI-1 — Docs Viewer Search Index v2 Delivery

## Status

In progress. DSI-1.0 readiness is complete and parked at its approval gate. Production and test implementation has not started.

## Complete Result

Every configured Docs Viewer scope uses one versioned inverted-index structure and one browser query and ranking path. Each scope still controls which source fields are searchable, but index structure is not a scope-specific choice. The runtime retains no v1 reader, format fallback, or Studio-only engine.

DSI-1 completes before [SM-1 — Studio Full-Text Search Delivery](/docs/?scope=studio&doc=d-20260715-084611-c2fa6f), which then adds headings, body prose, and authored code only to Studio's field policy.

## Boundary

DSI-1 includes the common document table and field-aware postings shape, shared tokenizer contract, per-scope field-policy seam, whole-index search rebuild behavior, one browser query/ranking path, coordinated migration of every configured Docs Viewer search index, and the metadata-only Analysis public projection.

It preserves each scope's accepted retrieval fields during the structural migration. It does not add body-text retrieval to any scope, change Catalogue Search, retain a dual-format transition reader, introduce an incremental postings cache, or redesign search results.

[Studio Full-Text Search Index](/docs/?scope=studio&doc=d-20260813-161942-b1e9e1) explains the inverted structure. [Docs Viewer Search Tokenizer](/docs/?scope=studio&doc=d-20260813-163802-5ca41f) owns term semantics. [Analysis Full-Text Search Extension](/docs/?scope=studio&doc=d-20260813-165124-16b0ab) distinguishes this metadata-only schema migration from later public body-text adoption.

**Gate:** Review the readiness result and linear sequence before any production or test implementation begins.

**Record:** Completed 2026-08-13. `build_search.py` is the single producer and currently hard-codes one v1 metadata policy for every scope; `docs_scopes.json` and `docs_scope_config.py` own scope identity, membership exclusions, routes, and output locations but have no explicit search-field policy. `docs-viewer-search.js` is the single browser normalization/ranking owner and `docs-viewer-search-controller.js` is its shared loader and UI caller. `docs_write_rebuild.py` and `docs_live_rebuild_watcher.py` own targeted search execution, while mutation plans supply affected identities.

The configured set is Studio, Analysis, Notes, Processing, and dotlineform. All five source roots and working search indexes were available during readiness, including both external-local roots. All five currently accept the same retrieval fields: title, parent title, update metadata, and exact full document identity; identity fragments are not ordinary terms. The proposed minimal stop-word list remains suitable for representative metadata across the five scopes, and lifecycle-bearing words such as `before`, `after`, and `while` remain indexed.

Analysis working search is copied unchanged to `site/assets/data/search/analysis/index.json`. The public publish gate is format-agnostic, but `docs_document_location_projection.py` and `docs_public_delete_cleanup.py` currently read or filter `entries`; DSI-1.2 must move those identity-only consumers to the v2 document table and remap postings during public deletion rather than retain `entries` compatibility.

The linear sequence remains valid. DSI-1.1 can add the explicit scope policy plus pure Python transformation/tokenizer and pure JavaScript tokenizer/query contract behind the inactive v1 producer/consumer, using one shared fixture. The expected review shape is roughly 250-350 production/config lines and 200-300 focused fixture/test lines across the existing scope-config, builder, and shared runtime owners; material expansion beyond that shape requires another review. DSI-1.2 then switches the producer, browser loader/query caller, expected schema, whole-index orchestration, Analysis auxiliary consumers, all five working indexes, and the tracked Analysis public index together, with no v1 reader.

Two sequencing conditions are explicit. Exact full-ID lookup is retained as structural identity handling outside ordinary tokenizer terms despite the broader full-text concept's statement that `doc_id` is not searchable. Both external-local roots must still be available at DSI-1.2; otherwise the all-scope cutover stops rather than leaving a v1 scope or adding a fallback reader. Gate outcome: ready for DSI-1.1 implementation approval; no production code, tests, prototypes, or v2 outputs were changed or run. The routine docs watcher regenerated only this delivery record's existing Studio document and v1 search projections.
