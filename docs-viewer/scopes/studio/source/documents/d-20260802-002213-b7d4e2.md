# TDL-2 — Tag Primary Document And Semantic Token Delivery

## Status And Purpose

TDL-2.1 and TDL-2.2 are complete in the [Tag Document Linking](/docs/?scope=studio&doc=d-20260804-160200-fa7bb7) sequence and are associated with [Semantic Tokens](/docs/?scope=studio&doc=d-20260725-153656-516b61). The delivery is parked before TDL-2.3 implementation approval. TDL-1 remains the association owner; TDL-2.1 replaced `tag_registry_v5.doc_url[]` membership editing with its complete ordered read-only reverse lookup and one optional Registry-owned `primary_document` override, while TDL-2.2 consumes those owners through one private single-link Tag target and ordinary resolved usage.

The delivery also adds Tag as a second Semantic Tokens family. It keeps Tag separate from Catalogue: a Work or Series resolves to one concrete catalogue destination, while a Tag resolves to its exact current primary override or otherwise the first current document in TDL-1's deterministic association order.

## Current Implementation Fit — 11 August 2026

TDL-1 supplies optional document-owned `tag_id`, normalized missing/valid/malformed evidence, the private deterministic `docs_tag_associations_v1` product with exact ordered targets and optional locations, and the current-source ordinary **Delete Tag** guard. TDL-2.1 has now migrated 245 exact legacy associations into declarations and cut Registry membership ownership over to `tag_registry_v6`.

The applied migration reconciliation resolves 245 legacy URLs to 245 distinct current Tag documents with no duplicate target, blocking conflict, or current multi-document Registry row. `bird-nerve` retains the sole unresolved legacy URL as review evidence, while four unrelated documents remain unassociated rather than inferred. The generated association product exactly matches the reviewed plan: 245 Tag rows, 245 documents, and no migrated `primary_document` values.

The semantic registry now exposes separate Catalogue and Tag families in the unchanged `docs_semantic_token_target_lookup_v2` single-`href` contract; Moment remains retired. The private generated lookup contains 2,074 Catalogue rows and 245 exact Tag rows. A Tag row carries canonical `tag_id`, its chosen public Analysis document link, group and current document-title context, and canonical aliases for later Tag-owned discovery. It chooses a current exact Registry primary when present or otherwise TDL-1 association row zero, then checks only that candidate for one workable public-safe location. An absent primary falls back to row zero; an unusable chosen candidate produces no row and never scans a later association.

The build parser now recognizes registered text-token families while retaining Catalogue-only image handling. A supported wrapped Tag token renders one ordinary anchor and one normal usage occurrence; unknown or unavailable Tag tokens remain literal, and targeted builds retain untouched occurrence rows. Canonical Tag data, the private target lookup, aliases, and usage indexes remain outside public projection. TDL-2.3 still owns the separate Source action, Tag discovery and Info UI, Semantic Tokens report contribution, and Broken Links diagnosis.

Both **Delete Tag** and **Demote Tag** now revalidate current document source rather than the generated association or Registry primary, so neither current nor stale `primary_document` state participates in canonical-removal eligibility. Both actions block and report current document declarations without rewriting or deleting documents.

## Complete Outcome

In Manage Source, an author selects meaningful text, chooses **Add tag token**, searches canonical Tags and aliases, and selects one exact canonical `tag_id`. The built document converts the authored text to the Tag's current resolved document link:

```text
[Nerve]
```

The source records stable Tag identity rather than copying document URLs. A normal rebuild reads the ordered derived Tag associations: a current associated primary overrides the list, otherwise the first current association is selected automatically. The rebuild records one Tag-token occurrence in the scope usage index. The public document contains ordinary resolved links and no Tag Registry, target lookup, or client-side semantic resolver.

## Fixed Product Direction

### Separate Family And Action

- Tag is a separate Semantic Tokens family with its own **Add tag token** action, discovery modal, parser contribution, and Info view.
- Tag is not added to **Add catalogue token** search. Catalogue continues to combine only Work and Series.
- The Tag family reuses the generic source selection, guarded range mutation, modal lifecycle, token registry, target lookup, build projection, usage index, report, and Broken Links seams.
- The canonical identity is `tag_id`. Aliases are discovery inputs only and always resolve to a selected canonical Tag.
- Group and the current resolved-document title are distinguishing lookup context; they are not copied into source identity.

### Resolved Association Is The Target

- A Tag target is a current associated Registry primary when one is selected, or otherwise the first current association in TDL-1's stable ascending `{scope, sub_scope, doc_id}` order. There is no separate Tag landing page.
- TDL-1 document declarations own association membership and canonical order. The Tag Registry editor displays the complete ordered list read-only and remains authoritative for canonical Tag identity, group, aliases, and the optional primary override. Semantic Tokens consume a focused generated target projection and do not inspect or mutate canonical Tag JSON directly.
- Document-location projection supplies current public-safe titles and URLs. A token never infers an association from document title, content, current route, report host, or neighbouring source.

## Wrapped Selection

The action replaces the captured selection with a token containing the occurrence text:

```markdown
[[tag:tag:nerve|nerve]]
```

The builder renders:

```text
[Nerve]
```

The token owns both the visible occurrence text and Tag identity; its Info view can edit the occurrence text while keeping identity readonly.

## Link Resolution

- A recognized Tag token resolves from the canonical Tag row and its exact current TDL-1 association set according to this fixed matrix:

| Current associated documents | Resolution |
| --- | --- |
| None | Unresolved. |
| One | Use that first and sole document; no primary override is required. |
| Several, with a current associated `primary_document` | Use that exact selected document. |
| Several, without a current associated `primary_document` | Use the first document in TDL-1's deterministic association order. |

- The occurrence Title stored in the token is the rendered anchor label. The associated document title may appear as discovery or Info context but does not replace the authored Title.
- Retained `doc_url[]` data is a migration input only. TDL-2 replaces canonical association membership with TDL-1's derived document declarations; focused consumers may use the complete derived association set.
- Candidate selection happens before location resolution. A stored primary absent from the current association set is not a current override, so selection returns to the canonical first document. Once the exact candidate is selected, a missing, unpublished, or otherwise unusable public-safe location leaves the token unresolved rather than scanning later associations.
- The default-first rule is deliberate product behavior, not inferred relevance: titles, availability, recent use, semantic-token usage, Registry ordering, and current UI state never choose the document. Unresolved source remains ordinary text, creates no resolved usage row, and can be diagnosed by Docs Broken Links.
- Public output is resolved at build time into one ordinary anchor. Public readers receive no Tag Registry, target lookup, usage index, or resolution runtime.

## Tag Registry Document Pills And Primary Override

The Tag Registry editor displays all current TDL-1 associations as document pills in canonical association order and treats membership and ordering as read-only. It cannot search for, add, remove, or reorder documents; only editing or deleting document source changes the list. The document label opens that exact Docs Viewer target. The pill has no `×` or other association-removal control.

Each current document pill has a trailing accessible radio-style circle. A hollow circle means the document is not the stored primary override; the one selected primary has a filled circle. Activating a hollow circle drafts that exact document as `primary_document`. If every circle is hollow, Semantic Tokens use the first displayed document automatically. Once a primary has been stored, the editor offers no clear action: selecting another pill replaces it, while activating the already-filled circle leaves it selected. The next Registry schema stores:

```json
{
  "primary_document": {
    "scope": "analysis",
    "sub_scope": "tags",
    "doc_id": "d-..."
  }
}
```

`primary_document` is optional and scalar. It is not a URL or association list and is never required for Semantic Token resolution when current associations exist.

- The association list is a read-only TDL-1 projection. The editor never writes membership back to documents or Registry association fields.
- With no associated document, the editor shows the empty state. With one, it shows the sole pill and its circle; leaving the circle hollow uses that first and sole document automatically, so no Studio selection is required.
- With one or several documents, the current pill circles form one accessible single-selection group. The initially empty automatic state or a selected identity is committed by the existing atomic Tag mutation boundary. Once selected, a primary can only be replaced by another current pill or removed with the complete Tag row. These are only the already-associated records supplied by TDL-1; this is not general document search.
- If a stored primary is absent from the reverse lookup because its document was deleted or reassigned, migration input is stale, or an out-of-band source change occurred, its exact identity remains visible separately as **Unavailable document** and every current pill circle remains hollow. Semantic resolution treats the absent primary as no current override and uses the first current pill. Selecting a current circle replaces the stale value; if no association exists, the stale identity remains until the Tag itself is deleted.
- Selection changes remain draft operations until Save. Close discards them.
- The pills preserve TDL-1 order so the first visible document is the automatic semantic destination. Title sorting, availability sorting, recently-used ranking, semantic-token usage, and Registry draft order cannot change that sequence.
- Selecting or replacing the primary changes whether the Tag Semantic Token destination is overridden or automatic. It does not transfer document lifecycle ownership to Tag Registry, synchronize a document with Tag identity, or participate in document or Tag deletion eligibility.
- Tag Registry remains the canonical Tag definition for Work tagging: canonical identity, group, aliases, and primary document stay Registry-owned. Documents own their declarations and may cross-reference one another in their content.

## Registry Migration

TDL-2 performs one bounded migration from `tag_registry_v5.doc_url[]` after TDL-1's Tag declaration and reverse-lookup contracts are available:

- every exact legacy association is converted into the corresponding document's `tag_id` declaration where the target can be resolved and safely updated;
- when the resulting reverse lookup contains several current associations, the exact identity represented by `doc_url[0]` becomes `primary_document` only if it is one of them; otherwise it is reported for review, and zero or one current association requires no migrated primary;
- later `doc_url[]` entries contribute only to document declarations and do not remain in the Registry row;
- unresolvable or conflicting legacy entries are reported for review rather than inferred, dropped silently, or turned into free-form URLs;
- the generated reverse lookup is compared with the migration plan before commit; and
- `doc_url[]` is removed after the scalar primary and reverse lookup are validated, with no continuing dual-write or dual-read compatibility layer.

## Target And Usage Projection

The current Semantic Tokens target row already assumes one workable `href`. Tag can reuse that shape without a multi-target schema: the focused Tag projection derives one candidate from the exact current primary override or canonical first association, then emits one workable `href` or no resolved row.

A proposed Tag target row contains:

```json
{
  "family": "tag",
  "target_type": "tag",
  "target_id": "nerve",
  "title": "nerve",
  "href": "/analysis/?doc=...&subdoc=...",
  "meta": ["subject", "Nerve"]
}
```

The exact field names and unavailable-record representation remain bounded implementation decisions within the existing Semantic Tokens target owner. Required semantics are:

- one lookup row per canonical Tag whose exact selected-primary-or-first candidate has a workable public-safe location under the zero/one/several matrix;
- one safe `href` resolved from that exact stored document identity;
- canonical aliases available to discovery without becoming target identity;
- the canonical group and associated document title available only as compact lookup context where useful;
- one ordinary resolved usage occurrence per authored Tag token; and
- exact source document and source range for report navigation and targeted build preservation.

The Semantic Tokens report treats Tag like another resolved family occurrence and links back to its source document. Docs Broken Links remains the read-only diagnosis owner for unknown Tags, zero associations, and unusable selected-primary-or-first destinations.

## Delivery Discipline

TDL-2 is one complete second-family vertical slice over the existing single-target Semantic Tokens contract. It should add a focused Tag lookup adapter and family-owned UI without introducing multi-target schema, rendering, or report behavior. It must not turn the registry into executable plugins, combine Tag and Catalogue search, add a generic graph, create a public Tag application, give the Tag Editor association-mutation authority, or move primary-override selection into Docs Viewer.

TDL-2.0 is a short scope-and-spec sanity gate over Tag migration, primary selection, target projection, Source authoring, build/usage, reports, and public isolation. It confirms broad owners, blast radius, deliverables, risks, and stop conditions without freezing exact files, fixtures, estimates, or implementation. Each implementation stage ends with focused evidence and an independent code/diff review. Any proposed expansion of the existing single-`href` contract is a pause-and-review signal because this delivery does not require it.

## Not In Scope

- combining Tag targets with Catalogue discovery or the Catalogue toolbar action;
- rendering, projecting, or reporting more than the one document resolved by the zero/one/several matrix;
- scanning later associations when the exact selected-primary-or-first candidate lacks a workable public-safe location;
- a multi-target Semantic Token schema, link group, display limit, or overflow state;
- automatic Tag-document creation, repair, deletion, or synchronization;
- Tag Editor search, membership mutation, or reordering of the complete document association set;
- a **Clear primary** action or any other way to return a stored primary to empty without deleting its complete Tag row;
- using `primary_document` to block or authorize document Delete, `tag_id` assignment/reassignment/clear, or Tag deletion;
- cascading Tag deletion into documents or document deletion/disassociation into Registry primary selection;
- deriving associations from document titles, content, source proximity, or usage rows;
- recursive relationship resolution or inferred relationship expansion;
- a public Tag registry, target lookup, usage index, or client-side resolver;
- changing document lifecycle because an association appears, disappears, or becomes primary.
