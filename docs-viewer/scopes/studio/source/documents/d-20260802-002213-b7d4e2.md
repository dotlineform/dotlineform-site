# TDL-2 — Tag Primary Document And Semantic Token Delivery

## Status And Purpose

Proposed as **TDL-2** in the [Tag Document Linking](/docs/?scope=studio&doc=d-20260804-160200-fa7bb7) sequence and associated with [Semantic Tokens](/docs/?scope=studio&doc=d-20260725-153656-516b61). It is not active and does not authorize implementation. TDL-2 replaces `tag_registry_v5.doc_url[]` with one optional Registry-owned `primary_document`; [TDL-1](/docs/?scope=studio&doc=d-20260804-160201-47af2d)'s reverse lookup becomes the complete Tag-document association set.

The delivery also adds Tag as a second Semantic Tokens family. It keeps Tag separate from Catalogue: a Work or Series resolves to one concrete catalogue destination, while a Tag resolves to its explicitly selected primary document.

## Current Implementation Fit — 11 August 2026

The current semantic registry exposes Catalogue Work and Series targets only; Moment has retired. Catalogue target records have since gained image context and Work detail availability, but each target still resolves through the same single safe `href`, so Tag needs neither a shared target schema expansion nor Catalogue coupling. The migration and primary-selection cutover must complete and be verified before the Tag family is registered or parsed, keeping canonical data migration separate from semantic implementation.

## Complete Outcome

In Manage Source, an author selects meaningful text, chooses **Add tag token**, searches canonical Tags and aliases, and selects one exact canonical `tag_id`. The built document converts the authored text to the Tag's current primary-document link:

```text
[Nerve]
```

The source records stable Tag identity rather than copying document URLs. A normal rebuild resolves the Registry's current explicit primary document through the derived Tag associations, and records one Tag-token occurrence in the scope usage index. The public document contains ordinary resolved links and no Tag Registry, target lookup, or client-side semantic resolver.

## Fixed Product Direction

### Separate Family And Action

- Tag is a separate Semantic Tokens family with its own **Add tag token** action, discovery modal, parser contribution, and Info view.
- Tag is not added to **Add catalogue token** search. Catalogue continues to combine only Work and Series.
- The Tag family reuses the generic source selection, guarded range mutation, modal lifecycle, token registry, target lookup, build projection, usage index, report, and Broken Links seams.
- The canonical identity is `tag_id`. Aliases are discovery inputs only and always resolve to a selected canonical Tag.
- Group and the current primary-document title are distinguishing lookup context; they are not copied into source identity.

### Primary Association Is The Target

- A Tag target is the Registry's explicitly selected primary document from the current derived associations. There is no separate Tag landing page.
- The Tag Registry remains authoritative for canonical Tag identity, group, aliases, and primary selection. TDL-1 document declarations own association membership. Semantic Tokens consume a focused generated target projection and do not inspect or mutate canonical Tag JSON directly.
- Document-location projection supplies current public-safe titles and URLs. A token never infers an association from document title, content, current route, report host, or neighbouring source.

## Wrapped Selection

The action replaces the captured selection with a token containing the occurrence text:

```markdown
[[tag:tag:nerve|nerve]]
```

The builder renders:

```text
[Nerve]
```

The token owns both the visible occurrence text and Tag identity; its Info view can edit the occurrence text while keeping identity readonly.

## Link Resolution

- A recognized Tag token resolves only the canonical Tag row's exact `primary_document` when that target remains a current derived association with a workable public-safe location.
- The occurrence Title stored in the token is the rendered anchor label. The associated document title may appear as discovery or Info context but does not replace the authored Title.
- Retained `doc_url[]` data is a migration input only. TDL-2 replaces canonical association membership with TDL-1's derived document declarations; focused consumers may use the complete derived association set.
- There is no fallback from an empty, stale, unpublished, or otherwise unusable primary selection to another association. The token follows the same tolerant Semantic Tokens rule as Catalogue: unresolved source remains ordinary text, creates no resolved usage row, and can be diagnosed by Docs Broken Links.
- Public output is resolved at build time into one ordinary anchor. Public readers receive no Tag Registry, target lookup, usage index, or resolution runtime.

## Tag Registry Primary Selection

The Tag Registry/editor owns the explicit primary-document choice from the current TDL-1 associations. TDL-2 therefore includes an accessible way to select or clear that primary in **Edit Tag**. The next Registry schema stores:

```json
{
  "primary_document": {
    "scope": "analysis",
    "sub_scope": "tags",
    "doc_id": "d-..."
  }
}
```

`primary_document` is optional and scalar. It is not a URL and it is not an association list.

- The primary selection is one exact document identity or empty and is committed by the existing atomic Tag mutation boundary.
- The editor may use the TDL-1 reverse lookup as eligible picker input, but it stores and presents only the primary rather than maintaining a multiple-document draft. It does not add, remove, or reorder association membership.
- If the stored primary no longer appears in the reverse lookup or its document has been deleted, the stored identity remains unchanged and the editor shows it as unknown through the existing **Unavailable document** state. Save preserves it unless the user explicitly clears or replaces it.
- Selection changes remain draft operations until Save. Close discards them.
- No title sort, availability sort, recently-used ranking, semantic-token usage, or association order may choose or rewrite the primary automatically.
- Changing the primary deliberately changes the Tag Semantic Token destination. It does not transfer document lifecycle ownership to Tag Registry or synchronize a document with Tag identity.
- Tag Registry remains the canonical Tag definition for Work tagging: canonical identity, group, aliases, and primary document stay Registry-owned. Documents own their declarations and may cross-reference one another in their content.

## Registry Migration

TDL-2 performs one bounded migration from `tag_registry_v5.doc_url[]` after TDL-1's Tag declaration and reverse-lookup contracts are available:

- every exact legacy association is converted into the corresponding document's `tag_id` declaration where the target can be resolved and safely updated;
- the exact identity represented by `doc_url[0]`, when present, becomes `primary_document`, including when that document is currently unavailable but the stored route still identifies its target;
- later `doc_url[]` entries contribute only to document declarations and do not remain in the Registry row;
- unresolvable or conflicting legacy entries are reported for review rather than inferred, dropped silently, or turned into free-form URLs;
- the generated reverse lookup is compared with the migration plan before commit; and
- `doc_url[]` is removed after the scalar primary and reverse lookup are validated, with no continuing dual-write or dual-read compatibility layer.

## Target And Usage Projection

The current Semantic Tokens target row already assumes one workable `href`. Tag can reuse that shape without a multi-target schema: the focused Tag projection derives one `href` from the exact explicit primary association.

A proposed Tag target row contains:

```json
{
  "family": "tag",
  "target_type": "tag",
  "target_id": "nerve",
  "title": "nerve",
  "href": "/analysis/?doc=...&subdoc=...",
  "meta": ["subject", "Nerve"]
}
```

The exact field names and unavailable-record representation remain bounded implementation decisions within the existing Semantic Tokens target owner. Required semantics are:

- one lookup row per canonical Tag with a currently workable explicit primary association;
- one safe `href` resolved from that exact stored document identity;
- canonical aliases available to discovery without becoming target identity;
- the canonical group and associated document title available only as compact lookup context where useful;
- one ordinary resolved usage occurrence per authored Tag token; and
- exact source document and source range for report navigation and targeted build preservation.

The Semantic Tokens report treats Tag like another resolved family occurrence and links back to its source document. Docs Broken Links remains the read-only diagnosis owner for unknown Tags and unusable or stale primary targets.

## Delivery Discipline

TDL-2 is one complete second-family vertical slice over the existing single-target Semantic Tokens contract. It should add a focused Tag lookup adapter and family-owned UI without introducing multi-target schema, rendering, or report behavior. It must not turn the registry into executable plugins, combine Tag and Catalogue search, add a generic graph, create a public Tag application, or move Tag Registry identity or primary-selection authority into Docs Viewer.

TDL-2.0 is a short scope-and-spec sanity gate over Tag migration, primary selection, target projection, Source authoring, build/usage, reports, and public isolation. It confirms broad owners, blast radius, deliverables, risks, and stop conditions without freezing exact files, fixtures, estimates, or implementation. Each implementation stage ends with focused evidence and an independent code/diff review. Any proposed expansion of the existing single-`href` contract is a pause-and-review signal because this delivery does not require it.

## Delivery Steps

### TDL-2.0 — Confirm Scope And Delivery

- [ ] Sanity-check the scalar-primary Tag migration and single-link Semantic Token outcome against the accepted TDL-1 association contract and current Tag Registry, document-location, Semantic Tokens, Source editing, usage/reporting, and Broken Links models; resolve only contradictions that would change the result.
- [ ] Confirm the broad blast radius across canonical Tag migration/read/write/import, document `tag_id` declarations, primary editing, focused target projection, Source authoring/Info, build rendering, usage preservation, reports, and public isolation.
- [ ] Confirm the deliverables: one optional exact primary, no-fallback target projection, wrapped Tag token authoring, single-anchor build/usage, bounded migration evidence, focused verification, and concise durable owner updates.
- [ ] Stop for review if the result requires multi-target Semantic Tokens, dual-read/write compatibility, inferred associations or fallback, combined Tag/Catalogue discovery, a public Tag application, or another boundary excluded above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, TDL-1 dependency, broad owners, blast radius, deliverables, risks, migration/public boundary, and stop condition. Stop before TDL-2.1 implementation approval.

### TDL-2.1 — Registry Migration And Primary Selection

- [ ] Apply the reviewed migration plan to exact Tag documents and replace Registry `doc_url[]` with optional scalar `primary_document` without a dual-write compatibility period.
- [ ] Generate and validate the complete TDL-1 reverse lookup before accepting migrated Registry rows; report unresolved legacy associations without inventing membership.
- [ ] Update canonical Tag read/write/import contracts to retain identity, group, aliases, and primary-document authority for Work tagging while removing Registry-owned association membership.
- [ ] Replace Tag Editor association mutation controls with one accessible `primary_document` picker backed by eligible reverse-lookup candidates, without retaining a multi-document draft or changing its atomic Registry mutation boundary.
- [ ] Preserve a deleted or otherwise unknown stored primary visibly until the user explicitly clears or replaces it.
- [ ] Verify the migrated declarations, complete private associations, scalar primary selection, unresolved-entry report, and removal of the old Registry field before any Tag semantic implementation starts.

**Checkpoint:** focused migration, canonical Tag, association, primary-editor, unknown-primary, and public-isolation evidence passes for the specified states. An independent code/diff review confirms scalar primary ownership, no fallback, and complete retirement of the old Registry association field without a compatibility layer. Stop for approval before registering the Tag semantic family.

### TDL-2.2 — Single-Link Semantic Target And Build

- [ ] Implement tolerant parsing and single-anchor build rendering for wrapped Tag tokens and the specified unavailable-primary states.
- [ ] Generate one ordinary resolved usage occurrence while preserving untouched documents during targeted builds.

**Checkpoint:** focused target lookup, parser, builder, usage, targeted-build, unavailable-primary, no-fallback, Catalogue-regression, and public-isolation evidence passes. An independent final review confirms exact identity, guarded source mutation, no fallback, and separation from Catalogue discovery.

## Not In Scope

- combining Tag targets with Catalogue discovery or the Catalogue toolbar action;
- rendering, projecting, or reporting non-primary associations from a Tag Semantic Token;
- falling back to another association when the explicit primary is unavailable;
- a multi-target Semantic Token schema, link group, display limit, or overflow state;
- automatic Tag-document creation, repair, deletion, or synchronization;
- Tag Editor mutation or ordering of the complete document association set;
- deriving associations from document titles, content, source proximity, or usage rows;
- recursive relationship resolution or inferred relationship expansion;
- a public Tag registry, target lookup, usage index, or client-side resolver;
- changing document lifecycle because an association appears, disappears, or becomes primary.
