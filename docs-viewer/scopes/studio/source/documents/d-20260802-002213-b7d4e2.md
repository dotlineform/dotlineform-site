# TST-1 — Tag Semantic Token Delivery

## Status And Purpose

Proposed as **TST-1**, a standalone delivery associated with [Semantic Tokens](/docs/?scope=studio&doc=d-20260725-153656-516b61). It is not active and does not authorize implementation.

The delivery adds Tag as a second Semantic Tokens family after the Tag Registry acquired canonical document associations. It keeps Tag separate from Catalogue: a Work, Series, or Moment resolves to one concrete catalogue destination, while a Tag resolves to its first associated document.

## Complete Outcome

In Manage Source, an author selects meaningful text, chooses **Add tag token**, searches canonical Tags and aliases, and selects one exact canonical `tag_id`. The built document converts the authored text to the Tag's current associated document link:

```text
[Nerve]
```

The source records stable Tag identity rather than copying document URLs. A normal rebuild resolves the current `doc_url[0]` projection, and records one Tag-token occurrence in the scope usage index. The public document contains ordinary resolved links and no Tag Registry, target lookup, or client-side semantic resolver.

## Fixed Product Direction

### Separate Family And Action

- Tag is a separate Semantic Tokens family with its own **Add tag token** action, discovery modal, parser contribution, and Info view.
- Tag is not added to **Add catalogue token** search. Catalogue continues to combine only Work, Series, and Moment.
- The Tag family reuses the generic source selection, guarded range mutation, modal lifecycle, token registry, target lookup, build projection, usage index, report, and Broken Links seams.
- The canonical identity is `tag_id`. Aliases are discovery inputs only and always resolve to a selected canonical Tag.
- Group and current association titles are distinguishing lookup context; they are not copied into source identity.

### Associations Are The Target

- A Tag target is its `doc_url[0]` association. There is no separate Tag landing page.
- The Tag Registry remains authoritative for canonical Tag identity, group, aliases, and association order. Semantic Tokens consume a focused generated target projection and do not inspect or mutate canonical Tag JSON directly.
- Document-location projection supplies current public-safe titles and URLs. A token never infers an association from document title, content, current route, report host, or neighbouring source.

## Wrapped Selection

The action replaces the captured selection with a token containing the occurrence text:

```markdown
[[tag:tag:nerve|nerve]]
```

The builder renders:

```text
[Nerve]
```

The token owns both the visible occurrence text and Tag identity; its Info view can edit the occurrence text while keeping identity readonly.

## Link Resolution

- A recognized Tag token resolves only the canonical Tag row's exact `doc_url[0]` association.
- The occurrence Title stored in the token is the rendered anchor label. The associated document title may appear as discovery or Info context but does not replace the authored Title.
- `doc_url[1:]` remains canonical Tag Registry association data for later analysis and other consumers. TST-1 does not enumerate, copy, validate, or publish those later associations.
- There is no fallback from an empty, stale, unpublished, or otherwise unusable `doc_url[0]` to a later array entry. The token follows the same tolerant Semantic Tokens rule as Catalogue: unresolved source remains ordinary text, creates no resolved usage row, and can be diagnosed by Docs Broken Links.
- Public output is resolved at build time into one ordinary anchor. Public readers receive no Tag Registry, target lookup, usage index, or resolution runtime.

## Tag Registry Ordering

Association order becomes user-visible because `doc_url[0]` is the Semantic Token link target. TST-1 therefore includes an explicit way to change `doc_url[]` order in **Edit Tag**.

- Reordering edits the complete local association draft and is committed by the existing atomic Tag mutation boundary.
- The UI must expose deliberate accessible ordering controls. TST-1.0 decides between move-up/move-down controls and another equally explicit interaction; drag-only ordering is insufficient.
- Removing, adding, and reordering remain independent draft operations until Save. Close discards all of them.
- No automatic title sort, availability sort, recently-used ranking, or semantic-token usage may rewrite canonical order.
- Moving a URL into position zero deliberately changes the Tag Semantic Token destination. It does not transfer document lifecycle ownership to Tag Registry or synchronize a document with Tag identity.

## Target And Usage Projection

The current Semantic Tokens target row already assumes one workable `href`. Tag can reuse that shape without a multi-target schema: the focused Tag projection derives one `href` from the exact `doc_url[0]` association.

A proposed Tag target row contains:

```json
{
  "family": "tag",
  "target_type": "tag",
  "target_id": "nerve",
  "title": "nerve",
  "href": "/analysis/?doc=...&subdoc=...",
  "meta": ["subject", "Nerve"]
}
```

The exact field names and unavailable-record representation remain a TST-1.0 freeze decision. Required semantics are:

- one lookup row per canonical Tag with a currently workable `doc_url[0]`;
- one safe `href` resolved from that exact stored URL;
- canonical aliases available to discovery without becoming target identity;
- the canonical group and associated document title available only as compact lookup context where useful;
- one ordinary resolved usage occurrence per authored Tag token; and
- exact source document and source range for report navigation and targeted build preservation.

The Semantic Tokens report treats Tag like another resolved family occurrence and links back to its source document. Docs Broken Links remains the read-only diagnosis owner for unknown Tags and unusable `doc_url[0]` targets.

## Delivery Discipline

TST-1 is one complete second-family vertical slice over the existing single-target Semantic Tokens contract. It should add a focused Tag lookup adapter and family-owned UI without introducing multi-target schema, rendering, or report behavior. It must not turn the registry into executable plugins, combine Tag and Catalogue search, add a generic graph, create a public Tag application, or move Tag Registry authority into Docs Viewer.

TST-1.0 must record the exact proposed files, reused seams, and rough production/test diff per later checkpoint. Any proposed expansion of the existing single-`href` contract is a pause-and-review signal because this delivery does not require it.

## Delivery Steps

### TST-1.0 — Trace And Freeze The Tag Family

- [ ] Trace current Tag Registry ordering, aliases, document-location resolution, Semantic Token grammar, target lookup, Source contributions, builder projection, usage preservation, report, Broken Links, and public isolation.
- [ ] Freeze wrapped-selection syntax, occurrence Title handling, canonical Tag identity, alias discovery, group/document context, and Info update/removal behavior.
- [ ] Freeze exact `doc_url[0]` projection, empty and unavailable first-target behavior, the absence of fallback to later associations, and the ordinary resolved usage row.
- [ ] Freeze Edit Tag reordering interaction and complete-draft Save behaviour.
- [ ] Record the exact files, reused seams, rough production/test diff, and any proposed expansion before implementation approval.

**Checkpoint:** reviewed fixtures cover collapsed and non-empty selections, punctuation, canonical and alias discovery, one and several stored associations, reordered position zero, no association, stale or unpublished position zero with a workable later URL, duplicate visible titles, targeted rebuild, usage rows, and public output. They prove that only `doc_url[0]` participates and that later associations remain untouched Registry data. Stop before implementation.

### TST-1.1 — Tag Lookup And Single-Link Projection

- [ ] Add the focused Tag target generator over canonical Registry, aliases, and the public-safe document-location projection for exact `doc_url[0]`.
- [ ] Register the Tag family in the existing single-`href` target schema and shared consumers.
- [ ] Implement tolerant single-anchor build rendering for wrapped Tag tokens and the frozen unavailable-first-target states.
- [ ] Generate one ordinary resolved usage occurrence while preserving untouched documents during targeted builds.
- [ ] Keep Tag canonical data, aliases, target lookup, and usage data out of public output.

**Checkpoint:** focused lookup, parser, builder, usage, targeted-build, and public-isolation evidence passes for the frozen fixtures. Stop for approval before TST-1.2.

### TST-1.2 — Authoring, Info, And Target Ordering

- [ ] Add the separate **Add tag token** Source action and Tag discovery modal with canonical ID, alias, group, and first-associated-document context.
- [ ] Insert the wrapped token through captured, revision-guarded Source mutation only.
- [ ] Add the family-specific Info view with immutable identity, current target context, permitted occurrence editing, and exact-range removal.
- [ ] Add accessible association reordering to the Edit Tag draft without changing its atomic complete-array mutation boundary.
- [ ] Preserve validation, unavailable-target, and stale-range errors without adding redundant successful-mutation status messages.

**Checkpoint:** focused module and route evidence passes, and manual acceptance adds a Tag token from selected prose, rebuilds one ordinary link, moves another associated document into position zero, saves, rebuilds, and observes the link target change. Stop for approval before TST-1.3.

### TST-1.3 — Reports, Regression, And Transfer

- [ ] Extend the Semantic Tokens report and Docs Broken Links diagnosis for the frozen Tag occurrence and association states.
- [ ] Prove Catalogue Work, Series, and Moment insertion, Info, rendering, usage, and unresolved behaviour are unchanged.
- [ ] Verify canonical and alias discovery, zero/one/many stored associations, reordered position zero, unavailable first targets, later-entry non-participation, source edits, targeted rebuild preservation, public links, and public isolation.
- [ ] Run focused Python, browser-module, lint, whitespace, generated docs, and search checks, then perform the mandatory final diff and omission review.
- [ ] Transfer shipped behaviour to the concise Semantic Tokens, Tag Registry, Source Editor UI, Architecture, Target Lookup, and Usage Index owners.

## Not In Scope

- combining Tag targets with Catalogue discovery or the Catalogue toolbar action;
- rendering, projecting, or reporting `doc_url[1:]` from a Tag Semantic Token;
- falling back to a later association when `doc_url[0]` is unavailable;
- a multi-target Semantic Token schema, link group, display limit, or overflow state;
- automatic Tag-document creation, repair, deletion, or synchronization;
- deriving associations from document titles, content, source proximity, or usage rows;
- recursive relationship resolution or Resolver Token behaviour;
- a public Tag registry, target lookup, usage index, or client-side resolver;
- changing document lifecycle because a URL is added, removed, or reordered.
