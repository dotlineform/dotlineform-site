# SSP-8.1 — Superseded Nullable-State Cutover Evidence

## Outcome

This document retains implementation evidence for commit `8319b2a02`. Subsequent product review rejected its independently nullable Working, Editorial, and Published target. It is not the current SSP-8 contract and must not be extended.

The current direction is [SSP-8 — Revised Model](/docs/?scope=studio&doc=d-20260808-153226-a067d9): the Working `doc_id` owns a set of current Editorial children, Published is an optional URL attribute of a current Editorial child, deleting Working ends lineage, and `lineage_id` plus the orphan-lineage report are removed. [DPD-1 — Immediate Public Projection Cleanup On Document Delete](/docs/?scope=studio&doc=d-20260808-165751-1f159a) must deliver the Docs Viewer-wide Delete behavior before that replacement proceeds.

The private canonical table currently has the committed interim `docs_document_publication_lineage_v2` contract. Each row has an immutable branch ID and independently optional **Working**, **Editorial**, and **Published** states. The evidence below describes that committed implementation only.

The known SSP-7 review row was migrated deliberately to Working-only. Its prior workflow Editorial Delete is represented by `editorial: null`; no filesystem check, unavailable marker, or inferred history was used.

## Frozen Row Contract

```json
{
  "lineage_id": "sha256:<64 lowercase hexadecimal characters>",
  "working": {"scope": "...", "sub_scope": "...", "doc_id": "..."},
  "editorial": {"scope": "...", "sub_scope": "...", "doc_id": "..."},
  "created_at": "YYYY-MM-DDTHH:MM:SSZ",
  "last_copied_at": "YYYY-MM-DDTHH:MM:SSZ",
  "published": {"public_url": "..."}
}
```

Each of `working`, `editorial`, and `published` may independently be `null`, but a retained row must contain at least one state. Published carries only its current exact `{public_url}` evidence; it does not duplicate Editorial identity or add a presence marker.

For New Copy, `lineage_id` is `sha256:` plus the SHA-256 digest of the whitespace-free, key-sorted JSON object containing the initial exact `working` and `editorial` identity objects. That ID never changes when a later action removes a state. It therefore preserves one exact branch identity through Working-only, Editorial-only, Published-only, and mixed-state records while allowing one Working document to own zero-to-many New branches. Rows are persisted in `lineage_id` order.

`created_at` records the initial New Copy and `last_copied_at` records the latest New or exact Replace. Copy New creates Working plus Editorial with no Published evidence. Replace requires both current exact states, retains the branch ID and every other state, and updates only `last_copied_at`.

## Clean Cut And Current Consumers

The canonical JSON, strict reader/writer, Copy fixtures, Publish fixtures, and Projects projection fixtures all moved together to v2. A v1 table now fails schema validation; there is no dual reader or migration-at-runtime path.

Only the minimum read adaptations needed by the current actions were made:

- Copy planning reads branches containing the exact current Working and Editorial states; New and Replace continue to use their existing action and response contracts.
- Publish reconciliation reads nullable Editorial state safely and leaves a row without Editorial unchanged. SSP-8.2 still owns the revised post-Delete Publish behavior.
- Projects joins only a current Working-plus-Editorial branch into its existing `publication_targets` projection. A Working-only branch produces no unavailable Editorial target.

No Delete lineage mutation, highest-state report change, new report, filesystem scan, rollback, retry, repair, or public lineage projection is included.

SSP-8.1 is superseded and stopped. Do not add Delete or reporting behavior to the nullable-state model. The next implementation approval belongs to DPD-1.0; SSP-8 resumes later with a clean Working-owned replacement.
