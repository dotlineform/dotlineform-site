# Series Tag Editor

## Capability

`/studio/series-tag-editor/?series=<series_id>` edits one series assignment and
its per-work override deltas.

Series tags are inherited by every work in the series. A work row stores only additional tags; the service removes duplicates of inherited series tags. Empty work overrides are removed unless the workflow explicitly keeps the row.

## Execution Path

```text
series query ID
  -> load public series/work indexes
  -> load registry, aliases, groups, assignments
  -> build series + work editor state
  -> tag/weight/alias-assisted changes
  -> one Save action
     -> direct allowlisted API writes
```

The header/media area is catalogue context. Canonical writes are limited to
Studio-owned tag assignments.

## Persistence

Save posts the changed series row and work deltas directly to Local Studio.
Save sends the exact changed records as one validated workflow. The server validates IDs, weights, membership, inheritance, and canonical source before atomic replacement.

When the service is unavailable or a write fails, the current editor state
remains dirty and visible. The editor reports the failure and makes no
browser-local copy, background retry, or alternate persistence claim. A later
explicit Save retries the direct API.

## Durable Rules

- series ID is required and slug-safe; work IDs use the catalogue identity contract;
- assignment rows store flat canonical tag IDs; the editor displays `tag_id`
  and resolves group metadata through the registry;
- manual weights are the fixed values enforced by `tag_source_model.py`;
- one tag ID appears at most once in a row;
- aliases help resolve input and may preserve historical context, but canonical tag ID remains authoritative;
- effective work tags are derived, not stored as a complete copy.

## Code Map

- page/context boot: `series-tag-editor-page.js`
- editor coordinator: `analytics-tag-editor.js`
- domain/state/render/suggestion modules: `analytics-tag-editor-*`
- save policy: `analytics-tag-editor-save-controller.js`, `analytics-tag-editor-save.js`
- server planner: `studio/services/tags/tag_assignment_service.py`

The route root follows shared Studio ready/busy state; selected-work and
editor/empty modes are route-level state, not persistence authority.

## Weak Spots

- The editor coordinates catalogue context, tag search, inheritance, weights,
  and direct writes; module splits reduce file size but not conceptual breadth.
- Public catalogue indexes are a generated dependency and can disagree with canonical assignment state.
- One Save can issue several sequential API requests. Each write is atomic, but
  the group is not one multi-request transaction; a later request can fail after
  an earlier request succeeds.
