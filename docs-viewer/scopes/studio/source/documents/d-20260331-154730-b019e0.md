# Catalogue Media Pipeline Config

## What It Owns

`_data/pipeline.json` is the shared checked configuration for catalogue source-media roots, external staging subpaths, image variant naming, and encoding defaults.

It exists because source discovery, derivative generation, public templates, R2 publication, and consistency checks must agree on the same path and variant policy.

Main consumers load it through `studio/shared/python/pipeline_config.py`, including catalogue generation/build media, the standalone derivative builder, R2 publishing, project-media selection, and site consistency checks.

## Configuration Flow

```text
_data/pipeline.json
  -> pipeline_config.py validates and exposes named values
  -> catalogue/media tools resolve paths below DOTLINEFORM_PROJECTS_BASE_DIR
  -> generators and public shells use matching variant conventions
```

The external `catalogue/media` staging root has no repo-local fallback. Environment variables provide machine-specific base locations and secrets; pipeline JSON provides checked relative policy.

## Change Boundary

Keep here:

- relative source/staging/output subpaths shared across tools;
- primary and thumbnail widths, suffixes, and output directories;
- encoding format, codec, quality, preset, and compression defaults;
- environment variable names shared by pipeline helpers;
- configured workbook and source-root paths used by catalogue operations.

Do not put browser routes, UI text, credentials, or generated payload paths here when another registry owns them.

## Derivative Builder

`studio/services/media/make_srcset_images.py` converts staged source images into the configured primary and thumbnail variants. The normal Work and detail path is the scoped catalogue build, which resolves source images, calls this builder, copies public thumbnails, and reports readiness. Use the standalone command for explicit media maintenance or debugging, not as a second catalogue workflow:

```bash
$HOME/miniconda3/bin/python3 studio/services/media/make_srcset_images.py INPUT_DIR OUTPUT_DIR JOBS
```

Omitting the directories uses the configured Work staging and output roots. `--dry-run` previews derivative writes and staged-source cleanup. Optional selected-ID and success-ID manifests plus the default worker count use names defined in `_data/pipeline.json`; run `--help` for the exact current argument and environment contract.

The builder owns image decoding, scaling and cropping, encoding, variant filenames, parallel execution, and staged-source cleanup. It does not read or write canonical catalogue records, select publication scope, generate public JSON or search, copy final assets to R2, or promote confirmed media versions. Those responsibilities remain with catalogue build planning and [Publish Media To R2](/docs/?scope=studio&doc=d-20260508-093841-3e27b1).

## Why Changes Are Broad

A variant-policy change can affect source staging, derivative filenames, public HTML attributes, R2 object expectations, cache behavior, audits, and regeneration requirements. Treat it as a pipeline contract change and verify all active consumers instead of updating only the image builder.

The config file and `pipeline_config.py` are the exact authority for current values; this page deliberately does not copy the full JSON inventory.
