# Document Diagrams

## Purpose

Docs Viewer uses Mermaid for authored architecture and workflow diagrams that benefit from durable, reviewable source. It supports two source contracts:

- canonical `.mmd` plus a same-basename sanitized SVG for reusable or independently managed diagram media;
- one accessible fenced `mermaid` block for a diagram that belongs only to its document.

Studio uses the accessible fenced block as its working default for Mermaid-authored, document-owned diagrams. Choose canonical `.mmd` plus persistent SVG when the diagram needs an independently managed media identity or stable served URL. Finished SVG remains the direct-media option for authored or imported vectors, and imported local documents retain that media contract until an explicitly selected migration chooses a different canonical source.

The fenced block remains canonical Markdown. Managed local readers render it in memory. Configured public preparation derives a validated light and dark SVG pair, replaces the fence only in the public payload copy, and ships neither source nor Mermaid runtime to public browsers.

Finished SVG and Mermaid source share the source editor's **Add image…** action but keep different contracts. A staged `.svg` is already-finished vector media; a staged `.mmd` is retained as canonical source and rendered before its SVG token is returned.

The static-media workflow is shipped for every scope. Fenced Mermaid rendering is shipped for both managed-local scope types, and fenced Mermaid public projection is shipped for configured public scopes.

## Dependency And Registration

The feature-local Node package root is `docs-viewer/build/mermaid/`:

- `package.json` pins the direct Mermaid CLI dependency;
- `package-lock.json` is the resolved dependency authority;
- `mermaid-config.json` owns shared renderer settings;
- `node_modules/` is local, ignored installation output.

Install the locked dependency tree from the repository root:

```bash
npm ci --prefix docs-viewer/build/mermaid
```

[Runtime Dependencies](/docs/?scope=studio&doc=d-20260423-204839-111501) owns Node package-root policy. [Local Setup Toolchain](/docs/?scope=studio&doc=d-20260519-210908-2f8f00) owns the supported Node/npm baseline and environment checks.

Registration has two layers:

1. `docs-viewer/build/docs_builder/media_builds.py` allowlists the code-owned `mermaid` producer implemented by `docs-viewer/services/docs_mermaid_media.py`.
2. Each participating scope opts in through reciprocal external build-source and managed-media records in `docs-viewer/config/scopes/docs_scopes.json`.

```json
"media": {
  "build_sources": {
    "mermaid": {
      "producer": "mermaid",
      "publishes_to": "svg"
    }
  }
}
```

The same scope's `media.types.svg` record must declare:

```json
"build_inputs": ["mermaid"]
```

The build source derives to `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/media/<scope>/build-source/mermaid/`; the SVG derives to the same scope's managed `svg` directory. Sub-scopes share their parent scope's media namespace.

## Author Workflow

For initial intake through Docs Viewer:

1. save an accessible `.mmd` as a direct child of shared import staging;
2. open the target document's Markdown source editor and choose **Add image…**;
3. select the Mermaid source and provide useful Markdown alt text;
4. allow the service to render in temporary storage, publish and verify canonical source plus SVG, and insert the SVG token;
5. review the dirty Markdown buffer and choose **Rebuild doc**.

A render or publication failure inserts no token and writes no document source. Staged input remains in place after success.

For later edits, view the rendered document and open Document Info. Its manage-only **Diagrams** section lists verified diagram-title links. Choosing one delegates the logical source identity to VS Code without exposing a physical path. Save the canonical `.mmd`; Docs Watcher renders only that changed identity. The Markdown token and search index do not change.

Public routes never show these source links. Markdown source mode retains its semantic-token interface rather than becoming a Mermaid editor.

## Repository Workflow

Repository authors and Codex can work directly:

1. write canonical source to `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/media/<scope>/build-source/mermaid/<diagram-name>.mmd`;
2. add the same-basename SVG token to the owning Markdown document;
3. run the targeted document build:

```bash
$HOME/miniconda3/bin/python3 docs-viewer/build/build_docs.py --scope <scope> --only-doc-ids <doc-id> --write
```

The producer runs before the selected document payload is rendered. A full Docs build renders every configured Mermaid identity in the scope. The watcher, staged intake, targeted builds, and full builds all call the same registered producer.

## Source And Publication Contract

Use lowercase kebab-case identities:

```text
$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/media/<scope>/build-source/mermaid/<diagram-name>.mmd
$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/media/<scope>/svg/<diagram-name>.svg
```

Markdown uses the scope's ordinary SVG media token:

<pre><code>![Useful diagram alt text](&#91;&#91;media:docs/&lt;scope&gt;/svg/&lt;diagram-name&gt;.svg&#93;&#93;)</code></pre>

Each scope owns its source and derived SVG. Do not share canonical source across scopes, edit generated SVG by hand, or register an unversioned global `mmdc` executable.

The repository-pinned persistent-media renderer uses a neutral theme, white background, strict security, `htmlLabels: false`, and an explicit 1200 by 800 browser viewport. Every persistent `.mmd` source requires non-empty Mermaid `accTitle` and `accDescr`; every Markdown reference requires useful alt text. The shared SVG sanitizer must preserve a responsive `viewBox`, accessibility metadata, and visible content before publication succeeds.

## Fenced Document Workflow

Author a fenced `mermaid` block directly in the document when the diagram belongs only to that document and does not need its own managed media identity. Authored non-empty `accTitle` and `accDescr` remain preferred and authoritative. In a managed reader either directive may be omitted: the adapter supplies only the missing SVG accessibility text from the exact mounted document title and diagram ordinal, retains any authored value, and emits a console warning without changing canonical Markdown. Configured public projection remains strict and requires both authored directives before preparation. Canonical Markdown, the managed payload, Markdown export, and static HTML export retain the fence and its source.

In either configured managed local scope type, the manage reader finds those fences after the ordinary document mount, lazily loads the checked Mermaid `11.16.0` browser asset once for the application session, and replaces each successful fence with an accessible inline SVG host. Missing authored accessibility directives do not block rendering. Several fences render sequentially. Navigation invalidates late results, and a parser, renderer, or runtime failure retains its source with a concise visible status while technical detail stays in the console.

For a configured public projection, first make the ordinary Docs payload current, then prepare the complete theme pairs:

```bash
$HOME/miniconda3/bin/python3 docs-viewer/build/build_public_mermaid_projection.py --scope <scope> --write
```

Add `--sub-scope <sub-scope>` when the configured public sub-scope owns the document. The command uses the pinned renderer, shared sanitizer, and configured working-documents artifact adapter. It writes only projection-owned light/dark pairs plus `.publish/public-mermaid-projection/manifest.json`. Both variants must render, sanitize, preserve matching accessibility metadata and geometry, publish, and byte-verify before the family enters that manifest.

Run this preparation before the existing public publish status, confirmation, and apply flow. The publish gate does not render Mermaid. It revalidates the prepared manifest and exact SVG bytes, matches each family to the current document fence and source digest, replaces only the public payload copy, and publishes only consumed variants. A missing, partial, unsafe, or stale family blocks projection. The manifest remains private, and public routes receive neither Mermaid source nor the managed adapter or vendor runtime.

The active managed-local scope type remains the in-browser rendering rule: both `local` and `local_external` are eligible. External is a storage provider distinction, not a different ownership model, and no separate external-local trust capability is configured. An eligible document without a Mermaid fence loads no browser asset.

Runtime authority is `docs-viewer/runtime/js/management/docs-viewer-inline-mermaid.js`, composed only by the manage entrypoint and invoked through the ordinary document controller. The checked browser asset is owned beside other local runtime code at `docs-viewer/runtime/vendor/mermaid/11.16.0/`; the Docs Viewer service preserves its stable browser URL. Neither file lives in the public site tree or public runtime manifest. Shared content CSS owns the bounded neutral host and failure treatment.

## Reader Detail View

Supported rendered diagrams receive one overlaid **Open diagram** button while the diagram body remains ordinary document content. The button requests the shared `content-detail` main view with one exact mount-bound diagram target. The diagram adapter moves the accepted persistent image or managed-inline host into the expanded viewport and **Back to document** restores that same presentation and invocation focus.

A configured persistent SVG retains its stable served URL. A projected public Mermaid image retains the active light or dark variant and refreshes through the public theme owner. A successfully rendered managed-local inline Mermaid host retains the adapter-owned direct SVG, including its responsive `viewBox`, visible presentation, title, and description. Theme refresh while the detail view is active updates the moved presentation through those existing owners.

The existing `main-view` toolbar contributes **Open in new tab** only while the active adapter supplies a valid target. Persistent diagrams use their stable served URL, public-themed diagrams use the active prepared variant, and managed-inline diagrams use a temporary standalone `image/svg+xml` Blob. Theme refresh replaces the relevant toolbar target, and Back, navigation, document replacement, and adapter release revoke temporary resources before ownership ends.

The shared adapter accepts generated persistent and themed markers plus the managed-inline adapter's successful host. Public readers compose the shared adapter for persistent and themed projections; Manage additionally composes inline Mermaid rendering and resource creation; Review retains its returned-package composition. The component button and icon-only toolbar link use the same pill and external-open glyph language, remain native controls with **Open diagram** or **Open in new tab** accessible labels and tooltips, and keep visible keyboard focus. The expanded viewport provides scalable keyboard-focusable inspection at supported desktop widths and in both themes. Public projected diagrams own their separate narrow-width acceptance.
