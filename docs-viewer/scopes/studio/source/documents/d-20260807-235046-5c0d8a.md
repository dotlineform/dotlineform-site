# SSP-7.1b — Set Publishable Evidence

## Outcome

SSP-7.1b is complete. **Set Publishable…** now appears on the parent Index and default sub-scope selection surfaces only when their exact configured collection participates in a public projection. It changes the next-Publish inclusion gate for every exact checked document and does not invoke or alter scope-wide **Publish**.

## Contract Proved

- The parent request is exactly `{scope, doc_ids, publishable, confirm}`; the child request additionally owns exact `sub_scope`. Blank, padded, duplicate, missing, unavailable, local, or extra targets fail before mutation.
- The modal shows the exact checked count, requires **Include in next Publish** or **Exclude from next Publish**, and retains **OK** and **Cancel**.
- Include removes explicit `publishable: false`; Exclude writes only `publishable: false`. Already-matching rows remain unchanged and an all-no-op selection performs no write, rebuild, recent-edit advance, or activity entry.
- Every checked source is resolved before the write boundary. Changed sources are committed through one existing snapshot-checked atomic parent or child rebuild; stale snapshots fail before mutation and rebuild failure restores the complete changed selection.
- Parent and sub-scope UI refreshes return to the exact collection. Local surfaces omit the action. Existing **Excluded from next Publish** markers remain unchanged.
