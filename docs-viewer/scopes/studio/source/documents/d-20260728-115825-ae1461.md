# Sub-Scope Package Preparation Delivery

## Status And Order

Proposed as SSI-3, after
[Sub-Scope Detail Delete Delivery](/docs/?scope=studio&doc=d-20260728-115825-e2561b).
Implementation has not started.

SSI-3 is the broadest delivery. It follows SSI-2 so the manage controller,
capability projection, busy/error handling, collection refresh, public
isolation, and realistic header/list layout have already been proved by a
smaller exact-target workflow.

## Complete Outcome

Manage mode gives a `docs_subscope` list the same compact selection language as
the main Index:

- an Actions control enters selection mode;
- checkboxes appear as siblings to row navigation;
- Select all, Clear, and Done control the current collection selection; and
- the sub-scope Actions menu offers **Prepare package…** for one or more checked
  documents.

The package workflow reads exact sources from `{ scope, sub_scope }`, validates
checked IDs against that collection, and records the complete collection
identity in package provenance.

Every package prepared from a sub-scope is export-only in this delivery. It is
not actionable in Returned Packages, Docs Review, or Docs Import.

## Change Classification

| kind | work |
| --- | --- |
| shipped and retained | compact Index Actions/selection interaction; pure selection transitions; Prepare Package modal; package profiles and engine |
| refactored | isolate collection-neutral selection transitions and package source-context mechanics while preserving current Index behavior |
| extended | add a separate sub-scope selection owner and optional `sub_scope` package request/source/provenance support |
| genuinely new | sub-scope checkboxes, list Actions/selection controls, and package preparation from checked child documents |

The same interaction system is reused; the Index and sub-scope collection keep
separate state owners and cannot supply targets to one another.

## Selection Contract

The sub-scope selection owner is keyed by `{ scope, sub_scope }`.

- Only checked IDs are action targets.
- Opening Actions enters selection mode but does not preselect the parent report
  or an unvalidated detail target.
- Checkbox clicks do not navigate.
- Shift-check extends from the collection's range anchor across currently
  visible eligible rows.
- Row navigation remains available while selection is active.
- Returning from detail to the same mounted collection may preserve selection.
- Inventory refresh prunes missing IDs and retains eligible checked IDs.
- Collection change, report unmount, leaving manage mode, or Done clears the
  owner according to the accepted lifecycle.
- Select all selects the current eligible collection inventory.
- Clear empties checked IDs.
- Done exits and clears selection.
- The compact command group does not add a selected-count label.

The sub-scope action menu contains only capabilities deliberately adopted by
this feature. Copy, Move, bulk Delete, scope actions, and Review Package do not
appear merely because the main Index menu supports them.

## Package Contract

The existing Prepare Package workflow remains the modal and export owner. A
sub-scope request adds one normalized collection field:

```text
scope:     <parent scope>
sub_scope: <configured child>
doc_ids:   <effective checked IDs>
```

The browser and service must:

- list and validate documents from the configured child source root;
- treat the collection as flat and never infer parent-scope descendants;
- derive effective IDs after supported visibility/summary options;
- never add an ID excluded by the submitted checked selection;
- resolve selection and source records by `doc_id`, never title;
- render content through the existing package engine;
- include `scope`, `sub_scope`, selected/exported IDs, profile, and generated
  time in internal provenance and result payloads;
- project sub-scope runs as `supports_return_import: false`, even when the same
  profile supports return for a top-level scope;
- omit or replace return/import instructions in external context for that
  export-only projection; and
- exclude the resulting metadata/files from actionable returned-package
  listing and review.

Top-level scope package preparation remains unchanged when `sub_scope` is
absent.

## In Scope

- One sub-scope Actions control and menu containing Prepare Package only.
- Collection-local checkbox gutters and Select all/Clear/Done.
- Reuse or extraction of pure selection transitions without changing main
  Index behavior.
- A separate collection-keyed selection owner and lifecycle.
- Optional `sub_scope` support across the package browser client, config,
  documents, context, prepare request, source loader, engine handoff, result,
  activity, and metadata.
- Flat-collection effective-selection rules.
- Explicit export-only projection and returned-review exclusion.
- Non-viewable, missing-summary, stale-ID, empty-selection, cancel, success,
  failure, and retry evidence.
- Public/manage module isolation and narrow/dense UI review.

## Not In Scope

- Returned-package review, Docs Review materialization, or Docs Import from a
  sub-scope package.
- Copy, Move, bulk Delete, or any other selection action.
- Parent/descendant expansion inside a flat sub-scope.
- Selecting the parent report or documents from another collection.
- Package profile redesign, new external service adapters, or a new package
  engine.
- Tag Registry reads, group-based filtering, deduplication, or synchronization.
- General report filtering/search or main Index interaction redesign.

## Completion Gate

auditable export-only package, current Index selection/package behavior remains
unchanged, and no return/import or public capability has been implied.
