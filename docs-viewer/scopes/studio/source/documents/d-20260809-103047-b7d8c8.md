# DXM-1 — Packaged Media In Dated Export Delivery

## Status

Proposed and not started. This standalone Roadmap delivery specifies one complete generic Export outcome and does not authorize implementation. Begin with DXM-1.0, record the bounded findings, and stop for implementation approval.

The earlier Dated Export planning sequence is closed and is not revived as a container for this result. [Export](/docs/?scope=studio&doc=d-20260629-152159-ac1af9) remains the durable current-state owner and receives the shipped contract at closeout.

## Complete Result

Docs Viewer Export produces a self-contained dated HTML snapshot for the exact checked documents by copying every referenced, readable, scope-owned media object into the snapshot and rewriting its matching generated HTML reference to the packaged relative path. The result remains provider-neutral across repository, external-local, and R2 media locations and remains usable after the source scope, remote media, or served route is unavailable.

The snapshot does not crawl the web or copy unrelated scope media. References outside the active scope's exact configured served prefixes remain unchanged and are recorded as external dependencies. The package remains a visual and text reference, not canonical Markdown, an import package, a restorable scope backup, or a managed archive.

## Why This Matters Now

The current snapshot copies generated `content_html` while leaving images, downloads, rendered assets, and other media at their original URLs. That makes an apparently complete backup depend on repository routes, local services, or remote R2 objects that may later move or disappear.

The immediate Moments export exposes this gap, but Moments is expected to be removed after backup. The solution therefore belongs to generic Export and must not add Moments-specific Markdown, CSS, routing, storage, or cleanup behavior.

## Package Contract

The proposed `docs_static_html_snapshot_v2` artifact is:

```text
<dated folder>/
  index.html
  styles.css
  snapshot.json
  docs/
    <selected doc_id>.html
  media/
    <media type>/
      <confined relative identity>
```

`media/<media type>/<identity>` preserves the configured media type and confined logical identity. Identical references in several selected documents produce one packaged object. Rewritten document-page references are relative to the packaged object and preserve fragments where meaningful; CDN cache-query syntax does not become part of frozen media identity.

`snapshot.json` records each packaged object's media type, logical identity, provider kind, packaged relative path, byte size, SHA-256 digest, and referencing selected document ids. It also records unchanged external dependencies without credentials or absolute local paths. The preview plan revision covers selected generated documents, resolved media identities, and media byte digests so an apply cannot silently install a different package.

## Reference And Authority Boundary

Export inspects only the selected generated `content_html`. It recognizes references only from supported HTML URL attributes and only when an exact normalized URL is beneath an exact served prefix configured for the active scope and media type. DXM-1.0 freezes the supported attribute set, including the handling of `src`, `srcset`, `poster`, configured media links in `href`, and object data where current generated content demonstrates a need.

After a reference maps to `(scope, media type, confined identity)`, Export reads authoritative bytes through the existing artifact-location adapters. It does not download the served URL, trust a browser-facing URL as byte authority, search several providers, infer identity from filenames, or fetch an arbitrary remote host. Repository, external-local, and R2 remain physical providers behind the same exact read contract.

An exact matching scope-owned reference that cannot be normalized, confined, read, or verified blocks the plan before target replacement. A reference that does not match configured scope ownership remains external and unchanged. Provider failures cannot downgrade an owned reference into an external dependency.

Packaged HTML media objects are copied as exact objects but are not recursively crawled for their own scripts, styles, frames, or media. CSS `url()` discovery, site-shell asset capture, arbitrary download mirroring, and recursive dependency graphs are outside this delivery.

## Preview And Apply Contract

Preview remains read-only but may perform the provider reads and hashing required to produce an exact plan. Its confirmation adds packaged media count and total bytes without introducing an **Include media** mode; referenced scope-owned media is the normal v2 snapshot behavior.

Apply recomputes the selected generated-document plan, re-reads and re-hashes each exact media identity, and rejects stale source, media, configuration, or target state. It renders documents, copies media, rewrites recognized references, writes provenance, and validates the complete result in the existing sibling staging boundary before any final installation or guarded replacement.

Version 2 is the sole newly written schema. Existing version 1 snapshot folders do not gain a compatibility writer or hidden upgrade path; DXM-1.0 must confirm their explicit replacement classification under the existing recognized, unrecognized, and collision safeguards.

## Delivery Boundary

DXM-1 includes:

- exact selected-generated-HTML media-reference extraction;
- mapping only through active-scope configured served prefixes and confined identities;
- provider-neutral reads through current repository, external-local, and R2 artifact locations;
- exact-byte hashing, deduplication, manifest provenance, staged copying, and relative URL rewriting;
- unchanged and recorded external dependencies;
- v2 preview, stale-plan, target-replacement, and snapshot contracts;
- focused backend, route, capability, and existing management-workflow follow-through where the v2 payload requires it; and
- durable Export documentation transfer and proportional generated-document verification at closeout.

DXM-1 excludes:

- canonical Markdown, scope configuration, generated payload, or full-scope backup and restore;
- copying unchecked-document media or inventorying every object in the selected scope;
- arbitrary URL downloads, CDN crawling, provider fallback, a second media registry, or a generic asset bundler;
- recursive HTML, CSS, script, iframe, font, or site-shell dependency capture;
- media migration, deletion, garbage collection, R2 cleanup, scope deletion, or Moments retirement;
- an export mode, destination picker, background schedule, archive manager, or import workflow;
- Moments-specific Markdown rendering, stylesheet capture, or CSS correction; and
- weakening the existing exact checked-id, generated-payload, staged replacement, symlink, traversal, and user-owned target boundaries.

### Frozen V2 Contract

- Newly written provenance, preview, and apply responses use `docs_static_html_snapshot_v2`, `docs_static_html_snapshot_preview_v2`, and `docs_static_html_snapshot_apply_v2`. Apply request fields remain unchanged because `plan_revision` owns document and media freshness.
- Version 1 folders are classified as **unrecognized** after the v2 cutover. They remain explicitly replaceable through the existing danger confirmation; there is no dual reader, compatibility writer, or in-place upgrade.
- One focused HTML parser/rewriter processes `src`, `srcset`, `poster`, and `data`. `href` is packaged only when it maps to an exact configured media prefix; an unmatched ordinary hyperlink is not an external media dependency. `link[href]` and unmatched values in the other supported URL attributes are dependency candidates. Inline `data:` and fragment-only references remain unchanged and are not external dependencies.
- Each `srcset` candidate is planned independently and its descriptor is preserved. A configured absolute prefix matches only the same scheme, authority, and strict path boundary; a configured root-relative prefix matches only its strict path boundary. Scheme-relative, other-scope, lookalike-prefix, and other-host references do not match.
- Ownership matching ignores query and fragment. The path is URL-decoded once and then passed through `normalize_artifact_identity()`; an invalid, escaping, empty, missing, or unreadable owned identity blocks preview. Rewriting drops the cache query after bytes are frozen and preserves a fragment.
- Packaged output uses the exact confined path `media/<media type>/<identity>`. The plan rejects output-path collisions or a path the destination filesystem cannot represent; it does not invent renamed identities or a second mapping registry.
- `snapshot.json` adds `media_count`, `media_bytes`, `media`, `external_dependency_count`, and `external_dependencies`. Each media row contains `media_type`, `identity`, `provider`, `packaged_path`, `size`, `sha256`, and ordered referencing `doc_ids`. Dependency rows contain a query-free browser reference, element/attribute context, and ordered referencing `doc_ids`; generated HTML retains its original unmatched URL.
- Preview exposes only non-negative `media_count`, `media_bytes`, and `external_dependency_count`, not media identities or filesystem paths. Confirmation retains the destination as its first line, adds a human-readable included-media line, and adds an unchanged-external-media line only when the count is non-zero.
- Preview reads and hashes each exact referenced object once. Apply recomputes the plan, reads and hashes each exact object again, compares the v2 revision, retains those verified bytes only for the lifetime of that apply plan, and stages them through the existing exact file-set boundary. It does not list a provider or fetch a served URL.
- HTML media objects such as the current Library iframe are copied as exact objects. Their internal scripts, styles, frames, and assets are not recursively inspected or packaged.
- Export capability remains generated-document readiness. R2 credentials, object availability, and selected media bytes are exact preview concerns; capability projection must not authenticate unrelated providers or claim remote byte readiness.

### Scale, Risks, And Stop Conditions

The expected implementation diff is approximately 370–540 production lines: 260–360 in the focused Python media module, 90–140 in exporter integration, and 20–40 in the existing JavaScript workflow. Focused evidence is approximately 420–610 test lines: 260–360 in the new pure/service test module, 120–180 in exporter integration tests, and 40–70 in the existing module smoke. This is a material feature slice, but it remains three production owners and does not justify a registry, crawler, downloader, streaming framework, or alternate export format.

Preview and apply cost is proportional to the referenced media bytes, and the current adapter contract returns bytes in memory. DXM-1 may retain verified bytes for one apply plan, but if representative packages require streaming, caching, background jobs, archive chunking, or a new size-policy workflow, stop and propose that separately rather than widening this delivery. HTML rewriting must also preserve code blocks, inline Mermaid source, iframe attributes, entities, and ordinary links semantically; focused parser fixtures own that risk.

Actual R2 byte access was not tested at this checkpoint. The provider-neutral adapter contract and fake-client seam are proven current owners, while a credentialed Moments preview remains implementation/runtime evidence after DXM-1.1—not a claim made by DXM-1.0.

## Completion Gate

DXM-1 is complete only when a dated snapshot of an exact checked selection contains one verified local copy of every referenced readable scope-owned media identity, its selected document pages use those local copies, manifest provenance accounts for packaged and external dependencies, provider and target changes are detected before installation, and failure preserves the prior target.

A package that relies on current R2 or local-service URLs, copies the whole scope inventory, omits an owned missing object, fetches arbitrary remote URLs, follows recursive dependencies, leaks credentials or absolute paths, rewrites unowned references, changes source/configuration, or adds Moments-specific behavior is not a pass.
