# IFS-1 — Docs Import Folder Source Selection Delivery

## Status And Purpose

Proposed and parked as **IFS-1**, a future delivery related to [Docs Import](/docs/?scope=studio&doc=d-20260424-000000-fc8b5d).

Ordinary Import currently lists only direct children of `$DOTLINEFORM_PROJECTS_BASE_DIR/data-sharing/import-staging/`. This delivery lets a user choose another folder beneath `$DOTLINEFORM_PROJECTS_BASE_DIR`, list eligible ordinary sources there, and remember that relative folder between local browser sessions. Import staging remains the default.

The feature removes unnecessary copying for occasional standalone imports. It does not add recursive discovery, batch apply, or a second import workflow.

## Complete Outcome

The Manage-only app Import modal has one server-backed source-folder control. It begins at `data-sharing/import-staging/`, can browse to any validated real directory beneath `$DOTLINEFORM_PROJECTS_BASE_DIR`, and lists the same eligible direct-child ordinary files and one-document Markdown-package folders already accepted by Import.

The browser stores only the chosen base-relative directory for the next local session. The server re-resolves and revalidates it whenever the modal opens or the selection changes. A missing, unreadable, symlinked, or out-of-root value falls back safely to import staging.

Selecting a different source directory changes only candidate discovery and source provenance. Existing recognizer-first classification, frozen ordinary destination, conversion, media, create-only identity, source-write, rebuild, and exact-result contracts remain unchanged.

## Relationship To PRJ-2

IFS-1 is not a prerequisite for [PRJ-2 — Projects Customisation And Apple Notes Migration Delivery](/docs/?scope=studio&doc=d-20260801-133317-e8eb39). If it shipped first, its base-relative source locator could remove one small migration-specific adapter and make individual manual imports less awkward. It would not provide corpus inventory, multi-note folder handling, `folder_path` mapping, stable whole-plan identities, resumable apply, or the final reconciliation report.

PRJ-2 therefore remains a separate one-off migration and should not wait for IFS-1. The later IFS-1 implementation may reuse an already-shipped confined base-relative locator if PRJ-2 establishes one cleanly.

## Fixed Contracts

- IFS-1 extends ordinary standalone-source discovery only. It does not widen trusted returned-package or edited review-source-folder intake beyond the shared import-staging boundary.
- Registered collection recognizers still inspect an untouched candidate before generic Markdown or suffix handling. A trusted format encountered outside staging is not downgraded to an ordinary import.
- The server accepts and returns only `$DOTLINEFORM_PROJECTS_BASE_DIR`-relative directory markers. Absolute machine paths never become browser-owned state or public response data.
- Folder resolution reuses the shared external-workspace confinement primitives. It rejects blank paths, parent traversal, non-directories, symlinks, symlink escapes, missing paths, and resolved paths outside the configured base.
- Candidate discovery remains one level deep. It lists supported standalone files and eligible direct-child Markdown-package directories; it does not recursively scan the selected tree.
- Existing source-format allowlists and standalone-media exclusions remain authoritative. Folder selection does not make arbitrary files importable.
- A selected Markdown-package directory retains its own folder as the package root for relative image and attachment resolution.
- Opening Import still freezes one validated `{scope}` or `{scope, sub_scope}` destination for ordinary candidates. Source location is never a destination signal.
- The remembered folder is a local UI convenience, not configuration or authority. The server revalidates it and the browser replaces an invalid value with `data-sharing/import-staging/`.
- The source folder is read-only. Import neither moves nor deletes its inputs.
- Results and diagnostics use base-relative markers and never expose absolute local paths.

## Interaction Shape

- Reuse the existing Import modal and candidate list.
- Show the current relative source folder in the modal's existing header area with **Choose folder…** and **Use import staging** actions.
- **Choose folder…** opens one focused, server-backed directory browser rooted at `$DOTLINEFORM_PROJECTS_BASE_DIR`; it is not a native browser filesystem picker and cannot select outside that root.
- Browse directories lazily by direct children and show a base-relative breadcrumb. Confirming a folder refreshes the existing candidate list.
- Store the last confirmed relative folder in local browser state only after the server accepts it. Cancel leaves the current folder unchanged.
- Keep the existing Import status, retry, modal ownership, and stale-status clearing behavior.

## Not In Scope

- recursive search or whole-tree candidate expansion;
- multi-selection, batch apply, jobs, progress, or resumable corpus migration;
- PRJ-2 Apple Notes migration or `folder_path` assignment;
- trusted package or edited review-source intake outside import staging;
- native operating-system folder access or paths outside the Projects base;
- new source formats, media rules, destination selection, or overwrite rules;
- copying, moving, deleting, or synchronizing source material; or
- server-wide or multi-user preference synchronization.

## Completion Evidence

- Import staging remains the default and behaves byte-for-byte as before when no alternate directory is selected.
- Every selected and remembered source directory is server-resolved beneath `$DOTLINEFORM_PROJECTS_BASE_DIR` and represented externally by a relative marker only.
- Ordinary candidates from the selected folder retain existing classification, conversion, exact destination, create-only, media, and rebuild behavior.
- Trusted formats cannot bypass staging or fall through to ordinary Import.
- Invalid remembered folders fail closed to import staging without changing the current destination.
- No recursive or batch-import capability is introduced.
