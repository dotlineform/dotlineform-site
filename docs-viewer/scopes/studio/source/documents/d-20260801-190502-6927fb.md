# Docs Import Folder Source Selection

Shipped through [IFS-1](/docs/?scope=studio&doc=d-20260803-113717-fd92bc) on 2026-08-03. [Docs Import](/docs/?scope=studio&doc=d-20260424-000000-fc8b5d) and [Docs Import Architecture](/docs/?scope=studio&doc=d-20260514-164722-3de65e) own the current operator and architecture behavior. Further UI refinement is separate from this completed feature.

## Purpose

Ordinary Docs Import can choose a validated directory beneath `$DOTLINEFORM_PROJECTS_BASE_DIR` and remember that base-relative source between local browser sessions. Import staging remains the default.

The feature removes unnecessary copying for occasional standalone imports. It does not add recursive discovery, batch apply, or a second import workflow.

## Complete Feature Outcome

The Manage Import modal shows the active relative source and offers **Choose folder…** and **Use import staging** actions. **Choose folder…** opens a dedicated, server-backed directory browser rooted at the Projects base. Confirming a folder refreshes the existing ordinary candidate list; cancelling leaves the current source unchanged.

The server validates every requested and remembered directory. Invalid values fail closed to import staging. Only source discovery and provenance change: recognizer-first classification, frozen destination, conversion, media, create-only identity, source-write, rebuild, and exact-result contracts remain unchanged.

## Boundary

In scope are one app-neutral shared folder-picker component, an explicit Docs Viewer shared-asset boundary, a dedicated folder-picker modal and Import handoff, one shared confined-directory capability, lazy direct-child directory browsing, direct-child ordinary candidate discovery, exact source-directory and filename binding, and a browser-local remembered selection accepted by the server.

Out of scope are native operating-system dialogs, recursive or batch discovery, trusted package intake outside import staging, new formats or destinations, overwrite behavior, source mutation, and server-wide or multi-user preferences.
