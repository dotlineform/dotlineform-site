# TDL-0 — Tag Document Metadata Authoring Refactor Delivery

## Status And Purpose

Proposed as the standalone UI prerequisite to [TDL-1](/docs/?scope=studio&doc=d-20260804-160201-47af2d), after [SSC-1 — Unified Sub-Scope Customisation Contract Delivery](/docs/?scope=studio&doc=d-20260804-172012-5d91bf). This delivery moves Analysis Tags document `group` editing out of the app-level **Edit metadata** modal so that the shared modal can contain only document-common front matter.

The current generic modal has a dedicated `group` field populated from sub-scope configuration. The field is useful, but its ownership is wrong: `group` belongs to the registered Tag-document customisation, not to every document. SSC-1 first establishes one accepted customisation and aspect vocabulary; TDL-0 then relocates the field before TDL-1 adds another Tag-owned field, `tag_id`.

## Complete Outcome

On the local Manage route, Info remains read-only and displays all metadata projected by the exact active document's resolved scope/sub-scope configuration. For the current Analysis Tags registration, that includes the document's configured `group` state beneath the common document summary. Public Info receives no Manage customisation data or controls.

A resolved `sub_scope_customisation` that declares an assignable Tag-document field group may expose a focused Tag-document fields action and modal. `analysis/tags` is the current configuration registrant because its customisation declares the supported `group` field and choices; the browser, Info view, modal, and service do not activate through literal scope/sub-scope name comparisons. Availability derives from the declared assignable fields rather than a separate boolean.

The modal initially edits only document `group`, using the current configured choice order and exact source value. It owns confirmation, cancellation, exact `{scope, sub_scope, doc_id}` target, source revision, mutation feedback, and clear/unassigned behavior. TDL-1 later extends the same registered field group and modal with optional canonical `tag_id` selection while Info remains read-only.

After the migration, **Edit metadata** no longer contains, hydrates, renders, validates, or submits `group`. Together with SSP-0's Projects extraction, this restores the target boundary: **Edit metadata** owns common document fields, while configured sub-scope workflows own their fields.

Document `group` and canonical Tag Registry `group` remain independent fields. Existing create-time seeding stays create-only. Editing a Tag document's group through this modal never updates, compares, repairs, or triggers a build from the Registry group, and editing the Registry never rewrites document front matter.

## Awareness And Registration Boundary

- **Edit metadata** remains document-agnostic and knows only common front matter.
- **Info** resolves the active collection's registered metadata display contribution and renders its values read-only.
- The focused Tag-document modal resolves the active collection's declared assignable Tag-document fields and their choices.
- Current availability in `analysis/tags` is a configuration fact, not a hard-coded route or collection-name condition.
- `analysis/tags` public presentation as Concepts does not change its technical collection identity or expose Manage authoring capability publicly.

## Delivery Discipline

TDL-0 consumes SSC-1's accepted Info, assignable-field-group, exact-target, and access-projection seams, then reuses the current Analysis Tags group choices, management modal shell, revision receipts, atomic source mutation, and targeted sub-scope rebuild. It does not introduce a generic field-schema editor, editable Info panel, Tag Registry synchronization, generic cross-collection mutation service, public management contribution, or Tag association behavior.

TDL-0.0 is a short scope-and-spec sanity gate. Each implementation stage ends with focused evidence and an independent code/diff review before the next stage begins.

## Delivery Steps

### TDL-0.0 — Confirm Scope And Delivery

- [ ] Confirm SSC-1 has accepted the unified `sub_scope_customisation`, read-only metadata, assignable-field-group, exact-target, and access-projection contracts; then sanity-check common-versus-Tag metadata ownership, current group choices, focused mutation, generic-modal extraction, and public isolation against current broad owners.
- [ ] Confirm the likely blast radius across hosted-view context, active sub-scope target projection, Analysis Tags customisation, metadata modal shell/workflow, focused management modal, group mutation, targeted rebuild, and current group/report tests.
- [ ] Confirm the deliverables: read-only configured group display, capability-selected Tag-document modal, exact revision-safe group update, generic `group` control retirement, TDL-1 extension seam, focused evidence, and durable Info/management/customisation documentation transfer.
- [ ] Stop for review if the outcome requires inline Info editing, literal collection-name checks, Registry/document group synchronization, a generic field-schema framework, public authoring controls, or early `tag_id` association work.

**Checkpoint:** a concise sanity note confirms implementation fit, broad owners, blast radius, deliverables, risks, exact-target behavior, public isolation, and the TDL-1 handoff. Stop before implementation approval.

### TDL-0.1 — Add Read-Only Configured Tag Metadata

- [ ] Project the exact active managed-document target and its registered Tag-document metadata into Info without reparsing Markdown or hydrating a write service in the view.
- [ ] Render configured document group and unassigned/unavailable evidence read-only while preserving the compact common metadata summary.
- [ ] Project Tag-document fields action availability from the resolved assignable field declaration; prove the current Analysis Tags registration enables it while other collections and public routes remain action-free.
- [ ] Preserve outside-context Info view selection and the shared shell's view-agnostic lifecycle.

**Checkpoint:** focused exact-target, wrong-target, group-state, lifecycle, action-capability, other-collection, and public-isolation evidence passes. An independent code/diff review confirms Info remains a passive configured projection. Stop before TDL-0.2.

### TDL-0.2 — Move Group Editing Into The Tag-Owned Modal

- [ ] Add the focused Tag-document fields modal with configured group choices, exact target and source revision, confirmation, cancellation, clear behavior, and contained status/errors.
- [ ] Add a capability-restricted mutation that resolves the exact sub-scope configuration, accepts only its declared Tag-document fields and values, preserves revision conflict and atomic replacement, and triggers the exact required rebuild without a collection-name branch.
- [ ] Remove the dedicated group field, choice projection, hydration, validation, and payload handling from **Edit metadata** after focused equivalence evidence confirms the new owner.
- [ ] Preserve a bounded extension seam for TDL-1 to add optional `tag_id` selection to the registered Tag-document field group without changing Info or the generic modal.
- [ ] Preserve the independence of document group and Registry group across reads, writes, builds, reports, and failures.

**Checkpoint:** focused modal, configured choices, clear, cancel, stale revision, invalid choice, exact-target, atomic-write, targeted-build, generic-metadata independence, Registry independence, and public-boundary evidence passes. An independent code/diff review confirms the Tag customisation is the only group-editing owner. Stop before TDL-0.3.

### TDL-0.3 — Verify And Transfer

- [ ] Run focused service, browser-module, route-boundary, source-lint, generated-doc, search, and whitespace checks proportional to the changed contracts.
- [ ] Verify rendered-document and Markdown-source contexts, assigned/unassigned group, unavailable management service, stale revision, clear/cancel behavior, no-contribution collections, and public read-only presentation.
- [ ] Perform the independent final code/delivery review and reconcile completion claims with exact evidence and omissions.
- [ ] Update [Info Panel](/docs/?scope=studio&doc=d-20260623-000000-c99cef), [Management Operations](/docs/?scope=studio&doc=d-20260519-202931-66c794), and the current sub-scope customisation owner with the shipped read-only projection, configured authoring action, mutation, group independence, and public-isolation rules.
- [ ] Update TDL-1 to consume the accepted Tag-document field contribution before adding `tag_id` meaning and associations.

## Completion Evidence

- **Edit metadata** contains and submits only common document fields; its dedicated `group` control has retired.
- Info displays the exact active collection's registered metadata read-only, including Analysis Tags document group.
- The current Analysis Tags configuration exposes the Tag-document fields modal through its declared assignable group without literal collection-name availability logic.
- Document group updates are exact-target, revision-safe, atomic, choice-validated, and independently rebuilt.
- Document `group` and Registry `group` retain independent owners and mutation paths.
- Public routes receive neither private group metadata nor Tag-document authoring capability.
- TDL-1 can add optional `tag_id` to the same Tag-owned modal and read-only Info projection without changing shared surfaces.
