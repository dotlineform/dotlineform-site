# Tag-document linking

tags are defined in tag registry `studio/data/canonical/tags/tag-registry.json` and may also have associated documentation in `docs-viewer/scopes/analysis/source/sub-scopes/tags/documents`.

the documentation is not intended to be kept in sync with the summary information in the tag registry, nor be deleted when a tag is deleted from the registry.

the following is however needed:

- a one-off process to create documents for existing tags, where no document currently exists.
- the document link recorded in the tag registry record, and editable in the Studio tag registry modal for a tag.
- a way of linking from a tag in `/studio/tag-registry/` to the document in `/docs/?scope=analysis...`

there is also currently a structural problem: the registry recognises that tags are in groups, and a tag label can be in multiple groups. this is why `tag_id` is a concatination of `group` and `label`. the current sub-scope documents do not recognise this structure. documents can be listed in `/docs/?scope=analysis&doc=d-20260624-213316-478639` but cannot be filtered (or styled) by group. To do this, we would need an additional front-matter field 'group'.

## Current schema

tag-registry:
```
{
  "tag_id": "subject:bird",
  "group": "subject",
  "label": "bird",
  "description": "Depicted bird: an observable element the viewer can point to. Useful for content-level linking across media; keep separate from domain framing and theme inference to reduce ambiguity.",
  "updated_at_utc": "2026-03-03T17:43:04Z"
}
```

document:
```
---
doc_id: d-20260624-204534-0d6ae2
title: "bird"
added_date: 2026-06-24 20:45:34
last_updated: 2026-06-24
parent_id: ""
---
```
