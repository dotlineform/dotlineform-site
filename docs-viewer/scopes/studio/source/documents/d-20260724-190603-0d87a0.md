# Public Mermaid Projection Delivery

When a public-scope document contains an accessible Mermaid fence, public preparation produces one validated light SVG and one validated dark SVG from that source. The published document shows one image surface matching the active public-site theme, and **Open diagram in new tab** targets the same variant. Public browsers never receive Mermaid code or the Mermaid runtime.

## Current State

- Markdown rendering retains fenced Mermaid as `<pre><code class="language-mermaid">` in canonical and managed payloads.
- Managed local readers may replace that fence with an in-memory SVG; configured public preparation replaces only the public payload copy with a verified themed image.
- The pinned Mermaid producer currently transforms canonical `.mmd` media into one neutral sanitized SVG.
- Public document publication filters working payloads and assembles verified prepared Mermaid pairs. Status, confirmation, and apply do not render content or create prepared output.
- Public Docs Viewer decorates fixed and themed persistent SVG images with Diagram Detail View without loading the manage-owned Mermaid adapter or vendor asset.

## Accepted Contract

### Source And Projection Identity

- The fenced Mermaid block remains the sole canonical source. Do not create a `.mmd`, insert a media token, or rewrite Markdown.
- Require the same non-empty Mermaid title and description metadata as existing accessible Mermaid rendering.
- Allocate one deterministic projection identity per document fence and derive exactly two variants from it: `light` and `dark`.
- Record generated identities in a projection-owned manifest so rebuilding can replace changed variants and remove outputs for deleted fences or documents.
- Treat both variants as one generated diagram family in planning, reporting, cleanup, and verification.
- Do not infer pairing from filename suffixes in the reader. The public payload carries explicit light and dark variant references.

### Public Preparation

- Apply this transformation only while preparing a configured public projection. Ordinary managed payload builds and source-faithful exports retain the fence.
- Render both variants from the same source with the repository-pinned Mermaid toolchain, strict security, disabled HTML labels, one font/layout configuration, and the corresponding accepted Docs Viewer theme seed.
- Require both outputs to preserve accessible title and description metadata, visible content, responsive `viewBox`, and the same aspect ratio.
- Sanitize and validate both variants through the existing SVG publication boundary before either becomes publishable.
- Publish the pair atomically through configured artifact-location ownership. A missing or invalid variant blocks that diagram's public projection rather than publishing partial theme coverage.
- Complete Mermaid rendering before publish status, confirmation, or apply. The existing publish gate may assemble and compare prepared projection bytes, but it does not invoke Mermaid or create build output.

### Public Payload And Runtime

- Replace the fence only in the public projection payload with one explicitly marked themed persistent-diagram surface.
- Carry useful image alternative text from the validated Mermaid accessibility metadata.
- On document mount, select the light or dark URL from the already-applied `html[data-theme]` value before exposing the image.
- The public theme owner notifies the public diagram adapter after applying a new theme. The adapter changes only the registered themed image URL and matching detail target.
- Keep one image, one frame, one viewport, and one detail control in the document. Do not render duplicate light and dark images into the reading order.
- A theme change performs no Mermaid work and does not fetch source.
- Ordinary persistent SVGs retain their current fixed URL and presentation.

## Verification Boundary

Permanent evidence should protect source preservation, projection identities, atomic variant production, manifest cleanup, sanitizer and accessibility requirements, explicit public payload shape, theme selection, and runtime exclusion.

Manual browser review owns palette quality, diagram legibility, theme-transition appearance, narrow overflow, and standalone SVG presentation. Screenshot baselines and complete SVG-markup assertions are unnecessary.

## Explicitly Outside This Delivery

- Migrating existing `.mmd` diagrams, SVG tokens, or finished SVG media.
- Theme-sensitive treatment for arbitrary persistent SVG.
- Public Mermaid source, browser parsing, editing, or runtime delivery.
- Managed-local inline theme implementation.
- Reader-oriented export conversion.
- A general responsive-image, illustration, or asset-variant framework.
- Changes to public navigation, mobile information architecture, or unrelated theme surfaces.

## Completion Gates

- one accessible Mermaid fence remains canonical while producing one verified light/dark public pair;
- both variants are deterministic, manifest-owned, sanitized, accessible, and geometry-compatible;
- partial pairs cannot enter the public projection;
- public payloads expose explicit variant references without changing canonical Markdown;
- the public reader shows one image and keeps its `src` and detail target aligned with the active theme;
- public routes load no Mermaid runtime or source;
- ordinary persistent SVG, managed rendering, and source-faithful export behavior remain unchanged;
- focused automated evidence and manual public light/dark review pass.
