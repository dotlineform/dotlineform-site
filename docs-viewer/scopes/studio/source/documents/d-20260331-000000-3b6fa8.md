# Tag Groups

## Capability

`/studio/tag-groups/` is the read-only taxonomy reference. It shows the
configured short and long description for each tag group in Studio tag-policy
order.

It does not edit group identity or policy. Group descriptions come from
`studio/data/canonical/tags/tag-groups.json`; group order and coverage
participation come from
`studio/data/config/tags/tag-management.json`; allowed registry groups are
enforced by registry policy/model validation.

## Execution Path

```text
tag-groups.html
  -> tag-groups.js
  -> studio-tag-data.js
  -> GET /studio/api/tags/tag-groups
  -> tag-groups.json
  + analysis.groups ordering from runtime config
```

The route has no commands and never sets busy. Its Studio ready-state root
moves to list or empty after load.

## Code Map

- template: `studio/app/frontend/routes/tag-groups.html`
- controller: `studio/app/frontend/js/tag-groups.js`
- shared selectors/styles: `studio/app/frontend/js/tag-ui.js`,
  `studio/app/assets/css/studio-tags.css`
- API read map: `studio_tags_api.py::READ_ENDPOINTS`
- canonical prose: `studio/data/canonical/tags/tag-groups.json`
- order/coverage policy:
  `studio/data/config/tags/tag-management.json`

## Change Method

- prose change: edit `tag-groups.json`;
- display order or coverage membership: edit Studio tag policy and scoring tests;
- new group identity: treat it as a registry-model change, then update descriptions, policy, UI/scoring assumptions, imports, and tests together.

Do not use this page as a second exhaustive list of group values. Current JSON and config show the exact set.
