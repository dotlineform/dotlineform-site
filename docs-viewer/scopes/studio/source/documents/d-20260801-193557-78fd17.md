### Frozen Projects Customisation Contract

- The selected ID is `dotlineform_projects`; its settings object is strict and
  empty. It is registered for Manage only.
- Source front matter owns either no field or one scalar decoded relative path,
  such as `folder_path: projects/architecture`. The PRJ-1 grammar rejects an
  empty segment, `.`, `..`, absolute stored values, backslashes, control
  characters, and schemes.
- Metadata Save accepts the stored relative form or normalizes an absolute
  POSIX/Finder path, local `file:` URL, or shell-display escaped absolute path.
  Blank removes the field. Markdown and `dlf-local:` representations fail.
- The exact source read and successful save response expose only
  `record.customisation.folder_path`. The request customisation object accepts
  exactly `folder_path`; unknown fields and use on another collection fail.
- `manage-manifest.json` adds only the same decoded value to the exact row as
  `customisation.folder_path`. Its root descriptor is
  `{"id":"dotlineform_projects","data":{}}`. A pathless row has no row
  customisation value.
- The public manifest remains byte-compatible `{doc_id, title}` data and the
  public registry has no Projects loader.
- The browser contribution mounts one native text input labelled **Folder
  Link**. It performs no paste interception, clipboard write, `execCommand`,
  fake Undo, or paste status messaging.
- Save retains the shared modal lifecycle: the modal closes before the
  asynchronous server mutation. A rejected invalid or out-of-root value makes
  no source change and is reported through the existing Manage error surface.
- Rows show the exact path, no-link state, and duplicate use computed from the
  loaded manifest. The detail action submits only that row's exact path to the
  existing local-target client.
- PRJ-2.1 does not scan current folders or add `folder_exists`. A stored link is
  valid whether current, missing, or prospective. Project State later owns
  existence classification; explicit Open in Finder may return missing.

The additive metadata contribution contract is deliberately smaller than a
custom-field schema: the selected registered module may mount one editor into
the detached host, return its strict payload on Save, and destroy it on close.
The shared modal still owns its existing fixed fields and lifecycle.

### Frozen Migration Plan Contract

The command is fixed to:

```text
source:      $DOTLINEFORM_PROJECTS_BASE_DIR/Notes export - 2026-05-18/iCloud/dotlineform/projects
folders:     $DOTLINEFORM_PROJECTS_BASE_DIR/projects (direct children only)
destination: {scope: dotlineform, sub_scope: projects}
```

It has explicit `--plan`, `--apply`, and `--validate` modes. The local ignored
artifact directory is:

```text
var/docs/dotlineform-project-notes-migration/
  folder-mapping.json
  plan.json
  plan-report.md
  receipt.json
  result-report.md
```

`folder-mapping.json` is the only reviewer-edited artifact. Exact folder-name
matches are recorded as `exact_match`. Every unmatched exported top-level
folder starts as `review_required` and must become either an explicit
`mapped` target or `no_current_folder`. There is no normalization or fuzzy
match. The planner refuses to emit `plan.json` while a decision is outstanding.

Once mapping is complete, the first final plan allocates and records all
identities and is create-only. Re-running `--plan` validates the existing plan;
it does not replace it or allocate new identities. Replacing a reviewed plan is
an explicit operator action outside the command.

The plan schema is `dotlineform_project_notes_migration_v1` and records:

- exact collection and marker-rooted input/output identities;
- one operation timestamp shared by all records and one recorded
  `allocate_doc_id` result per Markdown file, ordered by case-folded
  export-relative path;
- every Markdown relative path and SHA-256, normalized title/body preview,
  target source path and SHA-256, and accepted/pathless mapping decision;
- every referenced asset relative path, input SHA-256, supported/unsupported
  classification, owning document, deterministic target filename, media class,
  and conversion plan;
- hashes of the export inventory, direct current-folder inventory, mapping,
  pre-existing Project source inventory, and canonical plan payload;
- all preserved missing, unsupported, already-normalized, `applenotes:`, and
  `sandbox:` references plus summary counts; and
- explicit readiness, blockers, and untouched existing document records.

Title selection reuses the ordinary order: first H1, then scalar ordinary front
matter `title`, then humanized Markdown filename stem. The current snapshot has
an H1 in all 240 Markdown files and no front matter. Duplicate titles remain
valid. Every Markdown file creates one document even when several files share
an exported folder, and all may share its reviewed `folder_path`.

The plan file retains normalized Markdown previews because apply must consume
the exact reviewed conversion and media filenames rather than reallocate them.
It remains under ignored local `var/`; `plan-report.md` is the sanitized human
review surface and the retained Studio companion records only hashes, counts,
exceptions, and deviations.

### Frozen Apply And Resume Contract

The write-free real plan does not require watcher shutdown. Immediately before
an accepted real apply, PRJ-2.3 quiesces the Docs live rebuild watcher through
its owning local service and records that neither the watcher nor a Docs build
is active. The Tags bootstrap left its watcher running and it regenerated
payloads during the seed; PRJ-2 must not repeat that behavior because this
contract commits the complete batch before one migration-owned rebuild.

Apply first rehashes the complete input, mapping, current-folder snapshot, and
every untouched pre-existing collection source. Current collection inventory
may differ from the baseline only by byte-identical targets owned by this plan;
an unplanned addition, removal, or change stops the run. Apply then prepares
every planned media output and invokes the existing media owner's complete-set
write-free preflight. Before any write, all source targets must be absent or
byte-identical planned resume targets, and all media targets must be absent or
byte-identical. Any other source, media, inventory, or plan collision stops the
run.

Each not-yet-committed record then follows the shared order:

```text
stored ImportContent + stored preview/media plan
  -> plan_import_document with recorded ID and timestamp
  -> verify projected source SHA-256
  -> materialize supported media
  -> write_text_atomic_new exact source
  -> atomically advance receipt
```

`receipt.json` is bound to the plan revision and records exact per-document
media/source completion and hashes plus rebuild state. A retry recognizes only
byte-identical targets named by the plan, whether or not the previous process
advanced the receipt before stopping. Mismatched content is never adopted.
No retry reparses targets, allocates an identity, chooses another filename, or
deduplicates by title/body.

After every plan target is exact, apply invokes the existing confined child
rebuild once. A rebuild failure leaves committed media and sources in place and
records `rebuild: failed`; a repeated `--apply` skips exact committed targets
and retries the rebuild only. `--validate` checks plan, receipt, source, media,
and generated manifest agreement without writes.

The watcher remains quiesced across a resumable partial failure; restarting it
would publish an intermediate collection outside the migration receipt. After
apply, the owned rebuild, and `--validate` all succeed, PRJ-2.3 restores the
previously running watcher/service and verifies its health. An operator may
choose a different recovery only explicitly and records the resulting visible
state.

The result report retains current direct folders grouped by zero/one/many
associated Project documents, pathless imports, explicit unmatched decisions,
untouched pre-existing documents, and unresolved link/asset exceptions. It
does not create or repair gaps.

  `var/`; only the sanitized reports and summary evidence are copied here.
