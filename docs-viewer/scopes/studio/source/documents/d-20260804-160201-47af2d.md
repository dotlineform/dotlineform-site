# TDL-1 — Tag Document Association Delivery

## Status And Purpose

Proposed as **TDL-1**, the first Tag-association delivery in [Tag Document Linking](/docs/?scope=studio&doc=d-20260804-160200-fa7bb7). [TDL-0 — Tag Document Metadata Authoring Refactor Delivery](/docs/?scope=studio&doc=d-20260804-170901-b2e74c) is complete and supplies the configured group-only Tag-owned modal, passive exact-target Info projection, generic-metadata exclusion, and revision-safe assignment seam consumed here. TDL-1 establishes explicit document-owned Tag identity and a complete derived association before Registry primary selection, migration, or Tag Semantic Tokens consume it.

## Complete Outcome

The registered `analysis/tags` customisation accepts one optional scalar-string canonical `tag_id` alongside its existing group metadata. Missing identity remains an ordinary document state. Malformed identity is retained as non-blocking authoring evidence. Tag identity is never inferred from title, group, body, filename, route, selected row, neighbouring source, or Registry membership.

The TDL-0 Tag-document fields modal adds optional `tag_id` selection beside independently owned document `group`; Info displays both values read-only. Availability continues to derive from the configured assignable field declaration rather than a literal `analysis/tags` comparison. **Edit metadata** remains free of both fields.

A private deterministic `tag_id -> documents[]` association contains exact `{scope, sub_scope, doc_id}` targets for every valid declaration. Several documents may declare one Tag. Association membership follows document source; group filtering remains an independent presentation concern; publishability and publication remain ordinary document lifecycle decisions.

Private association identity does not depend on public availability. Each row may compose a current public-safe title and URL when one exists, but a missing public descriptor does not erase, rename, or replace its exact authoring target. Management and diagnosis therefore remain exact-target operations while downstream public links consume only the optional location descriptor.

TDL-1 produces membership evidence only. Tag Registry continues to own canonical Tag identity, group, aliases, and its current `doc_url[]` field until TDL-2 performs the bounded migration. TDL-2 owns the scalar `primary_document` policy, eligible-primary editor, migration, target projection, and Tag Semantic Token family.

## Delivery Discipline

TDL-1 extends the existing Analysis Tags customisation, private sub-scope manifest, Analysis-only document-location projection, and focused association builder. The shipped `docs_document_subjects` receipt and atomic-build pattern is a useful exact-target implementation reference, but Tag associations remain a separate focused product rather than a new subject kind or a generic relationship graph. TDL-1 must not become a Registry scanner, lifecycle synchronizer, or public Tag runtime.

The accepted TDL-0 seam declares `tag_fields(group)` in the registered Analysis Tags definition. The server accepts exactly that declared field set through `/docs/assign-field-group`, while the focused modal and Info projection consume the exact collection's private configuration and manifest record. TDL-1 must extend the declaration, Analysis Tags metadata normalizer, private manifest projection, modal response contract, and passive Info fields together when adding `tag_id`; a client-only or loose optional-field addition is not compatible with the strict assignment boundary. Document `group` remains independent from both `tag_id` and Registry `group`.

### TDL-1.0 — Confirm Scope And Delivery

- [ ] Sanity-check optional `tag_id`, the accepted TDL-0 Tag-document field contribution, read-only Info, private manifest projection, exact Tag associations, existing group behavior, document locations, targeted builds, and public isolation against current broad owners; resolve only contradictions that would change the result.
- [ ] Confirm the broad blast radius across Analysis Tags front matter, customisation validation/import, Manage manifests, focused association output, document locations, and the TDL-2 migration handoff.
- [ ] Confirm the deliverables: optional scalar Tag identity, configured Tag-owned assignment and read-only display, deterministic zero-to-many associations, non-blocking malformed evidence, exact document targets, current location descriptors, focused verification, and concise durable owner updates.
- [ ] Stop for review if implementation requires inferred identity, Registry-owned membership reads as the new association source, a generic graph/query framework, automatic Tag-document creation, document lifecycle coupling, or another boundary excluded above.

**Checkpoint:** a concise sanity note confirms implementation fit, broad owners, blast radius, deliverables, risks, private/public boundary, TDL-2 handoff, and stop condition. Stop before implementation approval.

### TDL-1.1 — Implement Tag Declarations And Associations

- [ ] Extend the accepted TDL-0 assignable Tag-document field group and focused modal with optional canonical `tag_id` selection while Info remains read-only and **Edit metadata** remains document-agnostic.
- [ ] Extend Analysis Tags source validation, import, read/write, and manifest projection with optional scalar-string `tag_id` while preserving existing group metadata independently.
- [ ] Project normalized none, valid, malformed, and currently unavailable Tag identity states without making them lifecycle blockers.
- [ ] Generate deterministic exact `tag_id -> documents[]` associations from valid document declarations and compose current document-location descriptors without inferring identity or reading Registry membership as source truth.
- [ ] Preserve zero-to-many membership, stable exact target identity, targeted-build behavior, private association access, and public isolation.
- [ ] Expose sufficient bounded migration evidence for TDL-2 to compare legacy Registry links with the declared association result.

**Checkpoint:** focused customisation, import, manifest, association, location, zero/many, targeted-build, lifecycle-independence, and public-isolation evidence passes. An independent code/diff review confirms document declarations own membership, group remains separate, and Registry migration/primary selection remain TDL-2-owned. Stop before TDL-1.2.

### TDL-1.2 — Verify And Transfer

- [ ] Prove no identity, one identity, several documents per Tag, unknown canonical Tag, malformed identity, deleted document, unavailable location, unpublished document, configured modal assignment, read-only Info, and targeted rebuild preservation.
- [ ] Prove no identity is inferred from mutable presentation or current UI context and no association mutation changes Tag Registry or document lifecycle.
- [ ] Run focused Python, browser-module where presentation changes, source-lint, generated-doc, search, public-isolation, and whitespace checks.
- [ ] Perform the independent final code/delivery review and transfer the accepted declaration, association, location, freshness, and failure contracts to TDL-2.

## Completion Evidence

- `analysis/tags` accepts optional explicit canonical `tag_id` independently from group metadata.
- The Tag-owned modal edits configured document fields while Info remains read-only and **Edit metadata** retains only common document fields.
- The private association product preserves exact zero-to-many Tag-document membership and current location descriptors.
- Missing, malformed, stale, unpublished, and unavailable relationships retain explicit bounded behavior without changing document lifecycle.
- Registry identity, aliases, group, `doc_url[]`, and primary policy retain their current owner until TDL-2 migration.
- Public document payloads contain only ordinary published document content and locations; private association infrastructure remains local.
