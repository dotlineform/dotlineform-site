# Dated Export Snapshots Delivery

## Status And Purpose

This delivery is active at the DXS-3 review gate for [Dated Export Snapshots](/docs/?scope=studio&doc=d-20260716-193410-98d1a8). Preview, guarded staged apply, provider-neutral capability, and the exact checked-set Index Action are implemented. Final representative-artifact review and durable authority transfer remain in DXS-4.

The existing static HTML exporter already proves the useful rendering seam, but its provider restriction, fixed latest-folder destination, immediate destructive apply, scope-only selection, broad same-scope link rewriting, and delete endpoint do not satisfy the snapshot contract. This delivery replaces that behavior through the existing Export workflow rather than adding another export system.

## Complete Outcome

One **Export** item in the main index panel's **Index Actions** menu creates a browseable static HTML snapshot containing exactly the non-empty checked document set from the active configured scope. There is no export mode and no implicit descendant expansion. **Select all** naturally produces the whole-scope snapshot.

The destination is under `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-export/`. From the server's local export date, one checked document with unselected peers is labelled `<document title> - YYYY-MM-DD`, the complete checked set is `<scope> - YYYY-MM-DD`, and any other multi-document set is `<scope> selection - YYYY-MM-DD`. Complete-set classification takes precedence in a one-document scope because the checked ids cannot reveal whether **Select all** was clicked. The snapshot keeps original `doc_id` values and records the exact checked set in compact provenance.

If that exact dated folder is absent, confirmation creates it. If it exists, preflight identifies the existing recognized or unrecognized folder and offers only **Replace** or **Cancel**. Apply stages the complete new output before replacing a confirmed target and fails closed if the target changes after preflight.

The output is a user-owned visual and text reference. It is not canonical source, a managed archive, or a restore package.

## Delivery Contract

### Generated Input And Eligibility

- Continue to read `index-tree.json` and `by-id/<doc_id>.json`; do not read or render canonical Markdown.
- Resolve generated paths through configured scope providers. A configured scope is eligible when its generated tree and referenced document payloads are readable, whether the scope is public, repo-local, or external-local.
- Do not use canonical-source availability or source writability as an export gate.
- Include non-viewable documents already present in the manage generated tree.
- Keep sub-scope report collections and their Actions menus outside this delivery; they are not part of the active scope's generated index tree.

### Exact Snapshot Target

- Accept any non-empty checked `doc_id` set from the active generated tree. Opening **Index Actions** retains its existing behavior of entering selection mode and explicitly checking the currently displayed document; once checked, that id follows the same no-fallback rule as every other Index Action.
- Reject unknown, duplicate, stale, or cross-scope ids. Do not add parents, descendants, the active document, or any other unchecked id.
- Normalize the validated set into generated tree order. Equality with the complete generated id set—not a browser mode field—identifies the whole-scope naming case.
- Apply carries the scope, exact ordered `doc_id` values, local export date, normalized folder label, and preflight target revision as one validated plan. It does not reconstruct a different selection from presentation text.
- Folder-name normalization is deterministic and limited to filesystem safety. Folder labels are presentation, not identity; provenance owns source identity.

### Rendering And References

- Reuse and focus the current static HTML renderer rather than creating a package profile or another browser renderer.
- The snapshot index preserves an included parent/child relationship only when both documents are selected. A selected document with an unselected parent becomes a root.
- Use the configured default document when it is selected; otherwise use the first selected document in generated tree order.
- Rewrite a same-scope Docs Viewer link only when its target document is included in the snapshot. Preserve fragments.
- Leave same-scope links to unselected documents, cross-scope links, remote links, media references, downloads, and interactive-asset references at their existing targets.
- Continue to copy no media, download, script, style dependency, Mermaid render, or interactive-asset bytes.

### Provenance And Guarded Replacement

- Write one compact provenance record containing schema version, source scope, exact ordered selected `doc_id` values, document count, generated time, and artifact identity needed for replacement preflight.
- Preview distinguishes an absent target, a recognized snapshot, an unrecognized existing directory, and a non-directory collision without exposing an absolute workspace root to the browser.
- Existing directories require explicit replacement confirmation bound to the previewed destination state. A changed or newly occupied target fails and requires a fresh preview.
- Render and write into a sibling staging directory, validate the staged file set, then perform the guarded same-filesystem replacement. A render, validation, or staging failure leaves an existing target untouched.
- Remove the current static-export delete route and delete capability. Snapshot folders remain user-owned and Docs Viewer does not list, prune, rename, or delete them.

### Singular Index Actions Workflow

- Add one **Export** item to the main index panel's **Index Actions** menu and remove Export from the app-level **Actions** menu.
- Reuse the existing Index Actions entry behavior that checks the currently displayed document. Do not add an Export-specific active-document fallback.
- Enable Export for any non-empty eligible checked set. Do not add a mode chooser or an implicit descendant option.
- Preflight shows the source, exact document count, whether the checked set equals the complete scope, dated destination label, and existing provenance or an unrecognized-folder warning.
- An absent target has one create confirmation. An existing directory has **Replace** and **Cancel** only. A non-directory collision cannot be replaced.
- Capability projection reports preview/apply availability from generated input and workspace readiness. It must not inherit the current source-availability gate or project absolute paths to the browser.
- Do not add Export to sub-scope report Actions.

## Likely Authority

- `docs-viewer/services/docs_static_html_export.py` retains generated-payload loading, selection, rendering, destination planning, provenance, and guarded apply ownership.
- `docs_management_routes.py`, `docs_management_service.py`, and `docs_management_capabilities_service.py` own the management-only preview/apply and capability boundary.
- `docs-viewer-action-definitions.js`, `docs-viewer-management-index-controller.js`, and the index selection owner supply the Index Action and exact checked IDs without adding a fallback target.
- `docs-viewer-management-actions-renderer.js` removes the app-level item; `docs-viewer-management-client.js` and the existing management modal owners retain the singular Export workflow.
- `test_docs_static_html_export.py`, focused management route/capability tests, and a narrow runtime-module check own durable service and wiring evidence.
- [Export](/docs/?scope=studio&doc=d-20260629-152159-ac1af9) receives the shipped current-state contract.

Implementation may refine filenames after inspection, but must retain these ownership and no-fallback boundaries.

## Completion Gates

- Any non-empty checked set produces a complete browseable artifact from generated payloads through one renderer and one main-index Action.
- Export is absent from app-level and sub-scope Actions.
- Snapshot membership comes only from validated checked ids; **Select all** is the whole-scope case and the existing Index Actions auto-check is the only displayed-document handoff.
- The snapshot index preserves selected hierarchy, promotes selected orphans to roots, and chooses its default deterministically.
- Every eligible configured provider family is accepted on generated readability rather than canonical-source ownership.
- Same-scope links are local only when their target is included; excluded and external targets remain usable at their original locations.
- An existing target is never removed before explicit, state-bound replacement confirmation and complete staged output.
- Provenance distinguishes source identity from a colliding presentation label.
- Browser-visible payloads omit absolute project paths and no delete or archive-management capability remains.
- Focused negative evidence covers traversal, unsafe labels, missing payloads, invalid targets, stale confirmation, non-directory collision, render/write failure, and provider eligibility.
- Durable Export documentation and generated Studio projections describe the shipped contract.
- Final review finds no second renderer, package-profile coupling, browser mode field, selection expansion or fallback, compatibility delete path, or unplanned archive lifecycle.
