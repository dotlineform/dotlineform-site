# Docs Viewer Search

Docs Viewer Search provides one static inverted-index format and one browser query path for every configured parent scope. Studio currently uses that common machinery for authored full text. The intended direction is for Analysis and the other document scopes to adopt the same basic full-text field, tokenizer, and relevance policy through separately measured rollouts rather than acquire custom search systems.

## Durable Contracts

- [Docs Viewer Search Index](/docs/?scope=studio&doc=d-20260813-214350-4c7a21) owns payload structure, per-scope field policy, Studio source extraction, ranking inputs, complete rebuilds, and the extension boundary.
- [Docs Viewer Search Tokenizer](/docs/?scope=studio&doc=d-20260813-214351-98d3f0) owns normalization, technical-term derivation, exclusions, stop words, query prefix semantics, and Python/JavaScript parity.
- [Docs Viewer Search Relevance](/docs/?scope=studio&doc=d-20260813-223337-e6c261) owns the proposed shared corpus-adaptive ranking model, language and specialist-vocabulary policy, diagnostics, presentation options, and non-goals.

`docs-viewer/build/build_search.py`, `docs-viewer/config/scopes/docs_scopes.json`, `site/docs-viewer/runtime/js/shared/docs-viewer-search.js`, and the generated JSON remain exact code/config authority.

## Scope Policies

Studio enables `title`, `heading`, `body`, and `code`. Its parent title, identity, update time, and route remain document-table metadata for display, navigation, and deterministic ordering but emit no postings. Studio source extraction includes visible authored headings, prose, inline code, fenced code, image alt text, and visible raw-HTML text; it excludes front matter, report declarations, link destinations, media paths, attributes, scripts, styles, document IDs, date fragments, and 64-character hexadecimal digests.

Analysis, Notes, Processing, and dotlineform currently retain `title`, `parent_title`, exact `identity`, and exact `last_updated`. Analysis's explicit Publish projects its current metadata-only index to the public site. Their intended full-text policy is the same `title`, `heading`, `body`, and `code` boundary used by Studio, subject to each rollout's inclusion, privacy, payload, and publication evidence.

Manage-only roots, non-publishable documents, and their descendants do not enter the current parent index. Registered sub-scope documents currently remain outside parent Search, Index, and Recent. The accepted direction for [DSI-2 — Scope-Level Sub-Scope Search Delivery](/docs/?scope=studio&doc=d-20260813-225547-cd82d8) is to include eligible documents from visibly hosted sub-scopes in one scope-level Search corpus while leaving parent Index and Recent separate.

## Scope-Level Search Direction

One main search should cover the complete visible documentation experience for its active scope. Parent documents and eligible documents from registered, visibly hosted sub-scopes should therefore share one index, query, and relevance order. Report-local title search remains a list filter, not another full-text engine.

Sub-scope results retain exact `{scope, sub_scope, doc_id}` identity plus explicit report-host placement for active-route navigation. Configured collection/report title is display-only context, presented beneath the result title in the same compact metadata position as current parent context. Do not infer identity from that title or index it merely because it is displayed.

## Build And Publication

The builder reconstructs one complete selected-scope index. Watcher and write-service plans may target document payloads or decide whether search needs to run, but they do not patch postings. The content version excludes generation time, so an identical rebuild skips its write. No build touches an unrelated scope. Under the DSI-2 direction, an eligible sub-scope source or membership change rebuilds this same atomic parent-scope search artifact rather than a separate child index.

Working indexes live at their configured published-search locations. External-local scopes are served through the Docs Viewer service. A public scope's explicit Publish copies its accepted working index to the configured public destination; Analysis currently projects the same metadata-only v2 bytes to `site/assets/data/search/analysis/index.json`.

## Browser Query Path

Generated browser config declares the Docs Viewer domain, v2 schema, index URL, and `whole_index` rebuild policy. The collection provider reads the active scope's URL, `docs-viewer-search-controller.js` validates v2 and owns query/history/loading/paging state, and `docs-viewer-search.js` is the sole tokenizer, postings-intersection, ranking, and tie-breaking owner.

A multi-term query requires one matching posting set per normalized term. Prefix matching begins at three characters. Generic ranking prefers exact identity, exact title, title, heading, parent title, body/code, and update metadata; only enabled fields participate. Studio therefore ranks exact title, title, heading, then body/code. Ties sort by title and identity, and each document appears at most once.

## Extension Boundary

Adding a normal parent scope is configuration work, not a new builder or browser branch. Full-text scopes should converge on one field and relevance policy while continuing to own corpus membership and publication boundaries. Visibly hosted sub-scopes extend that parent scope's corpus; they do not receive another schema, tokenizer, cache, reader, query engine, vocabulary registry, domain dictionary, or separately queried index.

[Analysis Full-Text Search Extension](/docs/?scope=studio&doc=d-20260813-165124-16b0ab) owns the next public adoption and its membership, vocabulary-exposure, payload, and publication evidence. Notes, Processing, and dotlineform remain metadata-only until equivalent measured rollouts apply the shared full-text policy. Catalogue Search retains its separate builder, records, runtime, and roadmap.

The practical ceiling remains one client-loaded static index. Short prefixes can return broad result sets after full-text adoption; snippets, highlighting, stemming, synonyms, spelling correction, phrase positions, and section results remain outside the current contract.
