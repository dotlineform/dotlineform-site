# Export

Docs Viewer Export creates a browseable dated static HTML snapshot from existing generated document payloads. The output is a user-owned visual and text reference outside Docs Viewer; it is not canonical source, an import package, or a managed archive.

## Workflow

Export is available in the main index panel's **Index Actions** menu while Manage is active. It is not present in the app-level **Actions** menu or sub-scope report Actions.

Opening **Index Actions** enters the existing checkbox-selection workflow and explicitly checks the currently displayed document. After that handoff, Export consumes only the exact non-empty checked `doc_id` set. It does not infer a displayed, active, default, URL, parent, or descendant document, and it has no export mode or **Include descendants** option. **Select all** is the whole-scope case.

The confirmation identifies the destination and the v2 media plan:

```text
Export N document(s) to:
/docs-export/<dated folder>/
Includes M media file(s) (<total bytes>).
Leaves E external media reference(s) unchanged.
```

The external-reference line is omitted when its count is zero.

The primary button is **Create snapshot**, **Replace**, or disabled **Unavailable** according to the previewed target. Replacement uses the danger tone and initially focuses **Cancel**. Cancel, success, and failure preserve the checked selection.

## Input And Eligibility

A configured scope is eligible when:

- `$DOTLINEFORM_PROJECTS_BASE_DIR` resolves the external `docs-export` workspace;
- its configured generated `index-tree.json` is readable and non-empty; and
- every referenced generated `by-id/<doc_id>.json` payload is readable and valid.

Generated-path resolution supports repo-local, public, and external-local scope providers. Canonical-source ownership and source writability are not capability gates. Non-publishable documents already present in a publish-capable Manage tree remain eligible; local collections have no publication gate.

Export reads generated hierarchy, titles, and `content_html`. It does not parse canonical Markdown, rebuild documents, or apply a second publishability filter.

From the exact selected generated HTML, Export recognizes media only when a supported URL attribute maps beneath an exact configured served prefix for that scope and media type. It then reads the confined identity through that media type's configured repository, external-local, or R2 artifact location. Missing, invalid, escaping, or unreadable owned media blocks preview. Unmatched media references remain external and unchanged; Export does not fetch their served URLs or inventory unrelated scope media.

## Destination And Naming

Snapshots live under:

```text
$DOTLINEFORM_PROJECTS_BASE_DIR/docs-export/
```

The server derives the folder from its local export date:

- the complete checked set uses `<scope> - YYYY-MM-DD`;
- every non-complete set, including one checked document with unselected peers, uses `<scope> selection - YYYY-MM-DD`.

Complete-set classification takes precedence for a one-document scope. Labels receive only bounded filesystem-safe normalization. There is no **Save As**, arbitrary destination, or background scheduling.

One equivalent label and local date names one destination. If it already exists, preview classifies it as a recognized v2 snapshot, an unrecognized directory, or a non-directory collision. Version 1 snapshot folders are unrecognized after the v2 cutover. Recognized and unrecognized directories may be replaced only after explicit confirmation; a non-directory target is blocked.

## Preview And Apply

The management-only endpoints are:

```text
POST /docs/export/static-html/preview
POST /docs/export/static-html/apply
```

Preview accepts only the active `scope` and exact checked `doc_ids`. It returns `docs_static_html_snapshot_preview_v2` with the tree-ordered ids, selection kind, deterministic default, local date, display-safe destination label, packaged-media count and bytes, unchanged-external-dependency count, target state, existing recognized provenance when present, and plan/target revisions. Preview writes nothing and exposes no media identities or absolute workspace path, but it reads and hashes each exact referenced owned object to make the plan truthful.

Apply is assembled from that validated preview and carries:

```json
{
  "scope": "studio",
  "doc_ids": ["doc-a", "doc-b"],
  "export_date": "2026-07-31",
  "plan_revision": "<sha256>",
  "target_revision": "<sha256>",
  "confirm": true,
  "replace_existing": false
}
```

The service recomputes the complete plan and destination state, including complete selected generated-body digests and fresh media byte digests. A changed source, media object, configuration, or target requires a fresh preview. It renders and validates the complete output in a sibling staging directory before installing it. Replacement moves the confirmed existing directory aside, verifies that moved content, installs staging, and restores the original if the final switch fails.

There is no export delete route or capability. Snapshot folders are user-owned after creation; Docs Viewer does not list, rename, prune, retain, or remove them.

## Artifact Contract

Each snapshot contains exactly:

```text
<dated folder>/
  index.html
  styles.css
  snapshot.json
  docs/
    <selected doc_id>.html
  media/
    <media type>/
      <confined relative identity>
```

`index.html` preserves the selected hierarchy. A selected child whose parent is absent becomes a root. The configured default document is retained when selected; otherwise the first selected document in generated tree order becomes the default.

Each document page inserts its existing generated `content_html` without adding another heading. Same-scope Docs Viewer links become local only when their target is included. Links to unselected same-scope documents, other scopes, and external locations retain their original targets. Fragments are preserved.

Each exact referenced scope-owned object is copied once to `media/<media type>/<identity>`, even when several selected documents use it. Matching `src`, `srcset`, `poster`, `data`, and configured media `href` references become document-relative packaged URLs. Cache queries are removed after the bytes are frozen and fragments are preserved. Unmatched media references remain unchanged and are recorded as external dependencies without credentials or query strings.

The snapshot does not recursively inspect copied HTML, CSS, scripts, frames, fonts, or site-shell dependencies. Inline Mermaid remains readable source in its generated code block rather than becoming a rendered dependency.

`snapshot.json` uses `docs_static_html_snapshot_v2` and records the source scope, exact ordered ids, selection kind, document count, default id, local export date, generation time, and plan revision. Each packaged media row records its media type, confined identity, provider kind, packaged path, byte size, SHA-256 digest, and referencing selected document ids; separate rows record unchanged external dependencies. Folder names are presentation labels; provenance owns snapshot identity for guarded replacement.
