# ESA-1 — Graceful Per-Scope Availability Delivery

## Status

Proposed and not started. This document specifies one complete integrated-runtime outcome and does not authorize implementation. Begin with the sanity gate, confirm the exact owners and likely footprint, then stop for implementation approval.

## Complete Result

With a valid configured `DOTLINEFORM_PROJECTS_BASE_DIR` and external Docs workspace, the integrated Docs Viewer HTTP service and its default live watcher remain running when one configured external-local scope root is absent, unreadable, or otherwise unavailable. The exact scope is retained in capability and browser presentation with `available: false` and a non-sensitive reason, operations targeting it fail before mutation, and available repository or external scopes continue their ordinary read and management behavior.

Startup and capability inspection do not create any missing external scope directory. Selected-scope and intentional all-scope operations still fail explicitly when they require unavailable coverage. The result distinguishes source availability, generated document availability, and generated search availability rather than treating one boolean as proof of every scope capability.

## Why This Matters Now

Current configuration loading has a targeted seam but several integrated paths still resolve the complete scope registry:

- Docs Viewer startup calls configured media-directory materialization before binding the server;
- media materialization loads all configured scopes and creates published media descendants with `parents=True`;
- management dispatch refreshes all scope configurations before unrelated requests;
- the capabilities payload already projects scope `available` and generated-read booleans, but complete external resolution must currently succeed before that report can be produced; and
- the default live watcher and `bin/local-all` composition can turn one child exit into loss of the complete local session.

The accepted core boundary already says selected external operations fail loudly while unrelated providers are not resolved merely because another operation starts. ESA-1 makes that invariant true in the current integrated service without waiting for or silently starting the wider Core Refactor.

## Availability Model

| condition | ESA-1 result |
| --- | --- |
| iCloud network synchronization is paused, but configured local paths remain readable | No availability change; ordinary local filesystem behavior continues. |
| `DOTLINEFORM_PROJECTS_BASE_DIR` is missing, unmounted, invalid, or unreadable | Whole-environment configuration failure; outside the graceful per-scope claim. |
| configured projects base and `docs-viewer` workspace exist, but one external scope source root is absent or unreadable | Docs Viewer remains running; exact scope reports unavailable; unrelated scopes continue. |
| unavailable scope retains generated document or search products through a supported topology | Source and generated-read availability report independently; no source mutation is enabled. |
| operation explicitly targets an unavailable external scope | Clear exact-target non-success before write, rebuild, publication, package, media, or lifecycle mutation. |
| command intentionally requests all configured scopes | Exact incomplete-coverage non-success; do not silently skip and claim a complete result. |
| missing external scope later becomes available | A normal capability refresh and watcher cycle can observe the current filesystem state without a persisted recovery queue or service reinstall. |

Unavailable never means empty. No path may create a new scope, choose another scope, reuse stale identity, or suppress an error merely to keep the service alive.

## Delivery Boundary

ESA-1 includes:

- declarative enumeration of configured scope identities without eager resolution of every external path;
- targeted operational resolution for the exact scope or explicit all-scope operation;
- HTTP service startup that does not require every external scope root;
- per-scope capability records with browser-safe unavailable reasons and separately truthful generated-read flags;
- Manage presentation that identifies an unavailable configured scope and prevents its unsupported management actions;
- exact request failure for unavailable source, generated data, search, media, package, import, export, lifecycle, and publication capabilities as applicable;
- external media-directory materialization only after the exact scope root has passed its availability and ownership boundary;
- live-watcher containment so one unavailable scope is reported/skipped while available scopes continue and later restoration is observable through the normal cycle; and
- focused tests, maintained runtime checks proportional to the final footprint, generated documentation verification, and durable documentation transfer.

ESA-1 excludes:

- support for an absent or unmounted `DOTLINEFORM_PROJECTS_BASE_DIR`;
- iCloud download, synchronization, conflict resolution, placeholder hydration, or mount automation;
- changing scope create, rename, delete, backup, or restore semantics;
- treating stale generated data as canonical source or silently serving it as proof that source is available;
- making all-scope commands succeed with incomplete coverage;
- changing `bin/local-all` to ignore genuine child-process failures;
- the full Core Refactor, explicit composition-root extraction, standalone packaging, or replacement of every mutable process-global scope map;
- a second registry, compatibility reader, generic provider engine, persistent availability cache, retry queue, filesystem monitor, or background recovery framework; and
- any publication, Catalogue, Tag, media-provider, or public-site behavior change.

## Likely Owners To Inspect

The sanity gate should start with these current owners and narrow the final footprint before implementation:

- `docs-viewer/services/docs_scope_config.py` for declarative registry parsing, external marker resolution, targeted selection, and operational paths;
- `docs-viewer/services/docs_viewer_service.py` for startup, health, and request-level failure containment;
- `docs-viewer/services/docs_media_storage.py` for startup materialization and exact external scope directory creation;
- `docs-viewer/services/docs_management_service.py`, `docs_management_read_service.py`, and `docs_management_capabilities_service.py` for broad refresh, per-scope capability truth, and target dispatch;
- `docs-viewer/services/docs_generated_reads.py` for independently targeted generated-data availability;
- `docs-viewer/services/docs_live_rebuild_watcher.py` for long-running unavailable-scope containment and restoration observation;
- management scope configuration, selection, and unavailable-state browser owners under `docs-viewer/runtime/js/management/`; and
- current config, service, watcher, generated-read, capability, and browser tests using isolated external fixture roots.

This list is an inspection route, not a preapproved file list. Stop and re-scope if the complete result requires a generic configuration system, broad service rewrite, persistent monitoring state, or changes to external scope lifecycle ownership.

## Delivery Steps

### ESA-1.0 — Sanity And Contract Gate

- [ ] Reproduce three distinct states with isolated fixtures: missing projects base, valid base with one missing configured external scope, and valid available external scope.
- [ ] Confirm the exact startup, all-registry management, capability, media-materialization, watcher, and `bin/local-all` failure paths without modifying production external data.
- [ ] Freeze the browser-safe availability reason categories, source/generated capability separation, targeted request response boundary, restoration observation, and all-scope failure rule.
- [ ] State the final production and focused-test owners, likely diff scale, and the scope-creep stop condition.
- [ ] Stop if implementation cannot keep exact configured identity distinct from resolved provider availability or would need to weaken selected-scope validation.

**Gate:** Record the bounded findings in this delivery or a temporary child note and stop for implementation approval. Documentation completion is not runtime completion.

### ESA-1.1 — Targeted Configuration And Service Availability

- [ ] Separate configured identity enumeration from exact provider resolution only as far as the current integrated service requires.
- [ ] Start the HTTP service with one unavailable external scope under a valid base and leave `/health`, the Manage shell, and available scopes operational.
- [ ] Remove eager external-scope media materialization; preserve explicit lifecycle-owned directory creation and safe repository-owned setup.
- [ ] Return exact per-scope availability and non-sensitive reason evidence without exposing absolute user paths.
- [ ] Make every affected request resolve and reject only its exact unavailable target before mutation.

### ESA-1.2 — Watcher And Browser Follow-Through

- [ ] Keep the default live watcher running for available scopes when one external scope is unavailable, with concise state-change reporting rather than repeated noisy errors.
- [ ] Observe restoration through the normal watcher/capability refresh path without a persistent queue or new monitoring service.
- [ ] Present the configured unavailable scope accurately in Manage and disable only actions whose exact source or generated capability is absent.
- [ ] Do not label the scope empty, remove its configured identity, select a fallback, or imply that Docs Viewer repairs iCloud or File Provider state.

### ESA-1.3 — Verification And Durable Transfer

- [ ] Prove unavailable and restored external scope states alongside unaffected Studio, Processing, and one available external scope read/management paths.
- [ ] Prove startup and watcher do not create the missing scope root or any media/published descendant.
- [ ] Prove targeted unavailable operations fail before writes and intentional all-scope build/audit operations return explicit incomplete coverage.
- [ ] Verify existing external confinement, symlink, traversal, exact target, lifecycle, publication, and generated-read contracts remain unchanged.
- [ ] Run focused Python/service/watcher tests, the smallest justified maintained smoke profile, source lint for changed owners, generated Docs/search assertions, JSON parsing, and `git diff --check`.
- [ ] Transfer shipped behavior to Local Authoring Service And Publication Boundaries plus the exact Docs Viewer runtime/configuration owner, and assess the Core Definition Baseline without widening Core Refactor.

## Completion Gate

ESA-1 is complete only when one unavailable external scope under a valid projects base is explicitly visible and contained; Docs Viewer HTTP and watcher processes remain running; unrelated available scopes retain their ordinary reads and writes; exact unavailable targets fail before mutation; no missing scope directory is created; restoration is observed without reinstall or persistent recovery state; and intentional all-scope operations remain honestly incomplete or non-successful.

A health-only pass, repo-only service startup with no availability record, silent omission of the configured scope, an empty-scope presentation, automatic directory creation, swallowed selected-scope error, watcher exit, broad launcher failure, fallback target, or unexplained change to lifecycle/publication behavior is not a pass.
