# ESA-1 — Graceful Per-Scope Availability Delivery

## Status

Complete. The simplified implementation and evidence passed review, and the user approved closeout on 2026-08-12. The delivery remains in place as bounded implementation evidence.

## Problem

Before ESA-1, Docs Viewer startup called `ensure_configured_scope_owned_media_directories()` for every configured scope and its `mkdir(parents=True)` call could recreate a missing external scope folder or let an unavailable folder stop the complete service.

The surrounding behavior already exists: configured scope identity is retained, capabilities expose source availability, Manage disables management when the selected scope is unavailable, and the live watcher waits for a missing source and resumes when it returns. ESA-1 should reuse those seams rather than add a new availability model or error system.

## Delivery

- In `docs-viewer/services/docs_media_storage.py`, materialize published media directories for an external-local scope only when its exact configured scope root already exists as a directory.
- If that external scope root is missing or unavailable, skip its startup materialization and continue with the other configured scopes.
- Keep repository-backed media setup unchanged.
- Do not create the missing external scope root, infer another target, add availability reason categories, change the watcher, or add browser behavior.
- Add one focused regression test in `docs-viewer/tests/python/test_docs_media_storage.py` proving that a missing external scope is not created while repository and available external scope media directories are still materialized.

Expected footprint: one small production guard and one focused test, roughly 10–20 production lines and 15–30 test lines.

## Acceptance

- With a valid projects base and Docs workspace, a configured external scope folder may be absent without stopping Docs Viewer startup.
- Startup does not create that scope folder or any descendant.
- Media directories for repository-backed and available external scopes are still prepared as before.
- The existing capability, Manage, watcher, exact-target, and whole-environment behavior is unchanged.

Focused verification:

- `$HOME/miniconda3/bin/python3 -m pytest docs-viewer/tests/python/test_docs_media_storage.py`
- `bin/lint-python docs-viewer/services/docs_media_storage.py docs-viewer/tests/python/test_docs_media_storage.py`
- `git diff --check`

## Delivery Evidence

- `docs-viewer/services/docs_media_storage.py`: skips startup media-directory materialization when an external-local scope root is not an existing directory.
- `docs-viewer/tests/python/test_docs_media_storage.py`: proves the missing root remains absent while repository-backed and available external media directories retain their existing behavior.
- Focused tests: 7 passed.
- Explicit Python lint: passed for both changed implementation files.
- `git diff --check`: passed.
- Final implementation footprint: 5 production additions plus 9 test additions and one test-name replacement. No scope configuration, management dispatch, capability, browser, watcher, lifecycle, or publication code changed.

## Closeout

Closeout was approved on 2026-08-12. ESA-1 and its parent feature remain in place; no adjacent availability work, delivery retirement, or document deletion was started.
