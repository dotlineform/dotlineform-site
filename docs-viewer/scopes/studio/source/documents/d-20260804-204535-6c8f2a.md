# SSP-1.0 — Document Subject And Association Sanity Note

## Outcome

SSP-1 fits the shipped Docs Viewer owners as a bounded extension of SSP-0 and Sub-Scope Customisation. Implementation can proceed through one normalized subject reader, the existing Projects registration and assignment group, private Manage-manifest composition, a focused private association product, the existing Projects row/detail contribution, Catalogue target support, and exact document-location composition. The checkpoint is complete at its review gate and stopped before SSP-1.1 approval.

**Subsequent decision:** Resolver Tokens were later retired before implementation. The accepted subject foundation now feeds Project State, explicit SSP-3 subject-link insertion, collection-aware Copy, coverage reporting, and subject-driven public Work/Series metadata.

This note is Roadmap workflow material. SSP-1.2 transfers shipped behavior into maintained Docs Viewer and Studio architecture and operations documents outside Roadmap.

## Confirmed Contracts

- A document declares zero or one subject. `folder_path` remains meaningful only in `dotlineform/projects`; `work_id` and `series_id` are optional scalar-string document metadata that later configured collections can read without gaining Projects assignment capability.
- The normalized read state covers none, folder, Work, Series, malformed, and conflicting declarations. It preserves raw source evidence and remains separate from strict modal and import normalization.
- A structurally valid Work or Series declaration participates in the zero-to-many exact association even when its current Catalogue target is unavailable. Catalogue availability is reportable evidence rather than subject identity.
- The private association product derives only from document declarations, orders exact `{scope, sub_scope, doc_id}` members deterministically, and composes current Manage/public location descriptors through existing location owners. Studio Works remains the later reporting presentation owner.
- Manage cues consume normalized private manifest state. They remain observational authoring hints and retain ordinary lifecycle, Copy, viewability, and publication ownership.
- Public manifests retain their minimal public-safe rows. Private subjects, folder paths, association products, invalid-source detail, assignment capability, and Manage cues remain with local owners.

## Current Owners And Blast Radius

The shared source parser already preserves arbitrary raw front matter. The source mutation formatter owns round-trip serialization. The registered Projects customisation owns folder validation, metadata/import normalization, private manifest data, `authoring_subject`, and Manage composition. The sub-scope builder owns private/public manifest separation and exact collection rebuilds. SSP-0 owns the revision-bound assignment route and focused modal. Catalogue target support owns current Work/Series discovery and accessible selection. Exact Manage URLs and public document-location projections retain route composition.

SSP-1 therefore touches shared scalar subject reading/formatting, the Projects customisation and assignment declaration, private manifest and association projection, Projects Info/modal/row rendering, Catalogue picker reuse, location composition, targeted rebuild follow-through, focused tests, and final durable documentation transfer. Project State, Resolver Tokens, Copy, Studio Works presentation, and public Work/Series enrichment consume the result through their own deliveries.

## Risks And Required Evidence

- Digit-only catalogue IDs currently resemble integers to the source parser. SSP-1.1 must prove quoted/string-preserving mutation and import round trips, including leading zeroes.
- Existing Projects folder reads are strict build validation. SSP-1.1 must separate strict new input from non-blocking existing-source projection so malformed/conflicting evidence remains visible and ordinary lifecycle behavior survives.
- Catalogue target support includes more families than SSP-1. The subject modal must expose Work and Series only and submit the selected canonical scalar ID.
- The private association generation and Manage manifest must share explicit freshness. An unexpected derived failure retains clear bounded behavior; implementation stops for review if this requires changing SSP-0's accepted source/rebuild transaction or adding cross-system synchronization.
- Location descriptors compose exact configured routes. Association generation reads declared subject state plus configured location projections; Work subjects remain Work-only while Series subjects remain Series-only.

Focused SSP-1.1 evidence must cover string identity, none/folder/Work/Series/malformed/conflict states, unavailable current targets, several documents per subject, exact associations and locations, modal assignment, private cues, targeted rebuilds, lifecycle independence, and public isolation.

## Stop Condition

Stop before or during SSP-1.1 if the outcome needs a second metadata registry, broad generic schema/form machinery, widespread builder changes, live catalogue or folder scans during subject projection, a general relationship database/query service, creation of `analysis/works`, Studio Works UI work, Project State or Resolver implementation, public Work/Series payload mutation, or a change to the accepted SSP-0 source/rebuild transaction. Those results require a separately reviewed boundary.
