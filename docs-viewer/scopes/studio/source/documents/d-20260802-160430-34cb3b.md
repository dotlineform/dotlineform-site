# TE-7 — Table-To-SVG Publication Delivery

## Status And Purpose

Proposed as **TE-7**, after [TE-1](/docs/?scope=studio&doc=d-20260802-163320-9015b0) provides comment insertion and [TE-2](/docs/?scope=studio&doc=d-20260802-162149-3ba013) proves the first narrow table-comment consumer. TE-7 closes the Table Enhancements sequence and does not depend on a shared directive parser or diagnostics framework. [Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns the semantic working output, prepared projection, linked-SVG, accessibility, and harmless fallback boundaries implemented by this delivery.

TE-7 adds the second bounded table consumer: an author may place the exact maintained table-publication comment immediately before a Markdown table. The consumer may reuse TE-2’s small source-adjacency helper where that reduces duplication, but it independently recognises its own comment and ignores everything else. Publish stays unchanged and renderer-free.

## Complete Outcome

Canonical Markdown and local/Manage document payloads retain each marked semantic table. The ordinary authoring build attempts deterministic sanitized SVG preparation plus a private digest record only for comments it recognises and can associate. Public Publish preview/apply uses only complete current preparation, rewrites only its exact source table, and includes only the consumed current SVG files.

An unmarked table remains ordinary semantic HTML. A table carrying `table-detail` remains semantic HTML and can use Content Detail View. A table carrying a recognised `table-publish format=svg` comment becomes a scaled linked SVG preview whose click opens the raw SVG in a new tab when complete current preparation exists. Malformed comments, failed preparation, stale artifacts, duplicate IDs, and incompatible document presentation leave the table as ordinary semantic HTML without blocking the build or Publish. Removing the SVG comment and rebuilding restores ordinary HTML publication on the next publish. No table selection or conversion option appears in Publish.

## Current Seams And Expected Size

The likely owners are narrow source comment/table association, Docs item payload construction, configured SVG media producers and sanitization, prepared projection record ownership, `docs_publish_gate.publishable_docs_files()`, public diff/apply and stale-file cleanup, public search preparation, and focused build/publish/browser smoke.

The current indicative shape is 7–12 touched production files, approximately 450–750 production Python/renderer/CSS lines and 350–600 focused test lines. TE-7.0 must split this into exact comment recognition, SVG producer, prepared-record, public-payload, search, publish-gate, and presentation files before implementation. If the work requires a central directive framework, source diagnostics system, source mutation, a Publish UI workflow, a public runtime parser, or materially exceeds the estimate, stop for review and split the delivery.

## Rough Delivery Steps

### TE-7.0 — Trace And Freeze Source, Preparation, And Publication

- [ ] Trace Markdown comment preservation, table parsing and rendered HTML, item-payload construction, full/targeted builds, live watcher behavior, media producer registration, SVG sanitizer/font availability, public projection preparation, search preparation, publish preview/apply, byte diff, and stale generated-media cleanup.
- [ ] Freeze the one accepted `table-publish format=svg id=...` shape, safe ID subset, allowed blank lines, next-table association, and no-op behavior for incomplete, unknown, duplicated, misplaced, or unsupported forms.
- [ ] Freeze one representative rendering contract for natural column widths, wrapping, alignment, header/body styling, links, maximum geometry, native text, caption, alternative text, neutral theme, viewBox, and preview markup.
- [ ] Freeze source/table/config digests, prepared-record ownership, artifact paths, cache/version policy, targeted regeneration, stale removal, and renderer-free consumption of current preparation only.
- [ ] Freeze public search behavior and ordinary semantic fallback when `viewer_content_detail: table` or another condition makes SVG projection inapplicable.
- [ ] Record exact production/test files, any reused TE-2 adjacency helper, media/public-projection seams, and rough diffs for TE-7.1 through TE-7.4 before implementation approval.

**Checkpoint:** one concept fixture contains an unmarked table, two recognised table-publication comments, malformed lookalikes, duplicate IDs, an intervening block, incompatible document presentation, and representative table content. Dry-run evidence shows canonical/Manage semantic output, deterministic prepared artifacts, exact public replacements, new-tab links, search behavior, stale-artifact refusal, and semantic-table fallback for every no-op or failed case. Stop before implementation.

### TE-7.1 — Recognise The Exact Comment

- [ ] Recognise only the maintained table-publication comment shape and associate it only with the immediately following Markdown table, reusing a small TE-2 adjacency helper if appropriate.
- [ ] Preserve ordinary comments and semantic working/export output without requiring comment removal from generated HTML.
- [ ] Treat incomplete IDs, unknown attributes, intervening blocks, duplicate identity, unsupported contexts, and incompatible document-level presentation as no-op candidates rather than build errors.
- [ ] Add focused exact-match, ordinary-comment, table-association, copy-preservation, full/targeted-build, and semantic-fallback tests.

### TE-7.2 — Prepare Deterministic Table SVG

- [ ] Render from the accepted semantic table representation rather than reparsing cell meaning independently.
- [ ] Produce the frozen native-text SVG geometry, caption/description metadata, safe link behavior, neutral styling, viewBox, configured fonts, and sanitizer evidence.
- [ ] Write only record-owned artifacts with complete source/table/config/output digests and atomic candidate behavior.
- [ ] Reuse the configured SVG media role and provider boundaries without making generated output canonical media.
- [ ] Prove deterministic bytes, targeted regeneration, stale detection, unsafe-input no-op, renderer-failure fallback, geometry bounds, and cleanup planning.

### TE-7.3 — Project Linked SVG Public Payloads

- [ ] Extend prospective public by-id projection to consume only complete current prepared records and replace the exact recognised-comment/table pair.
- [ ] Emit one linked preview figure with frozen caption/alternative text, `target="_blank"`, safe `rel`, and no directive metadata or runtime dependency.
- [ ] Keep unmarked tables byte-equivalent apart from existing projection normalization and preserve local/Manage/export semantic tables.
- [ ] Apply the frozen public search contract and retain the semantic table when default Content Detail metadata makes replacement inapplicable.
- [ ] Include only consumed SVG artifacts in preview/apply diffs, ignore path-colliding candidates, byte-verify apply, and remove no-longer-consumed record-owned files.
- [ ] Keep Publish preview, confirmation, and apply request/response/UI contracts unchanged.

### TE-7.4 — Verify And Transfer

- [ ] Run focused comment recognition, renderer, sanitizer, prepared-record, public payload, search, publish-gate, media-provider, full/targeted build, lint, generated Docs/search, and whitespace checks.
- [ ] Manually inspect working semantic tables at supported desktop widths and public linked previews across narrow/wide viewports, short/wide/long content, light/dark surrounding pages, browser zoom, new-tab navigation, text selection in raw SVG, keyboard focus, and screen-reader naming.
- [ ] Prove unmarked and table-detail tables retain their TE-2/TE-3 behavior, every failed or inapplicable SVG candidate retains semantic HTML, Publish has no new choice, ordinary comments remain inert, and public routes import no comment or rendering runtime.
- [ ] Update the concise authoring syntax, projection, media, Publish, and source-documentation authorities with the shipped second-consumer contract.

## Not In Scope

- a third comment consumer, central directive grammar, validator, capability registry, or diagnostics system;
- the Source toolbar action for inserting comments, already owned by [TE-1](/docs/?scope=studio&doc=d-20260802-163320-9015b0);
- automatic table-size analysis or conversion recommendations;
- table-to-PNG/PDF/CSV, multi-page layout, interactive SVG, or theme variants;
- conversion during Publish preview/apply or any new Publish UI;
- changing canonical Markdown, working by-id payloads, Markdown export, or static HTML export to SVG;
- sub-scope-specific behavior beyond the ordinary configured public-projection path established during TE-7.0; or
- changing Content Detail View or blocking a build/Publish because an SVG comment cannot be acted upon.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns sequencing. TE-7 closes only when an exact recognised comment can produce and publish a safe current SVG while every unrecognised, failed, stale, or incompatible case demonstrably retains the ordinary semantic table. Later comment ideas require their own concept review before extending the Source menu or adding another consumer.
