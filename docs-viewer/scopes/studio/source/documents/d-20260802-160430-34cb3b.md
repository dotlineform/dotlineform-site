# TE-6 — Table-to-SVG Publication

## Status And Purpose

Stopped on 2026-08-04 by explicit product decision. This delivery will not proceed as part of [Table Enhancements](/docs/?scope=studio&doc=d-20260802-150245-4e7f85). The original **Table to SVG** Source action and menu item were retired the same day. Existing authored comments remain harmless source text, and their tables remain semantic HTML through working, exported, and public documents. The proposal below remains as the decision record; reconsideration begins with a new explicit lifecycle decision.

TE-6 was sequenced after [TE-1 — Directive Insertion](/docs/?scope=studio&doc=d-20260802-163320-9015b0) originally provided comment insertion and [TE-2 — Table Detail View](/docs/?scope=studio&doc=d-20260802-162149-3ba013) proved the first table-comment consumer. [Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns the current exact-comment and harmless no-op boundaries.

TE-6 adds the second bounded table consumer: an author may place the exact maintained table-publication comment immediately before a Markdown table. The consumer may reuse TE-2’s small source-adjacency helper where that reduces duplication, but it independently recognises its own comment and ignores everything else. Publish stays unchanged and renderer-free.

## Complete Outcome

Canonical Markdown and local/Manage document payloads retain each marked semantic table. The ordinary authoring build attempts deterministic sanitized SVG preparation plus a private digest record only for comments it recognises and can associate. Public Publish preview/apply uses only complete current preparation, rewrites only its exact source table, and includes only the consumed current SVG files.

An unmarked table remains ordinary semantic HTML. A table carrying `table-detail` remains semantic HTML and can use Content Detail View. A table carrying a recognised `table-publish format=svg` comment becomes a scaled linked SVG preview whose click opens the raw SVG in a new tab when complete current preparation exists. Malformed comments, failed preparation, stale artifacts, duplicate IDs, and incompatible document presentation leave the table as ordinary semantic HTML without blocking the build or Publish. Removing the SVG comment and rebuilding restores ordinary HTML publication on the next publish. No table selection or conversion option appears in Publish.

## Current Seams And Scope Guard

The likely blast radius is source comment/table association, semantic table-to-SVG preparation and sanitization, prepared-record ownership, and public Publish projection/cleanup. Working and Manage documents retain semantic tables.

If implementation requires a central directive framework, source diagnostics system, source mutation, a new Publish UI workflow, a public runtime parser, or a new canonical-media model, stop for review and split the result.

## Rough Delivery Steps

### TE-6.0 — Confirm Scope And Delivery

- [ ] Sanity-check the table-publication comment, deterministic SVG preparation, and public substitution flow against the current build, media, and Publish model; resolve only contradictions that would change the outcome.
- [ ] Confirm the broad blast radius across comment association, SVG preparation/sanitization, prepared records, public projection, and Publish cleanup.
- [ ] Confirm the deliverables: exact recognition, deterministic prepared SVG, current-record gating, linked public substitution with semantic fallback, focused end-to-end evidence, and concise durable contract updates.
- [ ] Stop for review if the result crosses the scope guard above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, broad owners, deliverables, and stop condition. Stop before implementation approval.

### TE-6.1 — Recognise The Exact Comment

- [ ] Recognise only the maintained table-publication comment shape and associate it only with the immediately following Markdown table, reusing a small TE-2 adjacency helper if appropriate.
- [ ] Preserve ordinary comments and semantic working/export output without requiring comment removal from generated HTML.
- [ ] Treat incomplete IDs, unknown attributes, intervening blocks, duplicate identity, unsupported contexts, and incompatible document-level presentation as no-op candidates rather than build errors.
- [ ] Add focused exact-match, ordinary-comment, table-association, copy-preservation, full/targeted-build, and semantic-fallback tests.

### TE-6.2 — Prepare Deterministic Table SVG

- [ ] Render from the accepted semantic table representation rather than reparsing cell meaning independently.
- [ ] Produce the specified native-text SVG geometry, caption/description metadata, safe link behavior, neutral styling, viewBox, configured fonts, and sanitizer evidence.
- [ ] Write only record-owned artifacts with complete source/table/config/output digests and atomic candidate behavior.
- [ ] Reuse the configured SVG media role and provider boundaries without making generated output canonical media.
- [ ] Prove deterministic bytes, targeted regeneration, stale detection, unsafe-input no-op, renderer-failure fallback, geometry bounds, and cleanup planning.

### TE-6.3 — Project Linked SVG Public Payloads

- [ ] Extend prospective public by-id projection to consume only complete current prepared records and replace the exact recognised-comment/table pair.
- [ ] Emit one linked preview figure with the specified caption/alternative text, `target="_blank"`, safe `rel`, and no directive metadata or runtime dependency.
- [ ] Keep unmarked tables byte-equivalent apart from existing projection normalization and preserve local/Manage/export semantic tables.
- [ ] Apply the accepted public search contract and retain the semantic table when default Content Detail metadata makes replacement inapplicable.
- [ ] Include only consumed SVG artifacts in preview/apply diffs, ignore path-colliding candidates, byte-verify apply, and remove no-longer-consumed record-owned files.
- [ ] Keep Publish preview, confirmation, and apply request/response/UI contracts unchanged.

### TE-6.4 — Verify And Transfer

- [ ] Run focused checks through the implemented comment, renderer/sanitizer, prepared-record, and public Publish path, including one representative semantic fallback; add search, provider, or cleanup checks only where those owners changed.
- [ ] Manually inspect one representative semantic table and its public linked SVG across desktop and public narrow presentation, including new-tab access and accessible naming.
- [ ] Exercise the existing `table-detail` path only if shared association or projection code changed.
- [ ] Update only the durable authoring, projection, media, or Publish owners whose shipped contract changed.

## Not In Scope

- a third comment consumer, central directive grammar, validator, capability registry, or diagnostics system;
- the Source toolbar action for inserting comments, already owned by [TE-1](/docs/?scope=studio&doc=d-20260802-163320-9015b0);
- automatic table-size analysis or conversion recommendations;
- table-to-PNG/PDF/CSV, multi-page layout, interactive SVG, or theme variants;
- conversion during Publish preview/apply or any new Publish UI;
- changing canonical Markdown, working by-id payloads, Markdown export, or static HTML export to SVG;
- sub-scope-specific behavior beyond the ordinary configured public-projection path established during TE-6.0; or
- changing Content Detail View or blocking a build/Publish because an SVG comment cannot be acted upon.

The completed [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns the stopped decision. Later comment-consumer ideas require a new explicit concept and delivery decision before extending the shipped source-writing convenience.
