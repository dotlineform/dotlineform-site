# Docs Viewer Import Scripts

## `docs-viewer/services/docs_management_import_service.py`

Purpose: thin management-service adapter for staged source imports.

Ownership: owns dependency wiring between route dispatch and the import source workflow.

Responsibilities:

- builds the import dependency object
- supplies management logging to the import workflow
- supplies source-write and rebuild follow-through helpers to the import workflow
- delegates actual import behavior to `docs_import_source_service.py`

Not responsible for:

- format conversion
- collision handling
- media materialization
- docs/search rebuild command details

## `docs-viewer/services/docs_import_source_service.py`

Purpose: staged source import workflow for the Docs Viewer import modal.

Ownership: owns staged-source dispatch, ordinary single-source request
interpretation, preview orchestration, fresh identity allocation,
interactive-companion confirmation, rebuild invocation, and response assembly.

Responsibilities:

- lists staged import files under the W0-configured shared import drop-zone
- gives trusted returned-package and edited-review-source recognizers untouched
  staged candidates before ordinary normalization
- imports Word, HTML, Markdown, Markdown packages, and text, while dispatching
  trusted document collections to their focused planner/apply owners
- converts imported content to Markdown source
- derives titles and source context, then allocates a fresh immutable local identity without loading target documents
- plans media tokens through focused preview/media services
- handles confirmed replacement of stable-name interactive HTML companions
- validates generated Markdown before returning success
- maps the ordinary staged source to one normalized `ImportContent` record
- delegates per-document source/media planning and apply to `docs_import_document.py`
- calls supplied source-write and rebuild follow-through helpers after successful writes

Not responsible for:

- HTTP routing
- source-config settings
- builder implementation

The service resolves `configured_workspace_paths(repo_root).import_staging`,
passes that explicit root through the workflow, and reports the marker-rooted
drop-zone path without exposing user-specific absolute paths.
`docs_import_content.py` defines the wrapper-neutral normalized record.
`docs_import_document_package_content.py` emits it for import-supported returned
packages; `docs_import_review_source_collection.py` emits it for complete
edited review-source folders. The active reviewed collection contract is
`document-content`; `document-full-source` is only a potential later Docs
Viewer feature and is not enabled.

## `docs-viewer/services/docs_import_document_package_collection.py`

Purpose: trusted returned document-package collection orchestration.

Ownership: thin public composition of document-package intake and wrapper-neutral collection planning.

Responsibilities:

- validates the target scope
- calls `docs_import_document_package.py` for trusted wrapper intake
- calls `docs_import_collection_plan.py` for complete write-free planning
- shapes the safe package identity projection supplied to the planner
- dispatches confirmed requests through `docs_import_collection_apply.py`

Not responsible for:

- package parsing or per-row normalization details
- collision, hierarchy, media, or response-planning details
- collection UI or decision state
- configured-source or media writes
- apply revalidation and partial-failure implementation
- Docs/search rebuild invocation

## `docs-viewer/services/docs_import_document_package.py`

Purpose: returned document-package wrapper intake and normalization.

Ownership: owns safe staged-package resolution, trusted export association, raw-row identity validation, and conversion to normalized collection record state.

Responsibilities:

- resolves a safe direct-child JSON/JSONL staged identity and matching trusted export metadata
- normalizes rows from declared import-supported profiles through `docs_import_document_package_content.py`
- preserves package order and represents every raw package record in typed planning state
- distinguishes wrapper/schema blockers from explicit per-record contract errors

Not responsible for:

- configured-scope collisions or hierarchy planning
- body conversion or media planning
- API response projection

## `docs-viewer/services/docs_import_review_source_folder.py`

Purpose: recognize and validate one complete staged edited Docs Review source
folder.

Ownership: owns the `edited_review_sources` transport contract before generic
Markdown normalization.

Responsibilities:

- claims only direct staged folders whose untouched Markdown front matter
  identifies Docs Review provenance
- rejects individually selected review-source Markdown before ordinary import
- validates direct membership, UTF-8 source, strict canonical front matter,
  filename/`doc_id`, safe paths, and consistent package/export/profile/target
  provenance
- revalidates the retained review manifest and trusted export sidecar,
  including return-Import capability, exact membership, and prepared source
  versions
- projects the reviewed display label separately from the staged request
  identity

Not responsible for:

- canonical target lookup, field ownership, planning, confirmation, writes, or
  rebuilds

## `docs-viewer/services/docs_import_review_source_collection.py`

Purpose: map one validated edited folder into the shared overwrite-only
collection plan and atomic destination apply.

Ownership: owns edited-review-source field mapping, fidelity warning,
scope/sub-scope provenance match, overwrite-only policy, and selection of the
atomic parent or child collection boundary.

Responsibilities:

- maps edited body, title, and summary to wrapper-neutral `ImportContent`
- validates prepared canonical versions against the exact
  `ManagedDocumentCollection`
- blocks creates, child hierarchy, non-flat child targets, and collection
  mismatch
- delegates body-free planning to `docs_import_collection_plan.py`
- delegates confirmed receipt revalidation and mutation to the shared
  collection apply owner with the appropriate atomic boundary

Not responsible for:

- raw folder/manifest/sidecar parsing
- generic Markdown handling
- browser confirmation state

## `docs-viewer/services/docs_import_collection_plan.py`

Purpose: wrapper-neutral write-free collection planning over normalized `ImportContent` records.

Ownership: owns typed collection record state and complete collision, hierarchy, parent-dependency, media-summary, blocker, warning, record-error, and body-free response planning.

Responsibilities:

- generates replacement previews through the shared content conversion boundary
- obtains candidate source targets and Docs/search ids from `docs_import_document.py`
- plans every valid record as create or overwrite and blocks the package on record errors
- resolves existing parents and supplied multi-level new-parent chains
- blocks malformed identity and hierarchy states
- reports inline media and declared-asset handling without materializing either
- exposes a body-free API projection plus internal per-document plans for confirmed apply

Not responsible for:

- wrapper schema or provenance rules
- collection UI or confirmation state
- configured-source or media writes
- apply revalidation and partial-failure handling
- Docs/search rebuild invocation

## `docs-viewer/services/docs_import_document.py`

Purpose: shared per-document Docs Import plan and apply boundary.

Ownership: owns one normalized record's create/overwrite validation, allowed front-matter application, canonical source formatting, target/search ids, media/source apply, and document result/activity shaping.

Responsibilities:

- consumes `ImportContent` records without requiring Data Sharing provenance
- plans create, overwrite, `replace`, `preserve-existing`, and `empty-new` behavior without writing
- preserves the current canonical body and unrelated front matter for metadata/hierarchy-only updates
- keeps the ordinary single-source replacement formatting contract unchanged
- rejects unsafe target ids and content intents that do not match the target action
- delegates media bytes and interactive asset materialization to their focused services
- atomically writes the planned document source
- returns changed paths and Docs/search ids to a caller-owned rebuild boundary

Not responsible for:

- package provenance or schema validation
- content-format conversion
- collection collision state or package ordering
- Docs/search rebuild invocation

## `docs-viewer/services/docs_import_collection_apply.py`

Purpose: synchronous package-order collection mutation and generation.

Ownership: owns the collection apply allowlist, server-issued planned-action
confirmation, refreshed-plan response, and confirmed collection apply,
including the common machinery used by both partially durable returned
packages and atomic edited review-source folders.

Responsibilities:

- accepts only scope, safe staged identity, explicit confirmation, package identity, server-issued planned identities/actions, and ordinary activity context
- returns a write-free refreshed plan when package identity, planned actions, hierarchy state, or blockers have changed
- applies records strictly in package order through `docs_import_document.py`
- treats asset materialization as best effort while keeping trusted intake and unsafe-path failures blocking
- preserves completed per-document writes and stops on the first source-write
  failure for ordinary returned packages
- can instead prepare every document, snapshot and recheck the complete exact
  source set, and delegate one atomic scope or sub-scope write/rebuild for
  edited review-source folders
- invokes the selected managed rebuild owner once with all affected paths and
  ids
- reports ordinary returned-package generation failure separately, or projects
  complete rollback evidence for an edited review-source failure
- records collection apply activity and delegates final response shaping

Not responsible for:

- collection UI or browser package confirmation
- inventing rollback policy for a wrapper, jobs, polling, cancellation after
  mutation begins, or generation retry

## `docs-viewer/services/docs_import_collection_result.py`

Purpose: body-free collection result shaping.

Ownership: owns safe grouped collection outcomes returned to the Import workflow.

Responsibilities:

- groups records as created, overwritten, failed, or not attempted while preserving package order
- projects generation status without commands, process output, diagnostics, or local paths
- includes warnings and manual-copy instructions

Not responsible for:

- import planning, confirmation, mutation, or generation
- persistence or result-specific logging
- changing import outcomes

## `docs-viewer/services/docs_import_preview.py`

Purpose: lower-level staged-file discovery and HTML/Markdown import conversion helpers.

Ownership: owns explicit-root staging resolution, supported file detection, preview generation, and format dispatch.

Responsibilities:

- constrains staged file reads to `$DOTLINEFORM_PROJECTS_BASE_DIR/data-sharing/import-staging/`
- detects supported source formats
- converts HTML and text sources to Markdown
- rewrites package-local images and attachments to docs media links
- materializes inline raster media plans
- applies SVG safety rules used by imports
- exposes content-based Markdown, HTML-to-Markdown, and plain-text entrypoints beneath the existing file wrappers

Not responsible for:

- endpoint dispatch
- writing final docs source files
- running docs/search rebuilds
