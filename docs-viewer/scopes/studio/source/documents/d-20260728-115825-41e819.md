# Sub-Scope Report Contribution Delivery

## Status And Order

Proposed as SSI-1, the first implementation delivery for
[Sub-Scope Index](/docs/?scope=studio&doc=d-20260728-113139-285eae).
Implementation has not started.

SSI-1 has no dependency beyond the shipped `docs_subscope` report and managed
document target contracts. SSI-2 and SSI-3 do not begin until this boundary has
passed public/manage isolation and realistic UI review.

## Complete Outcome

The shared `docs_subscope` report accepts an optional, caller-supplied
contribution contract for:

- list-row adornments;
- a list toolbar;
- a detail toolbar on the same header row as Back; and
- mount, state-change, refresh, and unmount notifications.

The manage bridge supplies the contribution. Public callers supply nothing,
render no empty hosts, and do not import the management controller or any
workflow module.

The existing manage-only Status and non-viewable icons move behind the row
contribution boundary without changing their appearance or data source. This
gives SSI-1 a real behavior-preserving refactor outcome rather than shipping
unused visible controls.

## Change Classification

| kind | work |
| --- | --- |
| shipped and retained | public manifest/list/detail navigation; manage inventory; existing Status/non-viewable icon behavior; validated detail state |
| extended | shared report accepts optional hosts and explicit contribution callbacks |
| refactored | manage-only row semantics move out of the public shared report and into one focused manage controller |
| genuinely new user workflow | none |

SSI-1 is an enabling delivery. It must not claim Delete, checkboxes, selection,
or Prepare Package as shipped.

## Contribution Contract

The shared report remains the only owner of:

- configured sub-scope validation;
- list membership and ordering;
- row and detail navigation;
- `subdoc` URL state;
- by-ID identity validation;
- public-safe rendering; and
- the current exact detail target.

When a contribution is supplied, the report passes only explicit values:

```text
collection: { scope, sub_scope }
row:        collection + document record + row host
detail:     { scope, sub_scope, doc_id } + detail toolbar host
state:      list | loading | detail | invalid | error | unmounted
```

The manage controller owns capability checks, management presentation, action
definitions, workflow loading, busy state, and reconciliation. It never reads
`subdoc` to invent a target, scrapes report markup, or falls back to the
selected parent document.

Hosts exist only when the contribution requests content. Public mode and a
manage contribution with no applicable control produce no blank toolbar or
layout gap.

Rows, accessible control state, and contribution handoffs retain exact
`doc_id`. Title remains ordinary display data and is not validated for
uniqueness.

## In Scope

- Define the smallest generic contribution interface required by the three
  approved host positions and lifecycle events.
- Keep the shared report free of management imports.
- Move existing Status/non-viewable row adornment behavior behind the
  manage-only contribution.
- Retain one compact inventory read; do not fetch one full record per row.
- Add manage-only presentation for contribution hosts.
- Preserve list/detail navigation, Back/Forward, explicit Back, and contained
  invalid-detail behavior.
- Cover missing Status, non-viewable rows, empty lists, failed inventory,
  remount, and unmount.
- Prove the public asset/import graph excludes the controller and future
  action/workflow modules.

## Not In Scope

- Delete or any other mutation.
- Checkboxes, selection state, or package preparation.
- Moving existing global Source, Edit metadata, or Open in VS Code controls
  into the report header.
- Public Status/non-viewable icons.
- New public payload fields.
- Filtering, search, bulk actions, or Tag Registry data.
- A generic contribution framework for every report type.
