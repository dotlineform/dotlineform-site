# Media Locations

## Status

This earlier proposal is deferred. [External Media Workspace](/docs/?scope=studio&doc=d-20260812-153836-b38d98) replaces its assumption that repository or R2 is the active managed-media location: every scope instead uses one external private media workspace, while `site/` or R2 becomes an explicit public projection. Any future provider-movement work must be reconsidered as public-projection policy and must not be implemented independently from that model.

## Purpose

Give each Docs Viewer scope one configured location for all of its published media. Media types remain separate logical namespaces, but `img`, `svg`, `files`, `html`, and future published types do not choose different storage providers within the same scope.

This replaces the current per-media-type location model with a simpler scope-level rule. Ordinary Add, Import, Replace, build, render, inventory, and serving workflows resolve the scope's one active media location without asking the author to choose a provider.

## Current Mixed Economy

The current configuration stores media by type. Most scopes already happen to use one provider, but Analysis is split between repository and R2 storage.

| scope | scope type | `img` | `svg` | `files` | `html` | current result |
| --- | --- | --- | --- | --- | --- | --- |
| Studio | local | repository | repository | repository | — | one provider |
| Processing | local | repository | repository | repository | — | one provider |
| Notes | external-local | external scope | external scope | external scope | — | one provider |
| Dotlineform | external-local | external scope | external scope | external scope | — | one provider |
| Analysis | public | repository | repository | R2 | repository | mixed by media type |

The type-level differences are configuration choices rather than different media identities. A document still addresses media as `scope + media type + relative identity`; the configured type currently determines where the bytes are written and how they are served.

## Simpler Defaults

| scope type | default media location | permitted alternative | rule |
| --- | --- | --- | --- |
| external-local | inside the external scope | none | All published media stays with the externally stored scope. |
| local | repository | external-local | All published media uses the repository unless the complete scope media root is deliberately moved outside it. |
| public | repository | R2 | All published media uses the public repository location unless the complete scope media root is deliberately moved to R2. |

Each scope therefore has exactly one active published-media root. Media types remain subdirectories or logical prefixes beneath that root; they are not independent provider selections. Scope access, canonical document storage, public document projection, and published-media location remain separate concerns.

## Moving Media Out Of The Repository

Local and public scopes need a management capability to move their complete published-media root when repository size becomes a practical problem:

- local scopes may move from repository to external-local storage;
- public scopes may move from repository to R2;
- all configured media types move together;
- logical identities and authored references remain unchanged;
- ordinary authoring immediately uses the newly configured location after the move; and
- there is no automatic size threshold, per-file routing, or provider fallback search.

The eventual move should remain one explicit scope-level maintenance action. Its preview reports the object count and total bytes, names the destination and affected products, and shows that the old location will be cleaned up. Apply copies the complete set, changes the one configured location after the copy completes, rebuilds affected products, and removes the exact old copies. A failed action reports where it stopped and leaves any manual cleanup visible; it does not introduce rollback copies, an automated rollback workflow, dual reads, or a recovery framework.

Analysis adopts the repository default. Its current R2 `files` move into the repository alongside its existing repository-backed `img`, `svg`, and `html`, leaving one repository media root for the scope. Its modest current media volume does not justify retaining the mixed provider arrangement; the public repository-to-R2 capability remains available later if the complete Analysis media root becomes too large.

## Delivery Stance

No provider-move delivery is needed until repository size makes it useful. Its specification should remain provisional until that real inventory and UI are available. Prefer the smallest preview and one direct action over a generalized migration engine, and test only the focused location/configuration boundary and object accounting that the final action genuinely needs. Ordinary visual and modal behavior belongs to manual review rather than a new browser-smoke matrix.

## Boundaries

- This feature governs published media, not canonical Markdown, document/search payloads, retained build source, or independently owned project files.
- It does not add provider selection to Add, Import, Replace, or other ordinary authoring actions.
- It does not retain per-media-type location overrides, multiple active roots, size-based routing, replication, background synchronization, or fallback lookup across providers.
- It does not add rollback, retained recovery copies, automatic retries, or a second authoritative location.
- External-local scopes do not move their media independently of their external scope.
- Moving media does not change scope type or publish document content.
- Scope Media Management may inventory and present location evidence, but media-location policy and whole-scope movement belong to this feature.

No delivery from this earlier model has been proposed or started. The document remains available for the External Media Workspace closeout decision.
