# SSP-2.5 — Project State Document Tracing Evidence

## Outcome

SSP-2.5 is complete at its review checkpoint. Project State now emits `docs_project_state_report_v2` and `docs_project_state_folder_lookup_v2`. The immediate `projects/` directory scan remains the only Folder-row authority. The producer retains every exact valid Project document subject, then places Folder subjects by exact scanned key, Work subjects through the canonical Work's first-level `project_folder`, and Series subjects into each distinct scanned Folder containing a current member Work.

Each placed report document retains its exact Docs Viewer target and presentation, unchanged `declared_subject`, and ordered `applicable_series_ids`. The matching lookup retains exact target and placement provenance without copying document or catalogue presentation into a second authority. A document is deduplicated once per Folder even when several Series member Works establish that placement. `matched_document_count` counts distinct placed documents; `document_placement_count` counts their total Folder appearances; `unmatched_document_count` records valid subject documents with no current scanned placement.

## Browser Projection

Folder view continues to show one physical Folder row with each placed document once. Series view now filters documents through producer-supplied provenance: a Series-subject document appears only under its exact Series, a Work-subject document appears under each current Series membership of that Work in the Folder, and a Folder-subject document appears with every current Series in the Folder. Any placed document without a current Series route remains visible in one blank-Series row.

Search, sorting, Copy table, and Copy Markdown consume the same visible projection. The focused browser fixture proves a Folder-wide document appears in two Series rows, one Series-subject document appears only in its exact Series row, and one Work-subject document with no current Series route appears only in the blank-Series row. Series-specific search and Markdown serialization retain only the documents belonging to the matched visible row.
