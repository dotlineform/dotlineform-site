# PRJ-1 — Docs Viewer Local Folder Links Delivery

## Status And Purpose

Proposed as **PRJ-1**, the first delivery under
[Projects](/docs/?scope=studio&doc=d-20260801-095819-30103c).

This delivery implements the reusable contract in
[Local File And Folder Links Concept](/docs/?scope=studio&doc=d-20260801-150013-f26b87).
It establishes body-link authoring, rendering, public projection, and confined
activation before Project metadata assigns any semantic meaning to a target.

## Complete Outcome

In a Manage Source editor, an author can paste a local `file:` URL, absolute
path, or shell-backslash-escaped absolute path contained below
`$DOTLINEFORM_PROJECTS_BASE_DIR/`. Docs Viewer strips that configured root and
inserts one marked Markdown link whose payload is a normalized relative path:

```markdown
[3 symbols](dlf-local:projects/3%20symbols)
```

Manage can open an existing target through the local service. A public
projection retains safe label text but removes the local-link behaviour and
target.

The link remains prose. It does not create Project metadata, enter a manifest,
or identify a folder to Studio.

## Fixed Contract

- The canonical target is a normalized POSIX path relative to
  `$DOTLINEFORM_PROJECTS_BASE_DIR/`; the configured root is never stored.
- Body source uses `dlf-local:<percent-encoded-relative-target>` so it cannot
  be confused with an ordinary relative web link.
- The focused editor reads only the current browser `paste` event. It does not
  monitor or poll the clipboard.
- One complete recognized in-root path is converted. Outside-root, mixed,
  multiline, ambiguous, and code-context input is pasted normally.
- Input is inert data: no shell evaluation, variable or home expansion,
  command substitution, or non-`file:` input scheme.
- Storage may describe a prospective missing target. Activation requires an
  existing target and repeats decoding, traversal, and symlink-aware
  containment checks server-side.
- Local Manage intercepts the rendered link and sends only the exact relative
  target to the management service.
- Public projection removes the marker and target, retaining a safe label as
  inert text or using the agreed placeholder.
- Ordinary relative and external links retain their current rendering and
  navigation behaviour.
- PRJ-1 adds no Semantic Token, registry, Project metadata, or general-purpose
  public secret/path redactor.

## Delivery Discipline

PRJ-1 should be a small integration over existing seams: one compact
normalizer/validator, one narrow local-open endpoint, a focused-editor paste
handler, a `dlf-local:` rendering/public-projection rule, and focused tests.
It must not grow a registry, filesystem browser, metadata system, generic
secret scanner, platform framework, or Project-specific workflow.

PRJ-1.0 must record the exact proposed files, reused owners, and a rough split
of production and test diff size before implementation. Hundreds of new
production-code lines are a pause-and-explain signal; thousands mean the
delivery has escaped its design and must be split or simplified. Line count is
a review trigger rather than a target to game: duplicated or compressed code
does not make an oversized design acceptable.

## Rough Delivery Steps

### PRJ-1.0 — Freeze Input And Link Contract

- [ ] Trace current Markdown insertion/rendering, public projection, Source
  editor paste handling, and local management-service boundaries.
- [ ] Freeze accepted input, excluded editor contexts, relative-path encoding,
  label derivation, confirmation/Undo, errors, and exact activation payload.
- [ ] Freeze Manage anchor behaviour, inert public output and placeholder,
  server revalidation, and ordinary-link preservation.
- [ ] Record the exact file list, reused seams, rough production/test diff
  estimate, and any proposed expansion before implementation approval.

**Checkpoint:** representative Finder, terminal, encoded URL, missing-target,
outside-root, contained non-`projects/`, manually authored `dlf-local:`, public,
and malicious inputs have reviewed expected results.

### PRJ-1.1 — Implement Normalization And Confined Open

- [ ] Add the shared parser/normalizer and focused relative-target containment
  tests.
- [ ] Add the local opener over one exact validated relative target.
- [ ] Return contained missing, invalid, outside-root, and unsupported-platform
  states without invoking Finder.

### PRJ-1.2 — Integrate Authoring And Rendering

- [ ] Add paste/insert preview to the appropriate Source editing control.
- [ ] Render `dlf-local:` body links as clickable local links in Manage and
  route clicks through the exact validated opener.
- [ ] Project the same link as safe inert public output with no marker, target,
  endpoint, control, or activation capability.
- [ ] Preserve normal relative and external-link behaviour.

### PRJ-1.3 — Verify And Transfer

- [ ] Run focused parser, containment, route/service, renderer, editor, public
  projection, ordinary-link regression, lint, and whitespace checks.
- [ ] Manually test paths with spaces, `~` characters, percent encoding,
  backslash escaping, missing folders, and long iCloud paths.
- [ ] Record shipped link syntax and activation behavior in the durable Source
  Editor and Management Services owners.

## Not In Scope

- `folder_path` front matter or manifest projection;
- Projects sub-scope customization or seeding;
- Project State or Studio Work reads;
- Resolver Tokens;
- arbitrary filesystem browsing;
- content-wide public private-path transformation; or
- a final public-payload private-path verifier.

## Completion Evidence

- Accepted path forms normalize deterministically and unsafe forms fail closed.
- Existing allowed folders open through one exact server-validated action.
- Missing and prospective links remain readable without activating a fallback.
- Public output retains agreed safe labels or placeholders while containing no
  `dlf-local:` target, opener control, or management-service dependency.
- Real Source-editor and rendered-document review covers representative iCloud
  folder paths in `dotlineform`.
