# PRJ-1 — Docs Viewer Local Folder Links Delivery

## Status And Purpose

Active as **PRJ-1**, the first delivery under
[Projects](/docs/?scope=studio&doc=d-20260801-095819-30103c).

PRJ-1.0 is complete at its implementation-approval checkpoint. Runtime work
has not started.

This delivery implements the reusable contract in
[Local File And Folder Links Concept](/docs/?scope=studio&doc=d-20260801-150013-f26b87).
It establishes body-link authoring, rendering, public projection, and confined
activation before Project metadata assigns any semantic meaning to a target.

## Complete Outcome

In a Manage Source editor, an author can paste a local `file:` URL, absolute
path, or shell-backslash-escaped absolute path contained below
`$DOTLINEFORM_PROJECTS_BASE_DIR/`. Docs Viewer strips that configured root and
inserts one marked Markdown link whose payload is a normalized relative path:

```markdown
[3 symbols](dlf-local:projects/3%20symbols)
```

Manage can open an existing target through the local service. A public
projection retains safe label text but removes the local-link behaviour and
target.

The link remains prose. It does not create Project metadata, enter a manifest,
or identify a folder to Studio.

## Fixed Contract

- The canonical target is a normalized POSIX path relative to
  `$DOTLINEFORM_PROJECTS_BASE_DIR/`; the configured root is never stored.
- Body source uses `dlf-local:<percent-encoded-relative-target>` so it cannot
  be confused with an ordinary relative web link.
- The focused editor reads only the current browser `paste` event. It does not
  monitor or poll the clipboard.
- One complete recognized in-root path is converted. Outside-root, mixed,
  multiline, ambiguous, and code-context input is pasted normally.
- Input is inert data: no shell evaluation, variable or home expansion,
  command substitution, or non-`file:` input scheme.
- Storage may describe a prospective missing target. Activation requires an
  existing target and repeats decoding, traversal, and symlink-aware
  containment checks server-side.
- Local Manage intercepts the rendered link and sends only the exact relative
  target to the management service.
- Public projection removes the marker and target, retaining a safe label as
  inert text or using the agreed placeholder.
- Ordinary relative and external links retain their current rendering and
  navigation behaviour.
- PRJ-1 adds no Semantic Token, registry, Project metadata, or general-purpose
  public secret/path redactor.

## Delivery Discipline

PRJ-1 should be a small integration over existing seams: one compact
normalizer/validator, one narrow local-open endpoint, a focused-editor paste
handler, a `dlf-local:` rendering/public-projection rule, and focused tests.
It must not grow a registry, filesystem browser, metadata system, generic
secret scanner, platform framework, or Project-specific workflow.

PRJ-1.0 must record the exact proposed files, reused owners, and a rough split
of production and test diff size before implementation. Hundreds of new
production-code lines are a pause-and-explain signal; thousands mean the
delivery has escaped its design and must be split or simplified. Line count is
a review trigger rather than a target to game: duplicated or compressed code
does not make an oversized design acceptable.

Frozen authoring contract:

- The paste handler runs only on the Source body textarea. A selection is
  eligible only when its whole range is ordinary Markdown prose; inline or
  fenced code, indented code, HTML comments, and explicit `<pre>` ranges are
  excluded. Front matter is not present in this editor.
- `text/plain` must be one exact, single-line value with no surrounding
  whitespace. Accepted forms are an absolute POSIX path, the same path with
  shell backslash escaping, or a `file:` URL with an empty authority or
  `localhost`. Queries, fragments, other authorities and other schemes are
  rejected.
- The configured base and input are compared by decoded path components. The
  base itself, empty segments, `.`, `..`, NUL/control characters, literal
  backslashes after shell unescaping, invalid UTF-8/percent escapes, and a
  trailing shell escape fail closed. There is no shell, variable, tilde,
  command, case, Unicode, or filesystem-name expansion.
- Authoring containment is lexical and does not require existence. The
  normalized identity preserves decoded component spelling as a POSIX path.
  Link payloads percent-encode UTF-8 per component with `/`, unreserved ASCII,
  and `~` left literal. Manually authored payloads must round-trip to that one
  canonical encoding.
- The inserted label is the decoded final component with Markdown link-label
  metacharacters escaped. Conversion is immediate, has no confirmation modal,
  reports `Local link inserted. Undo to restore the pasted path.`, and uses the
  existing one-range textarea mutation so the paste remains one dirty,
  undoable edit. Ineligible or unrecognized input is pasted unchanged and does
  not show an error.
- Synchronous recognition needs the configured absolute base. Manage
  capabilities return runtime-only
  `local_folder_links: { authoring, activation, base_path }`; `base_path` is
  nonblank only when the configured base is usable, and `activation` is true
  only on macOS. The absolute value must not enter source, generated payloads,
  activity, errors, public config, or public output. This small local
  capability is preferred to intercepting every possible path and waiting on
  an asynchronous preview request, which would alter ordinary-paste and Undo
  behaviour.

Frozen rendering and activation contract:

- A valid `dlf-local:` destination becomes a normal Manage anchor with
  `href="#"` and one `data-docs-viewer-local-target` containing the canonical
  encoded relative payload. One delegated Manage listener prevents navigation
  and sends exactly `{ "target": "projects/3%20symbols" }` to
  `POST /docs/open-local-target`. It never supplies a scope, document, selected
  parent, displayed URL, label, or fallback target.
- The server decodes the encoded payload exactly once, requires its canonical
  re-encoding to match, and repeats relative-component validation. It resolves
  the configured base and existing candidate, rejects a resolved symlink escape,
  and invokes no process until validation succeeds. On macOS it calls `open`
  with direct arguments: a directory is opened and a file is revealed with
  `-R`. Other platforms return `unsupported_platform`.
- Endpoint outcomes are `opened` (200), `invalid_target` (400),
  `outside_root` (403), `missing_target` (404), `unsupported_platform` (501),
  or `base_unavailable` (503). Error responses contain no absolute path.
- Invalid manually authored local links render as inert labelled text in
  Manage. A valid empty-label link uses `[local file or folder]` so it is never
  an invisible action.
- Public projection replaces every valid or invalid explicit local-link anchor
  with escaped plain label text. A blank label, or a label whose complete text
  is itself an absolute path or `file:` URL, becomes
  `[local file or folder]`. The public by-ID payload contains no marker,
  encoded target, data attribute, endpoint or activation code.
- Ordinary relative, fragment, `mailto:`, external and other currently
  rendered links do not enter this branch and retain current behaviour.

Reviewed representative cases:

| case | expected result |
| --- | --- |
| `file:///configured/base/projects/3%20symbols` | `[3 symbols](dlf-local:projects/3%20symbols)` |
| `/configured/base/projects/3\\ symbols` | same canonical link |
| `/configured/base/archives/future folder` when missing | link is stored; activation returns `missing_target` |
| a contained target outside `projects/` | accepted; the configured base, not `projects/`, is the boundary |
| `/outside/base/project`, mixed prose, multiline text or a code-context paste | ordinary unchanged paste |
| `~/project`, `$HOME/project`, `https://...`, `file://remote/...` | ordinary unchanged paste; no expansion or alternate scheme |
| `/configured/base/projects/$(whoami)` | literal safe data; no command execution |
| `dlf-local:projects/%2E%2E/Desktop`, encoded `/`, bad UTF-8 or noncanonical escapes | inert invalid local-link label; activation is `invalid_target` |
| an in-base symlink resolving outside the base | link may be authored; activation is `outside_root` |
| valid Manage link | exact target opens through the loopback management service |
| valid public link with label `3 symbols` | inert plain text `3 symbols` |
| public link labelled `/Users/example/private` or with no label | inert `[local file or folder]` placeholder |
