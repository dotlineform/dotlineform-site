# EMW-1 — External Media Workspace And Public Projection Delivery

## Status And Purpose

This is a **proposed** delivery. It does not authorize implementation. Its first checkpoint confirms the current object inventory, exact external folder shape, configuration split, migration safety, and public-rendering seam before any bytes or active scope configuration move.

## Complete Outcome

Every configured Docs Viewer parent scope stores managed media and registered media build sources in one external, scope-namespaced workspace. Repository and external-local document scope containers retain document and document/search roles but no media bytes. Add, Import, Manage, inventory, build relationships, Copy, and source evidence use the external workspace. Public-scope Publish derives the referenced media set from all publishable documents, projects it to the configured `site/` or R2 target with public URLs, and removes only stale public projections. Logical Markdown references do not change.

## EMW-1.0 — Confirm Inventory, Folder Model, And Cutover Fit

- [ ] Inventory every configured parent scope's ready media, registered build sources, evidence table, logical references, current location/provider, byte count, and public projection state across repository, external-local, `site/`, and R2.
- [ ] Confirm the exact `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/media/<scope>/` folder schema, scope/sub-scope ownership, naming, confinement, backup expectation, and unavailable-workspace behavior.
- [ ] Confirm one strict configuration model that separates external managed media from optional public media projection without retaining the old schema, aliases, dual reads, fallback search, or per-item provider choice.
- [ ] Confirm how one logical media token renders through the private Manage URL and a different public URL, including current parent/sub-scope payload projection and HTML-media behavior.
- [ ] Confirm a migration manifest and single-cutover order that can retrieve current R2 objects, byte-verify every external target, preserve live public copies until reconciliation, and identify exact obsolete repository paths.
- [ ] Freeze current public target policy for this delivery unless a separate decision explicitly changes it; EMW-1 separates private authority from public projection and does not silently consolidate providers.
- [ ] Restate the broad changed owners, migration and public-serving risks, focused evidence, and the exact stop condition before implementation.
- [ ] Stop if the result requires a general asset registry, content-addressed store, cross-scope deduplication, background synchronisation, dual-authority migration period, new backup system, or generic transaction/recovery framework.

**Checkpoint:** review one concise inventory and implementation-fit record. Do not change active configuration, move bytes, or begin EMW-1.1 without explicit approval.

## EMW-1.1 — Establish And Cut Over The External Managed-Media Contract

- [ ] Add one configured external media-workspace root and exact scope/type/build-source/evidence resolution with server-side confinement and no browser-visible absolute paths.
- [ ] Produce the frozen exact migration plan from EMW-1.0 for every current media identity, build source, and evidence table.
- [ ] Copy repository, external-local, `site/`, and R2 managed bytes to the exact external target and verify bytes before changing configuration or removing any old private copy.
- [ ] Apply one configuration and owner cutover that makes every scope's Add, imported-media materialisation, registered media build, inventory, local serving, exact media verification, and editorial Copy use the external namespace, with no compatibility aliases, dual writes, fallback readers, or filename/provider inference.
- [ ] Move source evidence beside the external namespace while preserving the strict `{media_type, identity, source_root, source_path}` rows and private-only contract.
- [ ] Move standalone media build sources such as Mermaid `.mmd` into the registered external build-source namespace while leaving inline Markdown Mermaid unchanged.
- [ ] Keep editorial Copy on its existing exact media plan while transferring managed bytes and evidence between exact source and target external namespaces without public Publish.
- [ ] Serve managed media to local Docs Viewer through the existing `/docs/media/<scope>/<type>/<identity>` boundary.
- [ ] Keep canonical document builds provider-independent and make unavailable managed media explicit without reading public projection bytes as a fallback.
- [ ] Preserve current `site/` and R2 public objects until media-aware Publish owns their reconciliation.
- [ ] Remove obsolete repository-private `source/media/` and `published/media/` files, tracked markers, and empty directories only after the external targets and all active owners verify successfully.
- [ ] Confirm canonical Markdown and exact `docs/<scope>/<type>/<identity>` references are byte-for-byte unchanged.
- [ ] Report any source object that cannot be retrieved or verified as a blocker rather than adopting the remaining public copy implicitly at runtime.

**Checkpoint:** the external workspace is the sole private managed-media authority; Add, Manage, Copy, build sources, and evidence use it; the repository contains no private media copies; and all pre-cutover public media remains reachable. Stop before Publish begins reconciling media.

## EMW-1.2 — Project Media Through Explicit Publish

- [ ] Extend Publish preview to derive the exact referenced media set from the complete publishable parent and sub-scope document set and list new, changed, missing, shared, retained, and stale public projections.
- [ ] Block confirmation when a publishable document requires managed media that is missing or unavailable.
- [ ] Render public document payloads with public served URLs while the unchanged logical source continues to render Manage payloads with local media URLs.
- [ ] Apply and byte-verify required `site/` or R2 media before exposing documents that reference them, then publish documents/search and remove exact stale public projections last.
- [ ] Keep a shared public media identity while any publishable document references it; remove it only when absent from the complete remaining public reference set.
- [ ] Preserve external managed media, retained originals, evidence rows, and registered build sources through unpublish, document Delete, public cleanup, and rerun after partial public failure.
- [ ] Keep public provider mechanics behind the existing location adapters and preserve current target policy unless it was separately approved at EMW-1.0.

**Checkpoint:** one Publish action reconciles documents and their media for representative `site/` and R2 targets, and unpublish removes only public projections no longer shared. Stop for end-to-end review before closeout.

## Likely Owners To Inspect

This is a broad responsibility map for EMW-1.0, not a frozen file or test plan:

| boundary | likely current owner |
| --- | --- |
| External workspace capability and scope configuration | configured workspace paths, scope config/manifest, and location adapters |
| Add, materialisation, serving, inventory, and evidence | existing staged/import media, media storage/inventory, local media route, and source-evidence services |
| Registered build sources | media producer configuration, Mermaid intake/builder/watcher, and diagram-source service |
| Editorial transfer | existing document-transfer media plan/apply and evidence decisions |
| Manage/public URL projection | document renderer/browser config and public payload projection |
| Public reconciliation | existing Publish status/confirm/apply planner and repository/R2 adapters |
| Migration and lifecycle | scope/media location planning, exact byte verification, and obsolete-path cleanup |

## Verification Stance

Choose exact checks only after EMW-1.0 identifies the changed seams. Prefer pure/service cases for path confinement, configuration, identity preservation, reference-set planning, shared-media retention, missing-media blockers, byte verification, and cleanup. Use direct route/module evidence for local serving and public URL projection when lower layers cannot prove integration. Use temporary manual browser review for the Manage/public image result and ordinary interaction; do not add broad choreography tests.

Because the final cutover changes storage authority and the public artifact, completion requires a real inventory reconciliation, a focused disposable migration rehearsal, targeted Studio docs/search regeneration, public-site validation for changed tracked output, and `git diff --check`. A broad profile is warranted only if EMW-1.0 shows a genuinely broad runtime boundary that focused checks cannot cover.

## Not In Scope

- Backup, synchronization, external-workspace installation, cross-device setup, or disaster recovery.
- Scope Media report UI, item deletion/replacement/relinking, source repair, automatic orphan cleanup, or publication-health scoring.
- Per-item provider selection, automatic size routing, multiple active private roots, provider fallback reads, or background publication.
- Cross-scope deduplication, shared physical files, nested identity migration, checksums as a persistent catalogue, or content-addressed storage.
- Public CDN cache invalidation/versioning, general R2 lifecycle management, or a new asset registry.
- Changes to document identity, lineage, publishability eligibility, retained-original selection, or public routes unrelated to media projection.

## Completion Evidence

- Every configured parent scope resolves managed media, build source, and evidence only through its external namespace.
- Existing media and build sources reconcile exactly after migration, and obsolete repository-private media paths are absent.
- Manage and public payloads render the same logical media identities through their correct distinct URLs.
- Add and Copy change only external managed media; Publish alone changes public media.
- Unpublish and shared-reference cases remove only eligible public projections and retain all private managed bytes.
- Durable owner documentation describes the shipped folders, workflows, extension boundary, and remaining weak spots.

No implementation or migration begins from this document until EMW-1.0 is explicitly approved.
