# Public Catalogue Data Flow

## Route Map

| Public route | Reads | Why |
| --- | --- | --- |
| `/series/` | `series_index.json` | list/grid of Series and their primary thumbnails |
| `/series/?series=<series_id>` | exact Series JSON | selected Series metadata, prose, and canonically ordered lightweight Work members |
| bare `/works/` | none | redirect to `/series/` |
| `/works/?work=<work_id>` | exact Work JSON and exact relevant Series JSON | rich Work content, details, and exact Series navigation |
| `/work-details/?detail=<detail_uid>` | parent Work JSON | selected detail and sibling/section context |
| `/recent/` | `recent_index.json` | publication snapshots with owned canonical destinations |
| `/catalogue/search/` | catalogue search index | flat search-oriented records |

The exact public route modules live under `site/assets/js/catalogue/routes/`. Static shells live under `site/series/`, `site/works/`, and `site/work-details/`.

## Execution Flow

```text
canonical catalogue source
  -> scoped catalogue generator
  -> lean Series list + exact Series/Work + Recent projections
  -> canonical-source Catalogue Search build
  -> static route shell
  -> route module fetches only its owned lean, exact, Recent, or Search payload
```

The browser never treats a public payload as writable source. Studio reads and mutates canonical or Studio-owned projections; the public build projects published canonical records into route-owned runtime shapes.

The lean Series list contains only `series_id`, title/year display fields, `primary_work_id`, and optional `single_work_id`. Ordered membership belongs to each exact Series payload. There is no flat public Works aggregate or list route.

## Detail Ownership

There is no public global detail index. `detail_uid` identifies the parent Work, and the exact Work payload carries sections plus nested details. This keeps ordering and navigation with the record that owns them and avoids a second payload family.

## Moment Records Boundary

There is no public `/moments/` route. Catalogue Moment records do not imply a Docs Viewer scope or a Local Studio Moment capability.

## Change Rule

When a public route needs new data, first decide whether it is:

- list-wide context for the lean Series index;
- selected-record context for a focused payload;
- detail context already owned by the exact Work payload;
- publication-snapshot context owned by Recent;
- search-only text for the search index;
- or data that belongs to another scope entirely.

Update the serializer, field registry, route module, and focused tests for that exact boundary. Do not restore a flat Works projection or add the field to every payload for convenience.
