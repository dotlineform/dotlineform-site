# Docs Viewer External Scope Availability

## Purpose

Keep Docs Viewer running when one configured external scope folder is unavailable. With a valid configured projects base and Docs workspace, startup must not recreate that scope or let its missing folder disable unrelated scopes.

This feature addresses a current integrated-runtime gap exposed during the iPad local-authoring assessment but is not iPad-specific. iCloud Drive remains local filesystem storage after synchronization; paused network sync is not an application outage when the configured local files remain readable.

## Delivery

[ESA-1 — Graceful Per-Scope Availability Delivery](/docs/?scope=studio&doc=d-20260808-222436-4f7c81) is complete. Docs Viewer startup now skips media-directory materialization when the exact configured external scope root is not an existing directory.

The existing capability response, Manage gating, and live watcher already retain and report the configured unavailable scope, disable its unsupported management behavior, wait while its source is missing, and resume when it returns. ESA-1 reused those seams without adding a new availability model or error system.

## Shipped Contract

- With a valid `DOTLINEFORM_PROJECTS_BASE_DIR` and Docs workspace, a missing configured external scope root does not stop Docs Viewer startup.
- Startup does not create that root or any media descendant.
- Repository-backed and available external scope media directories retain their previous setup behavior.
- The configured unavailable scope remains visible through existing capability, Manage, and watcher behavior; no fallback scope is inferred.
- A missing or unmounted projects base remains a separate whole-environment configuration condition.

## Ownership And Relationship

[Local Authoring Service And Publication Boundaries](/docs/?scope=studio&doc=d-20260808-215338-6b1e8c) owns the durable cross-system decision and availability terminology. ESA-1 changes only startup media-directory materialization; it does not start the broader [Docs Viewer Core Refactor](/docs/?scope=studio&doc=d-20260718-114645-7b9d24).

The feature does not change external scope lifecycle, storage ownership, publication, iCloud synchronization, scope configuration, browser behavior, or watcher behavior.

## Success Meaning

ESA-1 passed seven focused media-storage tests, explicit Python lint, and `git diff --check`. Closeout was approved on 2026-08-12. This feature does not make an unavailable scope readable or repair iCloud or File Provider synchronization.
