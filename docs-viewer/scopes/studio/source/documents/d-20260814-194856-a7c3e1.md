# Admin Retirement

## Status

Active. AR-1 assurance extraction and AR-2 activity-pipeline retirement are implemented. AR-2 is at its review gate; stop before the broader Admin application removal.

## Complete Result

The local Admin application, its routes, APIs, reports, Workbench, runners, smokes, and current-state documentation are retired. Independently useful repository assurance remains under top-level or application-owned tests without an Admin compatibility layer.

## Boundary

- retain the repository check-profile runner as test-owned evidence coordination;
- retain only independently justified projection, route-ready, and Catalogue consistency checks;
- put cross-repository contracts under `tests/` and Catalogue consistency under `studio/tests/`;
- move new profile evidence from `var/admin/test-runs/` to `var/test-runs/`;
- do not move Admin Checks reports, target-map machinery, CSS reporting, UI/API artifact readers, or Admin smokes into the test boundary;
- retire the shared activity pipeline end to end rather than moving its files or retained output;
- preserve ordinary diagnostic, service, script, and operation-specific logging that has an owner independent of the Admin feed;
- leave existing ignored `var/admin/activity/` files untouched and create no migration or compatibility reader;
- keep the separately classified Work storage index outside AR-2; its later retirement belongs to [Work Storage Index Retirement](/docs/?scope=studio&doc=d-20260814-204410-c4f892);
- add no aliases for old commands, paths, routes, or output locations.

Decision: the activity data is not retained or relocated. Its completeness and utility are unproven, so continuing to collect it would preserve cost and coupling without a justified consumer. Existing ignored feed/journal files are not migrated or deleted by this checkpoint.

Record: Admin Activity, the shared contract/writer/feed, and the Catalogue, Tag, Docs Viewer, Studio-browser, and Admin-audit telemetry hooks were one cross-application pipeline rather than a standalone frontend. The route/API/assets, browser `activity_context`, service `activity_log`, emitter helpers, contract verification, and activity-only tests/profile inputs are removed together. Ordinary script/service diagnostics remain. Docs Move, Copy, Import, source-open, and review-package logs remain operation-owned events; misleading activity-named symbols were renamed without changing their event names or payload behavior.

Adjacent findings: AR-2 kept `studio/data/generated/activity/work-storage-index.json` because its generator, cleanup, static exposure, field registry, and tests formed a separate Catalogue-owned chain. A follow-up consumer trace found that the current Catalogue Works report reads canonical `storage_location` through the Studio API and no checked-in runtime consumes the index; [Work Storage Index Retirement](/docs/?scope=studio&doc=d-20260814-204410-c4f892) owns its separate removal. Existing ignored `var/admin/activity/` files may remain locally but have no retained reader or producer; this checkpoint intentionally neither migrates nor deletes them. The Admin target-map `activity` heuristic and the `bin/local-studio` activity-route message were stale direct consumers and were removed. Broader Admin audits, checks, testing, Workbench, runtime, and launchers remain AR-3 scope.

Evidence:

- focused owner tests passed 218 checks with one existing skip: 18 Admin route/config checks, 60 Catalogue/Tag service and API checks, 128 Docs Viewer management/import/package/move/copy checks, and 12 Studio runtime/Catalogue cleanup checks;

Review: no compatibility reader, replacement telemetry store, moved feed data, or broader Admin deletion was introduced. Activity removal did not change canonical mutation, lookup/build, media, publication, package, audit-result, or operation-log ownership. AR-2 is ready for user review.
