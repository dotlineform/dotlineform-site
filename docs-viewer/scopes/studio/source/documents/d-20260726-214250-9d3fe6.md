# Bulk Tag Vocabulary Import Removal Delivery

## Complete Result

The Tag Registry and Tag Aliases have no bulk import controls or executable
import paths. Add, merge, and replace modes are absent from the browser, Studio
API, configuration, domain services, and current verification surface.

New Tag and New Alias continue through the first-class create contracts
delivered by the preceding deliveries.

## Dependency

[First-class Tag Creation Delivery](/docs/?scope=studio&doc=d-20260726-214250-55bc9d)
and
[First-class Alias Creation Delivery](/docs/?scope=studio&doc=d-20260726-214935-063d1d)
must both be complete before this delivery starts.

## In Scope

- Remove Tag Registry and Tag Aliases import controls, modals, upload parsing,
  import state, mode selection, result copy, and import-only browser modules.
- Remove both vocabulary-import routes, dispatch, capability/config projections,
  request handlers, add/merge/replace planners, import normalization, and
  import-only summaries.
- Remove vocabulary-import activity action registrations and current executable
  tests.
- Keep historical activity evidence readable without advertising a callable
  import action or retaining endpoint compatibility layers.
- Remove obsolete registry/alias import copy, selectors, service keys, and
  documentation.
- Reconcile shared modules carefully so the Series Tags offline
  assignment-session import keeps its independently owned behavior.

## Not In Scope

- Series Tags offline assignment-session import, including its preview/apply
  reconciliation; its retirement is owned by
  [Offline Tag Assignment Session Retirement](/docs/?scope=studio&doc=d-20260726-215805-ecf8a4).
- Catalogue workbook, document, media, package, or other import systems.
- Rewriting or reformatting `tag-registry.json` or `tag-aliases.json`.
- Tag-document linking, tag schema changes, or a replacement bulk-edit tool.
- Redirects, aliases, proxies, or dormant placeholder endpoints.

Searches must distinguish vocabulary-import ownership from the offline
assignment-session and catalogue imports.

## Completion And Evidence

- `/studio/tag-registry/` and `/studio/tag-aliases/` have no Import controls,
  modals, upload state, or import modes.
- The Studio tag API no longer registers, advertises, or dispatches either
  vocabulary-import endpoint.
- Scoped source searches find no executable registry/alias import routes,
  handlers, planners, client endpoints, modes, or test dependencies; historical
  Roadmap text is not an executable dependency.
- New Tag, New Alias, edit, delete, promotion, and demotion still work through
  their current first-class operations.
- The Series Tags offline assignment-session import remains present and
  independently verified.
- Existing historical activity can still be understood, while new UI/config
  projections expose no vocabulary-import actions.
- The canonical registry and alias files are byte-for-byte unchanged by the
  removal.
- Focused Python/service tests, JavaScript module checks, route boot/API smokes,
  and `git diff --check` support the bounded claims above.

## Durable Destination

Update [Tag Registry](/docs/?scope=studio&doc=d-20260331-000000-4519a5) and
[Tag Aliases](/docs/?scope=studio&doc=d-20260331-000000-519b1e) so their

[Tag Source Data](/docs/?scope=studio&doc=d-20260419-000000-86255c) only if the
shipped write-boundary description needs to distinguish create from the retired
bulk operations.
