# TE-1 — Source Editor Directive Actions Delivery

## Status And Purpose

Proposed as **TE-1**, the first [Table Enhancements](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) delivery. It has no dependency on [TE-2](/docs/?scope=studio&doc=d-20260802-162149-3ba013) or [TE-7](/docs/?scope=studio&doc=d-20260802-160430-34cb3b): inserted comments remain harmless and visually inert until a later consumer chooses to recognise them. [Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns the source forms, exact-table, and no-op boundaries implemented by this delivery.

TE-1 adds one authoring convenience to the existing Manage Source mode: a **Directives** button, presented in the style and interaction model of the existing Actions controls, opens the two maintained table comment templates. Choosing an item inserts the comment on its own line immediately before the exact Markdown table identified by the captured caret or selection.

## Complete Outcome

With the caret or selection inside exactly one supported Markdown table, the **Directives** menu offers:

- **Enable table detail**, inserting `<!-- dotlineform:table-detail -->`; and
- **Publish table as linked SVG**, inserting `<!-- dotlineform:table-publish format=svg id=table-name -->` and selecting only `table-name` for immediate editing.

The editor returns focus to the source textarea and marks the existing buffer dirty through the ordinary input path. It does not save or rebuild automatically and shows no insertion confirmation message. Before TE-2 or TE-7 ships, Save/Rebuild simply treats the inserted text as an ordinary HTML comment and the table renders normally.

The control appears wherever the existing Manage Source editor is available; it is not filtered by build or publication capability. A command is disabled when the captured source cannot identify exactly one eligible table, when the buffer changed after capture, or when that table already has one of the exact maintained comments immediately associated with it. The initial delivery leaves removal, malformed comments, and attribute editing to ordinary source editing.

## Existing Seams And Expected Size

The current Source editor already exposes main-view controls through the view registry and contribution maps. Its context adapter can capture a selection with the current buffer revision, replace a verified range with `textarea.setRangeText`, select a verified inserted range, return focus, dispatch the normal input path, and project busy/disabled control state. The existing Index and sub-scope Actions controls provide the menu interaction and accessibility precedent; TE-1 reuses their presentation behavior without adopting selection-mode document targeting.

The likely production owners are `docs-viewer-action-definitions.js`, `docs-viewer-management-hosted-views.js`, `docs-viewer-manage.js`, `source-editor/source-editor.js`, one bounded `source-editor/directive-actions.js` module, and `docs-viewer-source-editor.css` or the existing Manage menu CSS. Focused pure/module tests should own table-range recognition, insertion text/ranges, already-marked state, revision rejection, focus/dirty integration, and menu wiring.

The current indicative shape is 5–7 touched production files, approximately 240–400 JavaScript/CSS lines and 260–450 focused test lines. TE-1.0 must replace this estimate with exact files and rough diffs after tracing the current control/menu renderers and ordinary Markdown table behavior. If the work requires a new editor framework, server round trip for every caret move, general directive registry, modal workflow, custom undo manager, or materially exceeds the estimate, stop for review.

## Interaction Contract

The button is one Source-mode main-view control. Its popup is keyboard accessible, closes through the same outside-click, Escape, focus-return, route-change, and disabled-state behavior as the existing Actions menus, and does not introduce a second toolbar or inline table chrome.

The source caret or selection is authoritative. A collapsed caret anywhere in the exact table source range may identify that table; a non-collapsed selection must intersect one table and no other Markdown block. The action never falls back to the active rendered table, table occurrence, nearby heading, document title, previous invocation, or first table in the document.

The captured buffer revision and table range are revalidated immediately before insertion. The comment is inserted at the table’s source start with exactly one separating newline according to the immediate-next-table form frozen by TE-1 itself. The SVG placeholder selection is computed from the inserted text rather than found later by searching the document.

The browser UI may conservatively decline Markdown it cannot identify exactly. It only needs enough source awareness to place one maintained comment safely; it neither parses rendered HTML nor predicts whether a later build consumer will act. Unknown or hand-edited directive text is ordinary source and does not need browser validation.

The edit uses the existing textarea `setRangeText` and input-event seam. TE-1 does not use deprecated `execCommand`, synthesize keyboard events, intercept the clipboard, maintain a fake undo stack, or claim a native Undo guarantee. Any actual browser undo behavior is recorded at TE-1.0 and accepted as native textarea behavior rather than emulated.

## Rough Delivery Steps

### TE-1.0 — Trace And Freeze The Source Action

- [ ] Trace Source-mode control registration/rendering/dispatch, Actions menu lifecycle and accessibility, adapter capture/range replacement, dirty revision handling, focus behavior, route cleanup, and current focused module tests.
- [ ] Freeze the smallest browser-side source range contract needed to place a comment before one ordinary Markdown pipe table.
- [ ] Freeze the control label/icon, menu labels and order, already-marked behavior, blank-line insertion normalization, SVG placeholder range, and no-status-message behavior.
- [ ] Record actual browser-native Undo behavior for the existing `setRangeText` seam without adding `execCommand` or a synthetic history.
- [ ] Record exact production/test files, reused control/menu/adapter seams, and rough diffs for TE-1.1 and TE-1.2 before implementation approval.

**Checkpoint:** a static source fixture demonstrates a caret above, inside, and below a table; a selection intersecting one table; a selection spanning two tables; ordinary comments; existing exact and malformed directive comments; changed buffer revision; and SVG placeholder selection. The expected enabled state and exact inserted source/range are recorded. Stop before implementation.

### TE-1.1 — Add The Contextual Directives Control

- [ ] Register one Manage Source main-view **Directives** control and reuse the established Actions-style popup lifecycle, keyboard behavior, focus return, and route cleanup.
- [ ] Supply the two bounded maintained comment templates without consulting build or publication capability.
- [ ] Recompute menu item state from the current adapter capture whenever the menu opens and disable ambiguous, already-marked, busy, unloaded, or stale actions.
- [ ] Keep the menu independent of Index checked-document selection, rendered-table identity, and Publish state.

### TE-1.2 — Locate The Exact Table And Insert Source

- [ ] Implement pure source helpers that locate exactly one supported Markdown table from the captured caret/selection and detect its immediately associated maintained directives.
- [ ] Insert the chosen comment immediately before the verified table through one revision-bound adapter edit, preserve surrounding source bytes apart from the required newline, and dispatch the existing dirty/input path.
- [ ] For the SVG form, select the exact inserted `table-name` placeholder; otherwise place the caret after the inserted directive and return focus to the textarea.
- [ ] Refuse stale or ambiguous captures without modifying source, saving, rebuilding, opening a modal, or displaying a success message.

### TE-1.3 — Verify And Transfer

- [ ] Run focused pure/module checks for source ranges, table boundaries, insertion bytes, placeholder selection, already-marked tables, stale revisions, control registration, menu lifecycle, and dirty-state integration.
- [ ] Manually verify keyboard and pointer opening, item activation, Escape/outside-click closure, focus return, placeholder replacement, narrow toolbar fit, route changes, and the observed native Undo behavior in the supported browser.
- [ ] Run targeted lint, generated Docs/search, internal-link, JSON, and whitespace checks.
- [ ] Update the concise Source editor and authoring syntax authorities, then hand the UI to the user for tactile review without changing the TE-2/TE-7 build contracts.

## Not In Scope

- recognising, validating, projecting, or otherwise acting on a directive during a build;
- a generic directive/plugin registry, user-configurable menu, or automatic discovery of arbitrary comments;
- inserting a directive without one exact eligible Markdown table at the captured caret or selection;
- editing attributes after insertion, generating a semantic SVG ID, removing/reordering directives, or converting one directive into another;
- parsing rendered HTML, selecting a table by title/occurrence, or adding controls to rendered tables;
- save, rebuild, Publish, conversion progress, or success/status messages;
- `execCommand`, clipboard manipulation, synthetic key events, fake undo, or a custom editor history;
- a modal, second source toolbar, parallel editor model, rich-text editing, or inline table editor; or
- sub-scope-specific behavior beyond using the same exact target and Source editor contracts.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns delivery order. TE-1 is complete when the two comments can be inserted safely through the existing Source control model while canonical Markdown, ordinary rendering, transfer behavior, Content Detail, SVG preparation, and Publish remain unchanged.
