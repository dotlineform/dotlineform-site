# TE-1 — Source Editor Directive Actions Delivery

## Status And Purpose

Proposed as **TE-1**, the first [Table Enhancements](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) delivery. It has no dependency on [TE-2](/docs/?scope=studio&doc=d-20260802-162149-3ba013) or [TE-7](/docs/?scope=studio&doc=d-20260802-160430-34cb3b): inserted comments remain harmless and visually inert until a later consumer chooses to recognise them. [Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns the source forms and build-time recognition/no-op boundaries; TE-1 owns only convenient insertion.

TE-1 adds one authoring convenience to the existing Manage Source mode: a **Directives** button, presented in the style and interaction model of the existing Actions controls, opens maintained code-owned source snippets. Choosing an item inserts its predefined bytes at the captured source insertion point. The button saves the author from typing; it does not decide whether a build consumer will recognise or accept the inserted text.

## Complete Outcome

The initial **Directives** menu offers:

- **Enable table detail**, inserting `<!-- dotlineform:table-detail -->`; and
- **Publish table as linked SVG**, inserting `<!-- dotlineform:table-publish format=svg id=table-name -->` and selecting only `table-name` for immediate editing.

The editor inserts the selected snippet on its own line, returns focus to the source textarea, and marks the existing buffer dirty through the ordinary input path. It does not save or rebuild automatically and shows no insertion confirmation message. Before TE-2 or TE-7 ships, Save/Rebuild simply treats the inserted text as an ordinary HTML comment and the table renders normally.

The control appears wherever the existing Manage Source editor is available; it is not filtered by build or publication capability. Editor readiness, busy state, an exact captured insertion range, and unchanged buffer revision are mutation-safety preconditions rather than directive validation. TE-1 does not inspect the document to decide whether the directive is useful, supported, duplicated, correctly associated, or valid for a later consumer.

TE-1.0 may retain at most two cheap line-local affordances if they fall naturally out of insertion: require a blank insertion line, and for the two table snippets check that the immediately following line resembles the start of a Markdown pipe table. These checks are optional placement hints, not validation. If they require a Markdown parser, block-range recognition, table discovery, or significant test machinery, omit them.

## Existing Seams And Expected Size

The current Source editor already exposes main-view controls through the view registry and contribution maps. Its context adapter can capture an insertion range with the current buffer revision, replace that verified range with `textarea.setRangeText`, select a verified inserted placeholder, return focus, dispatch the normal input path, and project busy/disabled control state. The existing Index and sub-scope Actions controls provide the menu interaction and accessibility precedent; TE-1 reuses their presentation behavior without adopting selection-mode document targeting.

The likely production owners are `docs-viewer-action-definitions.js`, `docs-viewer-management-hosted-views.js`, `docs-viewer-manage.js`, `source-editor/source-editor.js`, one bounded `source-editor/directive-actions.js` module, and `docs-viewer-source-editor.css` or the existing Manage menu CSS. Focused tests should own exact snippet bytes, guarded insertion, placeholder selection, revision rejection, focus/dirty integration, and menu wiring. They do not need a table parser or directive validator.

TE-1.0 must record exact files and rough diffs after tracing the current control/menu renderers and insertion adapter. If the work requires Markdown block parsing, table-range discovery, duplicate-directive analysis, a new editor framework, server round trip, general directive registry, modal workflow, custom undo manager, or hundreds of lines devoted to eligibility, stop for review.

## Interaction Contract

The button is one Source-mode main-view control. Its popup is keyboard accessible, closes through the same outside-click, Escape, focus-return, route-change, and disabled-state behavior as the existing Actions menus, and does not introduce a second toolbar or inline table chrome.

The captured Source insertion point is authoritative. The action never falls back to the active rendered table, table occurrence, nearby heading, document title, previous invocation, or first table in the document. It does not search for a target block.

The captured buffer revision and insertion range are revalidated immediately before insertion. The predefined snippet owns its required newline shape. The SVG placeholder selection is computed from the inserted text rather than found later by searching the document.

The browser UI neither parses rendered HTML nor predicts whether a later build consumer will act. Unknown, duplicated, misplaced, or hand-edited directive text is ordinary source and does not need browser validation. Dedicated build consumers own recognition and must fail quickly and cleanly by leaving unsupported source inert.

The edit uses the existing textarea `setRangeText` and input-event seam. TE-1 does not use deprecated `execCommand`, synthesize keyboard events, intercept the clipboard, maintain a fake undo stack, or claim a native Undo guarantee. Any actual browser undo behavior is recorded at TE-1.0 and accepted as native textarea behavior rather than emulated.

## Rough Delivery Steps

### TE-1.0 — Trace And Freeze The Source Action

- [ ] Trace Source-mode control registration/rendering/dispatch, Actions menu lifecycle and accessibility, adapter insertion/range replacement, dirty revision handling, focus behavior, route cleanup, and current focused module tests.
- [ ] Freeze the smallest browser-side insertion contract: exact predefined bytes, current insertion point, newline handling, and non-collapsed-selection behavior without locating a Markdown block.
- [ ] Decide whether blank-line and immediate-next-line pipe-table hints are trivial enough to retain; omit them if they require parsing or meaningful eligibility machinery.
- [ ] Freeze the control label/icon, menu labels and order, SVG placeholder range, and no-status-message behavior.
- [ ] Record actual browser-native Undo behavior for the existing `setRangeText` seam without adding `execCommand` or a synthetic history.
- [ ] Record exact production/test files, reused control/menu/adapter seams, and rough diffs for TE-1.1 and TE-1.2 before implementation approval.

**Checkpoint:** a static source fixture demonstrates blank and non-blank insertion lines, an immediately following pipe-table start, ordinary prose, existing exact and malformed comments, changed buffer revision, non-collapsed selection, and SVG placeholder selection. It records exact insertion bytes and proves no block or duplicate-directive analysis is required. Stop before implementation.

### TE-1.1 — Add The Contextual Directives Control

- [ ] Register one Manage Source main-view **Directives** control and reuse the established Actions-style popup lifecycle, keyboard behavior, focus return, and route cleanup.
- [ ] Supply the two bounded maintained comment templates without consulting build or publication capability.
- [ ] Recompute only editor-readiness and mutation-safety state from the current adapter capture whenever the menu opens; apply only the cheap placement hints accepted at TE-1.0.
- [ ] Keep the menu independent of Index checked-document selection, rendered-table identity, and Publish state.

### TE-1.2 — Insert The Predefined Source

- [ ] Insert the chosen predefined snippet at the verified source insertion point through one revision-bound adapter edit, preserve surrounding source bytes apart from the frozen newline behavior, and dispatch the existing dirty/input path.
- [ ] For the SVG form, select the exact inserted `table-name` placeholder; otherwise place the caret after the inserted directive and return focus to the textarea.
- [ ] Refuse stale or unsafe mutation captures without modifying source, saving, rebuilding, opening a modal, or displaying a success message.

### TE-1.3 — Verify And Transfer

- [ ] Run focused checks for insertion bytes, newline behavior, placeholder selection, stale revisions, control registration, menu lifecycle, and dirty-state integration; prove no directive or Markdown-block validation is performed.
- [ ] Manually verify keyboard and pointer opening, item activation, Escape/outside-click closure, focus return, placeholder replacement, toolbar fit at representative laptop/desktop widths, route changes, and the observed native Undo behavior in the supported browser.
- [ ] Run targeted lint, generated Docs/search, internal-link, JSON, and whitespace checks.
- [ ] Update the concise Source editor and authoring syntax authorities, then hand the UI to the user for tactile review without changing the TE-2/TE-7 build contracts.

## Not In Scope

- recognising, validating, projecting, or otherwise acting on a directive during a build;
- a generic directive/plugin registry, user-configurable menu, or automatic discovery of arbitrary comments;
- validating that a directive has an eligible build-time consumer or exact target block;
- locating Markdown tables from a caret/selection, parsing table ranges, or detecting duplicate directives;
- editing attributes after insertion, generating a semantic SVG ID, removing/reordering directives, or converting one directive into another;
- parsing rendered HTML, selecting a table by title/occurrence, or adding controls to rendered tables;
- save, rebuild, Publish, conversion progress, or success/status messages;
- `execCommand`, clipboard manipulation, synthetic key events, fake undo, or a custom editor history;
- a modal, second source toolbar, parallel editor model, rich-text editing, or inline table editor; or
- sub-scope-specific behavior beyond using the same exact target and Source editor contracts.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns delivery order. TE-1 is complete when the two comments can be inserted safely through the existing Source control model while canonical Markdown, ordinary rendering, transfer behavior, Content Detail, SVG preparation, and Publish remain unchanged.
