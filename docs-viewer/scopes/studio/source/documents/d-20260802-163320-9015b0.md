# TE-1 — Source Editor Directive Actions Delivery

## Status And Purpose

Complete. **TE-1.0–TE-1.3** shipped as the first [Table Enhancements](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) delivery, and the user accepted the verified implementation and presentation for closeout on 2026-08-03. TE-1 has no dependency on [TE-2](/docs/?scope=studio&doc=d-20260802-162149-3ba013) or [TE-7](/docs/?scope=studio&doc=d-20260802-160430-34cb3b): inserted comments remain harmless and visually inert until a later consumer chooses to recognise them. [Authoring Directives Concept And Examples](/docs/?scope=studio&doc=d-20260802-160429-69a5f6) owns the source forms and build-time recognition/no-op boundaries; TE-1 owns only convenient insertion.

TE-1 adds one authoring convenience to the existing Manage Source mode: a **🧩** icon pill with the accessible label **Directives**, presented in the style and interaction model of the existing toolbar controls, opens maintained code-owned source snippets. Choosing an item inserts its predefined bytes at the captured source insertion point. The button saves the author from typing; it does not decide whether a build consumer will recognise or accept the inserted text.

## Complete Outcome

The initial **Directives** menu offers:

- **⊞ Table detail**, inserting `<!-- dotlineform:table-detail -->`; and
- **📐 Table to SVG**, inserting `<!-- dotlineform:table-publish format=svg id=table-name -->` and selecting only `table-name` for immediate editing.

The editor inserts the selected snippet on its own line, returns focus to the source textarea, and marks the existing buffer dirty through the ordinary input path. It does not save or rebuild automatically and shows no insertion confirmation message. Before TE-2 or TE-7 ships, Save/Rebuild simply treats the inserted text as an ordinary HTML comment and the table renders normally.

The control appears wherever the existing Manage Source editor is available; it is not filtered by build or publication capability. Editor readiness, busy state, an exact captured insertion range, and unchanged buffer revision are mutation-safety preconditions rather than directive validation. TE-1 does not inspect the document to decide whether the directive is useful, supported, duplicated, correctly associated, or valid for a later consumer.

TE-1.0 may retain at most two cheap line-local affordances if they fall naturally out of insertion: require a blank insertion line, and for the two table snippets check that the immediately following line resembles the start of a Markdown pipe table. These checks are optional placement hints, not validation. If they require a Markdown parser, block-range recognition, table discovery, or significant test machinery, omit them.

## Existing Seams And Expected Size

The current Source editor already exposes main-view controls through the view registry and contribution maps. Its context adapter can capture an insertion range with the current buffer revision, replace that verified range with `textarea.setRangeText`, select a verified inserted placeholder, return focus, dispatch the normal input path, and project busy/disabled control state. The existing Index and sub-scope Actions controls provide the menu interaction and accessibility precedent; TE-1 reuses their presentation behavior without adopting selection-mode document targeting.

The traced exact owners below supersede the earlier broad candidate list; no action-definition or Source-editor implementation changed. Focused tests own exact snippet bytes, guarded insertion, placeholder selection, revision rejection, focus/dirty integration, and menu wiring. They do not need a table parser or directive validator.

TE-1.0 froze the exact files and rough diffs after tracing the current control/menu renderers and insertion adapter; the implemented surface below stayed within that boundary. If later work requires Markdown block parsing, table-range discovery, duplicate-directive analysis, a new editor framework, server round trip, general directive registry, modal workflow, custom undo manager, or hundreds of lines devoted to eligibility, stop for review.

## TE-1.0 Frozen Delivery Contract

### Reused Seams

- `docs-viewer-management-hosted-views.js` owns the Source-mode main-view control definition and order. `docs-viewer-manage.js` composes its renderer, handler, and busy/disabled projection alongside the existing Catalogue-token contribution.
- The shared control-surface host already provides delegated control dispatch, active-mode filtering, labels, disabled state, and stable root reuse. The Directives contribution does not add another toolbar or action registry.
- `source-editor/source-editor.js` already provides the required revision-bound `captureSelection`, `getBufferSnapshot`, `replaceCapturedRange`, `selectCapturedRange`, and focus seams. Its ordinary synthetic `input` event increments the buffer revision and projects dirty state. No Source-editor production change was required.
- The existing shared toolbar-button and Manage Actions menu CSS supply the presentation. The new contribution owns only its two menu items, captured invocation state, close/focus lifecycle, and insertion plan.

### Frozen Control And Insertion Behavior

- The main-view button is the **🧩** toolbar icon pill with the accessible label **Directives**. The menu order is **⊞ Table detail**, then **📐 Table to SVG**.
- The maintained comment bytes are exactly `<!-- dotlineform:table-detail -->` and `<!-- dotlineform:table-publish format=svg id=table-name -->`. The SVG placeholder is offsets 45–55 within its 59-byte comment.
- Opening the menu captures the current selection and buffer revision. A non-collapsed selection supplies its start as the insertion point but is not deleted: the one guarded range replacement inserts the shaped directive before the captured selected bytes and writes those selected bytes back unchanged. This also revalidates the full captured range immediately before mutation.
- Newline shaping is character-local. Insert one leading newline only when the preceding byte exists and is not a newline. At EOF, insert one trailing newline. Before following source, insert only enough trailing newlines to leave two consecutive newlines between the comment and that source. Existing surrounding bytes are not removed or normalised.
- After the one replacement, the actual current buffer snapshot supplies the revision and offsets for the non-mutating final selection. **⊞ Table detail** places the caret after the complete inserted newline shape and before preserved following source. **📐 Table to SVG** selects only the inserted `table-name` bytes computed from the insertion result.
- Blank-line eligibility and immediate-next-line pipe-table hints are omitted. They add no safety to the exact insertion and would begin eligibility behavior that belongs to later consumers. Existing exact, duplicate, malformed, misplaced, prose-adjacent, or unsupported comments are never inspected.
- Success and stale-capture refusal produce no Source or global status message. Both close the menu and return focus to the textarea; stale refusal performs no edit, save, rebuild, or other action.
- The popup uses the existing Actions classes, button/menu roles, native button Tab order, outside-click closure, Escape closure with button focus return, disabled-state closure, and DOM-removal cleanup on route or mode change. It adds no modal or generic menu framework.

### Static Fixture

`<caret>` marks a collapsed insertion point and square brackets mark a selected range. Each case is a direct source-string expectation rather than Markdown recognition.

| case | source before | source after **⊞ Table detail** |
| --- | --- | --- |
| blank line before a pipe table | `Lead\n<caret>\n\| A \|` | `Lead\n<!-- dotlineform:table-detail -->\n\n\| A \|` |
| table starts on the insertion line | `Lead\n<caret>\| A \|` | `Lead\n<!-- dotlineform:table-detail -->\n\n\| A \|` |
| ordinary non-blank prose | `Lead<caret> prose` | `Lead\n<!-- dotlineform:table-detail -->\n\n prose` |
| existing exact or malformed comment | `<caret><!-- existing source -->` | `<!-- dotlineform:table-detail -->\n\n<!-- existing source -->` |
| non-collapsed selection | `Before [nerve] after` | `Before \n<!-- dotlineform:table-detail -->\n\nnerve after` with `nerve` preserved |
| changed buffer revision | any case above | guarded replacement returns `false`; source is byte-identical |
| SVG placeholder | any accepted insertion | only offsets 45–55 of the inserted SVG comment are selected |

The fixture deliberately produces the same insertion around table-like, prose, exact-comment, and malformed-comment source. It requires no Markdown block scan, duplicate analysis, rendered target, or consumer capability.

### Native Undo Observation

On 2026-08-03, the current local Manage Source editor was exercised in the supported in-app Chromium through the existing Catalogue-token `setRangeText` plus synthetic `input` path. The insertion marked the buffer dirty, but `Meta-Z` did not remove the inserted bytes. The temporary unsaved bytes were discarded through **Return to doc** and no source file changed. This is an observed browser behavior, not a universal invariant; TE-1 does not emulate or promise Undo.

## Interaction Contract

The button is one Source-mode main-view control. Its popup is keyboard accessible, closes through the same outside-click, Escape, focus-return, route-change, and disabled-state behavior as the existing Actions menus, and does not introduce a second toolbar or inline table chrome.

The captured Source insertion point is authoritative. The action never falls back to the active rendered table, table occurrence, nearby heading, document title, previous invocation, or first table in the document. It does not search for a target block.

The captured buffer revision and insertion range are revalidated immediately before insertion. The predefined snippet owns its required newline shape. The SVG placeholder selection is computed from the inserted text rather than found later by searching the document.

The browser UI neither parses rendered HTML nor predicts whether a later build consumer will act. Unknown, duplicated, misplaced, or hand-edited directive text is ordinary source and does not need browser validation. Dedicated build consumers own recognition and must fail quickly and cleanly by leaving unsupported source inert.

The edit uses the existing textarea `setRangeText` and input-event seam. TE-1 does not use deprecated `execCommand`, synthesize keyboard events, intercept the clipboard, maintain a fake undo stack, or claim a native Undo guarantee. Any actual browser undo behavior is recorded at TE-1.0 and accepted as native textarea behavior rather than emulated.

## Not In Scope

- recognising, validating, projecting, or otherwise acting on a directive during a build;
- a generic directive/plugin registry, user-configurable menu, or automatic discovery of arbitrary comments;
- validating that a directive has an eligible build-time consumer or exact target block;
- locating Markdown tables from a caret/selection, parsing table ranges, or detecting duplicate directives;
- editing attributes after insertion, generating a semantic SVG ID, removing/reordering directives, or converting one directive into another;
- parsing rendered HTML, selecting a table by title/occurrence, or adding controls to rendered tables;
- save, rebuild, Publish, conversion progress, or success/status messages;
- `execCommand`, clipboard manipulation, synthetic key events, fake undo, or a custom editor history;
- a modal, second source toolbar, parallel editor model, rich-text editing, or inline table editor; or
- sub-scope-specific behavior beyond using the same exact target and Source editor contracts.
