# Dated Export Snapshots

## Outcome

Docs Viewer can write a small, browseable snapshot before significant document or roadmap changes without filling Docs Viewer itself with an archive that later needs organisation and retirement.

The snapshot is rendered static HTML on the external projects drive. It is useful as a visual reference or last-resort manual source of text, but it is deliberately not exact canonical source and has no restore, import, editing, synchronization, or return path.

## Snapshot Selection

Export consumes the exact non-empty checked set from **Index Actions**. Opening that menu uses its existing behavior of explicitly checking the currently displayed document for the common one-document case. After that, checked ids are authoritative: Export does not infer an active, displayed, default, URL, parent, or descendant document.

- The complete checked set writes the complete manage tree to `<scope> - YYYY-MM-DD`. Complete-set classification takes precedence in a one-document scope because the checked ids cannot reveal whether **Select all** was clicked.
- Every other checked set writes to `<scope> selection - YYYY-MM-DD`, including a single checked document when the scope has unselected peers.

These are server-derived labels, not browser modes. A partial selection exports exactly the checked documents; a selected document whose parent is not included becomes a root in the snapshot index.

Folder labels use the local export date and only the minimum filesystem-safe normalization needed for the scope id. The snapshot preserves original document ids inside the non-canonical artifact.

If the destination folder does not exist, confirmation creates it. If it already exists, the only choices are **Replace** and **Cancel**. There is no **Save As** or naming workflow, and apply must never wipe an existing folder before explicit replacement confirmation.

The complete new snapshot is staged before an existing target is replaced. A failed render or write leaves the existing dated snapshot intact.

Because every same-day non-complete selection in a scope shares one dated folder name, each snapshot carries a small provenance record with its source scope, exact selected `doc_id` values, document count, and generation time. The service uses that provenance to guard replacement without expanding the confirmation beyond the document count and destination.

## Boundaries

- Snapshot input is existing generated Docs Viewer payloads, including the manage-visible non-viewable tree; it does not parse or package canonical Markdown.
- Any configured scope shown in `/docs/` may participate when its generated tree and document payloads are readable, regardless of whether its source is public, repo-local, or external-local.
- The export copies no media, download, or interactive-asset bytes. Rendered references retain their existing targets.
- Links between selected documents become local snapshot links. A same-scope link to an unselected document retains its Docs Viewer target rather than becoming a broken local link.
- Every checked selection shares one service contract, destination policy, HTML renderer, and Replace/Cancel boundary.
- Export is removed from the app-level **Actions** menu. Sub-scope report Actions do not offer this workflow.
- Snapshot folders remain user-owned external files. Docs Viewer does not index, list, retain, prune, or manage them as an archive.
- The feature remains separate from Publish, Data Sharing packages, and Copy Subtree To Scope.
