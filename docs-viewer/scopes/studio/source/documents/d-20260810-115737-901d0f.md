# Works Report

## Purpose

Works is the published-Series-first complement to Project State and Projects. Its title follows the public-site vocabulary used by `analysis/works`; its row identity remains exact canonical `series_id`, not `work_id`.

| report | row authority | question answered |
| --- | --- | --- |
| Project State | immediate physical Project folders | Which source folders have no current canonical Series relationship? |
| Projects | current `dotlineform/projects` documents | What documentation exists? |
| Works | published canonical Series | Which published Series have nothing written about them? |

## Complete Outcome

One local-only report in scope `dotlineform` shows one row for every published Series. The Series cell links to the exact Series page on the configured local site preview. The Docs cell links to every current `dotlineform/projects` document whose exact valid subject is either that Series or a published Work currently belonging to that Series. Each document retains the Series or Work subject icon that explains why it covers the row.

A published Series is **written about** when its Docs collection is non-empty. One published Work-subject document is sufficient regardless of how many other member Work IDs have no document. Draft Works do not contribute coverage. A blank Docs cell means the published Series has nothing written about it at either level.

## Feature Contract

- The browser reads the Studio-owned Series search projection and filters exact records with `status: published`; documents and Work membership never create a Series row.
- The browser reads the Studio-owned Work search projection and uses only exact records with `status: published` when expanding Work subjects through `series_ids`.
- The browser reads the current private Projects Manage manifest for document title, exact target, and normalized `authoring_subject`; it does not require a second subject-association read.
- An exact Series subject reaches only its declared `series_id` row.
- An exact published Work subject reaches every published Series currently named in that Work's canonical `series_ids` membership. A draft or unknown Work reaches no row.
- Each document appears at most once in one Series row and retains its exact declared subject kind and identity.
- Folder, None, malformed, conflicting, and unknown subjects enter no row.
- Document titles remain presentation labels, not subject or membership evidence.
- Series and document links use their exact existing activation targets; neither is inferred from a title, filename, report host, selected row, or route state.
- Empty rows remain visible because absence is the report's useful result.
- The report is composed in the browser from current local read projections, is read-only and local, creates no persisted coverage product, and exposes no public report capability.
- Public Catalogue JSON is a downstream delivery projection, not publication authority or a Works report input. Projection drift belongs to a separate Catalogue audit.
- The existing Local Studio read boundary serves the two lookup projections; Works adds no report producer, versioned report response, Docs Viewer service method, or report endpoint.

## Boundary

Works does not identify undocumented individual Work IDs, calculate a completeness percentage within a Series, treat every Work as requiring its own document, read semantic-token mentions, include Folder-subject documents, inspect editorial or public document copies, read public Catalogue aggregate or exact-record JSON, consume public `doc_url[]`, display documentation on public Catalogue pages, change Series membership, mutate document subjects, refresh Project State, or introduce a general relationship/reporting engine.

The report title does not change the canonical distinction between Series and Works and does not make `analysis/works` its source collection. Coverage comes only from exact current subjects in `dotlineform/projects` and exact current Catalogue membership.

Project State currently retains canonical Work/Series relationships without distinguishing draft from published records. Works does not silently change that completed report. If the folder-first question must be restricted to published Series, that is a separate Project State refinement with its own review boundary.
