# Sub-Scope Ordinary Document Import Delivery

## Status And Order

Active as SSO-1. This is the first Import-parity delivery for configured
sub-scopes and must complete before
[Sub-Scope Returned Package Import Delivery](/docs/?scope=studio&doc=d-20260730-102954-1b363f).

It extends the shipped ordinary staged-source Import workflow. It does not add
returned-package recognition or canonical overwrite.

SSO-1 also applies one shared ordinary-Markdown hygiene rule before extending
the destination target: after any registered integrated collection recognizer
has declined the untouched candidate, a well-formed leading front-matter block
is stripped from ordinary Markdown preview and body content without becoming
identity, routing, or overwrite metadata. Top-level and sub-scope ordinary
Import therefore inherit the same normalization.

## Complete Outcome

A local Manage `docs_subscope` report provides one compact 📥 **Import** icon
beside **New** and 🔧 **Actions**.

The control opens the existing Docs Import surface with the mounted
`{ scope, sub_scope }` collection frozen as its exact destination. Supported
ordinary HTML, DOCX, Markdown, text, and one-document Markdown-package sources
retain their existing preview, conversion, media, create-only, and result
semantics while writing the new document into that configured child collection.
Ordinary Markdown front matter is removed before body preview rather than
rendered as a heading.

Success runs only the owning sub-scope rebuild and refreshes the mounted report.
No parent-scope Index, Recent, search, or selection state is used as an
alternative destination.

## Exact Target And UI Contract

- The 📥 button is a sibling report-toolbar control and never enters checkbox
  selection mode or consumes checked IDs.
- The management contribution supplies one validated mounted
  `{ scope, sub_scope }` target. The Import surface displays the configured
  collection label and does not offer a parent-scope fallback.
- Public reports expose no Import control, service probe, or management module.
- Ordinary source discovery and format registration remain shared with
  top-level Docs Import; a second sub-scope file picker or converter is not
  introduced.
- Registered integrated collection recognizers receive untouched staged
  candidates before ordinary Markdown normalization. SSO-1 does not consume or
  strip provenance that a later edited-review-source recognizer owns.
- Activating Import does not infer a target from the displayed detail document,
  URL text, selected parent, staged filename, or most recently used scope.
- Cancel applies nothing and returns focus to the same report toolbar control.
- Success refreshes only the owning report inventory and may display the newly
  created document through its exact child identity.
- Failure retains the same frozen collection for retry and never creates the
  document in the parent scope.

## Create Contract

- Ordinary sub-scope Import remains create-only. The destination allocates a
  new immutable document identity and uses the same atomic create boundary as
  top-level ordinary Import.
- For an unclaimed ordinary Markdown source, a well-formed leading front-matter
  block is stripped before title/body preview and media scanning. A scalar
  `title` may be a fallback when no H1 exists; all other fields are ignored and
  reported, never applied.
- Malformed or unterminated apparent front matter produces a clear diagnostic
  rather than partial stripping. Plain Markdown without front matter is
  unchanged.
- Imported title and converted body are mapped through the existing
  `ImportContent` and per-document planner. The child collection's flatness,
  metadata defaults, and allowed fields are validated before writing.
- A source document never supplies canonical overwrite identity. Existing
  child IDs, filenames, titles, and links do not create a collision prompt.
- Media and supported staged dependencies use the existing format adapters and
  publication plan, confined to destinations valid for the child collection.
- Multi-file selection retains current ordinary Import sequencing and result
  semantics; this delivery does not turn ordinary Import into an atomic
  collection apply.
- The exact child source root is validated before the write. Success invokes
  the existing confined sub-scope rebuild owner and does not rebuild parent
  discovery or public projections.

## Ownership

- The sub-scope management contribution owns the toolbar placement and frozen
  mounted-collection request.
- The document-report management host validates that request and hands it to
  the existing lazy Import controller.
- The shared Import format registry, preview converters, normalized
  `ImportContent`, and per-document create planner retain ordinary source
  behavior.
- The shared management target resolver and sub-scope source mutation/rebuild
  services own exact child confinement and follow-through.
- The existing Import modal owns focus, busy, retry, result, and cancellation
  lifecycle.

## Boundary

In scope:

- one report-toolbar Import entry for a validated configured sub-scope;
- ordinary supported staged-source listing, preview, and create-only apply;
- shared post-recognizer ordinary-Markdown front-matter stripping for both
  top-level and sub-scope destinations;
- exact child source targeting and confined rebuild;
- report refresh and focused service, module, format, and realistic browser
  evidence; and
- reusable scope/sub-scope Import target projection for later registered
  formats.

Not in scope:

- returned JSON/JSONL package listing, collision planning, or overwrite;
- edited Docs Review source-folder recognition;
- changing ordinary top-level Import behavior beyond the shared front-matter
  hygiene rule;
- importing into public reports or unconfigured child directories;
- checked-ID, displayed-document, title, or URL-derived destinations;
- hierarchy, move, delete, or cross-collection writes; or
- all-or-nothing multi-file ordinary Import.
