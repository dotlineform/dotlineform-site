# TE-5 — Diagram Detail View Migration Delivery

## Status And Purpose

Proposed as **TE-5**, sequenced after TE-4 but dependent only on TE-3 establishing the `content-detail` main view, expanded-main panel layout, exact transient targets, public/Manage composition, existing-toolbar ownership, return behavior, and cleanup lifecycle.

The current Diagram Detail action opens a stable SVG or temporary inline SVG resource in a new browser tab. That was a practical way to gain viewport space, not a requirement that diagram inspection leave Docs Viewer. TE-5 moves diagram inspection into the same Content Detail View used by tables while preserving optional new-tab access as a view action.

## Complete Outcome

Every currently supported persistent, public-themed, and managed-inline diagram surface keeps one subtle **Open diagram** component control. Invoking it requests the registered `content-detail` main view with an exact diagram target from the current document mount.

The diagram occupies the expanded main panel and uses the existing `main-view` toolbar for **Back to document** plus an optional **Open in new tab** action when the adapter has a valid stable or temporary target. Returning restores the rendered document and the existing diagram presentation. No new Mermaid renderer, source identity, SVG publication, or theme system is introduced.

## Current Seams And Expected Size

The delivery should reuse `docs-viewer-diagram-detail.js`, the managed inline Mermaid adapter, public themed-diagram adapter, Document Diagrams contracts, the TE-3 target/view/layout owners, and their focused smoke tests.

The indicative shape is 3–6 touched production files, approximately 200–350 production JavaScript/CSS lines and 200–350 focused test lines. TE-5.0 must record the exact diagram resource and cleanup paths plus revised estimates. If migration requires a diagram-only main view, second toolbar, new rendering pipeline, or duplication of the Content Detail lifecycle, stop for review.

## Rough Delivery Steps

### TE-5.0 — Trace And Freeze Diagram Target Adaptation

- [ ] Trace persistent SVG, public themed Mermaid, managed inline Mermaid, Diagram Detail wrapper/control, temporary Blob URL, theme refresh, document replacement, and public/manage import ownership.
- [ ] Freeze the exact diagram target descriptors accepted by Content Detail View, including stable URL and direct rendered-SVG cases.
- [ ] Freeze primary **Open diagram** behavior, optional new-tab toolbar eligibility, current-theme presentation, Back/restoration, stale-mount response, and resource cleanup.
- [ ] Decide whether existing wrapper/control modules are adapted or replaced, and identify the durable authority updates needed when new-tab-only presentation is retired.
- [ ] Record exact files, reused TE-3 seams, rough production/test diff, and any public composition expansion before implementation approval.

**Checkpoint:** maintained fixtures cover persistent SVG, managed inline Mermaid, public light/dark themed Mermaid, missing target, failed inline rendering, theme change, Back, navigation, and optional new-tab action without adding another view or render path. Stop before implementation.

### TE-5.1 — Route Diagrams Into Content Detail View

- [ ] Change the supported diagram component control to request `content-detail(kind=diagram)` through the main-view coordinator rather than treating an external URL as the detail model.
- [ ] Adapt stable persistent/public URLs and direct managed-inline SVG into the frozen exact target contract.
- [ ] Render the diagram through the shared expanded-main body while preserving accessible title, description, scalable geometry, current theme, and normal document ownership.
- [ ] Project **Open in new tab** on the existing main-view toolbar only when the active adapter supplies a valid target.
- [ ] Return to the original rendered document and release temporary resources through the shared view/document lifecycle.

### TE-5.2 — Verify And Transfer

- [ ] Run focused diagram-target, view lifecycle, resource cleanup, theme refresh, public/manage import-boundary, module smoke, lint, and whitespace checks.
- [ ] Manually inspect persistent, inline, and themed diagrams at realistic wide/tall density and supported desktop widths in public and Manage readers; exercise narrow layouts only on public routes, plus light/dark themes, Back, navigation, and optional new-tab behavior.
- [ ] Prove tables retain their TE-3 view and toolbar behavior and that unsupported images/SVG remain ineligible.
- [ ] Update [Document Diagrams](/docs/?scope=studio&doc=d-20260719-123719-fb7565), [Panel Hosts and Control Surfaces](/docs/?scope=studio&doc=d-20260528-224754-964108), and Diagram Detail evidence to describe the unified shipped view and remaining new-tab action.

## Not In Scope

- changing Mermaid source syntax, rendering, sanitization, theming, media tokens, or public projection;
- diagram editing, pan/zoom engines, annotations, export formats, or persisted viewer state;
- treating arbitrary images or page SVG as diagrams;
- changing static table behavior delivered by TE-3 or Manage tools delivered by TE-4;
- a diagram-specific panel, main view, toolbar, modal, or route; or
- preserving the old new-tab control as an alternate primary detail workflow.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns sequencing. [Content Detail View Concept And Architecture](/docs/?scope=studio&doc=d-20260802-150246-bb3f88) owns the shared static-source and panel/view contracts.
