# TE-4 — Diagram Migration

## Status And Purpose

Complete. **TE-4.0** through **TE-4.2** shipped as the fourth [Table Enhancements](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) delivery. The user accepted the verified persistent and inline diagram presentation, stable and Blob new-tab behavior, and icon-only pill action for closeout on 2026-08-04.

Before TE-4, Diagram Detail opened a stable SVG or temporary inline SVG resource in a new browser tab. That was a practical way to gain viewport space, not a requirement that diagram inspection leave Docs Viewer. TE-4 moves diagram inspection into the same Content Detail View used by tables while preserving optional new-tab access as a view action.

## Complete Outcome

Every currently supported persistent, public-themed, and managed-inline diagram surface keeps one subtle **Open diagram** component control. Invoking it requests the registered `content-detail` main view with an exact diagram target from the current document mount.

The diagram occupies the expanded main panel and uses the existing `main-view` toolbar for **Back to document** plus an optional **Open in new tab** action when the adapter has a valid stable or temporary target. Returning restores the rendered document and the existing diagram presentation. No new Mermaid renderer, source identity, SVG publication, or theme system is introduced.

## Current Seams And Scope Guard

The likely blast radius is the existing diagram-detail adapters and resource cleanup plus the TE-2 target, view, layout, and toolbar extension seams across public and Manage composition.

If implementation requires a diagram-only main view, second toolbar, new rendering pipeline, new diagram identity, or duplication of the Content Detail lifecycle, stop for review and split the result.

## TE-4.0 Sanity Note

Completed on 2026-08-04. The feature parent is in progress, TE-1 through TE-3 are complete, and its delivery order names TE-4 as the next bounded outcome, so the scheduling dependency is satisfied.

The intended result fits the shipped broad owners. The diagram-detail adapter already owns supported persistent, public-themed, and managed-inline diagram decoration plus stable or temporary new-tab resources. The public theme adapter owns selection of the active prepared light/dark URL, the managed inline Mermaid adapter owns the current rendered SVG and its theme refresh, and the rendered-document controller coordinates their mount and release lifetimes. TE-2 already supplies the exact immutable target context, expanded-main layout, existing `main-view` toolbar, Back/restoration behavior, and presentation cleanup required for the migration.

One bounded seam needs extension: the shared Content Detail lifecycle currently delegates presentation mounting directly to the table adapter. TE-4 may select the explicitly composed table or diagram adapter from the exact target `kind`; that is a focused extension of the existing view, not authority for a generic content-adapter registry. Persistent diagrams retain their stable served target, public-themed diagrams retain the active prepared variant, and managed-inline diagrams retain the exact adapter-owned rendered SVG while any Blob URL remains a secondary new-tab resource.

The broad blast radius is exact diagram target registration and invalidation; public theme and managed-inline refresh/resource lifetime; Content Detail adapter selection and presentation lifecycle; existing-toolbar control contribution; document restoration and navigation cleanup; public/Manage composition; and focused target, theme, cleanup, shared-table compatibility, and import-boundary evidence where those owners change. Deliverables remain shared-view entry for every supported diagram surface, accessible scalable presentation, Back/restoration, optional valid-target new-tab access, focused verification, and concise durable authority updates.

The main benefit is one consistent in-app inspection model for tables and diagrams while keeping existing diagram rendering and publication ownership intact. The main risks are stale diagram targets, a theme refresh diverging between document and detail presentation, early revocation of a temporary resource, incomplete focus/scroll restoration, and management runtime entering the public graph. Exact mount-bound targets, adapter-owned refresh and release, the existing hosted-view lifecycle, and explicit route composition bound those risks. If implementation needs a diagram-specific view or toolbar, another renderer or identity, a generic registry, or duplicated lifecycle state, pause and split before widening TE-4.
