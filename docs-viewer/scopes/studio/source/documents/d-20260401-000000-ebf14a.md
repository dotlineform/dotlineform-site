# Catalogue Works

## Live Report

[Open the Catalogue Works report](/docs/?scope=dotlineform&doc=d-20260810-222148-99daec). It sits with the other local `dotlineform` reports; this Studio page remains the durable ownership and extension guide.

The Studio home **works** entry resolves this target through `app.runtime.sites.docs_viewer.base`. The server uses `DOCS_VIEWER_BASE_URL` when supplied and otherwise constructs the Docs Viewer origin from `DOCS_VIEWER_HOST` and `DOCS_VIEWER_PORT`, so the link opens the Docs Viewer service instead of inheriting Studio's port.

The report loads every canonical Work with `status: published` but shows rows only after a Work or Series search. Results retain exact Work identity, every Series membership, year, and curator-only storage context in one seven-column semantic table. Work, Year, Title, Series, and Storage remain the five embedded and sortable columns. Medium type and Medium caption are present in the same live table but appear only in Expanded Report View. **Copy table** exports the current sorted result as five-column TSV while embedded and seven-column TSV while expanded.

## Data And Ownership

The local report registry maps `catalogue_works` to its exact allowlisted loader, and `docs-viewer/runtime/js/reports/catalogue-works-report.js` reads the browser-safe Local Studio Catalogue API keys `catalogue_works` and `catalogue_series`. Canonical Work rows already own `storage_location`, `medium_type`, and `medium_caption`; expansion added no API, schema, generated payload, or parallel data read. The report does not read the generated public Catalogue or treat a public projection as its application model.

The report module owns validation, published-only selection, Work/Series search, five sortable columns, exact public-preview links, one seven-column render, presentation-aware clipboard projection, and contained unavailable or invalid states. Editing remains in the [Catalogue Work Editor](/docs/?scope=studio&doc=d-20260422-000000-45a776) and [Catalogue Series Editor](/docs/?scope=studio&doc=d-20260422-000000-ec1a69). [Catalogue Drafts](/docs/?scope=studio&doc=d-20260418-000000-16bf7e) remains the recovery and maintenance route for unfinished records.

## Expanded Presentation

After its canonical inputs and first complete render succeed, the module returns the exact live semantic table through the optional `expandedPresentation` handle. One frozen ordered column model supplies stable ids, labels, and `both` or `expanded` visibility; headers and body cells use the same seven identities. Manage moves the existing report root into Content Detail, so search, sorting, rows, links, Copy table, event listeners, and route state remain on one report instance with no second data request or renderer.

Manage alone supplies accessible pointer and keyboard resize handles. One direct `colgroup` keeps headers and rows aligned through valid notified rerenders, while a mismatched header/body model fails closed. Widths exist only for the active expanded presentation: **Reset widths**, Back, or document navigation removes them, and reopening starts from the natural layout. Widened output scrolls inside the expanded viewport. Source, registry JSON, URLs, browser storage, canonical data, and generated payloads retain no width state.

## Extension And Weak Spots

- Add a report column only when the accepted canonical local read owns its value and its stable id, label, `both` or `expanded` visibility, sorting participation, and active TSV projection are explicit.
- Add curator-only context through a Studio-owned read, never by expanding or treating public payloads as an application model.
- Keep the report search-required: empty search reveals no rows, and a failed current read never retains an older result.
- Search continues to match Work and Series only; an expanded-only value does not silently broaden that contract.
- Keep `catalogue_works` local-only. Public report metadata, loaders, data, and CSS do not expose it.
