# Tag Vocabulary Import Retirement

## Result

`/studio/tag-registry/` and `/studio/tag-aliases/` maintain individual canonical
tags and aliases without bulk vocabulary-import capabilities.

New Tag and New Alias use first-class create operations. Their import uploads,
add/merge/replace modes, APIs, configuration, and executable implementations are
removed after both create paths are proven.

## Why

Bulk import was useful when establishing the current registry and aliases. It is
now a high-blast-radius way to replace canonical vocabulary and can silently
discard new fields as those records evolve.

Retiring both vocabulary imports also gives the downstream
[Flat Tag Identity](/docs/?scope=studio&doc=d-20260727-110004-ab0433)
migration one ordinary create/edit contract rather than import-specific merge
and replacement semantics. Tag-document linking follows that identity
migration.

## Boundary

- Preserve the current canonical tag IDs, registry records, and alias records;
  this feature has no data migration.
- Preserve New Tag, New Alias, edit, delete, promotion/demotion, direct local
  writes, activity evidence, atomic replacement, and the supported manual patch
  fallback.
- Remove the tag-registry and tag-alias import routes rather than retaining
  redirects, aliases, proxies, or compatibility adapters.
- Offline assignment-session retirement is owned separately by
  [Offline Tag Assignment Session Retirement](/docs/?scope=studio&doc=d-20260726-215805-ecf8a4).
- Do not remove catalogue workbook import or unrelated import infrastructure.
- Do not implement tag-document association or change the tag registry schema.

## Delivery Order

1. [First-class Tag Creation Delivery](/docs/?scope=studio&doc=d-20260726-214250-55bc9d)
   removes the New Tag workflow's dependency on registry import.
2. [First-class Alias Creation Delivery](/docs/?scope=studio&doc=d-20260726-214935-063d1d)
   removes the New Alias workflow's dependency on alias import.
3. [Bulk Tag Vocabulary Import Removal Delivery](/docs/?scope=studio&doc=d-20260726-214250-9d3fe6)
   removes both now-unneeded bulk capabilities and their executable surfaces.

The removal delivery depends on both create deliveries. Each remains proposed
until explicitly promoted through the Roadmap workflow.

## Durable Destination

Shipped behavior belongs in
[Tag Registry](/docs/?scope=studio&doc=d-20260331-000000-4519a5) and
[Tag Aliases](/docs/?scope=studio&doc=d-20260331-000000-519b1e).
[Tag Source Data](/docs/?scope=studio&doc=d-20260419-000000-86255c) receives
only any lasting source-schema or write-boundary consequence.
