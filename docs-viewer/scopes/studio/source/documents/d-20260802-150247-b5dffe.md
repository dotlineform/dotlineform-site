# TE-3 — Public Static Content Detail View Delivery

## Status And Purpose

Proposed as **TE-3**, after [TE-2](/docs/?scope=studio&doc=d-20260802-162149-3ba013) projects exact table-detail eligibility from canonical authoring intent. [Content Detail View Concept And Architecture](/docs/?scope=studio&doc=d-20260802-150246-bb3f88) owns the panel/view integration, exact-target, expanded-layout, toolbar, public-composition, and static-source boundaries implemented by this delivery.

The delivery extends the existing shared main hosted-view model and proves it with ordinary rendered Markdown tables in both public and Manage Docs Viewer. It does not add a modal table application, change Markdown source, or introduce managed table tools.

## Complete Outcome

Every Markdown table carrying the projected `data-docs-content-detail="table"` marker in a public or Manage rendered document has a subtle **Open table** control. Unmarked tables remain ordinary. Invoking the control requests the registered `content-detail` main view with the exact current document target and table occurrence.

The existing main panel expands through panel-layout projection, the existing main-view toolbar provides **Back to document** and the presentation label, and the table view provides natural column sizing, a sticky header row, a sticky first column, and one unified horizontal/vertical viewport. Leaving restores the prior rendered-document and panel context.

TE-3 does not resize columns, copy or export data, or persist view state. Dynamic report lists and Review composition remain unchanged.

## Current Seams And Scope Guard

The likely blast radius is the shared main-view and panel-layout lifecycle, a Markdown-table target adapter, table presentation CSS, and explicit public/Manage composition. TE-2 remains the eligibility owner and TE-4 remains the Manage-tools owner.

If implementation requires a new shell, toolbar host, global registry, route model, table identity scheme, or Manage dependencies in the public composition, stop for review and split the result.

## Rough Delivery Steps

### TE-3.0 — Confirm Scope And Delivery

- [ ] Sanity-check the proposed `content-detail` extension against the current hosted-view, panel-layout, document-mount, and app-composition model; resolve only contradictions that would change the outcome.
- [ ] Confirm the broad blast radius across shared view/layout lifecycle, exact table targeting, static table presentation, and public/Manage composition.
- [ ] Confirm the deliverables: shared view entry and restoration, exact TE-2 table targeting, bounded static presentation, focused lifecycle/composition evidence, and concise durable owner updates.
- [ ] Stop for review if the result crosses the scope guard above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, broad owners, deliverables, and stop condition. Stop before implementation approval.

### TE-3.1 — Extend Main View And Panel Layout

- [ ] Register one public-safe `content-detail` main hosted view through the existing code registry and explicit public/Manage app composition.
- [ ] Extend hosted-view requests with a bounded immutable target context and lifecycle cleanup without exposing broad runtime state.
- [ ] Extend view state and panel layout with the named expanded-main projection, preserving and restoring prior index and info state through one detail session.
- [ ] Register Back and a presentation label on the existing `main-view` surface, with live state supplied by the active content-detail owner.
- [ ] Make document/scope navigation and replaced mounts invalidate the active target through existing route and document lifecycle owners.
- [ ] Prove search, Recent, source mode, metadata Info, and ordinary rendered-document controls retain their current view/mode behavior in each applicable app kind.

### TE-3.2 — Add The Markdown Table Adapter

- [ ] Query and decorate only tables carrying the exact TE-2 eligibility marker in the accepted rendered-document mount before dynamic extras, using a subtle accessible component control.
- [ ] Supply the exact table target to `content-detail` without reselecting from title, header text, URL, displayed row, or another table.
- [ ] Have the table adapter clone and normalize the accepted semantic table into one bounded two-axis viewport with natural widths, sticky header and first column, correct top-left layering, and ordinary link/text behavior; the generic view must not rebuild table markup or parse Markdown.
- [ ] Preserve the static presentation contract: no column resizing, Reset, clipboard action, download, or persisted viewer state.
- [ ] Release transient target, scroll, and event state on Back, navigation, mount replacement, or view disposal.

### TE-3.3 — Verify And Transfer

- [ ] Run focused checks for the changed view/layout lifecycle, exact table target, and public/Manage composition boundary; choose the lowest layer that proves each implemented contract.
- [ ] Manually review one representative wide/long table in public and Manage desktop readers, plus the public narrow case, covering entry, scrolling, sticky intersections, Back, and document navigation.
- [ ] Exercise ordinary document and dynamic-report paths only where the implementation touched their shared owner.
- [ ] Update only the durable panel, toolbar, or table-presentation owners whose shipped contract changed.

## Not In Scope

- column resizing, Reset, and Copy as CSV, which belong to TE-4;
- diagram migration, which belongs to TE-5;
- Review route composition;
- more than one frozen column, user-selected frozen columns, or persisted widths;
- sorting, filtering, grouping, row actions, selection, editing, formulas, charts, or virtualization;
- clipboard or download export;
- stable table identity or direct URLs to table detail state;
- raw application/report tables mounted after the rendered document;
- automatic eligibility based on table width, height, overflow, row count, heading, or viewport; or
- a second panel, toolbar, modal, route shell, or view-state owner.

The [Table Enhancements feature](/docs/?scope=studio&doc=d-20260802-150245-4e7f85) owns sequencing. TE-3 table integration begins only after TE-2 supplies the exact eligibility marker. TE-4 and TE-5 begin only after the shared view target, layout, toolbar, return, public composition, and cleanup contracts work independently with marked tables. TE-5 is sequenced after TE-4 but does not technically depend on it.
