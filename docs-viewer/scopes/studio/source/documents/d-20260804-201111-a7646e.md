# SSP-0.2 — Focused Projects Subject Assignment Checkpoint Evidence

## Outcome

The local Manage Projects detail toolbar now exposes **Assign subject** only when its resolved browser descriptor declares the `authoring_subject` group. The focused modal loads the exact source revision and current Projects subject, offers None or Folder, confirms one mutation, contains validation or service errors, and refreshes the same `{scope, sub_scope, doc_id}` detail after success. Cancellation performs no mutation or refresh.

The new management mutation accepts one exact confirmed field-group request. It resolves the configured sub-scope definition, requires an exact declared group identity and field set, applies the existing Projects customisation normalizer and shared structured local-target resolver, checks the revision both while planning and immediately before the atomic write, and rebuilds the exact sub-scope projection. Absolute paths and local `file:` URLs become portable relative `folder_path` values; invalid, marked-up, and outside-base inputs are rejected.

Projects no longer contributes a custom editor to **Edit metadata**. The generic metadata service rejects fields reserved by any declared assignable group while retaining universal metadata and independently configured customisation owners. Info remains a passive read projection.

## Evidence

- Focused mutation tests prove exact schema and capability resolution, file-URL normalization, outside-base and invalid input rejection, Folder assignment, None clearing, stale revision conflict, race-at-write protection, atomic source replacement, and targeted Projects rebuild.
- Sub-scope report smoke proves capability-gated action registration, exact request and refresh targets, current-state initialization, cancellation, asynchronous error containment, successful assignment, generic editor removal, and Analysis action absence.
- Manage service smoke proves the exact browser-client route and preserves the existing metadata workflow; modal-focus, metadata-Info, router, and public-boundary checks pass.
- The Projects builder dry-run reports no projection drift. Explicit JavaScript and Python lint, Python compilation, route/config validation, and `git diff --check` pass.

## Independent Review

Shared and server mutation code contains no Projects collection-name availability branch. The generic server resolves only the configured group declaration and exact field names; Projects-specific code owns the None/Folder UI and `folder_path` response validation. Public configuration and runtime imports remain isolated from the management action and mutation client.

SSP-0.3 remains unstarted. It owns the full proportional check profile, unavailable-service and source-context verification, final independent review, and durable documentation transfer to Info, Management Operations, Projects ownership, and SSP-1.
