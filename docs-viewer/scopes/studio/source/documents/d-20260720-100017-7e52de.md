# Scope Media Report Delivery

## Status And Purpose

This is a **proposed** delivery. Its specification may change after a short UI trial, and implementation does not begin until the first [Media Sources](/docs/?scope=studio&doc=d-20260812-102047-a3c9e7) outcome supplies the small source-evidence seam.

## Complete Outcome

One local, read-only Scope Media report opens with one configured scope selected and presents two directions over the same joined data:

- Documents lists exact parent and sub-scope documents with referenced-media count, total bytes, and source/published gap counts; selecting a document shows its media.
- Media lists logical published-media identities with type, byte size, reference count, published state, and source state; selecting an item shows its referencing documents.

The report distinguishes referenced, unreferenced, published-missing, no-source-recorded, recorded-source-missing, and provider/source-root-unavailable states without declaring deletion eligibility or attempting repair.

## SMI-1 — Joined Read Model

- [ ] Extend the existing provider-independent inventory with exact parent/sub-scope document identity and the Media Sources evidence join.
- [ ] Aggregate media count and bytes per document and exact referencing documents per media identity.
- [ ] Return the small evidence-state vocabulary needed by the accepted UI.
- [ ] Keep credentials, absolute roots, raw provider exceptions, and filesystem authority server-side.
- [ ] Treat missing and unavailable evidence as contained row/report states rather than verification failures.

## SMI-2 — Read-Only Report

- [ ] Register one local report-backed document and focused report module.
- [ ] Add the accepted Documents and Media views, scope selection, minimal filtering/search, selected detail, and explicit refresh.
- [ ] Offer only safe read actions already justified by the UI, such as copy logical reference and open/download.
- [ ] Keep the report and its local data seam unavailable to public routes.
- [ ] Manually review realistic Dotlineform density, long identities, empty results, and unavailable source/provider states.

## Likely Owners To Inspect

This is a broad owner map, not a fixed file or test plan:

| boundary | likely owner |
| --- | --- |
| Published objects and references | existing `docs_media_inventory.py` service |
| Recorded original association | Media Sources evidence owner established by its first delivery |
| Local response | existing Docs management read service and route registration |
| UI host | report metadata, one Studio report document, and one focused Manage report module |
| Presentation | existing report/list/table styles, extended only after the UI trial |

## Verification Stance

Use the smallest checks that protect the actual seams:

- focused pure/service cases for parent and sub-scope reference attribution, per-document byte totals, reverse references, no-source-recorded, and missing states;
- one direct read-contract test when the response crosses the local HTTP seam;
- one narrow module/loader check only if registration cannot be proved below the browser; and
- manual UI review for density, switching, selected detail, copy, focus, layout, and general workflow feel.

Do not add a broad smoke profile, duplicate public-isolation suites, or permanent browser choreography tests. Reuse an existing durable boundary check when one already proves that Manage-only report modules and local APIs stay out of public entrypoints.

## Not In Scope

- Media mutation, source association, source repair, replacement, relinking, deletion, or automatic orphan cleanup.
- Hashing, source/published byte comparison, background jobs, caches, thumbnails, OCR, content indexing, or archive expansion.
- Provider migration, nested published identities, multiple active destinations, or [Media Publication Check](/docs/?scope=studio&doc=d-20260812-114603-9706aa) behavior.
- Rollback copies, rollback actions, automatic retry, recovery orchestration, or transaction frameworks.
- A generic report plugin, schema-driven dashboard, or new management route unless SMI-0 first demonstrates a concrete host failure.

## Completion Evidence

- Representative parent and sub-scope documents show the correct media identities and byte totals.
- Each media identity shows its exact referencing documents and truthful published/source state.
- The report opens with the intended scope selected and remains readable in manual review.
- The local read seam and report module remain absent from public entrypoints through the smallest existing or focused boundary evidence.
- [Reports](/docs/?scope=studio&doc=d-20260513-105343-6de36b) and [Media And Asset Handling](/docs/?scope=studio&doc=d-20260514-184303-7914e2) receive only the stable shipped contract at closeout.

No implementation begins from this document until SMI-0 and the Media Sources prerequisite are accepted.
