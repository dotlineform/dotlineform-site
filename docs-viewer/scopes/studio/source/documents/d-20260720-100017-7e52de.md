# Docs Media Report Delivery

## Status And Purpose

This is a **proposed, not-started** delivery. The first-report product contract is approved in [Docs Media Report Concept](/docs/?scope=studio&doc=d-20260720-100017-e094d8), but no checkpoint, code, report registration, service route, host document, or generated product has started.

## Complete Outcome

One manage-only **Docs Media** report document in the Dotlineform scope uses the [Project State](/docs/?scope=dotlineform&doc=d-20260805-155400-4c341f) list format to show one row per distinct exact ready-media or registered build-source file returned by the selected configured parent scope's live storage listing. Its only columns are sortable **Type**, **File name**, and **Documents**. Type displays the configured ready-media or build-source type; File name displays the relative identity and reveals its exact role-specific external-workspace target in Finder. Each Documents cell contains exact `/docs/` links directly associated with that identity and is blank when the file is unreferenced. Its toolbar contains a scope selector, refresh pill, and search across file names and document titles. Referenced identities absent from the live listing do not appear; a separate future **Media Broken Links** report will own those.

## DMR-1 — Exact Media Rows

- [ ] Produce one row for each distinct `{scope, media_type, identity}` returned by the live listing of configured ready-media and build-source locations.
- [ ] Collect distinct exact document title and Manage URL entries directly associated with each row, deduplicating repeated occurrences only within the same document and never inferring identity from title, route, selected row, report context, or a same-basename derived output.
- [ ] Return separate exact `media_type` and relative `identity` values plus the confined role-specific Projects-relative local target for each listed file; `build-source/mermaid/<identity>` returns Type `mermaid`.
- [ ] Include existing unreferenced ready-media and build-source files with no document entries; do not materialize rows from referenced identities absent from the live listing.
- [ ] Keep absolute paths, credentials, raw provider exceptions, retained-original evidence, and filesystem authority server-side.

Stop after this checkpoint for review before the report UI.

## DMR-2 — Project State-Format List

- [ ] Register one local Docs Media report and one report-backed host document in the Dotlineform scope.
- [ ] Render the Project State list-backed table with only sortable **Type**, **File name**, and **Documents** columns, defaulting to Type then File name ascending and using the exact complementary fields as deterministic tie-breakers.
- [ ] Add a toolbar containing only a configured-scope selector defaulting to Dotlineform, a refresh pill, and the Project State-style search field with clear control; persist the scope as `report_scope`.
- [ ] Make refresh rerun the selected scope's live ready-media and build-source listing plus document join while preserving and reapplying current search and sort state.
- [ ] Filter loaded rows by case-insensitive substring match against the displayed File name or any document title, excluding Type from search and using a contained no-match state distinct from an empty scope.
- [ ] Render Type as plain configured-id text; reveal each live-listed ready-media or build-source file from its File name link through the current local-target action; stack exact direct document links and leave an unreferenced file's Documents cell blank.
- [ ] Keep the report module and local read seam absent from public routes.

## DMR-3 — Verify And Transfer Ownership

- [ ] Manually review representative Dotlineform density, all configured media types, nested relative identities, several documents for one file, repeated document titles, blank unreferenced cells, long file names, scope changes, refresh, file-name and document-title searches, all three sorts, empty and no-match results, exact document navigation, Finder reveal, and omission of missing referenced identities.
- [ ] Run only the focused read-model, direct response, registration/module, public-isolation, changed-source lint, docs-build, and `git diff --check` evidence warranted by the implemented seams.
- [ ] Transfer the stable report contract to Reports and Media And Asset Handling, present the closeout list, and stop before any second media report or management action.

## Verification Stance

Use the smallest checks that protect the actual seams:

- focused pure/service cases for live ready-media and build-source row grouping, Mermaid type/target projection, parent and sub-scope attribution, same-document deduplication, exact document URLs, blank unreferenced rows, no inferred source/output relationship, and omission of missing referenced identities;
- one direct read-contract test when the response crosses the local HTTP seam;
- the smallest existing report module/loader check for scope selection, refresh, two-field search, sorting, stacked links, blank cells, empty states, and registration; and
- manual UI review for density, refresh, search, sorting, scope switching, navigation, Finder activation, and general workflow feel.

Do not add a broad smoke profile, duplicate public-isolation suites, or permanent browser choreography tests. Reuse an existing durable boundary check when one already proves that Manage-only report modules and local APIs stay out of public entrypoints.

## Not In Scope

- Aggregate counts, byte totals, additional filters, detail views, grouping controls, copy controls, or retained-original evidence.
- Missing-reference rows, broken-link diagnosis, or delivery of the separate future Media Broken Links report.
- Inferred build-source-to-output relationships or copying an output file's document references onto its build-source row.
- Media mutation, source association, source repair, replacement, relinking, deletion, publication, provider movement, or automatic orphan cleanup.
- Hashing, byte comparison, background jobs, caches, thumbnails, OCR, content indexing, or archive expansion.
- A registry, semantic media target, nested managed identity, multiple active destinations, or [Media Publication Check](/docs/?scope=studio&doc=d-20260812-114603-9706aa) behavior.
- Rollback copies, rollback actions, automatic retry, recovery orchestration, or transaction frameworks.
- A generic report plugin, schema-driven dashboard, second reference scanner, or parallel local-file activation path.

## Completion Evidence

- Every ready-media and registered build-source file returned by the live listing produces one exact grouped row; absent referenced identities do not.
- Existing ready-media and build-source files reveal the selected object in Finder; unreferenced files remain visible with a blank Documents cell.
- Every referencing document link preserves exact parent and sub-scope identity, including repeated titles.
- The report opens in Dotlineform with Dotlineform selected, changes scope through the selector, refreshes the live listing, searches file names and document titles, and sorts all three columns deterministically.
- The local read seam and report module remain absent from public entrypoints through the smallest existing or focused boundary evidence.
- [Reports](/docs/?scope=studio&doc=d-20260513-105343-6de36b) and [Media And Asset Handling](/docs/?scope=studio&doc=d-20260514-184303-7914e2) receive only the stable shipped contract at closeout.

No delivery checkpoint or implementation has started. DMR-1 requires separate explicit approval.
