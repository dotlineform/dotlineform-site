# Sub-Scope Detail Delete Delivery

## Status And Order

Delivered as SSI-2, after
[Sub-Scope Report Contribution Delivery](/docs/?scope=studio&doc=d-20260728-115825-41e819).
SSI-2.1 through SSI-2.3 are complete. The exact child service mutation has a
capability-aware manage-only detail workflow, confirmation, local inventory
projection, replacement-history repair, recovery refetch, and maintained
destructive route evidence against temporary configured sources.

SSI-2 is the first new user workflow in the feature. It proves the detail
toolbar, exact-target mutation, local rebuild, route repair, and inventory
reconciliation path before selection and package preparation widen the collection
surface. [SSI-3](/docs/?scope=studio&doc=d-20260728-115825-ae1461) remains
proposed and has not started.

## Complete Outcome

Manage mode shows **Delete** in the detail toolbar on the same header row as
Back only after `docs_subscope` has validated and rendered one listed document.

Delete previews and, after explicit confirmation, removes exactly:

```text
{ scope, sub_scope, doc_id }
```

It rebuilds only the affected child collection, removes `subdoc` from the URL
with replacement history, reconciles the management inventory, and returns to
the list. Public mode has no button and does not load the controller, delete
client, modal, or mutation workflow.

## Change Classification

| kind | work |
| --- | --- |
| shipped and retained | main-index Delete workflow and confirmation patterns; managed target resolver; sub-scope builders; report detail validation |

This is not sub-scope lifecycle deletion and must not reuse the capability that
deletes an entire configured sub-scope.

## UI And Target Contract

- The button exists only in a validated detail state.
- Loading, failed, unknown, unlisted, list, and unmounted states have no Delete
  target.
- The button label, confirmation title, preview rows, and focus return identify
  the exact document.
- Confirmation defaults focus to Cancel.
- Cancel leaves the detail and URL unchanged.
- The workflow never derives a target from the URL, selected parent document,
  title, focused row, or Tag Registry association.
- Normal success emits no redundant status message; blockers, stale state,
  unavailable data, and errors remain visible.

The Delete implementation is manage-owned and lazy. The shared report only
provides the validated target and toolbar host.

## Service And Mutation Contract

Preview and apply retain one exact normalized target. Apply re-resolves the
source after confirmation and rejects a stale or changed target before writing.

For a sub-scope document:

- resolve only the configured one-level child source root;
- require source filename/front-matter identity agreement;
- reject multiple IDs and hierarchy expansion;
- delete only that one canonical Markdown source;
- never inspect or alter the parent scope's default document;
- rebuild the child manifest and by-ID projection;
- do not rebuild the parent `index-tree`, Recent, or global search;
- retain `scope`, `sub_scope`, and `doc_id` in preview, result, and activity;
  and
- never read or update Studio JSON.

The existing parent-scope Delete contract remains unchanged. Shared mechanics
must not force parent hierarchy/default-document semantics into the flat child
collection.

There is no sub-scope search builder or child search output in the shipped
configuration. The sub-scope rebuild helper runs only the child document
builder, and its service-used `--skip-browser-config` flag is valid only with a
sub-scope build. Adding a child search subsystem is not part of Delete; future
sub-scope search adoption belongs to the overall Docs Viewer search surface.

## Independent Ownership

An external reference is not a blocker. Deleting a tag document may leave a
stale Tag Registry `doc_id`; that is allowed by
[Independent Canonical Documents](/docs/?scope=studio&doc=d-20260728-113139-95a885).

Preview and apply use exact `doc_id`; title is display data and does not
participate in mutation validation.

The parent document that loads `docs_subscope` is only a presentation host.
Ordinary parent-scope Delete may remove that document under the existing parent
hierarchy contract, but it does not delete the registered report module,
configured sub-scope, or any child document. A configured child with no report
host and a registered report module with no loading document are both valid.

## In Scope

- One manage-only Delete button in the validated detail header.
- Capability-aware availability and busy state.
- Write-free preview, explicit confirmation, stale-target revalidation, and
  exact apply.
- Confined source deletion and targeted child rebuild.
- URL replacement, detail teardown, inventory reconciliation, and list return.
- Exact-target identity, cancel, failure, and retry behavior.
- Focused client, service, mutation, activity, report-controller, public
  isolation, and realistic UI evidence.

## Not In Scope

- Bulk or checkbox-backed Delete.
- Deleting the report parent, Tag Registry record, tag alias, or configured
  sub-scope.
- Cascade, synchronization, association repair, or delete prevention based on
  external references.
- Choosing or navigating to a replacement document.
- Parent index reload or sidebar selection change.
- Undo, Trash, archive, or filtering.

### Request Boundary

The existing endpoints remain the mutation family. Their request shapes become
a strict union:

```text
parent preview: { scope, doc_ids }
parent apply:   { scope, doc_ids, confirm: true }

child preview:  { scope, sub_scope, doc_id }
child apply:    { scope, sub_scope, doc_id, source_revision, confirm: true }
```

The parent branch and responses do not change. Presence of `sub_scope` selects
the singular child branch, whose allowed keys are exact. `doc_ids`, `tag_id`,
association data, fallback IDs, and other extra fields are rejected rather
than ignored.

### Preview And Result

Child preview returns:

```text
operation: preview
target: { scope, sub_scope, doc_id }
scope, sub_scope, doc_id
title
source_revision: sha256:<canonical source bytes>
allowed, blockers, warnings
delete_count: 1
delete_documents: [{ doc_id, title, path }]
generated_outputs: [child manifest rebuild, exact by-ID removal]
```

Confirmed apply repeats the exact target, revision, deleted source path,
`deleted_doc_ids: [doc_id]`, `delete_count: 1`, child rebuild diagnostics, and
summary. It carries no parent hierarchy, descendant, default-document, Studio,
or external-association fields.

A failed rebuild response repeats the target and reports
`source_restored`, `recovery_rebuild`, and `retry_safe`; it never presents a
failed attempt as a completed deletion.

### Stale Proof

Preview hashes the resolved canonical Markdown source. Apply:

1. normalizes the strict child request;
2. re-resolves the configured child and exact direct-child source;
3. rechecks filename/front-matter identity;
4. compares the current source revision with the confirmed preview revision;
5. rejects missing, moved, mismatched, unconfigured, or changed source before
   writing; and
6. only then plans one source deletion.

A stale revision is a conflict, not a fresh implicit preview. The browser keeps
the detail visible and requires a new preview. Confirmation never authorizes a
different current source merely because the same `doc_id` still resolves.

### Rebuild And Failure Boundary

The committed mutation removes one Markdown source under the configured child
root, using the existing child watch-suppression owner, then runs:

```text
build_docs.py --scope <scope> --sub-scope <sub_scope> --write --diagnostics \
  --skip-browser-config
```

That builder reconciles the child manifest and removes the stale exact by-ID
payload. SSI-2.1 adds the explicit service-used browser-config suppression and
removes the separate parent-search command, so this path does not write the
parent index tree, Recent, parent search, public projection, or browser
configuration.

The singular source unlink is atomic. If the child builder fails, the service
atomically restores the exact confirmed source bytes, reruns the same confined
child builder to reconcile derived outputs, and returns a structured error
without activity success. The response states source restoration and recovery
rebuild outcomes. A restored source keeps the same revision receipt, so retry
repeats the same exact-target validation; no broad repair or parent rebuild is
introduced.

### Test-Owned Fixture Matrix

| case | fixture expectation |
| --- | --- |
| ordinary | one synthetic child source and a sibling; only the target source and by-ID payload disappear |
| missing | exact child source absent; preview/apply reject without writes |
| mismatched | filename `doc_id` differs from front matter; resolver rejects |
| unconfigured child | valid-looking child ID absent from scope config; resolver rejects |
| multiple/broadened | `doc_ids`, nested/path-escape ID, association fields, or extra target keys reject |
| cancel | preview succeeds; modal cancellation sends no apply request and retains URL/detail |
| stale source | source bytes change after preview; apply conflicts and deletes nothing |

All destructive route and browser evidence must create its own temporary
configured scope/sub-scope and canonical sources. The Analysis `tags`
collection is a manual read/review surface only.
