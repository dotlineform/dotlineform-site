# External Media Workspace

## Purpose

Give every Docs Viewer scope one private external workspace for managed media. Add, Import, build, Manage, inventory, and editorial Copy use that workspace; the existing explicit Publish action projects the current public media set to `site/` or R2 alongside public documents.

This keeps repository scope containers document-centred and makes public media truthful: media bytes appear in the repository only when they are part of the tracked public `site/` artifact.

The feature is active at the EMW-1.2 review gate. The strict external managed-media contract is implemented, and explicit Publish now plans and independently reconciles the complete referenced public-media set. The first real Analysis media-aware preview remains unapplied for review.

## Complete Feature Outcome

- Every configured parent scope owns one exact namespace under an external Docs Viewer media root; sub-scopes continue to use their parent scope's media ownership.
- Retained originals remain beneath configured Projects-relative source roots and are never used as public serving paths.
- Managed image, SVG, file, HTML, and future ready-media bytes live outside Git for every scope.
- Registered media build sources, including standalone Mermaid `.mmd`, live in the external media workspace rather than a document scope container.
- Canonical Markdown keeps the same provider-neutral `docs/<scope>/<type>/<identity>` references.
- Manage serves managed media through local Docs Viewer routes.
- Public scopes use the existing explicit Publish action to project the complete referenced public media set to `site/` or R2 and render public URLs.
- Unpublish and document deletion may remove a public projection but never remove the external managed artifact or retained original.

## Relationships

[Media Sources](/docs/?scope=studio&doc=d-20260812-102047-a3c9e7) already owns selection from retained source folders and exact private evidence. This feature changes the destination of the managed artifact and moves that evidence beside the external media namespace; it does not change source-root selection or infer historical originals.

The earlier [Media Locations](/docs/?scope=studio&doc=d-20260812-095531-6fd2b1) proposal is deferred because it treats repository or R2 as the active managed-media location. Under this feature, managed media is always external-local; a separate location decision concerns only the public projection target and must not change ordinary Add behavior.

[Scope Media Management](/docs/?scope=studio&doc=d-20260720-100017-9855dd) may later report retained-source, managed-media, and public-projection states. It does not own this storage migration or Publish mutation. [Media Publication Check](/docs/?scope=studio&doc=d-20260812-114603-9706aa) remains a later verification outcome and is not started here.

## Boundaries

- No backup, synchronization, provider fallback, cross-scope deduplication, content-addressed storage, or background replication.
- No per-item storage or publication-provider choice in Add, Import, Replace, or Copy.
- No canonical document-link migration; physical location remains outside Markdown identity.
- No automatic deletion of managed media because a document is unpublished, deleted, or no longer references it.
- No Scope Media report, publication-health UI, cache-busting policy, or general asset registry in the first delivery.
- No compatibility alias or dual-reader end state across the current repository/external/R2 managed-media locations.

The feature and EMW-1 are in progress at the EMW-1.2 review gate. The external private-media cutover and Publish reconciliation implementation are complete; EMW-1.3 manual verification and closeout require separate approval.
