# CII-1 — Catalogue Image Source Insertion Delivery

## Status

Proposed for review. No product implementation has begun. This is one standalone delivery directly under the [Roadmap](/docs/?scope=studio&doc=d-20260428-000000-f5ff18).

## Complete Result

The Docs source editor adds **Add Catalogue image** beside **Add image** and **Add catalogue token**. An author searches the existing mixed Catalogue target set, selects an exact published Work or Series, applies the current image presentation options, and inserts one semantic Catalogue image occurrence into the source buffer.

After the ordinary source save and rebuild, the occurrence displays the target's current Catalogue image. Clicking the image opens the exact Catalogue destination: a Work image opens that Work, while a Series image opens that Series even though its displayed image comes from the Series' primary Work.

This is one source-authoring and rendering workflow. Resolution during insertion versus the immediately following rebuild is an implementation detail, not a separate product mode or delivery phase. The current single-user save, dirty-state, and rebuild lifecycle is sufficient.

## Accepted Contract

### Identity, Image, And Destination

The source occurrence preserves three distinct meanings:

- semantic identity is the selected Catalogue family, target type, and canonical target id;
- image presentation is resolved from the exact target lookup row; and
- activation uses that same row's exact Catalogue destination.

For a Work, the image projection comes from that Work's current primary Catalogue image and the destination remains the Work page.

For a Series, the image projection comes from the Work identified by the Series' exact `primary_work_id`, while semantic identity and destination remain the Series. The image source must not retarget the occurrence to the primary Work.

Only current published lookup targets are selectable. Missing image data, a missing or invalid Series `primary_work_id`, a primary Work that is not a current Series member, or an unusable destination fails closed. The workflow does not fall back to the first member, infer identity from title or route, or choose another image.

### Source And Rendering

The new occurrence belongs to the existing Catalogue semantic family but has an explicit image presentation. Existing text Catalogue tokens keep their current grammar and rendering.

Canonical source stores the exact target identity and authored presentation values rather than copying Catalogue media into the Docs scope. Rebuild resolves the browser-safe image and destination through the existing generated target lookup and emits a linked image or linked semantic figure.

The lookup remains the single focused projection shared by authoring and rendering. Extending its Work and Series rows with an allowlisted image projection must not expose canonical records, filesystem paths, provider credentials, or unrelated media metadata.

The occurrence contributes the same exact Catalogue identity to semantic usage and broken-link behavior as a text occurrence. Image presentation does not create a second relationship family or usage index.

### Authoring Surface

**Add Catalogue image** reuses the current mixed Work and Series search, result identity, keyboard navigation, and exact selection contract from **Add catalogue token**.

After target selection it provides the current **Add image** presentation values:

- required alt text;
- optional caption;
- optional summary when a caption is present;
- full-column, image-left, or image-right placement; and
- fill available width or natural width.

Target selection may suggest the current Catalogue title for alt text and caption, but those values are authored occurrence snapshots. A later Catalogue title change does not rewrite source text automatically.

Confirmation inserts at the captured source selection, returns focus, and uses the normal dirty state. It does not save or rebuild independently, publish media, or mutate Catalogue data.

## Delivery Boundary

CII-1 includes:

- one manage-only **Add Catalogue image** source action;
- exact Work and Series target selection through the current Catalogue picker;
- one focused semantic image occurrence and renderer without changing text-token behavior;
- allowlisted Work and Series image fields in the existing generated target lookup;
- linked plain-image and semantic-figure output using the existing image presentation classes and validation;
- existing semantic usage and broken-link follow-through for the exact Catalogue identity;
- focused parser, lookup, rendering, source-adapter, and contribution evidence; and
- current durable UI and target-lookup documentation at closeout.

CII-1 excludes:

- uploading, copying, replacing, resizing, or publishing Catalogue media;
- changing Work media, Series membership, `primary_work_id`, or Catalogue save validation;
- selecting a Series member other than its exact primary Work;
- Moment targets or another semantic family;
- retroactively converting existing text tokens, Markdown images, or figures;
- a generic media-token framework, second Catalogue lookup, compatibility grammar, or fallback reader;
- automatic source rewriting when Catalogue titles, images, or Series primary Works change;
- public Catalogue route redesign or Docs image-layout redesign; and
- background work, receipts, locking, or multi-user concurrency machinery.

## Likely Owners To Inspect

Implementation should begin at the current ownership seams and narrow the exact changed set during CII-1.0:

- the semantic-token registry, generated target-lookup builder, and Catalogue Work/Series source adapters for the allowlisted image projection;
- the semantic-token parser, renderer, usage projection, and broken-link owner for the visual occurrence;
- the Catalogue target picker and source-action contribution for exact selection and insertion;
- the existing staged-image presentation and figure-fragment owners for shared validation and output classes without invoking staged-media publication; and
- the focused semantic-token, target-lookup, staged-media-fragment, source-editor module, and builder tests.

This is an inspection route, not a frozen file inventory. Stop and re-scope if the result requires copied media, a new provider abstraction, a second identity registry, a generic token engine, or changes to Catalogue write authority.

## Delivery Steps

### CII-1.0 — Sanity And Source Contract Gate

- [ ] Compare the complete result with the current Catalogue lookup, semantic-token grammar/rendering, source-action contribution, image-presentation fragment, and Work/Series image owners.
- [ ] Confirm the smallest unambiguous source representation for one Catalogue image occurrence while leaving existing text tokens byte-compatible and separately editable.
- [ ] Freeze the allowlisted lookup image shape, exact Work and Series resolution rules, authored occurrence fields, unresolved behavior, and linked output contract.
- [ ] Confirm the likely blast radius across generated lookup refresh, source insertion, Docs rebuild, semantic usage, broken links, Manage rendering, and public rendering.
- [ ] Record the bounded production owners, focused evidence, risks, and stop conditions, then stop for implementation approval.

**Gate:** Documentation completion is not product implementation. Stop before CII-1.1 until the source and projection contract is reviewed.

### CII-1.1 — Exact Image Projection And Rendering

- [ ] Extend the existing target lookup with the minimum browser-safe image projection for eligible Works and Series.
- [ ] Resolve Series presentation only through its exact valid `primary_work_id`, while preserving the Series identity and destination.
- [ ] Parse and render the focused Catalogue image occurrence as a linked plain image or linked semantic figure using current presentation validation and classes.
- [ ] Preserve exact semantic usage and broken-link evidence for resolved and unresolved visual occurrences without changing text-token output.

**Gate:** Focused lookup, parser, renderer, usage, and broken-link evidence passes; independently review the bounded diff before the source-editor action begins.

### CII-1.2 — Add Catalogue Image Authoring

- [ ] Register **Add Catalogue image** as a separate manage-only source action using the existing action-contribution boundary.
- [ ] Reuse the mixed Catalogue picker, then collect alt text, caption, summary, placement, and fill-width values through the current image-presentation contract.
- [ ] Insert the serialized occurrence through the captured-selection adapter and preserve cancellation, focus return, dirty-state, save, and rebuild behavior.
- [ ] Keep **Add image** and **Add catalogue token** unchanged and independently available.

**Gate:** Focused source-action and adapter evidence passes, followed by manual review of keyboard selection, formatting controls, cancellation, insertion, and focus behavior.

### CII-1.3 — Integration And Closeout

- [ ] Verify one Work and one Series from source insertion through rebuilt Manage output, including exact image, exact click destination, presentation variants, and semantic usage.
- [ ] Verify draft/unpublished targets and missing or invalid image projections are unavailable or unresolved without fallback.
- [ ] Confirm public-safe rendering uses only projected browser data and no local service or canonical Catalogue source.
- [ ] Run the smallest relevant source lint, focused Python and JavaScript checks, generated lookup and Docs projection assertions, and whitespace review.
- [ ] Update [Semantic Tokens Source Editor UI](/docs/?scope=studio&doc=d-20260623-180405-631ef4) and [Target Lookup](/docs/?scope=studio&doc=d-20260726-185814-c5e581) with shipped behavior, then prepare the explicit retain-or-retire closeout recommendation.

## Completion Evidence

- A Work selected through **Add Catalogue image** rebuilds as its current image and opens that exact Work destination when clicked.
- A Series selected through the same action rebuilds with its exact primary Work's image but opens the exact Series destination and remains a Series semantic occurrence.
- Alt text, optional caption and summary, placement, and fill-width behavior match the current **Add image** presentation contract.
- Existing text Catalogue tokens and staged **Add image** behavior remain unchanged.
- The generated target lookup is the only Catalogue-to-Docs image projection and contains no private source or provider data.
- Missing, draft, stale, or malformed targets create no inferred image, destination, or relationship.
- Source insertion remains an ordinary local buffer mutation committed by the existing save and rebuild workflow.
