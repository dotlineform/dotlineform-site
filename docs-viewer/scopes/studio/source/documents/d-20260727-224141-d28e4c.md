# Tag Document Bootstrap Delivery

## Target Result

One guarded migration creates a new public document in the Analysis `tags`
sub-scope for every current canonical tag without a `doc_id`, copies the
registry description into that document once, and stores the allocated ID in
the registry row.

The current planning snapshot contains 245 flat registry tags with no
`doc_id` and three independent sub-scope documents. If that snapshot remains
the cutover input, the delivery creates 245 new linked sources and leaves the
three existing sources unchanged, producing 248 manageable documents in total.
Execution must freeze and report the actual counts again.

This is a bootstrap, not feature closeout. It makes the complete real
collection available so its navigation, discovery, metadata, and source-editing
needs can be reviewed before follow-on work is chosen.

## Frozen Output Contract

For each input registry row, the migration allocates one immutable document ID
and creates:

```markdown
---
doc_id: <allocated immutable document ID>
title: "<tag_id>"
added_date: <cutover timestamp>
last_updated: <cutover date>
parent_id: ""
viewable: true
---
# <tag_id>

**<group>**

<tag registry description>
```

The corresponding registry row gains that exact `doc_id`. The migration
preserves tag order, `tag_id`, scalar `group`, `description`, row timestamps,
policy, aliases, assignments, and the three existing tag documents.

The registry schema advances only far enough to retain and validate an optional
unique `doc_id` during the feature transition. The bootstrap populates it for
every frozen input row; making it required for later New Tag and Edit Tag
writes belongs to follow-on delivery work.

## In Scope

- Add one repository-owned preview/write/validate command for this one-off
  bootstrap.
- Require the current flat registry schema, unique tag IDs, one allowed scalar
  group per tag, a description string, and no pre-existing registry `doc_id`
  values.
- Inventory every existing Analysis `tags` source before allocating IDs.
- Produce an inspectable preview containing the exact tag-to-document mapping,
  target paths, source count, registry projection, and input fingerprints.
- Allocate immutable IDs without matching documents by title, group, or
  content.
- Create every new Markdown source with exclusive-create semantics before
  atomically replacing the registry.
- Add and validate unique registry `doc_id` values while preserving every
  pre-existing tag value and all alias and assignment sources.
- Rebuild the Analysis documents, sub-scope manifest, and by-ID payloads;
  reload the local management inventory; and confirm the sub-scope documents
  remain excluded from parent-scope search.
- Reconcile the complete registry-to-document relationship and inspect the
  resulting collection through the delivered sub-scope management workflow.

## Not In Scope

- Reusing, rewriting, moving, linking, or deleting the three existing tag
  documents.
- Changing New Tag to create a document.
- Adding `doc_id` to Edit Tag or implementing stale-link repair.
- Synchronizing registry descriptions with document content in either
  direction.
- Changing tag deletion or document deletion behavior.
- Adding group data, filtering, styling, or management fields to the public
  sub-scope manifest.
- Redesigning the report, metadata editor, source editor, or management
  toolbar.
- Creating Tag semantic-token targets.
- Editing the generated prose beyond the fixed one-time seed template.

Any discovery, filtering, bulk action, repair, or authoring need revealed by
the real collection becomes separate follow-on work.
