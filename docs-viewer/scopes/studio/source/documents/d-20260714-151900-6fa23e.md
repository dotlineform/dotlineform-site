# Index Multiple Selection

## Purpose

Add explicit checkbox selection to the manage-mode index, then let deliberately designed batch actions consume that selection without changing the displayed document.

This is the feature parent. It does not act as an implementation tracker.

## Current State

The checkbox-selection foundation is complete. The manage tree exposes **Select**, a sibling checkbox gutter, Shift-range selection, a selected count, **Select all**, **Clear**, and **Done**. **Select all** replaces the checked set from the complete manage-index model, including collapsed and non-viewable documents; it does not inspect rendered rows. `docs-viewer-index-selection.js` independently owns checked ids, the range anchor, mode, bulk selection, and reload/lifecycle reconciliation. [Runtime Module Ownership](/docs/?scope=studio&doc=d-20260605-125108-1d1ef3) records the shipped foundation.

One independent, always-enabled **🛠️** **Index actions** menu now contains the shipped checked-document consumers: **Prepare package…**, **Copy to scope…**, **Move to scope…**, and **Delete…**. The existing **Select** button remains the only owner of checkbox-mode entry and exit; the menu stays visible and shows disabled items when nothing is checked.

Prepare package's [completed delivery](/docs/?scope=studio&doc=d-20260722-133457-e90e21) covers its compact workflow; [Copy And Move Documents Between Scopes](/docs/?scope=studio&doc=d-20260716-193410-6d4efe) owns cross-scope transfer; Delete uses its one preview/apply path. All four consume checked ids without displayed- or context-document fallback. The [Consumer Assessment](/docs/?scope=studio&doc=d-20260722-000158-9c0f3e) retains Export and same-scope group Move as separately gated candidates, so this feature parent remains in progress. Ordinary Import is not a selection consumer, and Returned packages remains a whole-package scope workflow with no index-selection input.
