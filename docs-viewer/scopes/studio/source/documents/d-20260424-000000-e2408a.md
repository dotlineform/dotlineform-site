# Publishable field

## Purpose

`publishable` is the source-owned inclusion gate for the next scope-wide **Publish**. It exists only for an exact parent or child collection with a configured public projection. It is not current-public evidence, a local discovery control, a privacy boundary, or a separate per-document Publish action.

Local and local-external collections have no Publish projection, so they have no `publishable` field, exclusion icon, or publishability action. Their complete source set remains in local index, Recent, search, by-ID, and management projections.

## Source Contract

The canonical excluded form is:

```yaml
publishable: false
```

Rules:

- omission means included in the next Publish;
- write paths normalize an included document to omission;
- `publishable: false` excludes the document from the next Publish;
- a false parent also excludes all of its descendants from that public projection without rewriting their source fields;
- the legacy `viewable` field is rejected rather than read as an alias; and
- `ui_status` remains presentation metadata and does not affect Publish.

New documents and Copy targets use the included default and therefore omit `publishable`. Import may explicitly supply the boolean for a publish-capable target; overwrite preserves the current value unless the returned record explicitly changes it. Local targets reject the field.

## Private Build Projection

The builder renders every configured source document for management. For a publish-capable parent collection, the private `index-tree.json` carries `publishable: false` only on excluded rows; included rows omit the field. For a publish-capable child collection, the Manage manifest follows the same false-only rule. Local collection projections omit the field entirely.

Excluded documents remain loadable in Manage through their private by-ID payloads and retain the **Excluded from next Publish** index/report cue. Public reader by-ID payloads and public manifests do not carry management publishability metadata.

## Search, Recent, And Publish

For a publish-capable parent collection, the search and prepared public Recent projections omit excluded documents, their descendants, and configured manage-only roots. Local search and Recent include the normal complete local source set because local collections have no publication gate.

Scope-wide **Publish** remains the sole public mutation. It copies the prepared public projection, omitting excluded parent and child rows, their public by-ID and reference payloads, and stale public files. Changing `publishable` does not itself add or remove a public file; that happens only after the next successful Publish.

This distinction supports simple publication stages: an excluded document may still be **🟢 Published** while its prior public projection exists, then become **🟠 Pre-publish** after Publish removes it.

## Management And Packages

**Edit metadata** does not expose or accept publishability. SSP-7.1b owns the later checkbox-aware **Set Publishable…** selection action; SSP-7.1a changes only the field contract and removes the old metadata control.

Package profiles use `include_non_publishable`. The option can exclude rows carrying `publishable: false` from package composition, but it does not mutate source or publish. Local package records omit publishability, so the option subtracts nothing from a local selection.

`publishable: false` does not prevent local rendering, package export, management access, or direct source access and must not be used as a sensitive-data boundary.
