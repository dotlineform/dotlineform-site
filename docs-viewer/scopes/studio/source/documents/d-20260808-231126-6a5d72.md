# Scope Media Storage Locations

## Purpose

Allow a Docs Viewer scope to choose and later change the storage location for each configured media type independently from the scope's access mode and canonical document workspace.

Repository, external-local, and R2 placement are practical policy choices driven by size, provenance, delivery, availability, and cost. They do not define whether the scope itself is local or public, and changing them must not change logical media identity or authored document references.

## Concept

[Scope Media Storage Locations Concept](/docs/?scope=studio&doc=d-20260808-231127-db19cc) owns the independent configuration axes, supported provider constraints, creation defaults, location-change workflow, byte migration transaction, scope-type interaction, ownership boundaries, and proof gate.

No delivery has been proposed and no implementation has started.

## Feature Contract

- Each configured media type has one exact current storage destination resolved from scope configuration.
- Scope access, canonical document workspace, and media destinations are independent configuration concerns.
- Scope creation may offer useful presets, but a preset supplies defaults rather than permanently coupling media providers to scope type.
- Ordinary Add Image, Add File, build, render, and reference workflows use the configured destination; they do not ask authors to choose a provider per item.
- A scope-level **Media storage** workflow previews and applies later destination changes for exact media types.
- Migration preserves `scope + media type + relative identity`, logical references, media records, metadata, and producer relationships.
- Bytes are inventoried, copied, and verified before configuration changes authority. Success leaves one configured destination per identity and no provider-search fallback.
- Public access requires media used publicly to have a publicly deliverable destination, but scope-type migration does not silently choose or move that destination.
- Local scope access does not imply private media storage. Repository public assets or R2 objects may remain publicly served until an explicit media-location migration removes that exposure.

## Relationship And Boundaries

[Scope Media Management](/docs/?scope=studio&doc=d-20260720-100017-9855dd) owns media identity, canonical records, inventory, reference evidence, and future item-level inspection or lifecycle actions. This feature owns the per-media-type destination policy and movement of owned bytes between providers; inventory is evidence for that migration, not the migration owner.

[Docs Viewer Scope Type Migration](/docs/?scope=studio&doc=d-20260808-225257-c06ae2) changes the scope workspace/access profile while preserving explicit media policy. Media configured as scope-local follows a relocated scope root by definition; other media destinations remain unchanged. An incompatible public destination blocks scope publication enablement until this feature moves it explicitly.

The feature does not add arbitrary filesystem roots, provider selection to ordinary authoring, per-object automatic routing, multi-provider lookup, content rewriting, media identity changes, automatic orphan deletion, a second media registry, or migration of independently owned external asset collections.

## Success Meaning

The feature succeeds when an eligible scope can show the exact current destination for each media type, preview a supported target, migrate the complete owned byte inventory with verification and explicit cleanup, and continue resolving every unchanged logical identity from the new single authority. Editing a provider field manually, copying only referenced files, or retaining an undisclosed fallback destination is not completion.
