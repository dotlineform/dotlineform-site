Explore useful source-documentation and lint conventions that improve code re-entry and automated feedback without demanding comments on obvious code.

## Backfill Order

Backfill source documentation by value and risk:

- shared and cross-application contracts;
- exported JavaScript options, callbacks, events, controllers, and lifecycle boundaries;
- Python services, adapters, value objects, write plans, builders, commands, and error translation;
- stateful or side-effectful modules that repeatedly require source archaeology;
- complex code where documenting the contract exposes a useful simplification.

Do not backfill trivial accessors, obvious wrappers, generated or vendor source, or test functions whose names and fixtures already state the contract.
