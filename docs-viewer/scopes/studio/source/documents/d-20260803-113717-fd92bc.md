# IFS-1 — Docs Import Folder Source Selection Delivery

## Status And Purpose

Proposed as **IFS-1** under [Docs Import Folder Source Selection](/docs/?scope=studio&doc=d-20260801-190502-6927fb). The [Concept And Architecture](/docs/?scope=studio&doc=d-20260803-113716-8ef8e5) is the authority for component ownership, modal handoff, confinement, and source-selection behavior.

This delivery establishes an honest shared folder-navigation capability with Docs Viewer as its first consumer, then integrates it into ordinary Docs Import without changing classification, targeting, or apply semantics.

## Complete Delivery Outcome

Manage Import shows the current relative source with **Choose folder…** and **Use import staging** actions. Choosing opens a dedicated folder-picker modal backed by lazy, server-confined directory listing. Confirming one validated folder restores Import and refreshes its direct-child ordinary candidates; cancelling restores Import unchanged.

The shared frontend component contains only app-neutral folder navigation. A shared Studio Python capability contains only Projects-base confinement and child-directory listing. Docs Viewer explicitly exposes the shared frontend asset, and its Import adapter retains all staging, candidate, recognizer, destination, preview, and apply policy.

## Delivery Discipline

- A shared component may have one initial consumer when its responsibility and dependency direction are genuinely shared.
- Docs Viewer receives an explicit supported shared-asset boundary; there is no copied or accidental private import.
- Folder selection has a dedicated modal and deliberate handoff; the existing Import modal does not become a second application view.
- The Works Editor picker is not migrated merely to manufacture a second consumer.
- The delivery adds narrow folder navigation and confinement seams, not a generic filesystem framework.

## Current Seams And Expected Shape

The contract checkpoint must re-trace these seams immediately before implementation:

- the existing shared frontend file picker and its Works Editor wrapper;
- Docs Viewer static asset routing and module boot boundaries;
- the Import modal, controller, candidate inventory, recognizer dispatch, marker paths, preview/apply requests, and local preference patterns;
- the existing collection-modal handoff and focus-restoration behavior; and
- shared Studio external-workspace path helpers and Docs Viewer server adapters.

Expected production change is roughly 600–850 lines: 180–260 for the shared component and styles, 100–160 for shared Python confinement/listing, and 300–450 for Docs Viewer routing, API, modal, and Import integration. Focused tests are expected to add roughly 450–700 lines. IFS-1.0 records exact files and pauses for review if the shape materially exceeds these bounds or requires a new framework.

## Not In Scope

- recursive search, whole-tree candidate expansion, multi-selection, batch apply, jobs, progress, or resumable corpus migration;
- PRJ-2 Apple Notes migration or `folder_path` assignment;
- trusted package or edited review-source intake outside import staging;
- native operating-system folder access or paths outside the Projects base;
- a Works Editor picker migration or requirement for a second consumer;
- new source formats, media rules, destination selection, or overwrite rules;
- copying, moving, deleting, or synchronizing source material; or
- server-wide or multi-user preference synchronization.

## Completion Evidence

- Import staging remains the default and preserves existing behavior when no alternate source is selected.
- Every selected and remembered source is server-resolved beneath `$DOTLINEFORM_PROJECTS_BASE_DIR` and represented outside the server by a relative marker only.
- The shared frontend capability is explicitly reachable by Docs Viewer, contains no Docs Import policy, and works through the dedicated modal handoff.
- Ordinary candidates retain existing classification, conversion, exact destination, create-only, media, and rebuild behavior.
- Trusted formats cannot bypass staging or fall through to ordinary Import.
- Invalid remembered folders fail closed to staging without changing the current destination.
- No recursive, batch-import, generic-filesystem, or Works Editor migration capability is introduced.
