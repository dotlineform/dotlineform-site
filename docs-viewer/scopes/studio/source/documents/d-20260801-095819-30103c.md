# Projects

## Purpose

Give current, historical, and prospective project folders a flexible notes layer while keeping Studio Works and Series as stable catalogue records. Projects owns the Docs Viewer notes, local folder links, optional `folder_path` metadata, and completed Apple Notes migration. Separate Project State and Resolver Tokens features may consume that foundation without becoming part of the Projects delivery sequence.

The feature keeps three deliberately different worlds visible:

| world | role |
| --- | --- |
| Studio | strict database owner of Works, Series, publishing workflow, and recorded source-path history |
| Docs Viewer | semi-structured owner of Project notes, optional convenience links, saved Project State, and local audit documents |
| folders | fluid human working world with no canonical identity or enforced lifecycle |

The completed Projects feature does not make one system manage the other two. Project State separately observes disagreement among them.

PRJ-1 and PRJ-2 are entirely Docs Viewer-owned and do not change Studio. The separate Project State feature owns the narrow integration exception that reads existing Work folder and Series evidence through a Studio-read-only post-commit observer.

## Delivery Order

| order | delivery | complete outcome |
| --- | --- | --- |
| 1 | PRJ-1 — Docs Viewer Local Folder Links | A pasted Finder or terminal path becomes a marked base-relative link: clickable through confined local Manage and inert in public output. |
| 2 | PRJ-2 — Projects Customisation And Apple Notes Migration | Project documents own optional `folder_path` metadata in their local Manage manifest, and a checked-in one-off command imports the reviewed Apple Notes corpus without inventing folder matches. |

Both direct deliveries are complete. PRJ-2 supplies Project-document evidence to Project State, but downstream generation, audit migration, and resolution have their own feature owners and delivery gates.

## Downstream Relationship

```text
Project documents[] <- folder_path -> Series[]
```

One normalized folder may later become one Project State row. Several Project documents may share it, and the Works historically sourced from it may contribute several Series. Project State owns that derivation; Resolver Tokens own bounded downstream expansion.

## Feature Boundary

In scope:

- ordinary body links for local folder paths;
- one optional Project-document `folder_path` convenience field;
- no Studio dependency for local links or Project-document metadata;
- `$DOTLINEFORM_PROJECTS_BASE_DIR` as the local-link containment boundary while `projects/` remains the initial Project discovery area;
- a registered Manage-only Projects sub-scope customisation;
- a write-free plan and exact create-only apply for the dated Apple Notes export;
- retained migration evidence and explicit unresolved seeding gaps.

Not in scope:

- a canonical folder registry or folder/document synchronization;
- automatic rename, move, merge, repair, import, or deletion from a report finding;
- use of `folder_path` by Studio media or publishing workflows;
- adding `folder_path` to Works or mapping it onto `project_folder`;
- Project State generation, saved reports, Studio observers, or Project Media Audit migration;
- Resolver Token parsing, rendering, semantic usage evidence, or authoring; or
- public activation of local targets or public projection of Project relationship/audit data.
