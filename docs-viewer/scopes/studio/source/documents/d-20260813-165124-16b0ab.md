# All-Scope Full-Text Search Baseline

## Status

The common baseline is complete and closed after explicit user approval. All five configured working indexes use `title`, `heading`, `body`, and `code`; focused policy and lifecycle contracts pass; and representative parent and hosted-child queries resolve through the shared browser query path. ## Purpose

Every configured Docs Viewer scope now uses the full-text Search baseline already shipped for Studio. All scopes share one v2 index producer and browser query path; the former Analysis, Notes, Processing, and Dotlineform metadata-only exception has been removed.

[SM-1 — Studio Full-Text Search Delivery](/docs/?scope=studio&doc=d-20260715-084611-c2fa6f) established the reusable extraction and ranking contract. [DSI-2 — Scope-Level Sub-Scope Search Delivery](/docs/?scope=studio&doc=d-20260813-225547-cd82d8) added eligible visibly hosted sub-scope documents to the same atomic scope index. The combined parent and sub-scope corpora now provide enough content to make full text the common baseline before any further Search improvement is considered.

This is a policy alignment, not a new search feature or a separate Analysis experiment.

## Common Baseline

Every configured Docs Viewer scope adopts exactly:

```json
"search_fields": ["title", "heading", "body", "code"]
```

The existing shared behavior remains unchanged:

- title matches rank above heading matches, which rank above body and authored-code matches;
- `doc_id`, URL, update date, parent identity, parent title, sub-scope identity, and collection title remain structural or display metadata and do not emit postings;
- visible headings, prose, inline code, and fenced code come from the shared Markdown extraction boundary;
- front matter, report declarations, link destinations, media paths, raw configuration, scripts, styles, and excluded documents do not contribute searchable terms;
- each scope owns one complete atomic index containing its eligible parent documents and eligible visibly hosted sub-scope documents; and
- exact `{scope, sub_scope, doc_id}` identity and the active-route resolver continue to own child navigation.

There is no scope-name branch, second schema, alternate tokenizer, independent child index, or browser-side result merger. New Docs Viewer scopes should start from this same field policy unless a deliberate exception is approved.

## Deliberate Omissions

This baseline does not change relevance weights, prefix behavior, snippets, highlighting, phrase search, stemming, synonyms, typo handling, query language, section results, deep links, cross-scope Search, or Search presentation. It does not change parent Index or Recent composition.

[Catalogue Search](/docs/?scope=studio&doc=d-20260602-160839-4ebe27) remains a separate domain-owned system and is not a Docs Viewer scope.

Search improvements should be considered only after this common baseline is implemented, rebuilt, published where required, and accepted.
