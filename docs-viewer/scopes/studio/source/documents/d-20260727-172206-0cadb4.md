# Tag Registry Label Retirement Delivery

## Target Result

`tag_id` is both canonical identity and the displayed tag name. Canonical
registry rows no longer store a duplicate `label`.

```json
{
  "tag_id": "moss",
  "group": "subject",
  "description": "<temporary document seed content>",
  "updated_at_utc": "<timestamp>"
}
```

The cutover input had 245 registry rows. All 245 labels were identical
to their `tag_id`, so retirement requires no naming decision, identity rewrite,
alias migration, or assignment migration.

## In Scope

- Remove `label` from every canonical registry row and bump the registry schema
  to `tag_registry_v3`.
- Preserve every `tag_id`, scalar `group`, description, row timestamp, policy,
  alias target, and assignment reference.
- Stop create, edit, promotion, and manual-patch paths from writing `label`.
- Stop validation and mutation evidence from requiring or returning a registry
  label where `tag_id` already carries the same value.
- Make Tag Registry, Tag Aliases, Series Tags, and Series Tag Editor consume and
  display `tag_id` directly.
- Update focused fixtures, planners, APIs, browser modules, validation, checks,
  and durable source documentation.

## Not In Scope

- Renaming a tag or changing any tag identity.
- Changing group membership, descriptions, aliases, assignments, weights, or
  inheritance.
- Removing generic UI or configuration fields named `label` when they do not
  represent `tag_registry.tags[*].label`.
- Adding `doc_id`, creating tag documents, or removing registry descriptions.
- Changing the group taxonomy or group-derived reporting.

## Delivery Steps

1. [x] **Freeze and validate the input.** Require `tag_registry_v2`, exactly one
   allowed scalar group per tag, globally unique flat IDs, and `label ===
   tag_id` for every row. Record tag, alias-target, and assignment-reference
   counts before changing source.
2. [x] **Change the canonical contract.** Add `tag_registry_v3` validation and
   a one-file projection that removes only `label`. Preserve tag order, policy,
   groups, descriptions, and row timestamps; update only the source-level
   version and cutover timestamp.
3. [x] **Update every writer.** Remove `label` from create, edit, promotion, API
   response, activity detail, state projection, and manual-patch behavior.
   Ensure ordinary group/description edits cannot reintroduce the field.
4. [x] **Update every reader.** Remove raw-label requirements and use `tag_id`
   for registry display, search, ordering, alias target choices, Series Tags,
   and Series Tag Editor suggestions/chips. Keep generic presentation labels
   only where they are derived values rather than canonical source.
5. [x] **Cut over once.** Apply the validated v2-to-v3 registry projection
   atomically. Do not add a dual-read source mode or retain empty/derived label
   compatibility fields.
6. [x] **Reconcile and close.** Prove 245 IDs, groups, descriptions, and row
   timestamps are preserved; aliases and assignments are byte-unchanged and
   still resolve; no registry row contains `label`; and no writer recreates it.
   Run focused model/planner/API tests, `studio-tag-smoke`, scoped source
   searches, and manual Registry/Aliases/Series Tags/Series Tag Editor checks.
