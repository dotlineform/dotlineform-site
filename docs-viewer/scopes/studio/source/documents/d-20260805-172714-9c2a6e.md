# SSP-2.3 — Project State Interaction Evidence

## Outcome

SSP-2.3 is complete at its review gate. The existing Project State module now derives Folder-first and Series-first projections from one accepted in-memory `docs_project_state_report_v1` response. Grouping, search, sorting, TSV, and Markdown generation perform no server reconciliation or resolver-lookup mutation; only mount and explicit Run/Refresh retain the existing complete service operation.

Folder view keeps one row per scanned folder with visible columns Folder, Series, Docs. Series view changes the order to Series, Folder, Docs and emits one row for each exact Series-folder relationship; a folder without an exact Series route emits one row with a blank Series cell. Switching projection preserves search and selects the new leading-column ascending sort. Search matches a case-insensitive substring over composed visible text only. Every visible heading toggles ascending and descending sorting, with canonical IDs and normalized folder identity providing deterministic ties.

The report toolbar uses equal icon pills for its actions. The projection toggle names the destination: Folder view shows the established site list icon with **Group by Series**, then Series view shows a folder icon with **Group by Folder**. Copy table reuses the managed Table View copy icon, while the Markdown action is the visible **MD** pill; both retain exact accessible labels and tooltips.

## Clipboard Transforms

Copy table serializes the current filtered and sorted projection as semantic TSV with visible headings and link text. Copy Markdown serializes the same projection with exact Folder, Series, and Project-document links. Its first line is `Project State - YYYY-MM-DD HH:MM` from the response generation time converted to GMT, followed by one blank line and the Markdown table. Multiple values join with `; `, blank cells remain blank, and Markdown table and link-label syntax is escaped. Both actions use only the in-memory projection, create no file or document, retain no archive, and show no success message.

Focused pure-function evidence proves that grouping, search, ascending/descending sorting, TSV, GMT conversion, Markdown links, blank Series values, repeated Series-view context, and Markdown escaping do not mutate the supplied rows. The report service is absent from those transformations, so interaction-time projection and serialization cannot initiate another Project State request.

## Live Evidence

The live Folder projection contained 206 rows. Series projection contained 208 rows: 62 retained blank-Series rows, one row for each ordinary Series-folder relationship, and two repeated multi-Series folders, `projects/collected 1989-1998` and `projects/nerve`. The Series projection remained within the 560-pixel report measure with equal client and scroll widths.

Live toolbar verification confirmed the initial list icon and **Group by Series** label, the toggled folder icon and **Group by Folder** label, equal pill sizing for refresh/group/copy actions, the Copy Table icon, the visible **MD** label, and matching tooltips. Toggling retained the 206-row Folder and 208-row Series projections without horizontal overflow.

Searching live visible text for `collected 1989-1998` in Series view returned four relationships spanning matching Folder and Series labels. Descending Docs sort composed with that search. A full Run/Refresh advanced the displayed generation minute while preserving Series grouping, the search text, descending Docs sort, and the same four visible rows. The page reported no console errors. Clipboard text itself is covered at the pure serializer boundary so live verification does not overwrite the user's clipboard.
