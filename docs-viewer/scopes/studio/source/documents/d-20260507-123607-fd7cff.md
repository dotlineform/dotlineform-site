# Analysis Documents

Viewer report:

- `docs_index_table`

Purpose:

- review generated Analysis Docs Viewer records in a dense hierarchical list inside the Docs Viewer document pane

## Data Source

The report reads the generated Analysis docs index tree:

- `site/assets/data/docs/scopes/analysis/index-tree.json`

The report uses `viewer_report_scope: analysis`, so it reads Analysis docs even though this document lives in the Studio docs scope.
When local generated-data reads are available, the report can read the generated Analysis index tree through the Docs Viewer service.
Otherwise, it reads the static generated JSON asset.

## UI Contract

The report uses Docs Viewer-owned report styles and behavior.

It does not depend on Studio route state or Studio list primitives.

Rows follow the `index-tree.json` hierarchy by default, with child documents indented under their parent rows.

Columns:

- `title`
- `doc_id`
- `publishable`

All displayed columns are sortable.

Both the `doc_id` and `title` links open the `/docs/` management shell with `scope=analysis` for that document.

## Filters

The page exposes one filter pill:

- `non_publishable`

`non_publishable` shows records where `publishable` is `false`, labelled **Excluded from next Publish**.

## Availability

The report is local-only:

- `viewer_report_access: local`

If this document is opened in a public read-only Docs Viewer route, the document pane should show an unavailable state rather than rendering the local report.
