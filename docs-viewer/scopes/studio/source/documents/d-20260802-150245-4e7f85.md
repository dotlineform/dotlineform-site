# Table Enhancements

## Purpose

Table Enhancements coordinates the complete table authoring and presentation path: insert optional source comments, mark a table for enhanced viewing, present it through the existing panel/view model, add Manage-only tools, reuse the same detail view for diagrams, support flash-free default table presentation, and optionally publish a table as a linked SVG.

The feature keeps one sequence because the source comments, projected table marker, Content Detail view, table tools, diagram migration, default presentation, and SVG publication are different stages of the same authoring-to-reading workflow. It extends existing Source, build, panel, view, toolbar, media, and Publish seams rather than creating a table application or parallel model.

## Complete Feature Outcome

Manage Source first gains one **Directives** menu whose commands insert harmless comments against one exact Markdown table. The table-detail consumer later recognises its exact comment and projects the marker used by the public-safe Content Detail view. Unknown, malformed, misplaced, or unsupported comments remain invisible no-ops and never block a build.

The main panel can then enter one expanded `content-detail` view for an exact presentation in the currently rendered document. Author-marked Markdown tables use it for natural-width columns, sticky headers, a sticky first column, and unified horizontal and vertical scrolling. Manage contributes adjustable columns and **Copy as CSV** without creating another viewer. Persistent SVG and inline Mermaid diagrams later use the same view with their existing rendering and resource contracts.

A dedicated table document may carry a public-safe presentation hint that enters the detail view without an ordinary-document flash. Finally, a table-publication comment may prepare a deterministic linked SVG for public projection. Publish consumes only complete current preparation; otherwise the semantic table remains unchanged.

## Delivery Order

| order | delivery | complete outcome |
| --- | --- | --- |
| 1 | TE-1 — Source Editor Directive Actions | The existing Source toolbar inserts either maintained optional comment against one exact source table. |
| 2 | TE-2 — Table Detail Eligibility Directive | The table-detail consumer recognises its exact comment and projects the marker used by Content Detail View. |
| 3 | TE-3 — Public Static Content Detail View | The shared panel/view model supports one expanded content target, and explicitly eligible public and Manage Markdown tables receive a lightweight static presentation. |
| 4 | TE-4 — Managed Table Tools | The same table view receives Manage-owned resizable columns, Reset, and Copy as CSV without widening the public reader. |
| 5 | TE-5 — Diagram Detail View Migration | Existing diagram detail controls enter the shared view; optional new-tab opening remains a toolbar action rather than the primary presentation model. |
| 6 | TE-6 — Default Content Detail Presentation | A dedicated single-table document can enter the same view as its initial presentation with stable preflight layout and no ordinary-document flash. |
| 7 | TE-7 — Table-To-SVG Publication | The table-publication consumer uses a complete current prepared SVG when available and otherwise retains the semantic table. |

TE-1 is independently useful because it only inserts comments. TE-2 projects the marker required by TE-3. TE-3 establishes the public-safe view, target, layout, toolbar, return, and cleanup contracts. TE-4 adds Manage-only tools. TE-5 and TE-6 technically depend only on TE-3 but remain sequential so the shared view is extended and evidenced in one order. TE-7 closes the feature with the separate authoring-build and public-projection route.

## Boundary

Table Enhancements owns authoring conveniences and presentation for tables whose content remains owned by static document source. “Static” describes source ownership, not the rendering mechanism: an authored Mermaid fence may render dynamically and still qualify for the reused Content Detail view. Dynamic report lists, `docs_subscope` collections, search results, Recent, editors, spreadsheets, and generated application grids remain separate hosted or component views.

The feature does not add a central directive language, fourth panel, modal presentation framework, independent toolbar, detail route shell, spreadsheet editor, or generic widget registry. [Panel Hosts and Control Surfaces](/docs/?scope=studio&doc=d-20260528-224754-964108) remains the architecture authority; [Toolbar Model](/docs/?scope=studio&doc=d-20260531-152622-ed2451) remains the placement authority.

An unmarked table remains ordinary semantic HTML with no detail control. `table-detail` supplies the marker consumed by Content Detail; `table-publish` transforms its table only when complete current public preparation exists and is not another Content Detail adapter. Canonical Markdown, working payloads, and transfer retain the semantic table and comments throughout.
