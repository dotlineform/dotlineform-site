# Table Enhancements

## Status

In progress. [TE-1 — Directive Insertion](/docs/?scope=studio&doc=d-20260802-163320-9015b0) and [TE-2 — Table Detail View](/docs/?scope=studio&doc=d-20260802-162149-3ba013) completed on 2026-08-03; TE-3 is active at its scope-review checkpoint before implementation approval.

## Purpose

Table Enhancements coordinates the complete table authoring and presentation path: insert optional source comments, mark a table for enhanced viewing, present it through the existing panel/view model, add Manage-only tools, reuse the same detail view for diagrams, support flash-free default table presentation, and optionally publish a table as a linked SVG.

The feature keeps one sequence because the source comments, projected table marker, Content Detail view, table tools, diagram migration, default presentation, and SVG publication are different stages of the same authoring-to-reading workflow. It extends existing Source, build, panel, view, toolbar, media, and Publish seams rather than creating a table application or parallel model.

## Complete Feature Outcome

Manage Source first gains one **Directives** menu whose commands save the author from manually typing harmless source comments. Table Detail View then recognises an exact correctly placed comment, projects its eligibility marker, and supplies the public-safe static table presentation. Unknown, malformed, misplaced, or unsupported comments remain invisible no-ops and never block a build; TE-1 does not attempt that build-time validation.

The main panel can then enter one expanded `content-detail` view for an exact presentation in the currently rendered document. Author-marked Markdown tables use natural-width columns capped by a readable wrapping default, sticky headers, a sticky first column, and unified horizontal and vertical scrolling. Manage contributes adjustable columns and tab-delimited **Copy table** without creating another viewer. Persistent SVG and inline Mermaid diagrams later use the same view with their existing rendering and resource contracts.

A dedicated table document may carry a public-safe presentation hint that enters the detail view without an ordinary-document flash. Finally, a table-publication comment may prepare a deterministic linked SVG for public projection. Publish consumes only complete current preparation; otherwise the semantic table remains unchanged.

## Delivery Order

| order | delivery | complete outcome |
| --- | --- | --- |
| 1 | TE-1 — Directive Insertion | The existing Source toolbar inserts either maintained optional comment as predefined source text. |
| 2 | TE-2 — Table Detail View | The exact table-detail comment produces a public-safe static Content Detail presentation in public and Manage readers. |
| 3 | TE-3 — Managed Table Tools | The same table view receives Manage-owned resizable columns, Reset, and tab-delimited **Copy table** without widening the public reader. |
| 4 | TE-4 — Diagram Migration | Existing diagram detail controls enter the shared view; optional new-tab opening remains a toolbar action rather than the primary presentation model. |
| 5 | TE-5 — Default Presentation | A dedicated single-table document can enter the same view as its initial presentation with stable preflight layout and no ordinary-document flash. |
| 6 | TE-6 — Table-to-SVG Publication | The table-publication consumer uses a complete current prepared SVG when available and otherwise retains the semantic table. |

TE-1 is independently useful because it only inserts comments. TE-2 owns the complete comment-to-static-view outcome and establishes the public-safe target, layout, toolbar, return, and cleanup contracts. TE-3 adds Manage-only tools. TE-4 and TE-5 technically depend only on TE-2 but remain sequential so the shared view is extended and evidenced in one order. TE-6 closes the feature with the separate authoring-build and public-projection route.

## Boundary

Table Enhancements owns authoring conveniences and presentation for tables whose content remains owned by static document source. “Static” describes source ownership, not the rendering mechanism: an authored Mermaid fence may render dynamically and still qualify for the reused Content Detail view. Dynamic report lists, `docs_subscope` collections, search results, Recent, editors, spreadsheets, and generated application grids remain separate hosted or component views.

The feature does not add a central directive language, fourth panel, modal presentation framework, independent toolbar, detail route shell, spreadsheet editor, or generic widget registry. [Panel Hosts and Control Surfaces](/docs/?scope=studio&doc=d-20260528-224754-964108) remains the architecture authority; [Toolbar Model](/docs/?scope=studio&doc=d-20260531-152622-ed2451) remains the placement authority.

An unmarked table remains ordinary semantic HTML with no detail control. `table-detail` supplies the marker consumed by Content Detail; `table-publish` transforms its table only when complete current public preparation exists and is not another Content Detail adapter. Canonical Markdown, working payloads, and transfer retain the semantic table and comments throughout.
