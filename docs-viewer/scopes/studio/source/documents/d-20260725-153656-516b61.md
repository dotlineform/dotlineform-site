# Semantic Tokens

Semantic Tokens let an author associate displayed Markdown text with a stable
target identity. They are a manage-mode Docs Viewer capability; Catalogue is
the registered family, with Work, Series, and Moment targets.

## Workflow

1. In Markdown source, choose **Add catalogue token**.
2. Search the combined Catalogue list, select the exact target, confirm the
   occurrence Title, and add the token.
3. Put the caret in an existing token to inspect it. Its Title can be updated or
   the token removed; its target identity is read-only, so retargeting is
   **Remove** followed by **Add**.
4. **Rebuild** resolves a recognized token only when the target lookup supplies
   a workable destination. Unresolved token-like text remains ordinary text and
   does not block the build.
5. The manage-only [Semantic Tokens
   Report](/docs/?scope=studio&doc=d-20260726-181045-a7c2e1) lists resolved
   occurrences for a selected scope and links to their documents. [Docs Broken
   Links](/docs/?scope=studio&doc=d-20260423-165116-e7f7e9) diagnoses unresolved
   occurrences and hands repair back to the source editor.

## Ownership

- Docs Viewer source-editor core owns the Markdown buffer, selection, dirty
  state, save, and Rebuild workflow.
- Catalogue owns its canonical Work, Series, and Moment records and the
  reusable mixed-target discovery list.
- The Docs Viewer Semantic Tokens feature owns token definitions, parsing,
  build-time resolution, generated usage data, and the resolved-token report.
- Docs Broken Links owns read-only failure diagnosis. The author remains in
  control of source or canonical-data repair.

## Registry And Generated Data

The checked-in token-definition registry is:

```text
docs-viewer/config/semantic-tokens/registry.json
```

The rebuildable manage target lookup is:

```text
docs-viewer/data/generated/semantic-tokens/target-lookup.json
```

Each scope's resolved usage index is:

```text
docs-viewer/scopes/<scope>/published/documents/semantic-tokens/index.json
```

The usage index records occurrences in documents; it is not a registry or a
canonical target store. The registry, target lookup, and usage directory are
manage-only and are omitted from the public publish projection.
