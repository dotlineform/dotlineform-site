# Semantic Tokens

Semantic Tokens let an author associate displayed Markdown text with one stable target identity. They are a manage-only Docs Viewer capability with separate Catalogue and Tag families. Catalogue resolves Work and Series identities; Tag resolves one canonical `tag_id` to its exact current primary document or otherwise the first document in the canonical Tag-association order.

## Workflow

1. In Markdown source, select meaningful text and choose **Add catalogue token** or **Add tag token**.
2. Catalogue searches only current Work and Series targets. Tag searches canonical IDs and aliases while showing canonical ID, group, and the currently resolved document title. Selecting an alias still stores the canonical `tag_id`.
3. The modal inserts the wrapped token through the captured, revision-guarded Source range. Tag keeps selected prose as the occurrence Title; identity is immutable after insertion.
4. Put the caret inside a token to open its family Info view. The Title may be updated or the exact token range removed; retargeting remains remove followed by the family Add action.
5. **Rebuild** resolves a recognized token only when the private target lookup supplies one workable destination. Unknown or unavailable source remains literal and creates no usage row.
6. A resolved Tag keeps its exact relative Analysis parent-plus-subdocument link in rendered content and Tag Info, so Manage stays on the current Docs Viewer origin and public output stays on the current site origin. Catalogue destinations alone are rebased to the configured public-preview origin in Manage.
7. The manage-only [Semantic Tokens Report](/docs/?scope=studio&doc=d-20260726-181045-a7c2e1) lists resolved Catalogue and Tag occurrences. [Docs Broken Links](/docs/?scope=studio&doc=d-20260423-165116-e7f7e9) diagnoses unresolved kinds, unknown Tags, zero Tag associations, and unavailable chosen Tag destinations without writing source.

## Ownership

- Docs Viewer source-editor core owns the Markdown buffer, selection, dirty state, save, and Rebuild workflow.
- Catalogue owns canonical Work and Series records. Tag Registry owns canonical Tag identity, group, aliases, and the optional primary override; Analysis Tag documents own association membership and order.
- The Docs Viewer Semantic Tokens feature owns token definitions, family contributions, parsing, build-time resolution, generated usage data, and the resolved-token report.
- Docs Broken Links owns read-only failure diagnosis. The author remains in control of source, Tag association, primary selection, or canonical-data repair.

## Registry And Generated Data

The checked-in token-definition registry is:

```text
docs-viewer/config/semantic-tokens/registry.json
```

The rebuildable manage target lookup is:

```text
docs-viewer/data/generated/semantic-tokens/target-lookup.json
```

Each scope's resolved usage index is:

```text
docs-viewer/scopes/<scope>/published/documents/semantic-tokens/index.json
```

The usage index records resolved occurrences in documents; it is not a registry or canonical target store. The token registry, canonical Tags and aliases, private target lookup, and usage directory are omitted from public projection. Public documents receive only ordinary build-time anchors.
