# Semantic Tokens Concept

## Purpose

Let an author create and maintain structured relationships from ordinary
Markdown without needing to remember or safely edit token syntax.

A token occurrence connects readable document content to a stable target:

```text
canonical target
    -> token family + concrete target type + immutable target id
    -> editable occurrence metadata
    -> local projection and relationship report
```

The first family is Catalogue. It can associate text with a Work, Series, or
Moment. The author does not need to know which type is correct before searching:
the UI uses the selected words to present plausible catalogue associations and
the author chooses the concrete target during creation.

For `nerve`, that choice might be Work `00008` or Series `105`. Once selected,
the immutable identity includes the concrete type and id. The displayed title
remains editable occurrence metadata and does not change the target.

## Author Experience

The UI, not raw syntax, is the primary authoring path:

- each family has its own source-editor toolbar action and add modal;
- selected source text prefills the title or equivalent occurrence field;
- discovery can search several concrete target types within that family;
- result type, identity, and distinguishing metadata help the author choose the
  best association before insertion;
- clicking inside an existing token opens its family-specific Info view;
- identity is visible but cannot be changed through that view;
- editable occurrence metadata can be updated and the whole token can be
  removed;
- the existing local Docs Broken Links report finds unresolved semantic-token
  links and provides the route back to source for repair.

The source remains inspectable Markdown, but ordinary use should not depend on
hand-authoring delimiters, ids, or escaped metadata.

## Invariants

- The canonical target owner remains authoritative; Docs Viewer does not copy
  its records into the token-definition registry.
- Target identity is immutable after insertion. Re-targeting means remove and add.
- The add modal is the only semantic validation gate: it confirms a current
  target selection, required occurrence fields, and serializable syntax.
- Saving and rebuilding accept user-edited source as written. A malformed,
  unsupported, or unresolved token-like string remains ordinary text and
  produces neither a semantic link nor a usage-index row; a separate read-only
  broken-links audit may still report it.
- Occurrence metadata is distinct from canonical target metadata.
- Canonical and derived target data may be displayed but is not copied into the
  token; only occurrence-specific values are authored there.
- The token-definition registry is configuration for supported token kinds; the
  derived usage index records which occurrences documents actually contain.
- A token consumes only the named target projection declared for its kind. It
  does not inspect canonical records or resolve their arrays itself.
- Usage-index attributes are rebuild-derived context, not a substitute for
  current occurrence fields or canonical target lookup. Preview images and
  similar target context are obtained by identity through the declared lookup.
- A future public consumer receives a focused payload enriched at build time;
  public readers do not resolve tokens through manage lookup or canonical data.
- The source editor remains the only owner of buffer mutation, dirty state,
  saving, and rebuild.
- Token addition and editing are manage-only.
- Token resolution is best-effort projection, not build validation; failure to
  resolve a token-like string is not a build warning or error.
- One accepted family is one complete vertical capability, not just a
  token-definition row.
- Generic source-editor core contains no token-definition registry or
  family-specific UI.
- Core **Add image** and **Add file** continue to insert ordinary Markdown.

Catalogue entities and Tags are different semantic families. Work, Series, and
Moment are concrete things an author may be referring to; Tags are abstractions
used to classify or associate content. Their UI, syntax, and report meaning
should not be collapsed into one generic search.

## Not This Feature

- a public token browser or related-content report;
- a standalone semantic-token editor or service;
- a generic graph database or continuous validation system;
- automatic conversion of ordinary links or media into tokens;
- field directives, related lists, or other executable source instructions;
- Catalogue and Tag bundled into the first delivery.
