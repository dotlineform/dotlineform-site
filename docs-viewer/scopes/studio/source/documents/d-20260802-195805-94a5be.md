# SSP-6 — Work Document Metadata Publication Delivery

## Status And Purpose

Proposed as **SSP-6** after SSP-4 can create independent `analysis/works` editorial documents and the existing Analysis Publish workflow can project reviewed viewable copies. [Sub-Scope Publishing Concept And Architecture](/docs/?scope=studio&doc=d-20260802-194358-7717ee) owns the public association and failure boundaries implemented by this delivery.

SSP-6 makes published Analysis documents discoverable from their exact public Work pages without making canonical Work records own document associations or adding another browser lookup.

## Complete Outcome

Each public Work payload at `site/assets/works/index/<work_id>.json` contains a deterministic `documents[]` projection for zero or more viewable published `analysis/works` documents that declare the exact canonical `work_id`. Each item carries a current public-safe title and URL. The Work route presents those items as a distinct metadata row rather than merging them into canonical `work.links`.

Analysis Publish, unpublish, delete, and published `work_id` changes trigger bounded follow-through for the affected old and new Work payloads after the canonical document mutation. Failure never rolls back or repeats that mutation; the prior complete Work payload remains available with explicit stale evidence where the existing publication workflow supports it.

## Delivery Discipline

SSP-6 is a focused public projection and Work-page consumer. It must not add document links to canonical `works.json`, make Work publication own Analysis document lifecycle, publish non-viewable or Manage-only documents, load the association index separately in the browser, or turn the Work payload into a general relationship record.

SSP-6.0 is a short scope-and-spec sanity gate over the accepted SSP-1 public association, Analysis Publish follow-through, Work payload generation, and Work metadata presentation. It confirms broad owners, blast radius, deliverables, risks, and stop conditions without freezing exact files, fixtures, estimates, or implementation. Each implementation stage ends with focused evidence and an independent code/diff review before the next stage begins.

## Delivery Steps

### SSP-6.0 — Confirm Scope And Delivery

- [ ] Sanity-check public Work-document metadata against the accepted SSP-1 public association contract and current Analysis Publish, document-location, Work by-ID generation, scoped catalogue rebuild, and Work metadata models; resolve only contradictions that would change the result.
- [ ] Confirm the broad blast radius across public association reads, Work payload schema/versioning, existing metadata presentation, publish/unpublish/delete/reassignment impact handling, and public isolation.
- [ ] Confirm the deliverables: deterministic `documents[]`, distinct Work metadata links, exact old/new follow-through, prior-complete-data retention, focused evidence, and concise durable owner updates.
- [ ] Stop for review if the result requires canonical Work association ownership, another browser lookup, Analysis lifecycle coupling, non-viewable/Manage publication, a general relationship payload, or another boundary excluded above. Do not produce an exact file inventory, line estimate, frozen implementation, fixture implementation, or complete test architecture at this gate.

**Checkpoint:** a concise sanity note confirms the spec, SSP-1/SSP-4 dependencies, broad owners, blast radius, deliverables, risks, public boundary, and stop condition. Stop before implementation approval.

### SSP-6.1 — Enrich Work By-ID Payloads

- [ ] Add the public-safe association reader to the Work by-ID producer.
- [ ] Project `documents[]` separately from canonical Work fields and existing authored `links`.
- [ ] Recompute payload versions from the complete enriched payload and preserve ordinary zero-document output.
- [ ] Prove Manage-only paths, local `folder_path`, non-viewable documents, association infrastructure, and Registry data remain absent.

**Checkpoint:** focused association, payload-schema/version, zero/many ordering, stale/unavailable, targeted-generation, and public-isolation evidence passes. An independent code/diff review confirms `documents[]` is a derived public projection separate from canonical Work source and authored `work.links`; the browser continues to read the existing by-ID payload and presentation remains SSP-6.2-owned. Stop before SSP-6.2.

### SSP-6.2 — Present Work Documents

- [ ] Add one distinct Work metadata row for zero or more document links using the existing metadata-panel component.
- [ ] Preserve current title, catalogue, Series, download, and authored-link rows.
- [ ] Verify duplicate titles, long labels, several documents, unavailable payloads, keyboard navigation, and narrow layout without adding a new page section or modal.

**Checkpoint:** focused renderer/component evidence and representative keyboard/narrow-layout review pass for zero, one, and several document links. An independent code/diff review confirms the existing Work payload remains the sole browser read and current metadata rows retain their owners and values. Stop before SSP-6.3.

### SSP-6.3 — Add Follow-Through And Verify

- [ ] Rebuild only affected Work payloads after successful Analysis publication changes using exact old/new subject evidence.
- [ ] Preserve source mutation success and prior complete public data on derived failure; never retry publication or document mutation implicitly.
- [ ] Run focused association, payload, publication, renderer, public-isolation, targeted-rebuild, lint, whitespace, and realistic manual checks.
- [ ] Perform the independent final code/delivery review, reconcile completion claims with exact evidence and omissions, and record any bounded follow-up trigger.
- [ ] Transfer the shipped `documents[]` contract to the durable Catalogue payload and Work-page owners.

## Completion Evidence

- A published viewable `analysis/works` document appears only on the exact declared Work page.
- Several documents may appear for one Work in deterministic order without a scalar or inferred-primary shortcut.
- Non-viewable, unpublished, deleted, unavailable, or reassigned documents have explicit tested behavior.
- Canonical Work source and authored `work.links` remain unchanged.
- The Work route still performs its existing single by-ID payload fetch.
- Targeted follow-through updates exact affected Work payloads and does not repeat its initiating document mutation.

The [Sub-Scope Publishing feature](/docs/?scope=studio&doc=d-20260802-194357-4d857b) owns the flat SSP sequence. SSP-6 owns only public Work payload enrichment and presentation.
