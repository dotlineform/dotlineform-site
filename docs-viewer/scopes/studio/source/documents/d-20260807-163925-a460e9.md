# SSP-6.1 — Uncataloged Files Report Evidence

## Outcome

SSP-6.1 is complete. The ordinary local **Uncataloged Files** parent document now runs one focused producer on mount and Run/Refresh. It lists only Folder and File name for direct ordinary non-hidden files in exact existing canonical Work source directories that are not canonical Work primary sources. File name activates the existing local-target service, which revalidates the encoded `projects/...` target and reveals the file in Finder without opening it.

SSP-6 is parked before SSP-6.2. Missing Source Files remains unimplemented, and the current Studio Project State route, APIs, activity entry, generator, static Markdown, tests, and image-extension owner remain unchanged for SSP-6.3.

## Delivered Contract

- `docs_uncataloged_files_report_v1` derives distinct directories from complete canonical `project_folder` plus optional `project_subfolder`, scans no other directory and does not recurse, and excludes hidden entries, directories, and known Work-detail trees.
- Existing canonical Work source files are removed by resolved filesystem identity, so filesystem-equivalent Unicode spellings refer to the same file while every displayed filename retains its discovered spelling.
- The response's `report` object contains only `schema_version` and ordered `rows`; each row contains only `folder`, `file_name`, and the encoded `local_target`. The browser shows only the two specified columns, one Run/Refresh control, and ordinary busy, empty, or current-error state. It creates no count, summary, timestamp, generated Markdown, retained presentation, search, sort, copy, or mutation control.
- The local report registry, explicit loader, management service, `POST /docs/uncataloged-files`, and existing `POST /docs/open-local-target` are the complete runtime path. The public report registry does not expose this report, and no absolute filesystem path enters its response or browser state.
- The external local `dotlineform` source document `d-20260807-163356-b376d7` is the parent report host. Its generated by-ID document, tree, recent list, and search entry identify `viewer_report: uncataloged_files` with `viewer_report_access: local`.
