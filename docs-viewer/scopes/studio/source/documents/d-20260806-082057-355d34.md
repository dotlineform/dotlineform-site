# SSP-3.1 — Insert Subject Link Evidence

## Outcome

SSP-3.1 is complete at its implementation checkpoint. Manage Markdown Source now exposes one **Insert subject link** action for an exact sub-scope document target. The action rereads that target's canonical normalized subject, plans one exact reference through the existing semantic-token or local-folder serializer, and gives the resulting bytes to the Source editor's ordinary selection replacement owner.

Work and Series use the current exact Catalogue identity, current target title and existing semantic-token syntax. Folder uses the existing `dlf-local:` encoder plus a new non-opening validation route that shares the local-open owner's path confinement and existence checks. None, malformed, conflicting, invalid, missing, unavailable, mismatched metadata and failed replacement states insert nothing and report a contained reason.

The Source integration preserves ordinary input, dirty-state and focus behavior. It does not capture a revision, add a concurrency protocol, mutate front matter, save, rebuild, infer a fallback, or show a success message.

## Focused Evidence

- Exact planning and real Source-mode integration pass for Work, Series and Folder bytes, exact metadata targeting, ordinary replacement, dirty state, focus return, no write call and the explicit failure states.
- Configured-scope provider coverage confirms routed Source contexts forward metadata reads and local-target validation. A live check on the exact `dotlineform/projects` document `d-20260801-212422-3aa736` inserts `[[catalogue:series:001|10,000]]`, returns focus, marks only the unsaved buffer dirty and leaves no status message; the verification buffer was discarded without saving.
- Manage now rebases semantic links after an asynchronous sub-scope report finishes mounting, rather than before its detail HTML exists. The real Manage smoke protects the site-preview origin, and the exact live document resolves the inserted Series link to `http://127.0.0.1:4000/series/?series=001`.
- The Catalogue-token, sub-scope subject and local-folder module smokes pass after the shared subject normalizer was made idempotent for normalized states without evidence.
- The real Manage shell smoke passes with the action in the Markdown Source toolbar and the action registered against the active document.
- Focused local-link, route, metadata and static-asset service tests pass: 50 tests.
- Explicit changed-file JavaScript lint, Python lint, Python compilation and `git diff --check` pass.

## Independent Review

Diff review confirms identity comes only from the exact managed target and its metadata response; Work/Series lookup remains Catalogue-owned; Folder serialization and confinement remain local-link-owned; and insertion remains Source-owned. No Resolver, Project State, relationship expansion, generic Source-command framework, automatic rewrite, save or public-local behavior was introduced.

SSP-3 is stopped before SSP-3.2 verification and durable owner-document transfer.
