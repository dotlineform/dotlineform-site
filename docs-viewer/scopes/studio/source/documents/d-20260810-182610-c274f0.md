# RB-1 — Report Blocks Cutover Delivery

## Status And Purpose

RB-1 is in progress at the RB-1.0 review gate. It delivers the complete [Report Blocks](/docs/?scope=studio&doc=d-20260810-180114-003d2a) source-contract cutover: every report-host document moves from `viewer_report*` front matter to one validated block in its Markdown body, every consumer reads one normalized descriptor, and the browser mounts the report at that exact authored position.

RB-1.0 is complete as a specification and footprint sanity check. No parser, product, source-host migration, generated cutover, or durable-documentation transfer has started. Stop here for review before RB-1.1.

The feature contract is settled. RB-1.0 identifies the exact implementation seams and migration footprint; it does not reopen the rejected multiple-instance, parameter, registry, plugin, or capability models already owned by Report Blocks.

## Complete Outcome

- A document contains zero or one report block. Multiple blocks and a mixture of report front matter plus a report block fail source validation.
- One code-owned parser recognizes the fixed block grammar only in accepted Markdown contexts and returns one normalized document-level descriptor.
- The descriptor carries registered report identity and the existing closed assignment context: access intent, scope, preset, and sub-scope where applicable.
- The docs builder emits one inert report host at the block's exact content position plus one normalized payload descriptor. It no longer appends an independently created report root after the document.
- Public and Manage report composition resolve the descriptor through their existing separate metadata and executable loader allowlists, then mount into that exact generated host.
- The immutable document `doc_id` remains the report-host identity.
- Sub-scope lifecycle, location, publication, deletion, transfer, and other exact-host consumers use the same normalized source owner as the builder rather than reading private front-matter fields or independently scanning Markdown.
- Every current repository or external-local report-host source is converted in one bounded migration, every affected projection is rebuilt, and active product code contains no compatibility reader or precedence rule for the retired fields.
- Existing reports retain their report id, access, scope, preset, sub-scope, data authority, public/local composition, route state, and behavior apart from their authored placement.

## Current Owners To Inspect

RB-1.0 starts from these ownership seams and narrows the exact changed set before implementation:

- Docs source parsing, `DocRecord`, content-token resolution, Markdown rendering, Manage/public metadata projection, and report metadata registry validation;

- complete-source Copy, Import, Review, package, and static-export workflows that could otherwise treat a report block as ordinary transferable prose;
- every current report-host source across repository and configured external-local scopes, including lifecycle-created `docs_subscope` hosts;
- focused builder, service, public-boundary, report-module, sub-scope lifecycle, and route smokes; and
- [Reports](/docs/?scope=studio&doc=d-20260513-105343-6de36b), [Report Capability and Composition](/docs/?scope=studio&doc=d-20260810-173738-703ecd), and [Sub-Scope Customisation Architecture](/docs/?scope=studio&doc=d-20260731-155053-3929e2) as likely durable documentation owners.

This is an inspection route, not a frozen file inventory. RB-1.0 must report exact files, reused seams, estimated production/test footprint, and any workflow whose existing report-host behavior needs an explicit retain, omit, or reject decision.

#### RB-1.0 sanity record

**Source grammar.** One report block uses this exact source form:

```text
:::report
id: docs_index_table
access: local
scope: analysis
preset: scope_documents_admin
:::
```

The opener is exactly `:::report` and the closer is exactly `:::` at column one, each on its own line with no trailing content. The block must be separated from surrounding Markdown by at least one blank line unless it begins or ends the body. Interior lines use exactly `key: value`; blank lines, indentation, inline attributes, quoting, escaping, multiline values, and duplicate keys are invalid. `id` and `access` are required. Optional keys are `scope`, `preset`, and `sub_scope`; the emitter uses that canonical order, while the parser does not make key order semantic. Identifier values use lowercase ASCII letters, digits, `_`, and `-`, beginning with a letter or digit. `access` is exactly `local` or `public`. There are no aliases such as `report`, `subscope`, or `manage`.

The parser ignores apparent declarations inside backtick or tilde fenced code, indented code, inline code, HTML comments, and raw `<pre>` or `<code>` regions. A declaration-like `:::report` line outside those contexts is structural and must either form one valid block or fail. Two valid blocks, an unclosed block, malformed interior syntax, unknown keys or values, an unknown report id, a report block in a sub-scope child document, or any mixture with one of the five retired front-matter keys fails with the source path, line, and exact source range. The five retired keys fail even when blank.

The source registry remains `docs-viewer/config/reports/reports.json`; no new registry is introduced. Report ids and presets validate against it. `scope` validates against configured scopes and is accepted only by `docs_index_table`, `docs_broken_links`, and `semantic_tokens`. `preset` is accepted only by `docs_index_table` and must name one of that registry entry's presets. `sub_scope` is required only by `docs_subscope`, is forbidden for other reports, and must name one configured child collection of the host document's own scope. All other current reports accept only `id` and `access`.

**Normalized owner and projection.** The new shared Python owner returns one immutable descriptor with `id`, resolved `access`, optional `scope`, `preset`, and `sub_scope`, plus exact source offsets and line numbers used only in process. The JSON projection is one fixed-shape `report` object with those five keys; absent optional values are `null`, and source ranges are never projected. A non-report document has no `report` key.

Manage by-ID payloads retain every valid local or public descriptor. Public by-ID payloads emit a descriptor only when `access` is `public`. The builder replaces the source range with `<section class="docsViewerReport" data-docs-viewer-report-host aria-label="Document report"></section>` for each projection that carries the descriptor; it removes a local-only block from public content. Tree, Recent, search, manifests, and semantic-token indexes do not receive report metadata.

The existing Manage and public document-extras entrypoints read `payload.report`, require exactly one generated host inside the current document content, and pass that host to the existing separate registry and executable-loader allowlists. They never create or append a second root. A public-intended but unpromoted report keeps its descriptor and host and receives the existing contained unavailable state; a local-only report has neither in public output; promoted `docs_subscope` continues to mount through the public registry and loader. Navigation replaces the document content and therefore removes the exact host; the existing `docs_subscope` mutation observer publishes its unmount event, and stale asynchronous work must not mutate a host that is no longer contained by the current document root. No controller, stylesheet, loader graph, data authority, route, or report-module contract changes.

**Sub-scope lifecycle.** Parent-host discovery in the parent builder, canonical document URLs, document-location source and public projections, Publish placement, lifecycle claimant checks, recorded-host deletion validation, and transfer route rewriting all consume the shared descriptor. New sub-scope creation writes the canonical block immediately after the generated H1. Lifecycle deletion still requires the recorded immutable `report_host_doc_id`, exact source revision, `docs_subscope`, local access, the exact configured child id, and one claimant. The existing `analysis/works` and `dotlineform/projects` lifecycle source-revision receipts change once during migration; their ids, tool ownership, collection configuration, URLs, and deletion rules do not.

**Complete-source workflow decisions.** The direct Source editor retains report blocks and validates the complete candidate before write. Generic Copy/Document Transfer rejects a selected report-host document because Report Blocks authorizes no host-transfer contract; ordinary child copying is unchanged, and transfer route rewriting still resolves the source collection's parent host through the shared descriptor. Ordinary Import rejects any incoming report block and rejects replacement of an existing report-host document, so imported prose cannot acquire or erase report configuration. The current returned `document-content` Review flow may export report-host prose but cannot apply a replacement to that exact host; the inactive `document-full-source` idea receives no new support. `document-tree` omits report configuration, while rendered `document-content` packages explicitly omit the empty generated host. Static HTML export retains the generated host at its exact content position as inert markup; it exports no report descriptor, registry, loader, service, or report JavaScript. Metadata-only edits, Publishability changes, and exact Source edits retain and revalidate the existing block.

## Focused Evidence Contract

RB-1.0 chooses the smallest exact commands after the changed seams are known. Expected evidence includes:

- pure parser/normalizer tests for grammar, cardinality, ignored contexts, attributes, registry validation, and normalized descriptors;
- builder tests for exact placeholder position and projection-specific payload/HTML behavior;
- service tests for sub-scope creation/discovery, document locations, publish gating, deletion, transfer, and each affected complete-source workflow;
- JavaScript module tests or smokes proving public/Manage mounting into the existing host, unavailable behavior, navigation cleanup, and absence of a second appended root;
- a full current-host migration assertion over authoritative sources and generated payloads;
- focused `bin/lint-python` and `bin/lint-js` over changed source, affected scope docs/search builds, the warranted Docs Viewer smoke profile, and `git diff --check`.

Broad suites are warranted only when RB-1.0 finds a shared source or lifecycle owner whose risk cannot be proved through narrower tests. Browser checks are reserved for exact route/module/mount boundaries rather than ordinary layout or copy review.

## Acceptance

RB-1 is complete only when:

- every active report-host document has exactly one valid report block and no `viewer_report*` front matter;
- every non-report document has no report block and emits no report descriptor or host;
- invalid, duplicate, mixed, and unknown declarations fail with exact source evidence;
- builders and services consume one normalized source owner, and browsers consume one normalized payload descriptor and exact inert host;
- reports preserve current public/local availability, data sources, route state, lifecycle behavior, and immutable document host identity;
- `docs_subscope` creation, public child reachability, location composition, deletion, transfer, and recorded lifecycle host behavior remain exact;
- complete-source workflows cannot accidentally turn report configuration into unvalidated prose or executable browser configuration;
- active source, production code, config, tests, and generated products contain no compatibility reader or stale field contract;
- durable Reports and sub-scope documentation are current.

## Durable Closeout

The primary shipped contract moves into Reports. Exact sub-scope report-host discovery remains in Sub-Scope Customisation Architecture, and Report Capability and Composition continues to own public/local module, data, contribution, and stylesheet separation.

At closeout, Report Blocks should be reviewed for retention as a concise feature rationale or retirement after its stable mental model has been transferred. RB-1 remains as delivery evidence until the user explicitly approves its closeout treatment. Catalogue Works Report Migration becomes eligible for its own sanity checkpoint only after RB-1 is accepted and closed.
