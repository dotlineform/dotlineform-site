# Media Publication Check

## Purpose

Give an author a quick sense of media weight before working documents and their referenced media move into Analysis or become public. The author already decides whether an Excel file, large PDF, or other attachment is appropriate; the first check should support that judgement rather than replace it with a policy engine.

## Initial Direction

Reuse the existing Dotlineform-to-Analysis Copy preview and Analysis Publish confirmation. The first useful addition may be only:

- unique referenced media count; and
- total referenced media bytes.

Copy and Publish answer different moments. Copy is where selected working documents can bring media into Analysis storage. Publish is where reviewed Analysis documents become public. After the Scope Media report provides representative data, a short design checkpoint should decide whether both confirmations need the figures or whether one well-placed check is sufficient.

The labels must be honest. Total referenced bytes are not page-download size, and they may include media already present in Analysis or already public. Do not add new/newly-public calculations until there is a demonstrated decision that requires them.

## UI Direction

Keep the existing confirmation workflow looking simple. A compact line such as `12 media · 4.8 MB` is preferable to a table, scoring system, warning hierarchy, or additional modal. When more detail is useful, link to or open the relevant filtered [Scope Media Management](/docs/?scope=studio&doc=d-20260720-100017-9855dd) report rather than duplicating its document/media inventory inside Copy or Publish.

This is initially an information check, not an automatic blocker. It has no default size threshold and does not reject a document because of extension, missing source evidence, or media size. A later warning can be proposed only after real report use identifies a repeatable mistake that the number alone does not prevent.

## Delivery Order And Stance

Design this after [Media Sources](/docs/?scope=studio&doc=d-20260812-102047-a3c9e7) and the first Scope Media report. Those earlier outcomes establish source evidence, exact reference aggregation, and representative byte totals. This feature should consume that seam rather than create a second scanner or verification model.

The specification is deliberately provisional and UI-led. A future delivery should add the smallest visible figure to existing previews, reuse existing count/size aggregation, and stop if it begins to require a second Copy or Publish workflow.

Verification should normally be one focused aggregation/service case and any existing confirmation-rendering module check that can be extended cheaply. Visual placement and wording belong to manual UI review. Do not add a new browser smoke, large fixture corpus, or broad publication suite for a byte-count line.

## Boundaries

- No image optimisation or attachment transformation.
- No source verification, checksum comparison, content inspection, or file-type policy.
- No automatic threshold, rejection, scoring, health status, or background audit.
- No duplicate media report inside Copy or Publish.
- No new publication action, combined Copy-and-Publish workflow, or change to `publishable` ownership.
- No rollback, retained rollback copy, recovery workflow, or automatic retry.

No delivery has been proposed and no implementation has started.
