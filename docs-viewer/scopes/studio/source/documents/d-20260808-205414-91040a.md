# iPad Docs Viewer

## Purpose

Establish whether the integrated Docs Viewer and a bounded local Studio workflow can be run usefully on an iPad from a local repository checkout while retaining direct access to the external scopes already synchronized through iCloud Drive.

The intended result is a repeatable, evidence-backed working environment rather than a native iPad application or an assumption that every macOS development tool can be reproduced. The first proof should identify the reliable working slice, exact platform exclusions, and any repository change that would materially improve the setup.

- [iPad Docs Viewer Concept And Feasibility](/docs/?scope=studio&doc=d-20260808-205415-750cfd) owns the proposed stack, expected capability boundary, iCloud and runtime risks, and the configuration decision.
- [iPad Docs Viewer Installation And Proof](/docs/?scope=studio&doc=d-20260808-205416-9f6d6c) owns the current installation procedure, device proof gate, evidence receipt, and pass/fail rules.
- [iPad Studio Working Slice And Proof](/docs/?scope=studio&doc=d-20260808-212749-af71c2) owns the incremental Studio service composition, supported editing slice, build and media boundary, touch-layout risks, and Studio-specific proof gate.

There are no implementation deliveries yet. Add one only when a real-device proof exposes one independently complete repository or configuration outcome; record proof evidence in the installation guide without treating installation itself as shipped product work.

## Boundary

This feature is distinct from [Standalone Docs Viewer](/docs/?scope=studio&doc=d-20260511-120352-90ffa6), which owns a future packaged composition with an extracted core, and [Public Docs Viewer Mobile Experience](/docs/?scope=studio&doc=d-20260723-191039-f8cb88), which owns public-reader interaction design. This feature evaluates the current integrated repository checkout under iPadOS constraints.

Codespaces remains a useful remote development fallback for repository-local work, but it cannot directly mount the user's iCloud File Provider tree and therefore does not prove external-scope operation. This feature does not introduce cloud replication, a second external-scope authority, or a Codespaces-to-iCloud synchronization workflow. Adding Studio to the proof does not change Docs Viewer Project State ownership: Project State remains a read-only reconciliation surface, while Studio remains the exact destination for existing Work and Series editing links.
