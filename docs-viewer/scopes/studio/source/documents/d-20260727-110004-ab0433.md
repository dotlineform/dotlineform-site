# Flat Tag Identity

## Result

A canonical tag is one globally unique normalized name such as `moss`.
`subject:moss`, a singular `group`, a `groups` array, allowed-group policy, and
group-derived analytical behavior are not part of the tag model.

Assignments and aliases refer directly to the flat `tag_id`. Interpretative
meaning belongs in the tag's document after
[Tag-document linking](/docs/?scope=studio&doc=d-20260726-211842-cc8f6c);
this feature does not replace group with another classification field.

## Why this is separate

Flattening identity changes canonical registry keys and every assignment and
alias that refers to them. It also requires human decisions where the same
label currently appears in more than one group. That is a coherent vocabulary
migration, not part of document association or report filtering.

The existing registry `description` remains available through this feature so
Tag-document linking can use it as one-time seed content. Removing that field
before the documents exist would discard the current semantic source.

## Boundary

- [Tag Vocabulary Import Retirement](/docs/?scope=studio&doc=d-20260726-214250-28ae69)
  removes obsolete bulk paths before this feature changes canonical identity.
- This feature owns flat IDs, manual collision decisions, reference migration,
  and removal of group-dependent executable behavior.
- It does not create or associate documents, remove registry descriptions, or
  implement semantic-token targets.
- Tag-document linking follows this feature and establishes the required
  registry-to-document relationship.
