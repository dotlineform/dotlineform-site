# Working generation and publication

## Exact work during authoring

Source Save already has a validated candidate and the saved source it replaces. Rebuild has the exact requested source. Each can reuse saved navigation or manifest rows and carry changes through rendering and the direct relationships they affect. This keeps ordinary work proportional to the requested source, required metadata and affected targets. Complete maintenance is the explicit path when a change applies across the corpus. It reuses loaded records across generation, relationships, ready-media checks and discovery. [Exact and full generation](../reference/Builder.md#docs-build-flow) · [Save and Build optimisation history](../deliveries/Save_Build_Optimisations.md)

## Eligibility in Working

The authoring workspace owns Draft, the exclusion list, hierarchy, book placement and report hosts. It has the inputs needed to project the eligible tree and compare against its previous public membership. Keeping this decision before transfer preserves authored data and allows an inherited withdrawal or restoration to carry its exact effects. Related Links can preserve the authored destination when its document body is withheld. The generated views remain useful as input to the next preparation operation. [Eligibility and queue](../reference/Builder.md#publish-preparation) · [Original exclusion decision](../deliveries/Publication_Ignore_List.md#original-delivery-direction)

## Selected transfer and explicit release

The queue records completed operation effects instead of another document/media inventory. Publish applies each selection and removes it after successful distribution. A failure can leave partial destination effects and pending selections for correction. Preview remains an applied artifact between Working and the configured destinations. Pages deploys the chosen committed repository snapshot, while R2 transfers can take effect at Publish. Keeping these decisions explicit preserves a review point for the public site.
