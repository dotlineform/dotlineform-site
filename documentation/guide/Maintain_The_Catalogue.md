# Maintain the Catalogue

Start Studio with `bin/local-studio` and open the Catalogue Work Editor at `/studio/catalogue-work/`. Run Docs Viewer Manage for the later Regenerate and Publish steps. Studio owns the saved Works, Series, Galleries and memberships in `studio/data/canonical/catalogue/`. A Work belongs to exactly one Series and may belong to several Galleries. A Gallery can also be relevant to a whole Series while keeping its own members. [Start a local surface](How_The_Site_Fits_Together.md#start-a-local-surface) · [Work Editor](../studio/Catalogue_Work_Editor.md) · [Gallery and Series definitions](../studio/Catalogue_Work_Editor.md#gallery-and-series-definitions)

## Replace a Work’s image

1. **Save in Studio.** Open the Work, choose a replacement image and save. Studio saves the Work, prepares its image renditions and thumbnail in Projects staging, and records the Work ID and image selection in `working/catalogue-updates-pending.json`. The editor can show the staged image as soon as Save completes. [Work media authoring](../studio/Catalogue_Save_And_Refresh.md#work-media-authoring)
2. **Refresh Catalogue in Studio.** Use the button in the Work Editor header. Refresh prepares `working/generated/catalogue/works/index/<work_id>.json` and copies the selected ready images into Working. After the handoff and staging cleanup, it marks the Work as refreshed in the updates queue. [Refresh boundary](../studio/Catalogue_Save_And_Refresh.md#refresh-boundary)
3. **Regenerate in Docs Viewer Manage.** Open the Catalogue collection and choose **Regenerate**. It reads the refreshed Work and adopts its metadata, image facts and Gallery references into the Catalogue document with the same Work ID. After generation, it adds the Work and its selected image set to `working/catalogue-publish-pending.json` and removes the completed Work from the updates queue. [Regenerate timing](../studio/Catalogue_Save_And_Refresh.md#regenerate-timing) · [Adopted Work data](../studio/Generated_Data_Contracts.md#catalogue-reference-and-presentation)

Studio can show saved edits immediately because it owns canonical data and staged media. Refresh hands ready records and media to Working. Regenerate uses those completed inputs to keep the Work document and the selected media together for publication. To remove a Work from the Catalogue, start with **Delete** in Studio and follow the same two steps. The saved deletion selection carries the Work ID and its owned media through to Publish. [Updates queue](../studio/Catalogue_Save_And_Refresh.md#updates-queue) · [Work deletion](../studio/Catalogue_Work_Editor.md#delete)

## Rename a Gallery used by Works

1. **Save the definition in Studio.** Open the Gallery’s Edit dialog, change its title and choose **OK**. Save records the changed Gallery and its shared output in the updates queue. It also selects the Works whose documents use the Gallery, including direct members and Works in a Series to which the Gallery is relevant. [Gallery and Series definitions](../studio/Catalogue_Work_Editor.md#gallery-and-series-definitions) · [Gallery save service](../../studio/services/catalogue/catalogue_gallery_service.py)
2. **Refresh Catalogue in Studio.** Refresh updates the Gallery’s title in its by-ID record and selected shared indexes, including any affected Series-to-Gallery links. It places the completed public Gallery output directly in the publication queue. It also refreshes the affected Work records and marks those Work entries ready for Regenerate. [Refresh boundary](../studio/Catalogue_Save_And_Refresh.md#refresh-boundary) · [Shared publication output](../studio/Catalogue_Deployment.md#final-shared-output)
3. **Regenerate in Docs Viewer Manage.** Regenerate updates the affected Work documents so their Gallery links carry the renamed title. It adds those Works to the same publication queue. The rename itself selects no media transfers. [Regenerate timing](../studio/Catalogue_Save_And_Refresh.md#regenerate-timing) · [Adopted Work data](../studio/Generated_Data_Contracts.md#catalogue-reference-and-presentation)

A change limited to the Gallery’s **Description** or marker follows **Save → Refresh Catalogue**. These fields belong to the shared Catalogue report data, so Refresh queues the completed `galleries/report-search.json` and there are no Work entries for Regenerate from that edit. [Gallery report data](../studio/Catalogue_Indexes_And_Payloads.md#generated-read-models)

Check the refreshed Work in the Catalogue collection and check the Gallery link or search row for the renamed title. If Portfolio Search still shows the previous Gallery title, update discovery explicitly before publishing. [Refresh Search and Recent](Publish_And_Deploy.md#1-prepare-the-change)

After the relevant preparation finishes, use [Publish and deploy](Publish_And_Deploy.md) to release the queued output. Return to the [guide contents](README.md).
