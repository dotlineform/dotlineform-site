# Maintain the Catalogue

Start Studio with `bin/local-studio` and open the Catalogue Work Editor at `/studio/catalogue-work/`. Run Docs Viewer Manage for the later Regenerate and Publish steps. Studio owns the saved Works, Series, Galleries and memberships in `studio/data/canonical/catalogue/`. A Work belongs to exactly one Series and may belong to several Galleries. A Gallery can also be relevant to a whole Series while keeping its own members. [Start a local surface](How_The_Site_Fits_Together.md#start-a-local-surface) · [Work Editor](../reference/Catalogue_Work_Editor.md) · [Gallery and Series definitions](../reference/Catalogue_Work_Editor.md#gallery-and-series-definitions)

## Replace a Work’s image

1. **Save in Studio.** Open the Work, choose a replacement image and save. Studio saves the Work, prepares its image renditions and thumbnail in Projects staging, and records the Work ID and image selection in `working/catalogue-updates-pending.json`. The editor can show the staged image as soon as Save completes. [Work media authoring](../reference/Catalogue_Save_And_Refresh.md#work-media-authoring)
2. **Refresh Catalogue in Studio.** Use the button in the Work Editor header. Refresh prepares `working/generated/catalogue/works/index/<work_id>.json` and copies the selected ready images into Working. After the handoff and staging cleanup, it marks the Work as refreshed in the updates queue. [Refresh boundary](../reference/Catalogue_Save_And_Refresh.md#refresh-boundary)
3. **Regenerate in Docs Viewer Manage.** Open the Catalogue collection and choose **Regenerate**. It reads the refreshed Work and adopts its metadata, image facts and Gallery references into the Catalogue document with the same Work ID. After generation, it adds the Work and its selected image set to `working/catalogue-publish-pending.json` and removes the completed Work from the updates queue. [Regenerate timing](../reference/Catalogue_Save_And_Refresh.md#regenerate-timing) · [Adopted Work data](../reference/Generated_Data_Contracts.md#catalogue-reference-and-presentation)
4. **Publish in Docs Viewer Manage.** Check the image on the Working Catalogue document and then Publish. The Work unit applies the document and selected image set to Preview, distributes the document and thumbnail to the repository and the primary renditions to R2, and clears the completed unit. [Per-Work Publish](../reference/Catalogue_Save_And_Refresh.md#per-work-publish)

To remove a Work from the Catalogue, start with **Delete** in Studio, then Refresh, Regenerate and Publish. The saved deletion selection carries the exact Work ID and owned media through those steps. [Updates queue](../reference/Catalogue_Save_And_Refresh.md#updates-queue) · [Work deletion](../reference/Catalogue_Work_Editor.md#delete)

## Rename a Gallery used by Works

1. **Save the definition in Studio.** Open the Gallery’s Edit dialog, change its title and choose **OK**. Save records the changed Gallery and its shared output in the updates queue. It also selects the Works whose documents use the Gallery, including direct members and Works in a Series to which the Gallery is relevant. [Gallery and Series definitions](../reference/Catalogue_Work_Editor.md#gallery-and-series-definitions) · [Gallery save service](../../studio/services/catalogue/catalogue_gallery_service.py)
2. **Refresh Catalogue in Studio.** Refresh updates the Gallery’s title in its by-ID record and selected shared indexes, including any affected Series-to-Gallery links. It places the completed public Gallery output directly in the publication queue. It also refreshes the affected Work records and marks those Work entries ready for Regenerate. [Refresh boundary](../reference/Catalogue_Save_And_Refresh.md#refresh-boundary) · [Shared publication output](../reference/Catalogue_Save_And_Refresh.md#final-shared-output)
3. **Regenerate in Docs Viewer Manage.** Regenerate updates the affected Work documents so their Gallery links carry the renamed title. It adds those Works to the same publication queue without adding an image or attachment change. [Regenerate timing](../reference/Catalogue_Save_And_Refresh.md#regenerate-timing) · [Adopted Work data](../reference/Generated_Data_Contracts.md#catalogue-reference-and-presentation)
4. **Publish in Docs Viewer Manage.** Check the renamed Gallery in Working and its link on an affected Work. Publish after both paths are ready so the release carries the renamed Gallery and the updated Work links. Publish distributes the Work documents before the final Catalogue shared selections. [Final shared output](../reference/Catalogue_Save_And_Refresh.md#final-shared-output)

A change limited to the Gallery’s **Description** or marker follows **Save → Refresh Catalogue → Publish**. Refresh forwards the shared report update in `galleries/report-search.json`. This edit produces no Work entries for Regenerate. [Gallery report data](../reference/Catalogue_Indexes_And_Payloads.md#generated-read-models)

To release the renamed title in Portfolio Search too, run **Refresh Search and Recent** before publishing. [Discovery preparation](Publish_And_Deploy.md#1-prepare-the-change)

For an implementation change, follow the active route from its template and browser controller through the request, source transaction and Save/Refresh completion owners. The developer trace follows a Work edit and a shared definition change through those modules. [Studio composition](../reference/Studio.md) · [Save and Refresh implementation](../reference/Catalogue_Services.md#follow-a-work-save-and-refresh)

Review the resulting repository snapshot, then commit, push and deploy it separately. [Publish and deploy](Publish_And_Deploy.md) · [Guide contents](README.md)
