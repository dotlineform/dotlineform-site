# Catalogue Series Management

Series management lives in the Work editor at `/studio/catalogue-work/`. The standalone Series editor route and its dedicated browser modules are retired, with no redirect or compatibility route. Studio home links to the Work editor and field registry.

The left-hand Series search selects the saved membership list. Choosing a member Work opens it for editing. Series membership remains the exact `series_id` on each Work; assignment changes use the Work editor's ordinary Save. Series and Gallery membership remain independent.

The edit icon opens the title-only modal. OK saves the selected Series title, Cancel discards the modal changes, and New starts an empty title for a new Series. Creation occurs only on OK, with the next numeric ID suggested from a fresh canonical lookup. It selects the newly created, empty Series without changing the current Work draft. The adjacent delete icon is available only for an empty saved Series and uses preview, confirmation and server-side revision/membership validation.

Canonical Series records contain `series_id` and `title`. See the [Catalogue Source Model](d-20260519-000000-a0da45.md) for the exact save, membership and output boundaries. Retired Series dates and ordering fields are not restored by the modal.

## Runtime Ownership

`catalogue-work-series-browser.js` owns browsing and action availability, `catalogue-work-series-modal.js` owns title editing and creation, and `catalogue-work-series-actions.js` owns confirmed empty-Series deletion. `catalogue-series-records.js` supplies search and next-ID suggestions. These modules use shared search, record-list and modal controls; they do not depend on the retired editor.

The existing Series read/create/save and Catalogue delete APIs remain active for these Work editor controls. `catalogue-editor-service-client.js` owns browser write transport; services under `studio/services/catalogue/` own revision checks, canonical validation and writes. [Catalogue output completion](d-20260519-202931-0c703e.md) refreshes affected local records and lookups. A later output failure preserves the canonical save or deletion and remains visible.
