# Catalogue Series Editor

## What It Does

Use `/studio/catalogue-series/` to create, find, edit or delete canonical Series.

- `?series=<series_id>` opens one Series.
- `?mode=new` starts a new canonical Series, which may remain empty.
- New mode suggests an ID and permits a valid unused replacement.

Series metadata lives in `studio/data/canonical/catalogue/series.json`. Each Work holds its optional singular `series_id`; see the [Catalogue Source Model](/docs/?scope=studio&doc=d-20260519-000000-a0da45).

Ordinary Save maintains the generated Series and any Works whose membership changes.

## Open And Edit

Search reads the private Studio Series search projection. Opening a Series loads its exact record, server-issued revision and member Work summaries. New mode offers the form and Save; membership and deletion require a persisted Series.

Series retain descriptive metadata and `sort_fields`. They have no publication status, publication date, type or primary Work. Exact required fields and validation live in `catalogue-series-fields.js` and the canonical source services.

## Membership

- Member-list New opens the Work editor with this Series preselected.
- Removing a member stages a change; Save clears that Work's `series_id`.
- A removed Work remains a valid ungrouped Work. No replacement member or publication action is required.
- Assignment or reassignment of an existing Work is available in the Work editor, including bulk editing.
- `sort_fields` remains the Series ordering policy; membership itself is a single optional value on each Work.

Membership, document subjects, parentage and token composition remain independent.

## Save And Delete

Save sends the Series patch and its revision, plus only the changed Work memberships and their revisions. The service rejects a stale Series or changed Work before writing, validates the combined state and writes the affected canonical families through one transaction. Output completion refreshes the affected Series, changed Works, related indexes and any required media, then private Studio lookups. The editor updates its saved baseline and revisions.

A later output or editor-refresh error preserves the saved canonical result and identifies the incomplete step. There are no separate Build, Publish or Unpublish commands, and Save does not refresh Docs semantic lookups.

Delete previews the canonical effect, then checks the Series revision and validates again before applying. It deletes the Series and clears assignments on its member Works, preserving those Works and their Details. Output completion removes the deleted Series payload and refreshes the retained Works and indexes. Success returns to the Series editor; an output failure does not restore the deleted canonical Series.

## Runtime Ownership

The browser route, fields/form, selection, membership state and actions have focused modules under `studio/app/frontend/js/`. `catalogue-series-membership.js` owns staged membership changes; `catalogue-series-actions.js` coordinates Save and Delete. `catalogue-editor-service-client.js` owns transport.

Server dispatch starts in `studio/app/server/studio/studio_catalogue_api.py`. Series mutation and deletion services under `studio/services/catalogue/` own combined validation, revision checks and writes. Browser confirmation is not mutation authority.

The shared [Route Ready State](/docs/?scope=studio&doc=d-20260625-162242-b0b6c7) is exposed on `#catalogueSeriesRoot`. The retained Catalogue smoke covers the sibling Work route; Series mutations use focused service tests and manual UI acceptance.

One Save can affect both Series and Work records and several read projections. Keep the canonical transaction and subsequent [output completion](/docs/?scope=studio&doc=d-20260519-202931-0c703e) boundaries explicit when adding capabilities.
