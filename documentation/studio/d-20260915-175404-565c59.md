# Mermaid Publication Test Coverage

## Approved Scope

The user approved focused tests on 15 September 2026 for ordinary and sub-scope Mermaid identity, both prepared SVG variants surviving Publish/Deploy URL projection, and failures preventing a completed generated snapshot. The same approval covers removing the obsolete standalone preparation CLI test and those commands from the existing CLI workspace-override selection. Product authority is [Document Diagrams](/docs/?scope=studio&doc=d-20260719-123719-fb7565).

## Maintained Selection

| File and selector | Inputs and expected outcomes |
| --- | --- |
| `docs-viewer/tests/python/test_docs_mermaid_preparation.py::test_prepared_pairs_keep_collection_identity_through_publish_and_deploy` | One ordinary document and one configured child document with accessible fences; actual planner, pair producer, local artifact adapters, payload projection, Publish file planning, and Deploy payload URL projection retain exact collection paths and both SVG variants. Canonical source stays unchanged; accepted/deployed HTML contains no raw Mermaid fence; downstream projection must not call the renderer. |
| `test_working_keeps_fences_and_does_not_render` in the same file | A Working collection with fences receives no preparation or generated mutations. |
| `test_preparation_failure_prevents_complete_build` in the same file | Parameter groups omit authored accessibility text, fail the renderer, mismatch the payload document ID, or change the generated fence text. The complete rebuild coordinator removes its old completion manifest and propagates failure without recording completion. |
| `test_publish_rejects_unprepared_fences_and_missing_dark_variant` in the same file | Unprepared fenced HTML blocks Publish file planning; removing a required dark SVG from an otherwise prepared snapshot also blocks it. |

The new file uses the existing `repo_factory` and Docs pytest workspace isolation. Rendering is replaced at `render_mermaid_path` with deterministic SVG bytes; the actual Mermaid browser engine and sanitizer are outside this integration selection. The rebuild-failure cases also replace command execution with successful command results, keeping the real completion ordering and preparation failure boundary. Fixtures live in pytest temporary directories and are cleaned by pytest. Tests perform no HTTP requests, browser startup, R2 writes, real publication, or changes to configured user workspaces.

## Retained Producer Evidence

`docs-viewer/tests/python/test_docs_public_mermaid_projection.py` retains its three pure planner tests for document-local ordinals, accessibility, complete pair replacement/removal, and rejection of unowned manifest paths. Its old `test_cli_reports_both_variants_failures_and_no_writes` is removed with the retired standalone CLI.

`docs-viewer/tests/python/test_docs_public_mermaid_producer.py` is an existing unchanged lower-layer selection: deterministic mocked CLI output exercises real sanitization, accessibility/geometry verification, complete theme pairs, ownership conflicts, failed rendering, and byte-verification/transaction behavior through filesystem or in-memory remote adapters. It does not use a real browser or remote service.

`docs-viewer/tests/python/test_build_docs_cli.py::test_python_docs_builders_accept_independent_workspace_overrides_after_repo_local_env` retains the Docs, Search, and document-location `--help` commands under isolated workspace overrides. The two retired Mermaid CLI entries are removed. This selection checks argument/bootstrap handling, not document generation.

## Runs And Limits

Run the new integration file together with the retained planner and producer files using `python3 -m pytest <paths> -q`; run the exact CLI selector separately. Load `.env.local` in the invoking shell; the shared pytest fixture replaces both external workspace settings for collection and each test. The selected runs are expected to take under a minute with no network or rendering browser. The approved authoring/review estimate is 15–25 minutes. Repeat only after relevant changes or failures.

These checks do not prove actual Mermaid rendering, UI theme switching or Diagram Detail interaction, live Pre-publish/Publish, or R2 deployment. Those remain separate operational/manual evidence. No broader test profile membership is added.
