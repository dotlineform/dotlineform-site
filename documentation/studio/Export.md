# Export

Docs Viewer Export creates a browseable dated static HTML snapshot from existing generated document payloads. Every snapshot includes the existing multi-file site plus a text-first `portable.html` containing the same selected documents in one file. The output is a user-owned visual and text reference outside Docs Viewer; it is not canonical source, an import package, or a managed archive.

## Workflow

Export is available from an ordinary Index row's context menu and each Collection Actions menu while Manage is active. The top-row **Export** is the separate whole-ordinary-Index action; it does not expand collection hosts into collection contents.

The row's **Export** targets the invoked ordinary document and every descendant in the loaded Index hierarchy, including collapsed branches. The displayed document is independent of that target. The Index has no checkbox selection or All/Clear/Done controls. Descendant inclusion is fixed, with no export mode or **Include descendants** option. **Export workspace** captures all IDs from the loaded ordinary Index without another Index GET; an empty selection is disabled locally. Both actions retain their captured IDs through confirmation and complete without a detached capability refresh.

Collection **Export…** uses the existing collection checkboxes and All/Clear/Done controls shared with Prepare Package. Opening Actions enters selection mode; Export is disabled until at least one document is checked. All retains the existing filtered collection selection scope. Export captures the checked IDs and exact collection when invoked, including checks retained across page/filter changes, and uses the common confirmation and snapshot writer. Catalogue offers Export while its authoring and Prepare Package restrictions remain unchanged. No manifest reload, document build, Search refresh or publication work follows an export.

The confirmation identifies the destination and media plan, adding the collection identity for a collection export:

```text
Export N document(s) to:
/docs-export/<dated folder>/
Includes M media file(s).
Leaves E external media reference(s) unchanged.
```

The external-reference line is omitted when its count is zero.

The primary button is **Create snapshot**, **Replace**, or disabled **Unavailable** according to the previewed target. Replacement uses the danger tone and initially focuses **Cancel**. The document IDs are captured when Export starts and retained through its confirmation.

## Input And Eligibility

A configured workspace offers Export when:

- `$DOTLINEFORM_PROJECTS_BASE_DIR` resolves the external `docs-export` workspace;
- its configured generated `index-tree.json` is a file; and
- its configured generated by-ID root is a directory.

Capability discovery for the ordinary Index checks configured input locations without parsing the Index or opening document payloads. Collection actions use their mounted management contribution and existing loaded selection; they do not request another capability check. Explicit Preview resolves one configured Working owner, reads its `index-tree.json` for ordinary documents or `manage-manifest.json` for a collection, and opens only selected by-ID payloads. Missing configuration, metadata, payloads or export storage fails at that operation. Canonical-source ownership and source writability are not capability gates. Draft and publication-excluded documents present in Manage remain eligible.

Export reads generated hierarchy, titles, and `content_html`. It does not parse canonical Markdown, rebuild documents, or apply a second publishability filter.

An expanded `[[summary]]` contains the builder's restricted bold/italic markup, escaped literal HTML and explicit `<br>`/paragraph elements. Both the browseable snapshot and `portable.html` retain that formatting and include Summary panel/paragraph styling; YAML syntax is not part of either HTML output. Export does not place a metadata-only Summary into the body automatically. Rebuild the owning generated documents to obtain changed rendering before creating a new snapshot. Existing exported folders are unchanged until explicitly exported/replaced. [Package Prepare](Package_Prepare.md#package-output) separately flattens Summary for its text-oriented packages.

From the exact selected generated HTML, Export recognizes media only when a supported URL attribute maps beneath an exact configured served prefix for the workspace and media type. It then reads the confined identity through that media type's configured repository, external-local, or R2 artifact location. Missing, invalid, escaping, or unreadable owned media blocks preview. Unmatched media references remain external and unchanged; Export does not fetch their served URLs or inventory unrelated media.

The selected ordinary or collection owner supplies its resolved media-type map directly to media planning. Catalogue has no document-media owner: its Work images/files remain external dependencies under the same rule, so a Catalogue snapshot is not an offline Work-media package. Export does not adopt another collection's media or inspect Catalogue source records to fill that boundary.

## Destination And Naming

Snapshots live under:

```text
$DOTLINEFORM_PROJECTS_BASE_DIR/docs-export/
```

The server derives the folder from its local export date:

- the complete ordinary set uses `Docs - YYYY-MM-DD`;
- every non-complete set, including one document with unselected peers, uses `Docs selection - YYYY-MM-DD`.
- a complete collection uses `<collection title> - YYYY-MM-DD`; a partial collection uses `<collection title> selection - YYYY-MM-DD`.

Complete-set classification takes precedence for a one-document workspace. Labels receive only bounded filesystem-safe normalization. There is no **Save As**, arbitrary destination, or background scheduling.

One equivalent label and local date names one destination. If it already exists, preview classifies it as a recognized current-schema snapshot, an unrecognized directory, or a non-directory collision. Recognized and unrecognized directories may be replaced only after explicit confirmation; a non-directory target is blocked.

## Preview And Apply

The management-only endpoints are:

```text
POST /docs/export/static-html/preview
POST /docs/export/static-html/apply
```

Preview accepts exact `doc_ids` and an optional configured `collection`; the service resolves Working. It returns `docs_static_html_snapshot_preview_v2` with collection identity (empty for ordinary documents), IDs in generated tree/manifest order, selection kind, deterministic default, local date, display-safe destination label, packaged-media count, unchanged-external-dependency count, target state, existing recognized provenance when present, and plan/target revisions. Confirmation displays the number of packaged media files without a byte count. Preview writes nothing and exposes no media identities or absolute workspace path, but it reads and hashes each exact referenced owned object to make the plan truthful. The browser consumes this result directly without schema/count/ID/revision audits and retains the actual replacement-availability decision.

Apply is assembled from that preview and carries:

```json
{
  "doc_ids": ["d-20260426-164043-e14f49"],
  "export_date": "2026-07-31",
  "plan_revision": "<sha256>",
  "target_revision": "<sha256>",
  "confirm": true,
  "replace_existing": false
}
```

Collection Apply additionally carries the preview's `collection`; it does not infer the owner from the currently displayed view. Collection identity, title and the configured public viewer route participate in the existing plan revision.

The service recomputes the complete plan and destination state once for Apply, including selected generated-body digests and fresh media byte digests, and compares them with the confirmed revisions. A changed generated payload, media object, configuration or target requires a fresh preview. It then updates the confirmed destination in place: an absent final directory is created directly; the completion manifest and existing files are removed; directory paths still required by the new artifact are retained; other emptied directories are removed; and the complete desired file set is written directly, with `snapshot.json` last. One final file-set/byte verification confirms the written artifact, including its manifest bytes. No additional pre-install destination scan or post-install provenance parse/hash scan runs. Configured path/symlink safety remains. Regular Finder `.DS_Store` files are preserved and excluded from destination revision and artifact validation; no other extra entry is ignored.

There is no staging directory, backup rename, rollback, locking, or retry machinery. If writing or verification fails, the completion manifest is removed and the partial destination remains unrecognized; resolve the problem, preview again, and rerun **Replace**.

There is no export delete route or capability. Snapshot folders are user-owned after creation; Docs Viewer does not list, rename, prune, retain, or remove them.

## Artifact Contract

Each snapshot’s managed artifact contains exactly:

```text
<dated folder>/
  index.html
  portable.html
  styles.css
  snapshot.json
  docs/
    <selected doc_id>.html
  media/
    <media type>/
      <confined relative identity>
```

`index.html` preserves the selected ordinary hierarchy or flat collection manifest order and uses the owning collection title. A selected child whose parent is absent becomes a root. The configured default document is retained when selected; otherwise the first selected document in generated tree/manifest order becomes the default.

`portable.html` is an additive single-file view for platforms such as iPadOS where local `file` navigation between exported files is unreliable. It inlines the export stylesheet, renders one article per selected document, and uses in-page fragments for its index and selected document links within the same collection identity. Deep links to a selected document heading resolve to that document article in the portable view. Images are represented as `[image: alt text]`, or `[image]` without alt text; the existing multi-file pages and packaged media remain unchanged. Beneath each **Back to index** link, a caption-style code line shows a literal Markdown reference token using the configured public viewer route and the exact collection/document identity, such as `[document title](/?collection=library&doc=<doc_id>)`, for direct reuse in notes.

Each document page inserts its existing generated `content_html` without adding another heading. Docs Viewer links become local only when the target's collection identity matches the exported owner and its document is included. Links to unselected documents and other collections retain their viewer target; query-only links receive the configured public viewer route so they do not resolve within the exported folder. External locations retain their original targets. Fragments are preserved in the multi-file pages.

Each exact referenced workspace-owned object is copied once to `media/<media type>/<identity>`, even when several selected documents use it. Matching `src`, `srcset`, `poster`, `data`, and configured media `href` references become document-relative packaged URLs. Cache queries are removed after the bytes are frozen and fragments are preserved. Unmatched media references remain unchanged and are recorded as external dependencies without credentials or query strings.

The snapshot does not recursively inspect copied HTML, CSS, scripts, frames, fonts, or site-shell dependencies. All fenced code remains readable source; diagram images use ordinary imported SVG media.

`snapshot.json` uses `docs_static_html_snapshot_v3` and records collection identity (empty for ordinary documents), exact ordered IDs, selection kind, document count, default ID, local export date, generation time and plan revision, without scope/stage fields. Each packaged media row records its media type, confined identity, provider kind, packaged path, SHA-256 digest and referencing selected document IDs; separate rows record unchanged external dependencies. Preview, Apply, saved provenance and recognized-destination summaries carry no media byte total or per-media size field. Folder names are presentation labels; provenance owns snapshot identity for guarded replacement.
