# Export

Docs Viewer Export creates a browseable dated static HTML snapshot from existing generated document payloads. Every snapshot includes the existing multi-file site plus a text-first `portable.html` containing the same selected documents in one file. The output is a user-owned visual and text reference outside Docs Viewer; it is not canonical source, an import package, or a managed archive.

## Workflow

Export is available from an ordinary Index row's context menu while Manage is active. **Export workspace** is the separate whole-workspace action; flat collection documents have no HTML Export action.

The row's **Export** targets the invoked ordinary document and every descendant in the loaded Index hierarchy, including collapsed branches. The displayed document is independent of that target. The Index has no checkbox selection or All/Clear/Done controls. Descendant inclusion is fixed, with no export mode or **Include descendants** option. **Export workspace** captures all IDs from the loaded ordinary Index without another Index GET; an empty selection is disabled locally. Both actions retain their captured IDs through confirmation and complete without a detached capability refresh.

The confirmation identifies the destination and the v2 media plan:

```text
Export N document(s) to:
/docs-export/<dated folder>/
Includes M media file(s) (<total bytes>).
Leaves E external media reference(s) unchanged.
```

The external-reference line is omitted when its count is zero.

The primary button is **Create snapshot**, **Replace**, or disabled **Unavailable** according to the previewed target. Replacement uses the danger tone and initially focuses **Cancel**. The document IDs are captured when Export starts and retained through its confirmation.

## Input And Eligibility

A configured workspace offers Export when:

- `$DOTLINEFORM_PROJECTS_BASE_DIR` resolves the external `docs-export` workspace;
- its configured generated `index-tree.json` is a file; and
- its configured generated by-ID root is a directory.

Capability discovery checks configured input locations without parsing the Index or opening document payloads. The loaded browser Index owns action selection. Explicit Preview reads the required generated Index and selected payloads, reporting missing or unusable inputs at that operation. Canonical-source ownership and source writability are not capability gates. Draft and publication-excluded ordinary documents present in the Manage tree remain eligible.

Export reads generated hierarchy, titles, and `content_html`. It does not parse canonical Markdown, rebuild documents, or apply a second publishability filter.

An expanded `[[summary]]` remains escaped plain text with explicit `<br>` and paragraph elements. Both the browseable snapshot and `portable.html` retain those breaks and include Summary panel/paragraph styling; YAML syntax is not part of either HTML output. Export does not place a metadata-only Summary into the body automatically. Rebuild the owning generated documents to obtain changed rendering before creating a new snapshot. Existing exported folders are unchanged until explicitly exported/replaced. [Package Prepare](Package_Prepare.md#package-output) separately flattens Summary for its text-oriented packages.

From the exact selected generated HTML, Export recognizes media only when a supported URL attribute maps beneath an exact configured served prefix for the workspace and media type. It then reads the confined identity through that media type's configured repository, external-local, or R2 artifact location. Missing, invalid, escaping, or unreadable owned media blocks preview. Unmatched media references remain external and unchanged; Export does not fetch their served URLs or inventory unrelated media.

## Destination And Naming

Snapshots live under:

```text
$DOTLINEFORM_PROJECTS_BASE_DIR/docs-export/
```

The server derives the folder from its local export date:

- the complete ordinary set uses `Docs - YYYY-MM-DD`;
- every non-complete set, including one document with unselected peers, uses `Docs selection - YYYY-MM-DD`.

Complete-set classification takes precedence for a one-document workspace. Labels receive only bounded filesystem-safe normalization. There is no **Save As**, arbitrary destination, or background scheduling.

One equivalent label and local date names one destination. If it already exists, preview classifies it as a recognized v2 snapshot, an unrecognized directory, or a non-directory collision. Version 1 snapshot folders are unrecognized after the v2 cutover. Recognized and unrecognized directories may be replaced only after explicit confirmation; a non-directory target is blocked.

## Preview And Apply

The management-only endpoints are:

```text
POST /docs/export/static-html/preview
POST /docs/export/static-html/apply
```

Preview accepts exact `doc_ids`; the service resolves Working. It returns `docs_static_html_snapshot_preview_v2` with tree-ordered IDs, selection kind, deterministic default, local date, display-safe destination label, packaged-media count, unchanged-external-dependency count, target state, existing recognized provenance when present, and plan/target revisions. Confirmation displays the number of packaged media files without a byte count. Preview writes nothing and exposes no media identities or absolute workspace path, but it reads and hashes each exact referenced owned object to make the plan truthful. The browser consumes this result directly without schema/count/ID/revision audits and retains the actual replacement-availability decision.

Apply is assembled from that preview and carries:

```json
{
  "doc_ids": ["d-20260426-164043-e14f49"],
  "export_date": "2026-07-31",
  "plan_revision": "<sha256>",
  "target_revision": "<sha256>",
  "confirm": true,
  "replace_existing": false
}
```

The service recomputes the complete plan and destination state once for Apply, including selected generated-body digests and fresh media byte digests, and compares them with the confirmed revisions. A changed generated payload, media object, configuration or target requires a fresh preview. It then updates the confirmed destination in place: an absent final directory is created directly; the completion manifest and existing files are removed; directory paths still required by the new artifact are retained; other emptied directories are removed; and the complete desired file set is written directly, with `snapshot.json` last. One final file-set/byte verification confirms the written artifact, including its manifest bytes. No additional pre-install destination scan or post-install provenance parse/hash scan runs. Configured path/symlink safety remains. Regular Finder `.DS_Store` files are preserved and excluded from destination revision and artifact validation; no other extra entry is ignored.

There is no staging directory, backup rename, rollback, locking, or retry machinery. If writing or verification fails, the completion manifest is removed and the partial destination remains unrecognized; resolve the problem, preview again, and rerun **Replace**.

There is no export delete route or capability. Snapshot folders are user-owned after creation; Docs Viewer does not list, rename, prune, retain, or remove them.

## Artifact Contract

Each snapshot’s managed artifact contains exactly:

```text
<dated folder>/
  index.html
  portable.html
  styles.css
  snapshot.json
  docs/
    <selected doc_id>.html
  media/
    <media type>/
      <confined relative identity>
```

`index.html` preserves the selected hierarchy. A selected child whose parent is absent becomes a root. The configured default document is retained when selected; otherwise the first selected document in generated tree order becomes the default.

`portable.html` is an additive single-file view for platforms such as iPadOS where local `file` navigation between exported files is unreliable. It inlines the export stylesheet, renders one article per selected document, and uses in-page fragments for its index and selected ordinary document links. Deep links to a selected document heading resolve to that document article in the portable view. Images are represented as `[image: alt text]`, or `[image]` without alt text; the existing multi-file pages and packaged media remain unchanged. Beneath each **Back to index** link, a caption-style code line shows the exact literal Copy Link Markdown token, `[document title](/docs/?doc=<doc_id>)`, for direct reuse in notes.

Each document page inserts its existing generated `content_html` without adding another heading. Ordinary Docs Viewer links become local only when their target is included. Links to unselected documents, named collections and external locations retain their original targets. Fragments are preserved.

Each exact referenced workspace-owned object is copied once to `media/<media type>/<identity>`, even when several selected documents use it. Matching `src`, `srcset`, `poster`, `data`, and configured media `href` references become document-relative packaged URLs. Cache queries are removed after the bytes are frozen and fragments are preserved. Unmatched media references remain unchanged and are recorded as external dependencies without credentials or query strings.

The snapshot does not recursively inspect copied HTML, CSS, scripts, frames, fonts, or site-shell dependencies. All fenced code remains readable source; diagram images use ordinary imported SVG media.

`snapshot.json` uses `docs_static_html_snapshot_v2` and records exact ordered IDs, selection kind, document count, default ID, local export date, generation time and plan revision, without scope/stage fields. Each packaged media row records its media type, confined identity, provider kind, packaged path, SHA-256 digest and referencing selected document IDs; separate rows record unchanged external dependencies. Preview, Apply, saved provenance and recognized-destination summaries carry no media byte total or per-media size field. Folder names are presentation labels; provenance owns snapshot identity for guarded replacement.
