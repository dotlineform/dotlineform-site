## Requirements

Provide one reusable way for authored content to open an exact Catalogue target in Media View. Deliver the Work text-link path first, then update **Add Catalogue Image** to use that same activation behavior. The complete outcome is that either a text link or an inserted image opens the intended Catalogue presentation through the existing Media View.

Catalogue content is independent of document existence. Search the actual Catalogue for the Work, retaining the existing optional Detail selection for images. A Work or Detail needs no corresponding document and no document Subject association. The source retains the selected Catalogue identity; this is presentation of Catalogue data and creates no doc-to-doc relationship.

Use Catalogue's generated consumer output. The exact Work record is `$DOTLINEFORM_PROJECTS_BASE_DIR/catalogue/generated/works/index/<work_id>.json`; its Work media and selected Detail records supply the image data. The image and text paths must share the Media View target and activation owner. Source syntax and text-label defaults are settled at readiness before implementation.

The accepted behavior references are [Media View - Work 00523](/docs/?scope=analysis&stage=working&doc=d-20260906-164429-9892a8) and [Media View - Series 143 Gallery](/docs/?scope=analysis&stage=working&doc=d-20260906-164429-756174). They establish image activation, exact Work presentation, Back to document and the existing gallery/Work distinction. Their supplied HTML and data are demonstrations, not final source-token syntax or a requirement to embed complete galleries.

Use Working for implementation and authoring review. Operations remain synchronous from the user's perspective: finish the required work before controls become available for the next action, following [Development Checklist](/docs/?scope=studio&doc=d-20260523-190651-7157ec).

## Process

First, the author chooses a Catalogue Work through the new text-link action. The action writes the agreed source form, and Save runs Document Build. The resulting visible text link opens that exact Work in Media View. Its label is display text and never supplies the Work identity.

After that path is reviewed, the author uses **Add Catalogue Image** to choose a Work and optionally a Detail. Save retains the image reference and authored caption; the inline image and Media View resolve from the same current Catalogue owner. Detail selection must display and open that Detail, without silently substituting the parent Work's primary image.

### How Media View Opens

The authored text link is a button styled as inline link text: it opens a view and has no invented navigation URL or frozen image fallback. Its accessible button behavior supports keyboard activation. The source token remains `[[catalogue:media:work:00523|kylie structure 4]]`.

1. Document Build emits `data-docs-content-detail="media"`, exact `data-docs-media-kind="catalogue-work"` and `data-docs-media-id` attributes, and an opener marked `data-docs-media-open`. It embeds no Work JSON, image URL or Catalogue metadata. Authored labels remain literal and unchanged by later Catalogue updates.
2. Activation reads the exact current generated Work consumer record. Local Docs uses `/docs/catalogue-work?work_id=<work_id>` from the configured external Catalogue output. The public route config declares `catalogue_paths.work_records_base_url`, currently `/assets/data/catalogue/works/index/`, for the corresponding deployed consumer records. The public provider makes no local-service or archive fallback request.
3. The shared `docs-viewer-catalogue-media.js` projector validates identity and supplied media URLs and prepares the existing Media View presentation. The adapter opens it in the document-owned Content Detail host, retaining exact stage and child-document context.
4. Each activation reads again: local reads use `no-store`; public reads use HTTP revalidation with `no-cache`. There is no document-lifetime Work cache. Loading and errors appear beside the opener; controls recover for retry. Replaced documents, stale child selections and superseded requests cannot open a late response.

Build preserves valid references even when Catalogue data is unavailable, so later availability can recover without rebuilding the document. Insertion validates current media; Broken Links audits current generated availability. The existing supplied Work/gallery demonstrations and report presentation API remain distinct callers of the shared host; newly authored Work links use references exclusively.

This follows the deliberate current-Catalogue policy in [Publishing workflow concept](/docs/?scope=studio&doc=d-20260906-141142-5200b2). Public freshness means the latest deployed Catalogue record. [Catalogue Deployment](/docs/?scope=studio&doc=d-20260909-205938-3569d6) owns the distribution boundary and pending work; this step configures and tests the reader but does not populate that destination or deploy data.

The current activation owner is `docs-viewer/runtime/js/shared/docs-viewer-media-detail.js`: `mountDocument()` registers the opener, and its click handler requests the Media View presentation. Both new authoring forms should reuse that owner.
