# UAC 1 - Freeze The Legacy Catalogue

Historical completed delivery. The legacy Catalogue document-URL writer and its pause were subsequently removed by [Retire Public Document Locations](d-20260924-205346-c74d90.md). They are no longer waiting to resume. [Catalogue Deployment](d-20260909-205938-3569d6.md) owns the separate pending distribution of current consumer files; the frozen archive remains unchanged.

## Requirements

Today's public Work payloads are individual files at `site/assets/works/index/<work_id>.json`. They need to be archived beneath `/archive/` to form one immutable viewable snapshot of the current Catalogue site. The archive is functional and navigable:

1. links to remote media continue to work.
2. paginated thumbnail galleries and sortable lists continue to work.
3. Catalogue Search will search the frozen Catalogue; Recent will show the most recent entries **at the time of archiving**. After acceptance, neither is rebuilt from the changing canonical Catalogue.
4. remote media is served from `media.dotlineform.com/archive/catalogue/`. This is a full copy of the current R2 media, regardless of whether there are active links to all the media.
5. ordinary links out to Analysis, About or external resources remain links, not archive runtime dependencies.

### Site navigation

1. The site home page becomes `/analysis/`, reached through the top-left `dotlineform` link. Remove the redundant `analysis` top navigation item.
2. A link to `/archive/` is added to the site footer. This is the only visible link to the archive.
3. The archive has a single top level nav item 'archive', which returns the user to `/archive/` from anywhere inside it.
4. There is no top level nav item 'archive' displayed on the rest of the site. It is only visible when in the archive.
5. Redirects fron the old catalogue locations to the new archive are not required. No old/new schema adapter or synchronized output is permitted.

### Local workflows

1. The archive is deployed from `site/archive/`.
2. Studio Catalogue work, direct Catalogue builds and media operations will remain unused until the new projection is wired in. Existing machinery is retained without interim editor, thumbnail or public-link repairs. Docs token experimentation continues, with explicit exits from Catalogue write follow-through; active Docs and site operations must not regenerate old Catalogue outputs or mutate the archive.
3. No archived snapshot of Studio canonical data is required as part of this delivery. 
4. The freeze neither changes canonical schema/publication semantics nor implements their later replacement. No `catalogue/generated/` contract or parallel publishing lifecycle is created.
5. Existing active R2 source objects are not deleted by this delivery.
6. A pinned Git revision captures repo state immediately before the archiving happens.
