## Agreed Approach

The agreed browsing behavior is unchanged: A–Z on opening, a recent/A–Z button, title-fragment search with a 180 ms delay, 20 rows per page, and the existing richer Manage rows and subject actions.

Follow the [Catalogue Works Save-maintained metadata approach](d-20260925-134621-42c838.md): **Save updates generated report data efficiently; the report loads the completed data and displays it.** Manage Works must not require a separate Works Build, offline preparation, canonical-data query, or report-generation action to see the saved Catalogue changes.

| Data | Owner of updates | Reader behavior |
| --- | --- | --- |
| Works document membership, titles, dates, draft state and exact subject identities | Existing Docs document lifecycle | Read the generated Works collection metadata. |
| Catalogue Work/Series display metadata needed by Manage rows | Studio Save completion, using targeted updates | Read the current generated report metadata during normal loading; no canonical or live lookup reads. |
| Public Works dates used by the recent/A–Z control | Existing Docs builder and snapshot lifecycle | Read `last_updated` from the selected snapshot's `manifest.json`. |

The frontend still owns searching, sorting, pagination and rendering. It consumes generated files rather than reading canonical Catalogue records, querying Studio for list data, or rebuilding a projection when the report opens. Existing generated Catalogue associations retain exact Work-document navigation; Folder activation retains its existing local Finder helper.

Refresh ownership is now decided: **the relevant generated Catalogue report data is refreshed as part of Save, before Save reports complete success**. Afterward, normal Works list loading shows that latest data. There is no additional user operation. This does not require unsolicited live updates to an already-open list or change the existing Docs source-save/watcher lifecycle.

The private Catalogue output `reports/works/manifest.json` contains all Work and Series IDs mapped to their current titles, including empty Series. Its `works_collection_metadata_v1` envelope carries a content revision. Studio Save updates only affected identities using its already-loaded canonical records, removes explicitly deleted identities, and skips unchanged writes. This separate Catalogue-owned file survives Docs builds without copying titles into `manage-manifest.json`. Initial population and explicit repair use `studio/services/catalogue/works_collection_metadata.py`; ordinary Saves need no separate operation.

Manage fetches the saved file with `cache: no-store` through the existing local report-asset serving boundary, alongside its Docs manifest and generated Catalogue associations. The server serves file bytes with the same private origin checks as Catalogue Works; it performs no Catalogue query or generation on this read. Public code does not import the private reader or receive this file. The superseded Build-owned projection has been removed.

- Returning from an opened document preserves query, sort, page and the existing return position. Refresh reconciles the page against the updated result count. Cross-reload persistence and browser-history redesign remain outside this delivery.

Use focused shared browsing behavior with collection-specific data preparation and row contributions. Preserve Catalogue's latest-updated opening order, Work-ID search and thumbnails; do not spread Catalogue-only assumptions into Works or change other collections' behavior. ## Process

1. Save a relevant Work/Series change in Studio. Save updates the affected generated report metadata and completes only when its required output work has finished.
2. Open/load Works normally. Read its selected-stage document list, current saved Catalogue display metadata and existing generated Catalogue associations. Show the first 20 documents in A–Z order, without a separate build or report-generation step.
3. Enter a title fragment. After the typing delay, show page 1 of all matches; clearing restores the full list immediately.
4. Switch between A–Z and recently updated, or use an existing Manage heading sort. The selected order applies to every match before pagination.
5. Turn pages without reloading list data. Open a document and use the report's Back action to return to the retained list state.
6. In Manage, activate a subject using its existing exact destination; Folder subjects call the local Finder helper. Public snapshots continue through their existing preparation/publication owners.
