# Catalogue Images In Export And Review

## Requirements

Make exact Catalogue Work and Detail image references visible in HTML export and Docs Review. This delivery takes ownership of the export/Review finding from [Media View Text Links And Catalogue Images](/docs/?scope=studio&doc=d-20260908-224845-502b95): Document Build retains the image identity, but these consumers currently receive a hidden image without a source URL and have no Catalogue resolution step.

Both consumers first resolve the exact Work or Detail through current generated Catalogue consumer JSON to obtain the supplied R2 image URL. The image files already belonging to R2 remain the source for this delivery. Local generated thumbnails do not become an alternative image source, and neither a companion Work document nor a document Subject is required. Preserve authored alt text, captions, summaries and presentation settings; never substitute a parent Work image for an unavailable Detail.

The proposed policies deliberately serve different uses:

| consumer | proposed image handling | resulting behavior |
| --- | --- | --- |
| HTML Export | Download the selected image rendition from R2 into the existing export folder and emit package-relative image paths. | The exported Catalogue images remain available with the snapshot when R2 or the network is unavailable. |
| Docs Review preview | Resolve references while preparing or explicitly rebuilding the retained preview and emit ordinary images with the supplied R2 URLs. | The browser loads image bytes directly from R2; the preview package does not need downloaded Catalogue image copies. |

Here, preview means the [Docs Review](/docs/?scope=studio&doc=d-20260711-214307-b4c800) package preview. Export's own confirmation/preview step remains part of the export workflow. Confirm the two policies, rendition choice and failure behavior at readiness; this proposed delivery does not authorize implementation.

Retain the exact checked document set, generated-document input, destination ownership and replacement behavior of [Export](/docs/?scope=studio&doc=d-20260629-152159-ac1af9). Retain Docs Review's validated package identity, package-local source, explicit Build and read-only authority. Finish required lookups, downloads and generated writes before reporting the corresponding operation complete.

Interactive local/public Docs retains current-data Media View loading. [Catalogue Deployment](/docs/?scope=studio&doc=d-20260909-205938-3569d6) separately owns distributing public Catalogue JSON and media. This delivery does not add public deployment, change document publication, generalize external-image downloading, add Series/gallery authoring, alter document relationships, or provide interactive Media View parity in exported HTML and Docs Review. Existing text-first portable export remains text-first.

## Deliverables

- Exact Work/Detail image resolution from generated Catalogue consumer records for the two preparation flows, reusing the existing Catalogue ownership and validation boundary.
- Exported image files inside the snapshot, relative HTML references, reuse of duplicate image resources and an accurate media plan/inventory for the selected documents.
- Docs Review generated previews containing usable R2 image URLs, with explicit Build refreshing those references and normal navigation retaining the prepared preview.
- Clear unavailable-image outcomes, focused evidence, user review and durable updates to Export and Docs Review, with Catalogue Media View updated only where its shared contract needs clarification.

## Process

For Export, the author selects documents through the existing Index Actions workflow. Export resolves their Catalogue image references and prepares the required media plan. Creating or replacing the snapshot downloads the chosen R2 renditions, writes them within the export folder and produces HTML that refers to those local files. Success means the required images and generated output are complete. Later Catalogue changes do not rewrite an existing export; creating or replacing a snapshot resolves the then-current records.

For Docs Review, validated package preparation or explicit Build resolves the package's exact Catalogue references and writes image URLs into the retained generated preview. Opening a document loads those images from R2. The lookup belongs to preview preparation, so ordinary image display does not require Catalogue-reading browser JavaScript. Explicit Build refreshes the resolved references; the preview remains dependent on R2 availability and is not an offline image snapshot.
