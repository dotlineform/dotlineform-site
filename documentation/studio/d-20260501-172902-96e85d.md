# Catalogue Field Registry

## Purpose

`studio/data/config/catalogue/catalogue-field-registry.json` lists current source fields and the artifact families owned by Work, Series, Detail and Detail-section operations. Read and maintain the file directly. The former read-only `/studio/catalogue-field-registry/` page is retired.

The registry uses `catalogue_field_registry_v2`. It does not plan Save, classify publication eligibility or provide compatibility fallbacks. `catalogue_output_service.py` selects affected records; the producer and media services own completion. [Catalogue Build And Lookup Refresh](/docs/?scope=studio&doc=d-20260519-202931-0c703e) describes that workflow.

## Owners

- `catalogue_source.py` owns field existence, normalization and serialization.
- `catalogue-field-registry.json` inventories fields and current output families.
- `catalogue_field_registry.py` loads the checked inventory.

When adding or changing a field, update the canonical owner, editor, consuming projections and inventory together. Do not restore the retired field-aware Build planner or duplicate rules in the browser.

`media_source_id` remains optional Work metadata: omission means the configured default, and an explicit value must name a configured source. Details inherit the parent Work's identity. The registry records the affected media/output family; source resolution remains with the shared media resolver.

## Verification

```bash
python3 studio/services/catalogue/verify_catalogue_field_registry.py
```

The verifier checks that inventory families and field sets match the canonical model and that every declared artifact family exists. It is read-only and does not execute generation or prove browser behavior. Its focused test is `studio/tests/python/test_catalogue_field_registry.py`.
