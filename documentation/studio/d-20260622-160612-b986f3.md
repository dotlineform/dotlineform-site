# Catalogue Per-Work Detail Source

Retired by the Gallery conversion on 2026-09-23. Converted images are independent Works; Gallery identity and membership belong to the sources described in [Catalogue Source Model](d-20260519-000000-a0da45.md).

## Historical Migration Input

The converter's old input was one aggregate at `studio/data/canonical/catalogue/work_details/<work_id>.json`. Each aggregate contained Work-owned sections with source-media subfolders and nested Detail records. The runtime rejects those files. The explicit conversion owner retains the old schema readers needed to understand its migration input; they are not Studio editing capabilities.

## Studio Retirement

The Work editor no longer has the Detail browser, section-edit modal, section actions, Detail-only multi-image picker wrapper or Detail preview/link helpers. The shared file picker, record lists, modal frame, Work media picker and Work/Series editing remain.

The disconnected section-creation/save service, Detail lookup target, Detail bulk-edit/delete branches and private lookup projections are removed. The focused Work response is `studio_catalogue_work_record_v3` and contains no Detail sections. Ordinary Studio write authority excludes retired Detail storage.

Gallery editing and bulk Work creation are deferred to a separate Works/Series editor delivery. That work may reuse shared components; it does not preserve or adapt a hidden Detail workflow.

## Remaining Boundaries

The migration tooling, old source-schema helpers and residual generated/Docs Viewer Detail read contracts remain separate from Studio's retired browser and write services. Disposable authored Detail references remain unchanged, without aliases to converted Works. Frozen public archives and previously approved media cleanup are outside this retirement.

Historical tests have not been changed. `studio/tests/python/test_catalogue_detail_section_service.py` imports the deleted section service, and `studio/tests/python/test_catalogue_lookup_dependencies.py` imports retired Detail lookup helpers; they are not collectable as current implementation checks. Detail scenarios in the source-mutation, lookup-refresh and other Catalogue tests also require a separately agreed retirement specification. No replacement compatibility code is retained to satisfy those tests.
