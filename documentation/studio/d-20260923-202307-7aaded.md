# Work List And Bulk Gallery Editing

Proposed delivery for the [Work editor](d-20260422-000000-45a776.md). Implementation has not started.

## Requirements

- Select one Work with a click, a continuous range with Shift-click, and add or remove individual Works with Command-click.
- Show a Galleries column only in expanded-list view. Display Gallery titles separated by commas, with wrapping and vertical centring. Two lines fit within the normal row height; additional lines increase the row height. Most Works are expected to belong to at most two or three Galleries.
- Use one row dataset in both layouts. Extend the existing Work search API projection with Gallery IDs and resolve titles through the already-loaded Gallery registry; no persisted lookup JSON change is needed. Expanding or collapsing changes presentation only.
- Let the list component update individual Galleries cells without rebuilding rows or thumbnails. Preserve selection and the visible scroll anchor when wrapping changes row heights. These are updates to displayed values after Save; membership editing remains in the editor panel.
- Initially, Gallery membership is the only bulk-editable field. Other Work fields remain read-only. A full list refresh is acceptable if Series membership changes; general row reconciliation is unnecessary.

## Prerequisite: Catalogue Save And Targeted Publish

Currently [Save also completes Catalogue output and media](d-20260519-202931-0c703e.md). Repeated membership editing makes that expensive work a reason to separate the actions before this delivery.

The separate [Catalogue Save And Targeted Publish](d-20260923-211314-6e83f4.md) proposal owns this prerequisite and the inventory of Studio data dependencies. Save efficiently persists canonical edits and refreshes editor/list values through the current API path. Retain the persisted Studio lookup files and exporter, but remove their automatic refresh from Save; the lookup-versus-API decision is deferred. The editor and Save do not read or write consumer-facing JSON under `catalogue/generated/`. New or changed images remain immediate for Studio previews, including R2 upload; Docs Viewer image freshness waits for Publish. Gallery membership edits skip unnecessary media work.

Publish updates all saved pending Catalogue changes and affected indexes incrementally. Deploy remains a separate later step. Complete that prerequisite before implementing bulk editing; neither proposal changes the current runtime yet.

## Deliverables

- Multi-selection and targeted cell updates in the shared list component.
- One enriched Work-list dataset and the wrapping Galleries column.
- Bulk Gallery replacement through the existing editor Save and canonical membership service, retaining conflict validation and a coherent multi-Work transaction.

## Process

1. Select Works. The editor shows only the intersection of their Gallery memberships; an empty intersection shows no Gallery pills.
2. Edit that shared set. For example, Works in `{A, B}` and `{B, C}` initially show `{B}`. Adding `D` and saving gives both Works exactly `{B, D}`: some memberships are removed and others added.
3. Click **Save** to replace every selected Work's memberships with the final edited set, then update its Galleries cell in place. An explicitly cleared set removes all memberships. Merely selecting Works without editing must not normalize their different memberships.
4. Changing the Work selection discards unsaved bulk changes without saving. Expanding or collapsing the list preserves the selection and draft.
