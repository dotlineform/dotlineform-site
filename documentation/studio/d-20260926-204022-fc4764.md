## Requirements

Deliver one complete outcome: ordinary documents have a canonical nested `index-order.json` whose nesting and literal array sequence survive document operations, Build and Preview preparation, with one Position modal for Before/After/Inside movement of whole subtrees.

The tree includes all ordinary documents regardless of draft or unpublishable status. New inserts after the exact displayed ordinary document as its sibling; an empty tree receives its first root. Delete removes the complete subtree. Position changes parentage and order together without editing document content, cascading numeric updates or retaining authored ordinary `parent_id`.

Keep this a small synchronous JSON editor: read the file, move the subtree, write the file and refresh the tree. Check that the requested nodes exist and prevent a move into the node's own subtree. Report ordinary errors and stop. No new revision/concurrency handling, membership-audit system, repair/rollback machinery or validation framework is part of this delivery.

Prepare Preview retains ownership of draft/unpublishable branch exclusions and preserves the hierarchy and relative order of survivors. Publish/Deploy Repo consumes that prepared result. Flat collection rows and Catalogue sorting, previous/next navigation controls, broader metadata separation, Search/Recents lifecycle changes, Processing and native App changes are outside this delivery.

## Deliverables

- One `index-order.json`, initially populated from the existing hierarchy/order, with ordinary hierarchy readers switched to it and authored `parent_id` removed.
- Existing New, Import and Delete integration sufficient to keep canonical document membership and structure coherent; ordinary source edits preserve placement.
- One Position modal with Before/After/Inside and an explicit Root destination, opened by `arrow-up-down.svg` beside Index Actions and replacing the old ordinary reparenting interaction and drag route.
- Generated tree and browser consumers that preserve source order, plus Preview capture/filtering that omits excluded branches without reordering or promoting children.
- Required tracked public runtime projections, focused checks, code review and current organisation/positioning documentation.

## Process

Display an ordinary document and create New to insert its following sibling. Open Position for an existing document, choose Before, After or Inside and an exact valid destination, then Save to move the whole subtree and update the displayed tree before closing, or Cancel to close without changes. The modal is synchronous; no browsing occurs while it is open. Delete continues to remove the document and its descendants. Build uses the saved structure; Prepare Preview excludes ineligible branches and retains the order of the rest; Publish distributes the reviewed snapshot.
