# Catalogue And Analysis Storage Layout

## Purpose

Define the proposed physical layout for the Catalogue-to-Analysis architecture. Precious canonical Catalogue data remains in Git, replaceable Catalogue projection belongs to the external Catalogue workspace, public document source uses the retained `analysis.works` collection, and the archived Catalogue has its own frozen storage boundary. Works remains the public collection name; Catalogue is the internal domain term.

This is a path and ownership proposal, not implementation authority. `[current]`, `[proposed]` and `[frozen]` below describe lifecycle state rather than directory permissions.

The agreed Catalogue staging name is now `media-staging/`. The user is renaming the existing `media/` folder; code/configuration follow-through is tracked in [UAC - Change Backlog](/docs/?scope=studio&doc=d-20260904-183853-65ffcb).

## Why Catalogue Has `generated/` But No `published/`

The JSON currently written beneath `site/assets/works/index/` and related Series/Search locations is reproducible Catalogue-owned projection. Its active successor therefore belongs in `$DOTLINEFORM_PROJECTS_BASE_DIR/catalogue/generated/`, beside the existing Catalogue media workspace and outside the repository.

Catalogue does not acquire a second accepted publication lifecycle. Its generated records and optional HTML fragments are working dependencies for Analysis Build. Docs Publish alone promotes reachable document and Catalogue content into the accepted `analysis/published/` snapshot.

[Publish workflow](/docs/?scope=studio&doc=d-20260905-141447-c33de1) clarifies the intended removal of Catalogue record draft/published states and the generated-versus-published boundary for dynamic by-ID reads. Accepted runtime JSON belongs to the Analysis snapshot; its exact layout remains to be defined.

The archive files are physically relocated into `site/archive/` as part of the freeze. The relocation preserves the reviewed Catalogue behavior under an archive URL prefix and brings every required local runtime, stylesheet, configuration, payload and media dependency beneath the same owner. Catalogue-only files are then removed from the active route and `site/assets/` families so later site work cannot accidentally mutate or depend on frozen code.

Copying currently shared shell files into the archive is intentional snapshot ownership, not a maintained compatibility layer. The active shell may continue to change after the freeze without changing archive behavior. The archive manifest records the accepted file set and checksums; normal site validation rejects missing archive files, while the freeze contract prohibits regenerating the manifest merely to bless an unintended change.

Remote media follows the same ownership rule beneath `media.dotlineform.com/archive/catalogue/`. The freeze copies only the exact objects referenced by the reviewed Catalogue snapshot into `works/img/`, `works/files/` and `work_details/img/`, verifies source and archive bytes, records object keys, sizes and checksums in `site/archive/archive-manifest.json`, and rewrites the archived pages to those bases. The archive prefix is outside every active upload, replacement and cleanup target.

## Retain The Existing `analysis.works` Collection

The Markdown files are Analysis-owned document composition. The existing public-capable `analysis.works` collection already holds Series and Work subjects and retains its source, generated and published locations. Commentary and Catalogue-backed presentation can coexist in this collection; there is no separate Catalogue collection or naming migration.

Within that collection, a Series or Work may have its own Markdown document, a Work document may use a Series document as optional `parent_id`, and a Work may remain embedded-only with no source file. Root documents, child documents and token-only Catalogue records remain valid without changing physical storage ownership.

Retaining the Works name does not require creating a document for every Catalogue record. [Concept](/docs/?scope=studio&doc=d-20260904-014334-f3dab5) owns optional document composition. Bulk document migration is abandoned; batch New doc will create selected Work or Series documents, with its availability and destination in `dotlineform`, `analysis` or both still to be decided.

## Ownership Rules

- `studio/data/canonical/catalogue/` is the only canonical Catalogue record source and remains protected by Git history.
- `catalogue/media-staging/` is the agreed Catalogue staging workspace name; existing subtrees remain together. The configured root still needs updating as tracked in the Change Backlog.
- `catalogue/generated/` is disposable and reproducible. A complete build owns its contents and writes its completion marker last.
- `site/archive/` is the only tracked owner of the frozen Catalogue pages and their local dependencies; active routes and `site/assets/` contain no legacy Catalogue-only runtime, payload or media family after relocation.
- `media.dotlineform.com/archive/catalogue/` is the only public owner of frozen Catalogue remote media; its `works/img/`, `works/files/` and `work_details/img/` objects are copied and verified once rather than shared with active Catalogue prefixes.
- No active builder, media publisher, cleanup operation, code projection, Docs Publish or Deploy Repo operation writes into `site/archive/` or `media.dotlineform.com/archive/catalogue/`.
- `analysis/source/sub-scopes/works/documents/` remains the canonical source location for documents in the public Works collection. Catalogue references may also appear in ordinary Analysis documents elsewhere.
- `analysis/generated/` is replaceable integrated preview; `analysis/published/` is the sole accepted consumer snapshot.
- `analysis.works` retains its identity and public Works name. Existing document URLs, report-host references and upstream Copy-to-Analysis relationships do not need retargeting for this decision.
- Deploy Repo projects only the accepted active Analysis snapshot and excludes every frozen archive path from cleanup and reconciliation.
- Product configuration resolves the external Catalogue generated root beneath `DOTLINEFORM_PROJECTS_BASE_DIR`; Codex writable-root configuration is access permission, not application path authority.
- Both local `dotlineform` and `analysis` scopes obtain all Catalogue data, including subject selection, lookup indexes and media references, from that external generated root. Studio canonical JSON and repository-generated Catalogue lookups are not Docs consumer inputs. Public Analysis consumes the accepted Published projection; see Publish workflow.
- No repository fallback, shadow copy, compatibility alias or second canonical location is created when the external Catalogue workspace is unavailable.

## Open Decisions

- Name and schema for the configured Catalogue generated-root setting.
- Whether HTML fragments are persisted under `catalogue/generated/fragments/` or produced transiently while Docs Build reads the JSON projection.
- Exact Catalogue completion marker, revision hash and failure-cleanup contract.
- Exact shape of Catalogue-owned Search records before composition into Analysis Search.
- Presentation and navigation improvements within the retained `analysis.works` collection.
- Front matter, starter content, selection and destination for batch New doc; see Stage 6 of Delivery Sequence. No bulk migration cohort is planned.
- Complete and verify the exact frozen local-file and R2-object inventory, checksum-manifest schema and byte-copy evidence.
- Decide whether former top-level Catalogue URLs are removed or retained as bounded redirect shells and record their removal criteria.

## Status

Supporting storage proposal with the existing `analysis.works` location retained. No new document collection or collection-path migration is required. The complete Catalogue output and publication workflow remains a separate implementation decision; this document does not authorise storage changes.
