### Token Retirements

- **Add Catalogue Token** is retired because its purpose - to insert a link to a selected work on the public site catalogue - is now replaced by **Add Media View link**.
- **Insert Subject Link** is retired because its purpose - to insert a link to the work specified in the subject type field in front matter - is now replaced by **Add Media View link** and **Add Catalogue image**. Retiring this action does not remove Subject metadata or infer a replacement document from it.

Both old actions and their exclusive Work/Series text-token implementation are removed in DR-1A, following acceptance of Insert doc link. The user confirmed the buttons are removed on 2026-09-10. Subject-based insertion is removed; the document picker requires an explicit document selection, while the media actions require explicit Catalogue selection.

### Links View

**Links** uses the shared Content Detail host that already hosts Media View, tables, diagrams and reports. Links selects normal document width with no outer border, retaining the index panel's existing state. The host supplies the toolbar and **Back to document**, including restoration of the invoking document's scroll and focus. Links has its own presentation adapter and rendering owner within that host, avoiding a modal's overlay and sizing constraints.

- A **Links** action, using 🔀 in the document toolbar, opens relationships for the exact displayed document, including the child document when viewing a sub-scope entry. The selected host/report document must not substitute for that child identity.
- Identify the displayed document with a heading and group plain document links under **Concepts**, **Works** and **References**, following the design's simple layout. Concepts are documents in `analysis/concepts`; Works are documents with a Work subject in front matter, such as `work_id:`; References are plain scope-level documents only, as explicitly confirmed by the user. References does not absorb other sub-scope documents.
- Leave `analysis/moments` out of the initial Links presentation. Presentation of `analysis/processing` is deferred until it has content. Neither collection requires a new section or blocks this delivery. These are presentation-scope decisions; Document Build's relationship eligibility and scope-wide document-link authoring remain unchanged.
- Hide empty sections. Sort each section A–Z by document title. Combine incoming and outgoing relationships into one link per exact document identity, with no arrows or direction labels in this view. Retain both directions and their occurrences in the generated data.
- Selecting an entry performs ordinary navigation to that exact document. **Back to document** returns to the invoking document. The view remains one document deep.
- Read the displayed document's separate `links-by-id/<doc_id>.json` relationship record through its configured data owner. One relationship response supplies the entries and labels; the browser does not reconstruct relationships, fetch each neighbour for display metadata or require a scope index.
- Use the shared public-safe hosting mechanism in Manage and public compositions. Public rendering consumes published data without local services; public presentation cutover and deployment retain their separate delivery boundaries.

The user supplied the basic layout in [Links View design](/docs/?scope=studio&doc=d-20260910-140911-2b1153) on 2026-09-10 and confirmed that styling and pills can follow later. The implemented view uses normal document width and combines both directions into one link per document without arrows. That acceptance does not claim every originally listed manual case was performed. Full Series/Work/Detail association coverage in Works, semantic-token references and special sorting precedence remain future enhancements.

### Relationship Build

Document Build calls the links-builder and awaits its outcome. The links-builder compares current authored references and relevant metadata with its private baseline, prepares the internal graph and writes it through the current serializer. Only changed `links-by-id` files are written or removed. Relationship-only neighbour updates leave the neighbours' ordinary document payloads unchanged. Both endpoints are resolved across all configured Analysis Working collections. Apply the parent's exclusions for non-publishable and Folder (`folder_path`) documents, and silently omit targets missing their ordinary document by-ID records. A missing relationship file for an existing eligible document is an initialisation case, not a missing document. The generated relationship data contains no `resolution` field or missing-target placeholders.

Include otherwise eligible draft documents as both sources and targets. Draft readiness is separate from publication intent:

- `publishable: false` excludes a document
- `draft: true` does not.

The Working `links-by-id` data and relationship view must show these references before any Pre-publish operation; clearing draft readiness alone must not remove them.

Within the initial Concepts/Works/References presentation boundary, display all incoming and outgoing relationships admitted by these Build rules. Excluded endpoints and missing targets remain omitted from Links. Moments and Processing presentation is deferred as described above.
