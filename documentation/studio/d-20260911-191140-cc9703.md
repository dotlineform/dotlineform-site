# Public Docs Source Repository

Use one Git repository at `$HOME/docs-viewer`, connected to the proposed public GitHub repository `dotlineform/dotlineform-source`. An explicit `.gitignore` allowlist determines which authoring source folders enter Git. The source folders stay in their existing locations.

This is a setup guide. Creating this document does not initialize the source repository, create its remote, commit documents or push anything. The public scope selection remains a user decision; the starting allowlist below includes no scope content.

## What Each Repository Owns

| Repository | Contents |
| --- | --- |
| `dotlineform/dotlineform-site` | Application code, scope configuration, builders and the tracked public-site artifact. |
| `dotlineform/dotlineform-source` | Only the authoring source folders explicitly selected for public Git history, plus repository files such as `.gitignore` and an optional README. |

`DOTLINEFORM_DOCS_BASE_DIR` continues to select `$HOME/docs-viewer`. `DOTLINEFORM_PROJECTS_BASE_DIR` continues to select the separate Projects workspace. Git adds version history around the Docs folder; it does not change either setting or the scope configuration. [Source Organisation](/docs/?scope=studio&doc=d-20260423-000000-8fd731) owns the storage layout.

Keep `.git` at the Docs Viewer root, above `scopes/`, so it stays outside the source and output trees processed by the builders. There is no need for a separate Git repository inside each scope.

## Choose What May Be Public

The available authoring roots are:

| Source folder, relative to `$HOME/docs-viewer` | Meaning |
| --- | --- |
| `scopes/analysis/working/source/` | Working documents, sub-scopes and source media. |
| `scopes/studio/source/` | Studio documentation and source media. |
| `scopes/notes/source/` | Notes and source media. |
| `scopes/processing/source/` | Processing documentation and source media. |
| `scopes/app/source/` | Native App documentation and source media. |

These are choices, not an instruction to publish every scope. Selecting a source root includes all files beneath it, including drafts, front matter, attachments and collection data. Git does not apply the Docs Viewer `draft`, `publishable` or local-access rules. In particular, including Analysis Working exposes its draft sources as well as its ready documents. A folder containing both private and public material needs a narrower allowlist or must remain excluded.

Leave all `generated/` and `published/` output excluded. Also exclude the complete `scopes/analysis/pre-publish/` tree: its `source/` is prepared from Working and rebuilt by Pre-publish, so it is a replaceable derivative. The retained, unconfigured `scopes/dotlineform/` folder stays excluded.

The public source repository is not a backup of excluded scopes. Keep a separate private backup for that material. A clone will contain only the files committed to this repository.

## 1. Check Git And GitHub CLI

Run these commands in your local terminal:

```bash
git --version
gh --version
gh auth status --hostname github.com
```

Git and `gh` were available on the current Mac when this guide was written. On another Mac, the [GitHub CLI installation guide](https://github.com/cli/cli#installation) covers installation; with Homebrew already installed, the command is `brew install gh`.

If authentication is needed, use the browser login flow and sign in as `dotlineform`:

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com
gh api user --jq .login
```

The last command should print `dotlineform`. If that account is already authenticated but another account is active, use `gh auth switch --hostname github.com --user dotlineform` and check again. HTTPS is the example protocol here; an already working SSH setup can remain in use. [Login reference](https://cli.github.com/manual/gh_auth_login), [Git credential setup](https://cli.github.com/manual/gh_auth_setup-git).

## 2. Initialize The Existing Docs Folder

These initial setup commands assume `$HOME/docs-viewer` already contains the scope folders and has not already been initialized as a Git repository. Run each section in order. If a repository or remote already exists, inspect it before using the corresponding creation command.

```bash
cd "$HOME/docs-viewer"
pwd
git init -b main
git rev-parse --show-toplevel
git var GIT_AUTHOR_IDENT
```

The reported repository root must be your local `docs-viewer` folder. Check the author name and email because they will appear in commit metadata. If Git reports that an identity is missing, configure your chosen `user.name` and `user.email` for this repository before committing.

## 3. Create The Allowlist Before Adding Files

For this new repository, create `.gitignore` with the following command. It initially admits only repository control files; no scope is enabled. If `.gitignore` already exists, edit and reconcile it instead of overwriting it.

```bash
cat > .gitignore <<'EOF'
# Exclude everything unless a rule below explicitly allows it.
*

# Repository files.
!/.gitignore
!/README.md
!/.gitattributes

# Permit traversal into scopes, but exclude its contents by default.
!/scopes/

# Add only the selected source blocks below this line.
EOF

nano .gitignore
```

Add only the blocks for folders you have chosen to make public. The first lines open their parent directories; the final `/**` line includes the complete source subtree. Parent directories must be admitted before Git can include files below them. [Git ignore rules](https://git-scm.com/docs/gitignore).

Analysis Working:

```gitignore
!/scopes/analysis/
!/scopes/analysis/working/
!/scopes/analysis/working/source/
!/scopes/analysis/working/source/**
```

Studio:

```gitignore
!/scopes/studio/
!/scopes/studio/source/
!/scopes/studio/source/**
```

Notes:

```gitignore
!/scopes/notes/
!/scopes/notes/source/
!/scopes/notes/source/**
```

Processing:

```gitignore
!/scopes/processing/
!/scopes/processing/source/
!/scopes/processing/source/**
```

App:

```gitignore
!/scopes/app/
!/scopes/app/source/
!/scopes/app/source/**
```

After the selected blocks, put this rule last to exclude Finder metadata even inside an allowed source tree:

```gitignore
.DS_Store
```

A newly added scope remains excluded until it has its own explicit block. Add any individual exclusions after the inclusion blocks. Git ignore rules are selection rules, not a content scanner: review the files actually selected below.

## 4. Review And Make The First Local Commit

Temporarily stop the local services and watcher while reviewing this first snapshot so an authoring or rebuild operation does not change it during review.

First list the files Git would include, without staging anything:

```bash
git status --short --untracked-files=all
git ls-files --others --exclude-standard
git add --dry-run .
```

Expect only `.gitignore`, any intentionally added repository files, and the chosen source folders. No scope files will appear if no source blocks were enabled. Diagnose one unexpected path with `git check-ignore -v --no-index -- PATH`, replacing `PATH` with the actual relative file path. A printed rule beginning with `!` admits the file; an ordinary matching rule excludes it. [Check-ignore reference](https://git-scm.com/docs/git-check-ignore).

Source media is included by a whole-source block. Inspect attachments as well as Markdown. Large binary files may need Git LFS or a narrower selection before the first commit; [GitHub repository limits](https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits) and [Git LFS](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage) describe those choices.

When the candidate list is correct, stage it and review the exact snapshot:

```bash
git add .
git diff --cached --name-only
git diff --cached --stat
git diff --cached
```

Check the full file list and contents before continuing. A binary diff will not display attachment contents, so review those files separately. This is still local; nothing has been uploaded.

Once the staged snapshot is ready to be public:

```bash
git commit -m "Add selected public Docs sources"
git status --short
git log -1 --stat
```

`.gitignore` does not remove files that were already tracked. If an unwanted file entered a commit, stop before the first push and correct the local history; merely adding an ignore rule or a later deletion does not remove it from earlier commits. [Git ignore rules](https://git-scm.com/docs/gitignore).

## 5. Create The Public GitHub Repository And Push

Run this once, from `$HOME/docs-viewer`, after reviewing the initial commit. It creates the public repository, adds `origin` and uploads the local commit:

```bash
gh repo create dotlineform/dotlineform-source \
  --public --source=. --remote=origin --push
```

`--source=.` connects the existing local repository; it does not create another copy of the scope folders. `--push` uploads local commits. [Create-repository reference](https://cli.github.com/manual/gh_repo_create).

Verify the remote and upstream, then open the repository to inspect the public file tree:

```bash
git remote -v
git branch -vv
gh repo view dotlineform/dotlineform-source --web
```

The remote must identify `dotlineform/dotlineform-source`; the branch should track `origin/main`. Normal Docs Viewer authoring and services can then resume. Committing source does not run Pre-publish, Publish, Deploy Repo or Deploy Public.

## Routine Updates

From the Docs repository, review changes, stage the intended snapshot, inspect it and commit:

```bash
cd "$HOME/docs-viewer"
git status --short
git diff
git add .
git diff --cached --name-only
git diff --cached
git commit -m "Update public Docs sources"
git push
```

Choose a commit message describing the actual change. `git add .` stages all eligible changes beneath this root, including deletions; the staged review is the check of what the next commit will contain. If there are no changes, skip the commit and push. Saving a document does not automatically upload it to GitHub.

If another machine or a GitHub edit changed the remote, stop the local services and watcher and use a clean working tree before pulling:

```bash
cd "$HOME/docs-viewer"
git status --short
git pull --ff-only
```

`--ff-only` refuses a pull that requires merging diverged histories. If it refuses, inspect and resolve the divergence before continuing. Restart services afterwards; run the ordinary Docs Build for affected scopes when pulled sources leave generated output stale. Search remains a separate explicit rebuild. [Git pull reference](https://git-scm.com/docs/git-pull).

## Change The Public Selection Later

To include another source folder, add its complete allowlist block, then repeat the candidate-file and staged reviews before committing and pushing. To exclude an untracked folder, leave its block out.

If a folder is already tracked, removing its block alone will not stop Git tracking it. For example, to stop tracking previously committed Notes sources, first remove the Notes inclusion block from `.gitignore`, then run:

```bash
git rm -r --cached -- scopes/notes/source
git add .gitignore
git diff --cached --stat
git commit -m "Stop tracking Notes sources"
git push
```

`--cached` removes the files from Git's index while keeping the local files. Earlier public commits still contain the old content. If the aim is to remove sensitive material that was already published, that needs a separate history-removal response; this command does not make the previous content private. [Git rm reference](https://git-scm.com/docs/git-rm).

## Use Another Machine

Only when the destination is absent or empty:

```bash
git clone https://github.com/dotlineform/dotlineform-source.git "$HOME/docs-viewer"
```

The clone contains the selected authoring files and their history. It does not include excluded private sources, generated data or accepted Published snapshots. Keep the application repository separately, configure that machine's Docs root, restore any required private sources from their private backup, and use the normal build workflows. Do not clone over the existing populated Docs folder.
