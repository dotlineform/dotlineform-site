# UAC 2 - Prepare Catalogue Examples

## Requirements

Make the intended external Catalogue output location exist with a few representative JSON records and their Work and Detail thumbnails. Treat these examples as if the eventual workflow had delivered them, so the next design work can explore Docs tokens and sub-scope reports against concrete data before changing canonical schema, editors or build/publish machinery.

Use `$DOTLINEFORM_PROJECTS_BASE_DIR/catalogue/generated/`, the output location in the current [Storage Layout](/docs/?scope=studio&doc=d-20260902-123739-275b28) proposal. Here it contains manually prepared examples, not a complete generated Catalogue. Analysis `published/` remains the proposed accepted Docs snapshot; this delivery does not introduce a separate Catalogue Publish operation.

Copy examples from the frozen JSON under `site/archive/assets/`. Edit only the new copies. Represent the agreed removal of multiple Series membership with an optional singular Work `series_id`; a Work does not require a Series or a corresponding Series document. Keep other fields initially so the subsequent consumer work can identify what actually needs changing. In particular, whether consumers need the existing Series `member_works` list remains a design question.

Canonical Catalogue data, Studio editors, existing media, the archive and paused build/publish follow-through remain as they are. This delivery prepares files only; it does not wire them into a reader or make tokens and reports work yet.

Copy only the thumbnails needed by the selected examples from `site/archive/assets/works/img/` and `site/archive/assets/work_details/img/` into the corresponding `catalogue/generated/works/thumbs/` and `catalogue/generated/work_details/thumbs/` folders. These output folders contain thumbnails exclusively. Preserve their filenames. The archive retains its original files and continues to use them.

## Process

During the following design work, edit these example JSON files directly as needed and assess their effect on proposed tokens and reports. They stand in for workflow output until the agreed producer is implemented. The question is whether this JSON serves the scope consumers well; existing site payload shape is a starting point, not a requirement to preserve it.

Record manual folder and example-schema changes that need later workflow support in [UAC - Change Backlog](/docs/?scope=studio&doc=d-20260904-183853-65ffcb). It tracks the user's `catalogue/media/` → `catalogue/media-staging/` rename separately from this delivery's example copies.
