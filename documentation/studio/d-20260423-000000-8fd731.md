# Docs Viewer Source Organisation

Scope configuration is the storage authority. `docs-viewer/config/scopes/docs_scopes.json` uses `docs_scopes_v5`; `docs-viewer/services/docs_scope_config.py` resolves its registered roots and stage context. All currently configured scopes use the external workspace beneath `$DOTLINEFORM_DOCS_BASE_DIR/scopes/`. An unavailable configured root is an unavailable scope. The retired repository scope tree and old scope paths are never fallback sources.

`DOTLINEFORM_DOCS_BASE_DIR` selects the existing Docs Viewer folder directly, with no appended `docs-viewer/` component. It is required independently of `DOTLINEFORM_PROJECTS_BASE_DIR`, which continues to own Catalogue, Processing, Data Sharing, Folder subjects and HTML export destinations. Both values live in `.env.local`; neither is a fallback or alias for the other. Docs build commands accept an independent `--docs-base-dir` override after loading that file.

To relocate Docs storage, stop the local services and watcher, copy the complete `scopes/` folder to the selected new Docs root, then switch the Docs setting and restart. Verify the configured source/generated/published roots before resuming writes. Copying retains the lifecycle trees and document identities without a content migration. iCloud may remain a separately operated manual destination for published snapshots; remote delivery for the native app is a separate decision.

## Source, Generated And Published

| Role | Ownership |
| --- | --- |
| Source | Canonical Markdown, retained media input and registered producer input beneath the configured source root. |
| Generated | Replaceable document, Search and media output prepared from source. Local Manage reads this working output. |
| Published | The accepted local snapshot. It is separate from both editable source and replaceable generated output. |
| Public projection | Downstream repository or R2 output served by the website. It does not become local source or a fallback for missing generated media. |
| Rendered view | The viewer's presentation of document payloads and referenced media. It is not document source. |

A document retains its `doc_id` across representations. Stage, sub-scope, `parent_id`, Catalogue subject and media identity are independent. A stage name or source filename cannot select a different document or collection implicitly.

Concepts and Moments are ordinary document collections. A document in `concepts` discusses concepts; it does not declare a separate Concept entity or need to define exactly one concept. The existing `doc_id` identifies it. `concept_id`, `moment_id` and `group` metadata, allocation controls, specialised collection customisations and Concept-token Add/Info modals have been removed. Subject specialisation belongs to the Works sub-scope and its report/customisation owner. Ordinary scope-level documents have no Subject-specific lifecycle processing. Existing fields and authored values remain unchanged by the common lifecycle; Moment remains outside Subject.

Existing Concept-token references were converted to ordinary document links carrying the same exact stage and document destinations. Catalogue tokens retain their own data and controls. The source model, scope configuration, collection builder and management contributions implement this document-based model; no separate Concept/Moment allocation or group metadata remains.

Configured storage supplies collection membership; the Markdown front-matter field `sub-scope` records it. Its nonempty value is the exact configured collection name, such as `concepts`, `moments` or `works`. Missing, null or empty means an ordinary scope-level document. `sub_scope` remains the config/API target spelling and is not a front-matter alias. Changing metadata alone cannot move a document, select a different collection or change its stage.

Supported New, Archive, document placement and Import writes set `sub-scope` from the resolved destination. A sub-scope destination replaces inherited membership with its exact name; a scope-level destination removes the field. Existing body saves and actual metadata, Subject and publishability writes maintain the same rule. Metadata no-op requests remain no-ops. The shared rule lives in `docs_source_model.py`; each writer supplies its resolved collection. Direct filesystem edits must keep the field consistent with configured storage; the watcher does not move or reclassify documents from front matter.

The one-off backfill completed on 2026-09-08 for all 806 existing source documents in configured sub-scopes, including retained Analysis Working and Pre-publish sources. Original document identities, bodies, titles, timestamps and unrelated metadata were preserved. This maintenance operation did not change normal authoring permissions: Pre-publish remains read-only and staged Import support is unchanged.

Membership is source metadata only. No membership field was added to existing indexes, Search JSON, semantic-token JSON or generated document schemas, and no new UI was introduced. Collection-aware document-link search and relationship derivation remain separately scoped work.

## Current Scope Layout

```text
$DOTLINEFORM_DOCS_BASE_DIR/scopes/
  <scope-id>/                  analysis, studio, notes, processing, app
    working/
      source/documents/        authored Markdown and unpublishable.json
      source/media/
      generated/
    pre-publish/
      source/documents/        prepared derivative
      source/media/
      generated/
    published/                 accepted local snapshot
```

Every scope has Working, Pre-publish and Published in the shared stage selector. Working owns authoring, Pre-publish is a prepared read-only derivative and Published reads the accepted scope-root snapshot without a source tree. An empty or unavailable stage never reads another stage as a substitute. New scopes receive this same structure; Studio, Notes, Processing and App have no configured sub-scopes.

The shared layout is active across all five scopes. The user completed physical copying and removed Studio's unused `default` collection and report host. Normal services and the watcher use Working. Activation rebuilt replaceable local output without rewriting authored metadata, migrating disposable Links/token data or changing accepted Published snapshots.

Within each Working or Pre-publish source/generated stage, meaningful configured sub-scopes use the same collection structure:

```text
<scope-id>/<stage>/
  source/
    documents/
      <doc_id>.md
    media/
      img/
      svg/
      files/
      html/
      build-source/mermaid/
    sub-scopes/<collection>/
      documents/<doc_id>.md
      media/{img,svg,files,html,build-source/mermaid}/
      data/                    retained collection data, where present
  generated/
    documents/
      index-tree.json
      by-id/<doc_id>.json
    media/
    search/
    sub-scopes/<collection>/
      documents/
        manifest.json
        by-id/<doc_id>.json
      media/{img,svg,files,html}/
      search/
```

Analysis Working and Pre-publish configure ordinary documents plus `works`, `concepts`, `processing` and `moments`. Working owns authoring in every scope. The explicit Pre-publish action replaces its derivative sources/generated files from eligible Working documents. Missing `draft` is draft; draft subtrees and exact ordinary-document IDs in that scope's `working/source/documents/unpublishable.json` are excluded. An excluded sub-scope report host excludes its collection. An intentionally empty policy file contains `[]`; missing or invalid policy fails visibly. Empty candidates and absent defaults are valid, without a front-matter backfill. Existing source lineage files are retained but inactive; no production source-to-editorial Copy workflow is registered.

Authored Markdown lives directly in each collection's `documents/`; generated document JSON lives in `by-id/` beside collection indexes. Published uses the same documents/media/sub-scopes layout as Generated. Document hierarchy comes from `parent_id`, not physical subdirectories. Sub-scopes are separate flat collections with their own media.

A sub-scope report host is an ordinary document in the parent collection. Reparent it within the same scope and stage using `parent_id`; its immutable `doc_id` and report declaration retain the collection association, child URLs and media ownership. In Working, selecting that exact host as a move destination enters its configured collection. Documents with children, report hosts and the configured default silently retain their location on attempted collection entry; ordinary parenting remains available.

Working placement relocates the canonical Markdown between configured `documents/` roots while retaining `doc_id` and authored Subjects. Entering a sub-scope sets its exact `sub-scope` field and removes `parent_id`; returning to the ordinary collection removes `sub-scope` and sets the selected parent or Root. Destination-owned metadata validation runs before writing. Unsupported fields and conflicting media are visible errors, not silently discarded values or overwritten assets.

An explicit collection move preserves affected same-stage authored document destinations, including references from excluded source documents. Unrelated URLs retain their source escaping; code examples, external links, other-stage links and unrelated relative web links remain unchanged. Referenced collection media is copied or reused at the destination and its authored paths are updated, preserving URL-encoded filenames and associated Mermaid build sources for logical and relative references. Source assets remain available for other documents. Source revisions are checked before writes, and affected collection projections finish through Document Build before the action completes. This does not trigger Search, the scope Links aggregate, publication or cross-scope transfer.

`sub-scopes/` is always beside `documents/` and `media/`; no reader accepts the retired nesting inside `documents/`. Empty media directories are intentional and do not establish a configured producer.

## Exact Runtime Context

All configured source/generated reads and writes require an exact `scope` and explicit `stage=working` or `stage=pre-publish`. A child target also carries `sub_scope`; a document target carries `doc_id`. Missing, invalid or retired targets are rejected rather than inferred from a title, selected report or another stage. Published uses the accepted-snapshot endpoints with explicit scope/collection identity; it does not resolve source or generated output.

The configured-scope provider passes the selected stage to the generated-data runtime. Document navigation and rendered stage-qualified links retain their explicit stage, child selection and anchor. Source/management clients carry the same target to the owning endpoint; browser selection and control visibility do not grant write authority.

| Operation | Working | Pre-publish | Published |
| --- | --- | --- | --- |
| Browse documents, media and Search | Selected generated output | Prepared generated output | Accepted snapshot |
| Create, edit, Delete, Archive, document placement and Import | Existing authoring tools | Rejected | Rejected |
| Pre-publish preparation | Replaces and builds Pre-publish | Unavailable | Unavailable |
| Publish acceptance | Unavailable | Accepts the complete prepared snapshot | Unavailable |
| Sub-scope reports | Configured collection owner | Configured read-only owner | Accepted read-only output |
| Deployment | Separate configured capability | Separate configured capability | Separate configured capability |

Working management writes normally rebuild the affected ordinary or child collection through `docs_write_rebuild.py`. Draft/Ready instead saves only the revision-checked `draft` field and updates its button; the normal watcher owns that source change's build. The open Working viewer checks its existing generated index every two seconds and reloads it when it changes, including after manual field edits. The builder writes the index after its document payloads. This uses the existing generated reader, with no notification service or modal check. Ordinary stage rebuilds also project local browser configuration, including a cleared default after Delete or Archive; stage builds do not update public browser configuration. The normal watcher follows only Working source for every configured scope. Ordinary document writes and watcher updates do not rebuild Search or invoke unrelated media producers. A complete Working Build retains configured producers, including Studio/Notes Mermaid. Build and Search CLI commands require both `--scope <scope-id>` and `--stage working` or `--stage pre-publish`. Archive, Import, Settings and HTML Export retain exact stage targets. Document packages use configured Working sources while keeping their existing package identity format.

Archive is the single cross-scope document action. It moves selected ordinary Working documents to Notes Working and always includes every descendant, counting overlapping selections once. The confirmation body states only the number of documents to be moved. Notes has no Archive action; child collections and their report hosts are excluded. General Copy/Move controls, destination selection, optional descendant inclusion, sub-scope Copy and their service endpoints have been removed. Ordinary same-scope parenting and collection placement remain separate.

`docs_document_archive.py` plans the exact source selection and fixed Notes destination; `docs_document_archive_apply.py` validates the preview receipt before applying. Archive preserves document IDs, authored metadata and parent relationships within the moved set, making each moved root a Notes root. It rewrites moved documents' affected references and copies or reuses their referenced local media and Mermaid inputs without overwriting different bytes. Ready media is available in Notes Generated, and source assets remain available to other documents. Notes source and document output finish before source documents are removed and their collection output is rebuilt. If the source default is archived, its Working default is cleared. A failure reports the failed phase and completed document writes/removals. Publication eligibility remains owned by each scope's existing policy, and Archive does not prepare, publish or rebuild Search.

Delete remains a Working authoring operation, including the existing selected-document/descendant rules. The next explicit Pre-publish operation removes obsolete derivatives and rebuilds their indexes; the next Publish removes them from the accepted snapshot. Immediate cross-stage deletion remains separate. Neither ordinary Delete nor Pre-publish modifies Published or public documents/media.

Existing sub-scope report Refresh retains the exact configured stage/collection manifest and generated target. Refresh does not promote content or authorize Pre-publish source changes. Continuing token, report and specialised editing investigations use Working.

Sub-scope creation through `docs_sub_scope_lifecycle.py` binds the new host, collection configuration, source paths and rebuilds to the explicit Working stage. Missing stages and Pre-publish authoring are rejected; other stages and public projections are unchanged. The restored Moments collection uses this Working boundary, with its images retained locally and referenced through collection media tokens.

Whole-sub-scope Delete remains unavailable in the shared lifecycle. Its service fails before writes and its collection capability is disabled. This does not disable ordinary Working document Delete or whole-scope lifecycle operations.

Whole-scope Rename is available for eligible user-created local scopes only while no Published snapshot is present. Preview and Apply reject an existing snapshot before moving the scope, because accepted files retain their scope identity. Rename rebuilds both source/generated stages and does not rewrite authored links. There is no implicit publication or old-scope alias.

The executable boundary is maintained in `docs_scope_config.py`, the source/management services, `docs_write_rebuild.py`, the configured-scope provider and generated-data runtime. Focused evidence lives in `docs-viewer/tests/python/test_docs_workflow_stages.py`, the owning generator/service tests and `docs-viewer/tests/js/docs_viewer_stage_target_contract.mjs`. [Runtime](/docs/?scope=studio&doc=d-20260331-000000-c313fd) owns application composition and endpoint authority.

## Media And Location Ownership

Each configured media type resolves source, generated and accepted locations. Source media and registered inputs live beneath `source/media/`; build output lives beneath `generated/media/`. A ready input can be copied without conversion; registered producer inputs build their configured output type. Build does not write reproducible output back into source.

Ordinary Analysis documents use `docs/analysis/<type>/<identity>`; child documents use `docs/analysis/sub-scopes/<collection>/<type>/<identity>`. The exact document/build stage selects its own media; authored tokens remain the same across Working and Pre-publish. Builds resolve the document's collection namespace. Retired namespaces have no alias or generic remote-media fallback. Explicit external URLs retain their existing meaning.

Local child media routes use `/docs/media/<scope-id>/<stage>/sub-scopes/<collection>/<type>/<identity>`; ordinary routes omit the child segment. Publish places accepted child media in `analysis/published/sub-scopes/<collection>/media/`, beside that child's accepted documents. Published reads use `/docs/published/media/analysis/sub-scopes/<collection>/<type>/<identity>`. All configured scopes use the same stage-qualified local route shape.

Add image/file and Docs Import copy prepared media into the selected collection's Source and Generated locations. Same-named files in another collection are independent. Existing filenames in the destination use the normal replacement decision. Archive carries exact source and Notes ownership through media planning and reference rewriting, rejecting conflicting destination bytes. There is no shared-image registry. Mermaid source discovery and watcher output use the owning collection as well.

Logical media identity, storage provider and served reference remain separate. Location helpers confine filesystem paths or R2 keys and own listing, reads/writes, byte checks and served-reference resolution. A reference does not establish ownership of the referenced bytes; Catalogue media and retained external originals remain independently owned.

All public Analysis media types (`img`, `svg`, `files`, `html`) use R2. Paths inside the accepted Analysis `published/` snapshot map directly beneath `docs/analysis/`: parent `media/<type>/...` and child `sub-scopes/<collection>/media/<type>/...`. Public URLs use `https://media.dotlineform.com/` plus the R2 key. The tracked `site/` projection contains document payloads and these URLs, without copies of Analysis media.

`docs_public_media_reconciliation.py` deploys every accepted media file within each configured collection/type destination. References provide missing-file diagnostics; Working, Generated and existing remote bytes cannot replace missing accepted media. A failed preflight leaves public media unchanged, and a failed copy prevents stale-file deletion within that collection/type. Catalogue and unrelated prefixes remain separately owned. Analysis promotion controls remain deferred; this media migration does not enable them.

The accepted/public `tags` collection paths remain snapshot bindings, not aliases for the active `concepts` collection. Legacy R2 Moments and Analysis paths are held temporarily for the older live website. Remove those exact objects after public deployment and live-reference verification, as recorded in [Analysis Media In R2](/docs/?scope=studio&doc=d-20260907-201225-db6e8a).

[Media And Asset Handling](/docs/?scope=studio&doc=d-20260514-184303-7914e2) owns media intake and serving; [Document Diagrams](/docs/?scope=studio&doc=d-20260719-123719-fb7565) owns registered Mermaid authoring and builds.

## Current Limits

- Pre-publish and Publish are shared local lifecycle operations. Deploy Repo and legacy source-to-editorial lineage controls remain unavailable under their existing deferred capability; this lifecycle cutover does not authorise deployment.
- Working exposes ordinary authoring, Import and Settings. Service authoring guards reject Pre-publish and Published writes; settings reads identify the exact stage and mark Pre-publish fields read-only.
- Scope-wide Broken Links auditing still assumes one generated collection per scope. Existing sub-scope report Refresh has a separate, verified stage target.
- Local collection media structure and accepted-media R2 projection are implemented. Full Analysis promotion/deployment controls and public website release remain separate.
- Semantic-token, destination and specialised subject-tool review remains separate. Retained old-scope authored links and Folder-subject compatibility residue do not authorize retired-path resolution.
- Source, generated output, separate Search output and accepted/public snapshots can differ until their owning operation runs. Do not conceal that difference with fallback copies or automatic promotion.

Data Sharing, Docs Import and validated-package review use Docs Viewer-owned source/rendering boundaries. Their working packages are not scopes or alternative canonical roots.
