# Publication Media

`publication-media.json` has been retired. Source Save already has the saved document and edited candidate in memory, so it can compare their references directly. There is no replacement media-baseline file and no additional media list in generated by-ID JSON.

## What Happens On Save

1. Compare media references in the loaded saved body/fields and prepared candidate, including the independent thumbnail assignment.
2. Carry current references and exact owned removals through the same operation.
3. Write selected new/replacement media, persist source and complete exact document generation.
4. Save the publication selections in `working/docs-publish-pending.json`, then remove the selected owned Working files.

References are sets: a remaining occurrence keeps its file. Automatic removal covers the document's `<doc_id>/` body-media namespace and exact flat thumbnail identity. Replacement Import also compares its loaded target and candidate in memory and completes removals after its generation step.

## What Is Persisted

| Data | Purpose |
| --- | --- |
| Working source and media | The saved document and its ready files. |
| Generated by-ID JSON | The reader payload, without a media-reference ledger. |
| `working/docs-publish-pending.json` | Exact document/media writes and removals for Publish to apply. |
| `working/source/unpublishable.json` | The single exclusion-policy input read during index generation. |

Index generation reads `working/source/unpublishable.json` once per operation and carries the list in memory. Policy edits apply at the next index generation, including exact Save/Rebuild follow-through. Existing public indexes provide previous membership for withdrawal/restoration decisions. No second policy copy or policy-change record is persisted in `index-tree.json` or elsewhere. Publish uses the completed queue without reading the policy.

## Draft, Rebuild And Publish

A Draft Save stores new media in Working without selecting its public upload. Removing an owned reference can still queue its public removal. When the document becomes eligible, generation selects its current media for publication. Draft/exclusion alone does not delete Working media.

Exact Rebuild and CLI generation derive current publication references from their supplied source. They do not need a saved historical media list and do not reconstruct a prior external edit. Search, Recent and Docs Media retain their separate explicit refresh owners.

Publish consumes the completed queue selections and clears successful units. It does not compare document sources or maintain a reference baseline. A selected removal whose publication target is already absent remains a successful no-op.

If Working removal fails after generation, the error reports completed effects and the public removal remains queued. Remaining Working orphans, whole-document media and old flat files are cleaned manually; there is no saved comparison to replay.

[Media And Asset Handling](../Media_And_Asset_Handling.md#saved-ownership-and-exact-removals) owns the detailed lifecycle. [Builder](../Builder.md#publish-preparation) owns index eligibility and publication preparation.
