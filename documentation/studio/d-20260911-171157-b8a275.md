# Pre-publish And Publish - Delivery

## Approved Boundary

Restore the normal Working → Pre-publish → Published operations through code and configuration changes. Rebuild replaceable derivatives from current source instead of migrating old Pre-publish, Published or site JSON. Public deployment and cutover remain the subsequent delivery.

## Decisions

- Configure Works, Concepts, Processing and Moments in Working and Pre-publish, with matching accepted/public collection configuration. Use `concepts` rather than the former `tags` collection name.
- Omit `draft: true` and `publishable: false` documents, their descendants and collections whose report host is omitted. Missing Working draft metadata retains the existing default of draft.
- Processing remains configured but its report host is draft. This flag was already set; no Working status flags were changed.
- Working local collection report declarations become public declarations in the Pre-publish derivative. Other local management report documents are omitted; local report blocks in child prose are removed.
- Strip authoring readiness/intent metadata and Folder subjects from promoted source. Preserve exact valid Catalogue subjects; malformed/conflicting declarations cannot become inferred subjects through sanitization. Local folder links render as text in Pre-publish.
- Normalized reader `subject` is `{kind, key}` or `null` in every by-ID JSON and child `manifest.json` row. `sub-scope` remains source metadata and is not added to reader manifests. Management retains its separate diagnostic subject metadata.

## Implementation

- [x] Add a Working Pre-publish control and revision-bound preview/apply service. The operation replaces Pre-publish source and generated files, then awaits all configured document collections and Search before recording completion.
- [x] Allow the build-only Search owner to prepare Pre-publish while retaining service-enforced read-only authoring. Empty excluded collections do not require a visible Search report host.
- [x] Restore Publish in Pre-publish. It validates the exact stage's complete Build and the confirmed acceptance revision, then reconciles the scope-owned Published snapshot using the existing publication owner.
- [x] Keep Working Rebuild visible. Keep ordinary Pre-publish authoring and Deploy Repo unavailable.
- [x] Use ordinary rebuilds to replace obsolete derivatives, including stale source documents and generated files removed from the selected set.
