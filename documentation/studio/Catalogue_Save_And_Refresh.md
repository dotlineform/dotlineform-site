# Catalogue Save And Refresh

## Current Workflow

Studio owns canonical Work, Series, Gallery and membership source in `studio/data/canonical/catalogue/`. Save completes an authoring change, stages prepared media and queues its known effects. Refresh hands false-readiness entries to Working. Regenerate builds refreshed queued documents and forwards completed selections to publication. Publish completes each queued Work's Preview and Deploy, then shared output under [Catalogue Deployment](Catalogue_Deployment.md). Hosting changes remain separately scoped under [Catalogue Hosting And Storage Options](Catalogue_Hosting_And_Storage_Options.md).

```text
Save              canonical source + staged media + updates queue + editor records
Refresh Catalogue selected Working metadata/media + readiness + shared indexes/report
Regenerate        selected Catalogue source/Build + publication queue
Docs Publish      each Work's Preview/Deploy, then shared output
```

Use **Save → Refresh Catalogue → Regenerate → Docs Publish** for a new or changed Work, and **Delete → Refresh Catalogue → Regenerate → Docs Publish** for removal. The editor displays saved staged images immediately. Docs readers adopt Working metadata and media after Refresh; Catalogue documents adopt those inputs after Regenerate; Preview and configured repository/R2 destinations adopt them during Publish. Git commit/push and GitHub Actions deployment remain separate actions.

The workflow is implemented. On 2026-10-10, the user confirmed new Work addition and subsequent deletion through to R2 and perceived a quicker Catalogue queue Publish. Managed-file and other variants remain unverified; this evidence limit does not change the documented operation ownership. Detailed current limits are below, and [Catalogue Deployment](Catalogue_Deployment.md) owns publication behavior.

## Save Boundary

Single/New and bulk Work Save read the Work authority once, carry their before/after maps through the mutation and local completion, and return the completed canonical records for direct editor adoption. No Series read or post-Save Work lookup is needed for those paths. Required single/batch media finalization proposes copied record changes, persists bytes/metadata through the existing transaction owner and then updates the carried current map; it does not reread canonical source before or after media persistence. Failed media persistence leaves the carried map at its saved pre-media state, and Save reports the incomplete step while preserving canonical success. Series/Gallery definition writes also supply their loaded before/after records to this completion owner, avoiding dispatcher/completer reads. Batch/deletion records use the same handoff. Completion requires the supplied current map and has no canonical reread fallback.

Bulk metadata editing uses the fields maintained in [Catalogue Work Editor](Catalogue_Work_Editor.md#bulk-editing), alongside Gallery memberships and the explicit source-folder action. Exactly equal saved values display their common value; mixed metadata shows a blank control with a Mixed values placeholder, while list-selected Works always share one Series. Only explicit input marks a field for replacement across all selected Works. Untouched fields retain each saved value, even when another field is changed. The UI validates edited required/numeric fields; blank optional edits send nulls that remove only the supplied canonical keys. Gallery editing keeps its intersection baseline and sends an explicitly edited final set, including an empty set. Other metadata remains read-only.

Bulk Save retains a narrow metadata allowlist and the exact `kind`, selected `ids`, optional `set_fields`, `gallery_ids` and `source_folder` envelope. It patches supplied fields without passing untouched metadata, downloads, media versions or staging flags through full-record normalization. It carries its saved editor records/hashes through completion without recomputing them. Source-folder relinking changes location references only; bulk completion performs no media-change detection or production. Changed Works and known metadata/source/Gallery effects enter the existing updates queue, with accurate saved-but-incomplete reporting if queue completion fails.

Unchanged downloads are assumed to remain available. Download preparation and queue effects share the selected added filenames and supplied native replacement bytes. Metadata-only edits, download-label edits, removal-only edits and image changes with unchanged downloads perform no file-availability checks on those unchanged files. Selected additions/replacements retain filename/path safety, upload/reference agreement, byte limits, required nonempty-file checks and staging ownership. Image replacement/source changes through Choose image and explicitly confirmed regeneration retain their required image processing; an explicit single-Work source-folder relink excludes only folder/source changes from image selection. Save remains one awaited operation and keeps Refresh, Regenerate, Search and Publish separate.

Series–Gallery relationship choices are validated by the Gallery dialog: the Series resolves against loaded definitions, its checkbox supplies a boolean and the checkbox is disabled without a Series. Gallery Create/Save consume the supplied `series_id` and `related_to_series` without repeating their type or available-Series checks. The server still merges/removes the selected pair, preserves unrelated pairs, writes the canonical store and completes known effects. Saved-file representation checks and explicit canonical audits retain their separate owners. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) D.09 records this boundary.

The UI also owns Work title completion for downstream Work data consumers. Compact and Gallery-member rows, public Work records, private report inputs/metadata, Catalogue regeneration and live/static image and Entry rendering copy or consume the supplied title without nonblank validation or title-to-ID substitution. Local reports, the title picker and shared/public Media View follow the same boundary, including title-derived image alt text and labels. Document Build retains authored references without resolving Work presentation. Consumed string types, payload fields, identities, timestamps and media safety remain checked at their owners. D.03's existing UI required-title gate remains in place; D.01's allowance for repeated Work titles requires no code change.

Save preserves UI-authored Title, Medium, Duration and Storage location without trimming, text coercion, leading-apostrophe removal or substitute values. Saved editor controls, member/search lists, report display/copy and Entry/Media View consume the same values. Optional absence remains valid and displays empty; structural string/numeric/array checks and escaping remain. Numeric controls represent saved numbers as text; Copy table escapes TSV tabs/line breaks without collapsing other whitespace. Lookup, generation, source pickers and refreshed-source reports preserve Work Series/source references literally. Explicit media-source IDs resolve as supplied; documented absence selects the configured default and its existing canonical omission rule remains. Filename/path validation rejects unsafe representations without repairing them. Query matching and UI authoring input serialization/validation remain with the editor. Resource display/edit/delete labels follow D.14, and Refresh preserves complete download objects including server staging flags.

Year, Year display and physical dimensions follow the same UI-owned authoring boundary. Save serialization, lookup, public/report projection and rendering preserve supplied values; downstream report readers retain numeric/string representation without rechecking whole Year or nonblank Year display. Entry metadata displays every supplied physical dimension in height/width/depth order, including zero, negative and single values, omitting only absent/null optional dimensions. Media View omits the former unused descriptive metadata array. Save measures intrinsic pixel dimensions from the actual image file, stores them with the prepared rendition set and finishes before returning success. Live and static presentation consumers trust those pixel values and derived candidate widths without validation, coercion or fallback sizes; Document Build emits references without reading them for presentation. Configured rendition policy, exact identities, timestamps, media versions, escaping and file/URL safety retain their existing owners. [Catalogue Media View](Catalogue_Media_View.md) and [Generated Data Contracts](Generated_Data_Contracts.md#catalogue-reference-and-presentation) own the current presentation contract.

The Work editor validates metadata completion, numeric input and Series/Gallery choices against its loaded data, then sends exact Work IDs and the authored state. The UI owns Gallery membership list representation, string IDs, distinct selections and existing Gallery endpoints. Single/New, batch and bulk Work writes persist those choices without repeating Gallery array/member-type or membership validation, Series/Gallery endpoint checks, record/membership revision comparisons or a complete Catalogue audit. Single/New and subfolder-batch Save send the validated Gallery list; bulk Save sends it when edited. An empty replacement removes the selected Work's membership entry. Individual creation checks exact five-digit ID spelling and collision; existing Save/bulk targets must already exist. Other request envelopes, confined writes, required media processing and known-effect completion remain server-owned. Ordinary Series/Gallery definition writes and supported deletions likewise perform no complete canonical family audits. Series Create/Save accept only the exact identity and title-only record, with UI-owned title completion and no Save revision comparison or combined Work assignment. A successful canonical transaction remains saved if later local completion fails.

Series editing uses the editor's loaded definition and complete saved Work membership map; New allocates the next numeric ID from that loaded definition map. Opening/saving the modal requires no fresh Series definition/member/search read; the unused `catalogue_lookup_series_base` read and its payload builder are retired. The server rejects Create collisions and absent exact Save targets, preserving the supplied title without trimming/coercion or repeated title validation. Creation reads only Series. A changed title reads Works once to select affected members for metadata completion; unchanged Save needs no Works read. Neither path reads Galleries or accepts alternate payload forms/`work_updates`. Series search/Create/Save responses carry identity/title without an unused record hash; editor adoption uses the returned record directly. Definition records are final at mutation completion, so the completer does not rewrite or hash them. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) M.08 owns definition Save; M.11 owns the UI-confirmed empty-Series Delete boundary.

New Gallery derives its ID from the editor's already loaded `galleriesById`: highest numeric ID plus one, padded to at least three digits, with `001` for an empty map. Successful Gallery creation/deletion maintains that map. Create/Save send exactly `gallery_id`, `title`, `series_id` and `related_to_series`; the UI owns nonblank trimmed titles and the loaded Series choice. The server checks the request envelope and canonical Gallery identity, rejects an existing Create ID and requires an existing Save target. It persists the supplied definition/relevance without another Series lookup, title-type/completeness/uniqueness validation, Save revision check or complete Catalogue audit. It retains configured write confinement, transaction ownership and known-effect queue completion. Required reads for merging data and capturing downstream effects are separate from validation audits. Only changed canonical stores are serialized; a title/relevance Save does not build/sort unchanged Work memberships, and the response reuses the known definition and saved associations without another identity/member scan. Ordinary Gallery Edit retains its definition/Series-association read but no longer reads memberships or builds, sorts or returns a member-ID array. The UI calculates the deletion confirmation count from its complete saved `workSearchById` map. Gallery lookup/mutation responses carry neither an unused member-ID array nor a definition revision. Restart Local Studio and reload the editor together when adopting this response-contract change.

Gallery Delete sends only the UI-selected saved `gallery_id`. The server requires that string-ID request envelope and exact existing definition without repeating ID-spelling, revision or member checks. It reads Works, Gallery definitions/memberships and relevance pairs once, removes the exact definition and its current references and preserves unrelated records without a family-wide audit or Series-definition lookup. Pair removal captures former Series endpoints in the same pass; the final association list is known to be empty. The removed definition, captured members and former relevance endpoints determine which stores need writing, without comparing complete maps or rescanning relevance pairs. Known direct and Series-related Work effects flow through the existing queue completion owner using the loaded Work map; Works are retained. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) M.12 owns this UI/server boundary.

Subfolder creation sends UI-validated shared metadata and the picker's exact source/folder/subfolder/filename list to the focused batch-create service. It reads Works and Gallery memberships for allocation/merging, allocates consecutive five-digit IDs above the highest current Work ID and writes the supplied Works/memberships together. It does not load Series definitions or recheck Year, Year display, dimensions or memberships. Lower unused IDs remain available for deliberate individual creation; insufficient capacity above the highest ID rejects the complete batch before writes. Confirmed source identities, supported media forms and path confinement retain their operation checks. There is no directory enumeration or deduplication against previously imported images. The normal completion owner receives the completed current records and completes all created images in the same awaited request, carrying persisted dimensions/versions in the supplied map without another canonical read. Media preparation and finalization inspect their exact required inputs without a complete Catalogue audit. Failure returns all created IDs and the unfinished step. The editor releases batch-creation intent and adopts returned saved records directly so another Save cannot replay creation or require a post-Save Work lookup. [Catalogue Work Editor](Catalogue_Work_Editor.md#import-a-project-subfolder) owns the user workflow.

Series and Gallery titles may repeat within their own families. Their New/Edit definition dialogs compare the entered title against the editor's already loaded family map, ignoring case and collapsing whitespace while excluding the current exact ID. A match shows an advisory warning naming another record's ID and explicitly allows saving; it needs no additional lookup or server call. The warning has a separate field notice so save failures retain their own feedback. Cross-family title reuse has no warning. The [Series source validator](../../studio/services/catalogue/catalogue_source.py) and [Gallery validator](../../studio/services/catalogue/catalogue_galleries.py) perform no title-uniqueness checks in mutations or explicit audits; identity, representation and relationship validation retain their existing scope. Work titles may repeat. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) D.02 records implementation and manual-check status.

Save prepares an image for a new Work, a changed media source or an explicitly confirmed Choose image selection. New Works force conversion even if an unused ID has old local renditions left from a deleted Work. Confirmation requests complete primary/srcset and thumbnail conversion even when the source identity/path and modification time are unchanged. Save measures dimensions and advances `media_version` only when existing rendition bytes change; identical regenerated bytes and missing-rendition repair retain the version. A metadata-only or membership-only edit without confirmed image intent does not convert images. Save also writes pending native attachments and validates retained managed downloads. Removed references do not automatically delete shared or remote media.

A new Work with no existing renditions starts at media version 1. If its ID is reused while older rendition files remain, its first Save can advance that version because the new bytes differ from the existing files. The version identifies image changes at that media identity; it is not a count of saves of the current Work record. Refresh and Publish transfer prepared bytes without advancing it.

Missing originals or managed downloads, conversion errors and destination-write failures are reported as incomplete local Save completion after any successful canonical transaction. The editor adopts the saved record and revision while retaining unsatisfied native uploads and image intent. A successfully created Work becomes an existing Work even if media completion fails. Successful local media completion clears the pending operations; deliberate draft discard clears them too. Diagnose and correct the reported cause before another user-initiated Save: preserving the request does not imply that retrying alone will fix the failure. No automatic retry or persisted recovery marker is used.

Save persists completed image renditions, thumbnails and native uploads below Projects-owned `catalogue/media-staging/`. Work `image_staged` selects the complete image set; each download's independent `staged` boolean selects that file. False selects Working media. Metadata edits preserve flags, image edits preserve download flags, and same-name replacements remain explicit queued transfers. Public Work JSON omits these operational fields.

Mutation owners merge exact known Work IDs, metadata/image flags and filenames into `working/catalogue-updates-pending.json` (`catalogue_updates_pending_v5`), resetting affected Work entries to `refreshed: false`. Flags merge with OR; filenames accumulate while still referenced. The same write merges current/deleted Gallery and Series ID arrays, exact shared-output identities, explicit Gallery creations and Work candidates for member-row changes. Owners capture former memberships/association endpoints before deletion; Work title changes select their Galleries because member rows embed the title. Empty definitions contribute their own identity and required outputs without inventing a Work. Deletion replaces current selection; recreation replaces deletion. Mutations preserve the last successful Refresh time. Queue persistence is required completion; failures report saved-but-incomplete results.

Work Delete captures its image-set flag and exact download basenames before canonical removal, persists its deletion descriptor and removes those owned staged bytes. Staging cleanup accepts the complete deletion selection, filters out empty media descriptors and resolves pipeline policy and the checked staging root once for the remaining Works. The same loaded policy supplies staging layout and each Work's rendition paths without repeated config reads. A Work with no owned media still enters the deletion queue but requires no staging setup. Already absent bytes succeed; completed removals remain on failure. It does not scan other Works for ownership. Refresh and Publish retain descriptors for downstream removal; project originals and Gallery/Series definitions retain their owners. The confirmation describes those actual effects rather than promising shared-file preservation.

Work deletion removes only the selected saved Work IDs and their direct Gallery membership entries, retaining unrelated references rather than reconciling the family. The UI selects distinct saved identities. The service checks its exact request envelope, nonempty string-ID array and current saved targets without another spelling/distinctness check, ID sorting or revision comparison. It reads Works and Gallery memberships once, without loading Series/Gallery definitions, and carries before/after records and known effects into completion. Memberships are serialized independently of definitions and written only when a selected entry was removed. Request/path confinement, resource representation and queue integrity remain server-owned. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) M.10 records this agreement and evidence.

Series Delete's empty-member rule belongs to the dialog's complete saved Work map. It disables Delete for a populated Series and confirms the exact saved identity without an additional member/definition request. Confirmed deletion sends only `kind: series` and `series_id`. The server validates that string-ID envelope and existing target, then removes the definition and its current relevance pairs using one Series/pair read each. It performs no Work/Gallery-definition read, repeated member scan, ID-spelling comparison or revision check. Current pair removal, changed-store writes, queue integrity, confined persistence and saved-but-incomplete reporting remain server-owned. Works and Galleries retain their records. Direct callers must honor the same empty-Series precondition; the server intentionally does not recheck it. Series revision fields/comparison and their conflict response machinery are retired without aliases; Work response hashes retain their separate owner. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) M.11 records this ownership and evidence.

Complete canonical audits belong to the explicit [Catalogue source audit and repair CLIs](Catalogue_Source_Model.md#catalogue-source-audit). The UI supplies complete resource entries. Draft/Save serialization, effect comparison, lookup, Refresh projections and report readers preserve filenames, URLs and labels without coercion, trimming, leading-apostrophe removal or substitute text. Optional resource fields may be absent; explicit null/non-array values or non-object entries fail rather than becoming empty or disappearing. Save still owns download staging flags and file-processing checks. Private report inputs do not repeat the editor's nonempty-URL check; the browser retains URL-safety checks.

The response returns current canonical records, revisions and memberships for editor search, lists and reopened Works. Save does not generate consumer JSON or private Docs reports. It makes no R2 request and does not run Docs Build, Search or Publish.

## Updates Queue

`working/catalogue-updates-pending.json` is private to the configured Docs workspace and uses `catalogue_updates_pending_v5`. [The queue owner](../../studio/services/catalogue/catalogue_pending_state.py) separates parsing/persistence from explicit header, Work-entry and shared-selection validation. Normal Refresh/status and completed shared forwarding use parsing/persistence without content validation; other producer/consumer and maintenance owners retain explicit validation. The file must already exist; missing/unreadable state or unavailable data needed by an operation fails without creating an empty fallback. The retired collection-source queue, separate Refresh receipt and v4 updates reader have no runtime compatibility path. Publication uses `catalogue_publish_pending_v5`, excluding the two Refresh-only Gallery candidate arrays and all Preview progress flags.

Example of a changed Work awaiting Refresh:

```json
{
  "header": {
    "schema": "catalogue_updates_pending_v5",
    "last_refreshed_at_utc": null
  },
  "current_works": {
    "00008": {
      "metadata": true,
      "image": true,
      "file_names": ["00008-notes.pdf"],
      "refreshed": false
    }
  },
  "deleted_works": {},
  "current_galleries": ["003"],
  "deleted_galleries": [],
  "current_series": [],
  "deleted_series": [],
  "shared_outputs": ["works/works_index.json"],
  "created_galleries": [],
  "gallery_member_works": ["00008"]
}
```

Both maps use exact five-digit Work IDs and are disjoint. A current entry has `metadata`, `image`, `file_names` and `refreshed`; a deletion has the same fields except `metadata`. Every flag is an explicit boolean. `image` selects the complete configured primary/thumbnail set. `file_names` contains sorted, distinct, safe download basenames; an empty list selects no download transfer. Deletion retains these identities after canonical records disappear.

| State | Owning write and completion |
| --- | --- |
| Change selections | Save, Create, bulk, relationship and Delete owners merge their known effects once. Current flags accumulate with OR and filenames retain only still-referenced downloads. Deletion replaces current selection; recreation replaces deletion. |
| `refreshed` | A mutation resets its affected Work to false. Refresh sets true only after that Work's Working metadata/media handoff and staging-flag clears succeed. Completed true entries survive until Regenerate finishes their document work and publication merge. |
| Gallery/Series arrays | Sorted distinct exact current/deleted IDs, disjoint within each family. Refresh completes their selected records/relationships, merges publication selection and then removes the shared unit. They have no media or document-Regenerate flags. |
| `created_galleries` | Sorted distinct exact Gallery IDs, a subset of `current_galleries`. Only Gallery Create contributes them. They permit initial complete-member projection and creation of a missing by-ID file, including an empty new Gallery. Later edits retain the marker; deletion cancels it. Refresh clears it after shared completion. |
| `gallery_member_works` | Sorted distinct exact Work IDs with known title/identity or direct Gallery membership changes, each retained in a current/deleted Work queue entry. They accumulate independently of Work handoff readiness. Gallery rename/association edits and Year/Series-only Work edits contribute no member candidates. Refresh clears this array after shared completion. |
| `shared_outputs` | Sorted distinct Catalogue-relative system-file identities plus private `reports/series-galleries/metadata.json` and the three shared `private/` report inputs. Mutations select dependencies, not every index. Refresh completes selected builders once and forwards only public system files from the artifact inventory. Private Catalogue Works report rows remain part of the selected Work handoff. |
| `header.last_refreshed_at_utc` | Null until a successful Refresh; then its UTC completion time. Mutations, partial failures and Regenerate preserve the previous successful time. |
| Entry removal | Regenerate removes one true Work entry only after source/Build completion and publication merge. Refresh removes the selected shared unit only after all required Working output and shared publication merge complete. |

An empty Work map can still require Refresh because a Gallery/Series array or `shared_outputs` is nonempty. Status combines those selections with false Work readiness; it does not hash Catalogue/configuration files or infer readiness from the timestamp. Gallery create/delete/rename and association changes select the relevant Gallery/relation indexes and private Series/Galleries report. Work membership changes select old/new Gallery member records; the Gallery search index contains only ID/title under `catalogue_galleries_index_v3` and is not selected for membership changes. Work create/delete/title changes select the Work index, whose `catalogue_works_index_v3` rows contain only ID/title. Selected compact indexes merge queued rows into their saved maps rather than projecting the complete canonical inventory. Their headers contain only schema and generation time, and unchanged candidate rows cause no write. Work create/delete/title or membership changes select affected Gallery member records, whose `gallery_record_v3` member rows contain only ID/title and whose headers contain only schema, generation time and Gallery ID. Year/year-display and Series-only changes select neither the Work index nor Gallery member records; full Work by-ID output and private reports retain their ordinary handoff. Series title changes preserve member-Work contributions for private Work-report rows but do not rewrite the public relationship index, which contains no Series title. Media policy is selected only by explicit configuration maintenance through the same accumulation owner.

Compact Work candidates include every metadata-selected queued current Work and every queued deletion, independently of `refreshed`. A shared-output failure can therefore be retried after individual Work handoffs completed. Regenerate and document-design reconciliation require all shared selections to be empty before source/Build work, preserving candidate Work identities until shared Refresh and its publication handoff succeed. Missing/malformed selected compact output fails explicitly; normal Refresh does not create a baseline or repair it.

The selected Series–Gallery index replaces only queued current Series' association lists and removes queued deleted Series. The private Series/Galleries report replaces only rows touching queued Series/Gallery endpoints, retaining empty-Series and unassociated-Gallery placeholders from final canonical associations. Mutation owners already capture former endpoints before removal, including empty definitions. Each saved aggregate is read once and unaffected rows retain their values; unchanged candidate lists/rows avoid writes. Both outputs use minimal v2 schema/time headers without counts or hashes. One temporary lookup over loaded associations serves selected current Gallery endpoints; there is no persistent inverse map or complete relationship reconstruction during normal Refresh. Missing/malformed saved output requires explicit relationship maintenance.

For each selected existing Gallery, [the Gallery-record owner](../../studio/services/catalogue/catalogue_gallery_records.py) parses its saved record once and keys members without content validation. It upserts only `gallery_member_works` still in that Gallery's final canonical membership and removes queued deleted Works or current candidates no longer belonging there. Unrelated member rows retain their values without canonical Work joins or audits. A Gallery rename replaces only its definition; associated Work by-ID updates retain their ordinary owner without turning into member candidates. Unchanged Gallery content avoids a write and preserves generation time. Parsing, member indexing, changed-list ordering and full-file serialization still scale with member count; separate readers retain their saved-record validator.

Only queued `created_galleries` receive an initial complete list from current canonical membership. Refresh builds one temporary member-ID map for those new definitions, including empty lists; a new incarnation of a reused Gallery ID replaces any former members. Missing existing or malformed selected records fail visibly and require explicit maintenance. Creation/member candidates survive partial shared failure even when their Work entries already have true readiness; Regenerate requires every Refresh selection to be empty before consuming those Works. The public `gallery_record_v3` shape and publication of complete files are unchanged.

## Empty Gallery Cleanup

The [Work editor](../../studio/app/frontend/js/catalogue-work-actions.js) owns newly empty Gallery discovery. Before single/bulk Save, it captures Gallery IDs removed from the selected saved Works by the submitted replacement. After successful Save and saved-record adoption, it checks those candidates against its complete saved `workSearchById` membership map. Galleries that were already empty and Galleries with any remaining members are excluded. No removed candidates means no complete-map scan. Work Save responses carry no empty-Gallery candidate list; no extra server read, persisted count or membership index is needed. New Work creation does not remove memberships and does not trigger this workflow.

After Work Save and its required local/editor completion succeed, the editor opens the existing Gallery delete confirmation for each discovered ID, one at a time, using its cached Gallery definition. The prompt names the Gallery and states that the Work changes are saved and the Gallery has no Works. Gallery delete confirmations omit Series-association counts. **Keep Gallery** retains the definition. **Delete** sends only the exact Gallery ID to the Gallery delete owner; there is no Gallery reread, repeated emptiness check or definition revision/member precondition. Removal from the Work draft alone does not prompt or delete anything.

Deletion addresses the exact existing canonical Gallery, removes its current membership and relevance references, then completes the ordinary known-effect handoff. The editor reconciles its cached definition and membership references and invalidates Catalogue Refresh through the existing owner. Incomplete Work Save or editor adoption stops before cleanup. Cleanup failure preserves the completed Work Save and stops the remaining prompts; an error inside the confirmation remains visible until the user retries or closes it. Keeping every Gallery needs no further Save. Ordinary Gallery editing loads saved Series associations for its relevance control and counts saved members in the UI's complete Work map for deletion confirmation. Generated Catalogue readers and publication retain the normal separate Refresh/Publish timing.

## Work Media Authoring

Single and bulk **Choose source folder** relink unchanged originals. The browser checks expected filenames against the picker-loaded destination list and sends one confirmed `source_folder` with optional canonical source/subfolder omissions; one shared server envelope reader checks its exact location-only shape without repeating authoring validation. Python carries the supplied before/after Work maps through persistence and completion. Folder-only changes retain filenames, prepared media, dimensions, media versions and staging flags, selecting metadata/private Work-source effects only and preserving previously queued media work. Single Save supplies known relink targets to media selection, excluding folder/source changes while retaining actual filename changes, explicit regeneration and required attachment preparation. Bulk completion remains free of media detection/production. No source-file read, hash or image preparation is needed for a folder-only change. [Catalogue Work Editor](Catalogue_Work_Editor.md#relink-source-folder) owns the controls, draft lifetime and exact request behavior.

The Work editor's **links** section shows a file or link icon followed by one linked label for each attachment or added URL. Clicking the label opens its destination in a new tab. The label uses the remaining row width; filenames and URLs are visible through **Edit** rather than a separate destination column. Row selection still enables **Edit** and **Delete**. Pending attachment labels remain plain text until Save completes because their selected bytes are not yet in managed storage.

**Add file** opens the browser's native single-file chooser in existing and New Work editors. Selection holds the file in the current browser draft, uses its original filename including extension as the initial label and marks the draft unsaved; cancellation leaves it unchanged. **Edit** changes the label while keeping the filename read-only. The Catalogue write owner derives `<five-digit-work-id>-<normalized-filename>` from a safe basename. The stem becomes lowercase ASCII letters and digits, with runs of spaces or punctuation replaced by one hyphen and edge hyphens removed; an empty normalized stem becomes `attachment`. The last alphanumeric extension is retained in lowercase; names without that extension are normalized as one stem. Work `03188` selecting `composite for 3 symbols.PDF` stores `03188-composite-for-3-symbols.pdf`, while its initial label retains the selected spelling. The browser previews the same naming rule; the server derives and validates the actual destination independently.

Choosing a file that produces the same normalized identity replaces that attachment on Save, reuses the entry and preserves its edited label, including when no canonical metadata changes. Different original names can normalize to the same identity and receive that same replacement behavior; choose a distinct normalized basename to retain both files. Editing a New Work ID updates pending filename previews before Save. Existing differently named attachments retain their identities; selecting a new normalized identity does not rename or migrate them.

File bytes travel with Work create/Save as multipart data; UTF-8 metadata carries original filenames and binary parts are opaque. Existing limits remain 64 MiB combined attachments, 1 MiB metadata and 1 MiB multipart overhead per Save. Safe nonempty basenames are bounded to 255 UTF-8 bytes. The [attachment owner](../../studio/services/catalogue/catalogue_work_attachments.py) derives exact identities; the [upload adapter](../../studio/app/server/studio/studio_catalogue_upload.py) bounds requests. Native bytes replace that exact staged identity. Retained downloads are validated in their flag-selected staging or Working location; unrelated old staged bytes are never implicitly ingested.
