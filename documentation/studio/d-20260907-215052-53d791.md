# Sub-scope Report Reparenting

## Outcome And Boundary

Reparenting an ordinary report host within its scope and stage changes its tree position while preserving its document identity, report declaration, child destinations and media ownership. The existing Move action must read, write, rebuild and acknowledge the selected Working stage. Pre-publish authoring, invalid parents and hierarchy cycles remain rejected.

Whole-sub-scope deletion validates the configured host identity and its unique report association against current source. Ordinary reparenting or content edits must not fail a comparison against the host's creation-time revision. Missing, detached or ambiguous hosts remain blockers, and deletion retains its explicit preview/confirmation workflow.

This correction does not enable whole-sub-scope Delete in staged Analysis; that action remains deferred with the wider lifecycle work. No real documents are moved or deleted during implementation. Publish, Deploy, Search rebuilds and computer control are outside this slice.
