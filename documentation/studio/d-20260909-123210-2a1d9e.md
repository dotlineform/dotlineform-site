# Analysis Broken Links Report

Complete, accepted and closed on 2026-09-09. [Broken Links Script](/docs/?scope=studio&doc=d-20260423-165116-c83a81) owns the implemented behavior. Retain this completed delivery for manual archive; no implementation or closeout step remains open.

## Requirements

Provide a local Broken Links report in `analysis` Working so the author can find and repair broken references there. The existing [Studio Broken Links report](/docs/?scope=studio&doc=d-20260423-165116-e7f7e9) must no longer offer or include Analysis as a source scope. The complete outcome is that Analysis findings are inspected in Analysis and cannot appear through the Studio report's source-scope selection, while the shared audit remains reusable.

[Doc Relationships](/docs/?scope=studio&doc=d-20260907-125101-d3bde6) owns the relationship principle: generated records describe existing eligible documents. Document Build silently skips a linked target whose by-ID JSON does not exist. Broken Links supplies the separate authoring diagnosis; the relationship system does not retain missing-target placeholders or report those omissions.

- Audit Analysis/Working documents across the scope-level collection and all configured sub-scopes. Preserve the exact source scope, stage, collection and document identity when opening a finding for correction.
- Inspect the documents' actual links through the existing audit inputs, independently of filtered incoming/outgoing lists or the scope relationships index. Include source documents excluded from relationship data by `publishable: false` or `folder:`; they can still contain broken authored links.
- Report a document destination whose exact by-ID JSON is missing, including when an index entry still exists. Retain the offending reference and the owning document location so the author can fix it.
- Keep source-scope selection separate from destination lookup. A Studio-authored link to an existing Analysis document must still resolve correctly; excluding Analysis findings from Studio must not make valid cross-scope destinations appear broken.
- Remove Analysis from the Studio report's selectable and effective source scopes, including a stale `report_scope=analysis` route. Preserve its other configured non-Analysis scope behavior unless the readiness review identifies a separately agreed change.
- Reuse the existing supported document-link and token diagnostics and ignore rules. This delivery does not introduce new link categories, a general web crawler or front-matter validation.
- Keep the report read-only and local. Findings never block Save, Document Build, scope-build, Pre-Publish or Publish, and the report performs no automatic correction.

## Deliverables

- An Analysis/Working report-host document and normal local navigation to it, using the existing Broken Links report capability.
- A report request and audit path that preserves the selected Analysis Working context and includes its configured collections.
- An updated Studio report scope boundary that excludes Analysis source documents while retaining valid cross-scope target lookup.
- Findings that identify missing document by-ID targets independently of relationship output, and source links that open the exact document for manual correction.
- Focused verification, user review and an updated [Broken Links Script](/docs/?scope=studio&doc=d-20260423-165116-c83a81) as the durable audit-operation owner, covering current storage, source partition, request context and diagnostics.

The implementation reuses the shared broken-links audit, its Docs management service adapter and the `docs_broken_links` report module/registration. Report requests now preserve the owning report context and explicit Analysis stage, and the audit covers all configured Analysis collections.

Implementation of the relationship engine, the non-publishable documents inventory, changes to other reports and publishing actions remain separately owned work. This delivery can be implemented without waiting for relationship JSON because it audits document links independently.

## Process

1. Open Broken Links in Analysis/Working and run the read-only audit over the current Analysis authoring documents.
2. Inspect the offending reference and open its exact source document, retaining the correct collection and Working context.
3. Correct the link using ordinary source editing and Save, then rerun the report to confirm the finding has cleared.
4. Use the existing report in Studio for its supported non-Analysis source scopes. Valid destinations in Analysis remain available to its target lookup, but Analysis-authored findings are handled by the Analysis report.

Relationship data, when implemented, independently reflects the currently existing eligible targets during Document Build. Report findings do not trigger relationship repair or alter the publication workflow.
