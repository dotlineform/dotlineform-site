# Concept

## Intent

The Catalogue already provides an organised, canonical record of the Works. Analysis should make that material available for exploration, discussion, juxtaposition and reinterpretation, rather than reproduce a fixed catalogue with a different page renderer.

This is the working direction within [Unified Analysis And Catalogue Presentation](/docs/?scope=studio&doc=d-20260902-102745-8379ea). The single-Work Media View is implemented and accepted; the wider token, gallery, report and consumer-data model remains under design.

## Canonical Works, Documents About Works

There is one canonical Work, identified by its Catalogue ID and described by canonical JSON. There is no corresponding concept of a canonical Work document.

A Work may be associated with no Analysis documents, one document or many documents. A document may refer to several Works. These are normal many-to-many relationships, not missing or ambiguous representations that must be repaired.

A document's subject identifies what it is about; it does not give that document exclusive ownership of the subject. A `work_id` subject identifies the canonical Work without imposing a uniqueness constraint across documents. Documents retain their own independent `doc_id`. [Catalogue Data Model](/docs/?scope=studio&doc=d-20260903-231534-b63aa9) defines the five subject choices, including a new `detail_uid` field for documents about individual Details.

Consequently, “which single document represents this Work?” is not a meaningful global lookup. Docs Viewer contains documents about Works, not a guaranteed complete set of the Works themselves.

## Media View Presents The Work

One canonical Work has one canonical image and one canonical set of metadata. Media View presents that image and metadata, taking over the essential presentation of the current Work page without requiring an authored document to stand in for the Work.

[Media View - Work 00523](/docs/?scope=analysis&stage=working&doc=d-20260906-164429-9892a8) now proves this boundary with an exact Work, contained image, ordered text metadata, direct media action and return to the originating document. The shared public and Manage adapter consumes a complete browser-ready payload without fetching Catalogue data or creating document identity.

Work thumbnails are intended to open the Work in Media View rather than select a document about it. Work Detail thumbnails may use the same view for the selected Detail. Those gallery, sequence and Detail extensions remain to be designed, and both journeys must work independently of whether the displayed entity has its own document.

Documents can consume canonical Catalogue data through tokens that:

- list documents declaring a selected Work as their subject;
- render the image and metadata inline for an exact `work_id`;
- render a link that opens the image and metadata for an exact `work_id` in Media View.

A token cannot resolve “the definitive document about this Work”, because no such role exists. An explicitly authored link to a particular document remains an ordinary document link. Inline and focused Work presentation should share the same presentation component and data, rather than evolve separate versions of the Work's metadata display.

Often there will be only one associated document. That is an authoring decision, not a rule enforced by the presentation layer.

## Document Associations

The intended document-link list, referred to here as `doc_urls[]`, is a reverse association list containing Analysis pages where either:

- a semantic token explicitly references the Work by `work_id`; or
- a sub-scope document declares that exact Work as its subject.

Associations can originate throughout Analysis, not only in the Works sub-scope. Combine both sources and list each document once, even when it contains repeated references or also declares the Work as its subject. Arbitrary prose mentions are not explicit semantic references.

This list answers “which documents refer to or are about this Work?”, not “which document is the Work page?” Several results are useful information, not an ambiguity error. A current document's own association remains valid; whether its UI suppresses a self-link is a separate presentation choice.

The public projection must still respect the accepted public document set. This direction does not make unpublished documents publicly discoverable. Extending the current subject-derived association machinery to include semantic-token references remains implementation work.

Media View can display `doc_urls[]` for the current Work, giving the reader routes into documents about or referring to it. It does not automatically choose one, even when there is only one result. No associated documents is a valid state: the canonical image and metadata remain available.

## Selected Document Creation

There is no bulk document migration and no automatic policy of creating a Details document for every Work that has Details. [Projects](/docs/?scope=analysis&stage=working&doc=d-20260805-155400-4c341f) already provides the backlog for most Series. A batch New doc action will create ordinary documents for selected Works or Series with front matter and basic starter content; [Delivery Sequence](/docs/?scope=studio&doc=d-20260902-122221-1879db) records the open content, selection and destination questions.

A deliberately created Work-subject document may contain a token or block displaying that Work's Detail gallery. A separately authored document can use `detail_uid` to discuss an exact Detail. These are possible authored compositions, not an automatically generated document set. Media View owns image-and-metadata presentation without requiring either document.

That document can be one of the associated-document links shown in the Work's Media View. The proposed reading journey is:

1. A Series or other document displays a gallery of Works.
2. A Work thumbnail opens Media View with that Work's image, metadata and gallery navigation context.
3. The reader follows an associated-document link to the document containing that Work's Detail gallery.
4. A Detail thumbnail opens Media View for that Detail, with the Detail gallery's navigation context.

This provides a route to Details without requiring the Work's Media View to contain an embedded Detail gallery. The document remains free to include commentary or other tokens; its purpose is authored presentation, not exclusive ownership of a Work or its Details.

Other documents may contain the same gallery token or discuss the same Work. A document created by batch New doc gains no privileged status or exclusive relationship to its subject. The public collection retains `analysis.works` and the name Works; it is not the exclusive home of Work references. Catalogue remains the internal domain term.

## Navigation Consequences

Catalogue gallery navigation moves between canonical entities in Media View, not between sub-scope documents. A Series gallery supplies an ordered Work collection; a Work Detail gallery supplies its ordered Detail collection. Media View's previous/next and position/total controls operate on the collection that opened it.

For a Work opened from a Series gallery, previous/next cycles through that gallery's Works and a return link leads back to the originating document. Opening a Work without gallery context does not invent a sequence from its Series membership. Canonical membership and authored document destinations remain separate concerns.

This removes the proposed need for Work-gallery previous/next to resolve Work documents or live on the sub-scope report toolbar. Ordinary document navigation is independent. [Catalogue Navigation](/docs/?scope=studio&doc=d-20260903-222617-28475e) and [Nav Implementation](/docs/?scope=studio&doc=d-20260904-010247-b09f2e) need reconciliation; their loaded-sequence and caching ideas remain useful without one-Work-to-one-document resolution.

Any coverage report should describe associations and help curation, not enforce one document per Work or classify multiple documents as invalid.

## Independent Catalogue Outputs

A future EPUB catalogue of Works will be generated from canonical Catalogue JSON, not reconstructed from Analysis documents. Missing, additional or differently organised documents do not change the canonical Work inventory.

The organised Catalogue and the more exploratory document surface serve different purposes. Neither needs to replace the other's authority.

## Questions For Further Thought

- How should Media View label and arrange associated-document links, including any link back to its originating document?
- How should return links and browser history preserve context across Work Media View, an associated document and Detail Media View?
- How should Search present these associations without inventing a preferred Work document?
- What association or coverage views would support useful editorial choices without prescribing completeness?

## Status

The canonical Work and document-independence direction is accepted, and the simple Work Media View is implemented. Earlier proposals may still contain automatic documents for every Work, single-Work-document and ambiguity assumptions, Work-gallery links to documents, document-toolbar Catalogue navigation and a Detail-only role for Media View. Those assumptions are not constraints on this concept.

UAC 3 continues from the implemented view to decide the token set, galleries, associated documents, reports and consumer JSON. The current proof does not finalise those contracts or demonstrate a need to change the by-ID Work schema.
