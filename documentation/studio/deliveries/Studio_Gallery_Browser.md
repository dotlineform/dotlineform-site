# Studio Gallery Browser

## Current And Next State

SGB.4 code and optimisation review is complete. Local Studio now loads missing bulk-selection records in one request. SGB.5 awaits normal use and manual acceptance, including the user's upcoming larger Gallery edits. [Planned Features](../Planned_Features.md) parents this delivery.

## Requirements

### Search And Member List

- Search the left-hand browser for Series and Galleries by title or ID in one result list. Give Gallery rows the Gallery icon and an accessible type label. Series rows have no icon. Keep type and exact ID together when selecting a result so a Series and Gallery can share a title or ID. Reuse the existing keyboard and pointer selection behavior.
- Selecting a Gallery lists its saved direct member Works across Series, with thumbnails, titles, a count and an empty state. Expanding the panel reveals a Series column with the saved Series title for each Work. In Series view, the expanded column continues to show each Work's Galleries. Selecting a browser target or expanding the list preserves the open Work draft. Changing the Work selection follows the existing draft rules.
- The selected Gallery determines which Works appear in the list. Adopt completed Save records immediately so a Work that leaves the current Gallery drops out and the count updates. Keep the Gallery selected while it exists, including when its list becomes empty. An addition to another Gallery appears in the saved Work's metadata while the list continues to show members of the selected Gallery.

### Work Editing In Gallery View

- Open one Work or use the existing Shift-click and Command-click selection for bulk editing. Reuse the fields available to the corresponding Series editor mode for Work metadata and Gallery membership. Show Series membership as read-only. For a bulk selection across Series, show that the Works span multiple Series without offering a replacement. New Work and the panel's Series Edit action are unavailable in Gallery view. Enforce the same limits in the action handlers, including keyboard submission. The panel's shared New action is documented in the [Catalogue Work Editor](../Catalogue_Work_Editor.md#gallery-and-series-definitions).
- For one Work, the Gallery field shows its complete membership. Removing a pill edits the Work's draft. On Save, removing the selected Gallery removes that Work from the list and preserves its other memberships. Adding a pill for another Gallery adds that membership and leaves the Work in the current list. The removed Work can remain open after Save, as with a Work moved out of the displayed Series today.
- In bulk, the Gallery field starts with the memberships shared by all selected Works. Apply only the net additions and removals relative to those initial pills. For Works in `{A, B}` and `{A, C}` selected from Gallery A, adding D produces `{A, B, D}` and `{A, C, D}`. Removing A instead leaves `{B}` and `{C}` and both Works leave the list after Save. An untouched field or an edit returned to its initial state produces no membership change. Series-view bulk editing continues to use the existing full replacement behavior. [Catalogue Work Editor](../Catalogue_Work_Editor.md#bulk-editing)
- **Delete Work** is available for one or more selected saved Works in either view. Reuse the exact-ID confirmation and existing deletion action. It removes the canonical Works, their Gallery memberships and their owned Catalogue media through the existing lifecycle. Their Series and Gallery definitions and project originals are retained. Adopt the deletion by removing those Works from the browser's saved data and clearing the Work selection. Keep the browsed Series or Gallery selected and update its count, including when the list becomes empty. [Work deletion](../Catalogue_Work_Editor.md#delete)
- Retain the open selection and draft when browsing between Series and Gallery. A New Work draft or a draft with a pending Series reassignment can be saved only in Series view. A bulk selection stays visible when switching view types. Resume bulk editing and Save by returning to the originating view type or making a fresh selection from the current list under the existing draft rules. Switching alone cannot turn a cross-Series selection into a Series selection or change the meaning of a pending Gallery edit. Delete Work remains available for saved selections in either view.

### Gallery Definitions And Series Relevance

- In Gallery view, **Relates to all works in this series** is unchecked and disabled in New Gallery. Creating the definition can still add its pill to the Work draft through the existing flow. The Work's membership is saved with the Work.
- In Edit Gallery, show Series-wide relevance as unavailable in Gallery view. Saving a title preserves all existing Series relationships. Send the existing request without a Series target (`series_id: null`) for both New and Edit in Gallery view. Keep Series-wide relevance editing in Series view. [Gallery mutation service](../../../studio/services/catalogue/catalogue_gallery_service.py)
- After a successful single or bulk membership Save in either view, retain the existing **Delete Gallery** or **Keep Gallery** prompt for Galleries that lost their last direct member. Detect that change from the adopted saved memberships. When the displayed Gallery becomes empty, show its empty list. **Keep Gallery** leaves it selected. **Delete Gallery** requires an explicit choice and clears the browse selection if that Gallery is displayed. The prompt explains that deletion also removes any Series-wide relevance for that Gallery. Opening an already empty Gallery simply shows the empty list. The separate Delete Work action keeps its current behavior of retaining definitions.
- Ordinary Edit Gallery offers definition Delete in Series view. In Gallery view, definition deletion is available through the newly empty Gallery prompt. This keeps whole-Gallery deletion through an ordinary pill edit in Series view, since the pill may identify a Gallery other than the one being browsed.

Generated readers continue to follow their normal Refresh, Regenerate and Publish lifecycle. [Catalogue Save And Refresh](../Catalogue_Save_And_Refresh.md)

## Process

Find a Gallery by title or ID and select its icon-marked result. Open one Work to inspect its metadata or expand the list to see which Series each Work belongs to. Select one or more members, change metadata or Gallery pills and Save. The list reflects the saved membership of the same Gallery. Use [Add works](../Catalogue_Work_Editor.md#add-works-to-a-gallery) to populate an empty Gallery. Use Series view to create a new Work, reassign its Series or set a Gallery's relevance across a Series.

During normal use, the [Series and Galleries report](/docs/?doc=d-20261006-160017-e6589d) provides a cross-check after Studio Refresh. It shows explicit Series–Gallery relevance alongside the Gallery's total direct Work count. Studio's member list uses saved Work records immediately after Save.

## SGB.4 Review Findings

- **Bulk selection.** Each missing full Work record previously triggered its own request and parse of the Work and membership stores. Saved Gallery `154` has 523 direct members. The browser now reuses full records already loaded in the editor and sends the remaining exact Work IDs in one read-only local request. The server reads the Work store once and returns just those records. The browser supplies their Gallery memberships from its saved rows. Selection changes reuse the existing rendered list, and bulk draft construction prepares control values once without copying unused embedded resources.
- **Definition actions.** Gallery-view New and Edit continue to use loaded definitions with no Series target. Series-view Edit reads saved relevance when the checkbox can use it. The ordinary Gallery Delete count is computed when entering the confirmation. The empty-Gallery prompt uses the completed Save's candidate and needs neither a count nor another record read. Removed the check for Series relevance data on the saved definition response, since the editor adopts only its exact identity and title.
- **Persistence and completion.** Bulk Save parses the Work and membership stores once and writes only the changed stores through the existing transaction. Its existing read of original bytes for rollback remains necessary when writing. The writer carries before and after maps into queue completion, which skips queue and staging work for an unchanged mutation. Completed effects update the editor and member list without a follow-up lookup or Refresh. Bulk metadata and membership saves select no media preparation.
- **Retained boundaries.** The lookup uses Studio's existing local request authority and exact saved Work identities. Save keeps request shape, selection scope and destination confinement checks. Work and Gallery deletion keep explicit confirmation. A completed canonical mutation still updates the editor and reports any later local completion failure. No extra audit, hash, read-back, compatibility path or recovery workflow is needed.
