# Catalogue Works

## Live Report

Open [Catalogue Works](/docs/?doc=d-20260810-222148-99daec). The report is a local Docs Viewer document backed by Working output. This Studio page owns its implementation and extension guidance; Catalogue data and editing remain Studio-owned.

Use Working document navigation or the link above to open the report. Editing remains in Studio's Work editor and its shared Series controls.

The report loads generated metadata for all saved Works and shows rows after a search by Work ID, Work title, Series ID or Series title. It searches the full loaded dataset and renders 20 matching rows per page. Beneath the report, `chevron-left.svg` and `chevron-right.svg` surround a compact current/total indicator such as `1/2`. Previous is disabled on page 1; Next on the last page returns to page 1 using the retained matches, with a first-page tooltip and accessible label. One-page and empty results hide the entire pager. Search and sort changes reset to page 1. The initial list remains empty and the default sort remains ascending Work ID. Catalogue Works and Series have no draft/published state, and the report applies no publication filter. Document workflow and publication decisions are separate from Catalogue record identity.

Each canonical Work has an exact `work_id` and one required Series membership. Results retain year and curator-only storage context in one six-column semantic table. Work, Year, Title, Series and Storage are the five embedded and sortable columns. Medium appears only in Expanded Report View. **Copy table** exports all current sorted matches, across every page, as five-column TSV while embedded and six-column TSV while expanded.

## Data And Ownership

The Work UI owns whole-Year and Title/Year-display completion checks, and Refresh owns the completed projection. The report trusts saved schema, identity, field representation and Series facts without another row/membership/title audit, coercion or substitute text. Displayed Work/Series titles, Year display, Medium and Storage retain supplied text. Only explicit null Medium/Storage display and export as empty cells, without dash substitutes. Copy table prepares each row's cell values and Series text once, preserves other whitespace and escapes tabs/line breaks to keep valid TSV columns/rows. Search normalizes only its derived matching fields; Series ordering keeps its existing normalized sort text without changing displayed/exported labels. [Studio User Facing Rules](data/Studio_User_Facing_Rules.md) D.03 owns authoring validity.

The local report registry maps `catalogue_works` to its allowlisted loader. [The report module](../../docs-viewer/runtime/js/reports/catalogue-works-report.js) uses the existing report service to call parameter-free `GET /docs/catalogue-works-report` on Docs Viewer's configured local service. [The saved reader](../../docs-viewer/services/docs_catalogue_works_report.py) resolves the configured Working Catalogue location once and reads/parses only `working/generated/catalogue/reports/catalogue-works/metadata.json`. The route retains Docs Viewer's management-enabled and local-origin authority, configured path/symlink confinement and HTTP/JSON failure handling. It does not read canonical records, generate data or require a running Local Studio server. The retired Studio metadata URL has no alias; Studio no longer serves the private reports namespace.

`catalogue_works_report_metadata_v3` contains exactly `header: {schema}` and a `works` map keyed by exact five-digit Work ID. The header has no persisted count, content hash or generation timestamp. Readers derive totals from the loaded map; neither caching nor row comparison requires a version. Each row has `work_id`, `title`, `year`, `year_display`, nullable `storage_location` and `medium`, plus a `series` array containing zero or one exact `series_id`/`title` pair. [The browser data owner](../../docs-viewer/runtime/js/reports/catalogue-works-data.js) prepares literal rows, normalized search fields and Series sort values once per load; it performs no downstream schema/identity/field audit. Python's existing saved updater parses the aggregate and projects supplied rows/deletions without content checks. The producer remains v3 with no schema conversion or compatibility path. Search retains per-field whitespace normalization, NFKC/English lowercase substring matching; sorting retains the English numeric collator, numeric year comparison and ascending Work-ID tie break. There is no persistent report search index.

Typing waits for a 180 ms pause before applying search; clearing search applies immediately. Copy, sorting and page controls are disabled while that update is pending. The data owner filters the full dataset only when the normalized query changes; a sort change reorders retained matches, and an unchanged query/order reuses the same result array. A newly loaded dataset explicitly starts a new projection. Page turns and Copy table reuse the complete sorted matches without filtering, sorting or fetching metadata. Only the current page's rows are mounted, and headers remain mounted while their sort state/controls update.

The existing retained-view owner distinguishes a live retained report from a released one. Pending searches may finish inside their retained view even when detached, so Back restores matching results and enabled controls; search input records its page-one reset before capture, and restore applies a pending query before rendering. State restored during loading supplies the eventual query/order/page without an intermediate filter over an empty dataset. Disposal cancels the debounce timer, clears prepared rows, Work URL mappings and presentation listeners, prevents an immediate-disposal load and ignores late load/clipboard completion. It adds no data freshness checks, retries or persistent state.

[Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) owns generation and recovery. Save changes canonical source and the editor's live view; the report continues to read its previous private metadata until Refresh Catalogue projects the supplied Work rows and removes explicit deletions, including affected member Works for a Series title change. Unselected rows retain their saved values. Unchanged selected rows cause no aggregate write; changed output still requires complete JSON serialization, without computing a whole-map hash. Missing/malformed saved metadata stops the updater without implicit full generation. The report metadata remains private and outside the Catalogue publication inventory.

For initial population, deliberate complete regeneration, schema conversion or repair, invoke the existing metadata owner explicitly:

```bash
python3 studio/services/catalogue/catalogue_works_metadata.py --write
```

Without Work selection this generates the complete private report using the same row projector as normal Refresh. It writes only `working/generated/catalogue/reports/catalogue-works/metadata.json`, with no queue/lifecycle changes, media production, document/Search build or Publish. The command's returned `count` and `projected_count` are operation diagnostics, separate from the saved header. The v3 conversion on 2026-10-10 used this maintenance path from empty queues. Changed-source Python/JavaScript lint, Python syntax and whitespace checks passed. The Python saved-file reader and actual browser normalizer in a direct Node diagnostic accepted 4,619 Works across 140 Series. Both queues stayed empty and lifecycle timestamps were preserved. No tests or browser interaction ran; mutation/deletion, unchanged-row writes and malformed/failure paths received source review only. The local-only module requires no public projection or Publish.

The browser data owner supplies one frozen column model, row preparation, Work/Series search, ordering and TSV serialization without DOM/network dependencies. The report module owns metadata transport, five sortable controls, pagination, Work document links and Series labels, one six-column render, presentation-aware clipboard selection and unavailable states. Pager layout belongs to the existing local report stylesheet and reuses shared icon buttons. Editing remains in the [Catalogue Work Editor](Catalogue_Work_Editor.md) and its shared Series controls. There is no separate Catalogue Drafts workflow.

Work ID and title open the definitive Working Catalogue document through `viewerUrlForDocument(workId, {collection: "catalogue"})`. Its `doc_id` is the same five-digit Work ID, preserving leading zeroes. The report creates a URL when that Work first appears on a displayed page and reuses it for both cells and subsequent views; opening with an empty search builds no Work URLs. It reads no Catalogue document manifest or mapping file and does not recheck configuration or generated URLs. A direct Catalogue destination loads its exact by-ID payload before the list manifest; a missing document fails at that destination without selecting another target. Regenerate owns repair of missing Catalogue documents.

Linked Catalogue documents have a separate freshness boundary: Refresh Catalogue supplies current generated Work JSON and records pending document updates; Catalogue Regenerate updates document titles and bound image-token bodies where needed and builds the pending documents. Each Build resolves image alt text, caption and selected metadata from the captured generated Work record. A Work Save does not rewrite those documents or this report's metadata; [Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) and [collection architecture](Sub_Scope_Index_Architecture.md#catalogue-work-records) own those operations.

Each Series name is displayed as plain text. Series remains a Catalogue grouping; document Subjects use Work, Folder or None. This report does not open Series in Media View or fetch their membership or Work images. Search, sorting and TSV output retain their existing values.

## Expanded Presentation

After its generated inputs and first complete render succeed, the module returns the exact live semantic table and toolbar through the optional `expandedPresentation` handle. The adapter places its expanded-view button immediately after Copy table, on the search row. The button is disabled when no Works are displayed, hides while expanded and returns with the embedded report; the existing presentation refresh subscription keeps its disabled state current. One frozen ordered column model supplies stable ids, labels, and `both` or `expanded` visibility; headers and body cells use the same six identities. Page/query/sort rendering retains the header nodes and notifies the existing presentation subscription so shared resize/column checks and temporary widths retain their owner. Manage moves the existing report root into Content Detail, so search, sorting, current page, pager, rows, Work links, Copy table, event listeners, and route state remain on one report instance with no second data request or renderer.

Manage alone supplies accessible pointer and keyboard resize handles. One direct `colgroup` keeps headers and rows aligned through valid notified rerenders, while a mismatched header/body model fails closed. Widths exist only for the active expanded presentation: **Reset widths**, Back, or document navigation removes them, and reopening starts from the natural layout. Widened output scrolls inside the expanded viewport. Source, registry JSON, URLs, browser storage, canonical data, and generated payloads retain no width state.

Series labels in Expanded Report View remain plain text. Returning from Expanded Report View restores the embedded report with its search, sorting and current page retained; temporary expanded widths are released.
