# Catalogue Works

## Live Report

Open [Catalogue Works](/docs/?doc=d-20260810-222148-99daec). The report is a local Docs Viewer document backed by Working output. This Studio page owns its implementation and extension guidance; Catalogue data and editing remain Studio-owned.

Use Working document navigation or the link above to open the report. Editing remains in Studio's Work editor and its shared Series controls.

The report loads generated metadata for all saved Works and shows rows after a search by Work ID, Work title, Series ID or Series title. It searches the full loaded dataset and renders 20 matching rows per page. Beneath the report, `chevron-left.svg` and `chevron-right.svg` surround a compact current/total indicator such as `1/2`. Previous is disabled on page 1; Next on the last page returns to page 1 using the retained matches, with a first-page tooltip and accessible label. One-page and empty results hide the entire pager. Search and sort changes reset to page 1. The initial list remains empty and the default sort remains ascending Work ID. Catalogue Works and Series have no draft/published state, and the report applies no publication filter. Document workflow and publication decisions are separate from Catalogue record identity.

Each canonical Work has an exact `work_id` and one required Series membership. Results retain year and curator-only storage context in one six-column semantic table. Work, Year, Title, Series and Storage are the five embedded and sortable columns. Medium appears only in Expanded Report View. **Copy table** exports all current sorted matches, across every page, as five-column TSV while embedded and six-column TSV while expanded.

## Data And Ownership

The local report registry maps `catalogue_works` to its allowlisted loader. `docs-viewer/runtime/js/reports/catalogue-works-report.js` reads `/studio/catalogue-output/reports/catalogue-works/metadata.json` from the configured Local Studio origin. Studio serves the generated bytes from the configured Working Catalogue directory, using its existing local-origin policy. The report has no canonical-list API read or fallback.

`catalogue_works_report_metadata_v3` contains exactly `header: {schema}` and a `works` map keyed by exact five-digit Work ID. The header has no persisted count, content hash or generation timestamp. Readers derive totals from the loaded map; neither caching nor row comparison requires a version. Each row has `work_id`, `title`, `year`, `year_display`, nullable `storage_location` and `medium`, plus a `series` array containing zero or one exact `series_id`/`title` pair. The browser validates these rows and prepares normalized search fields and Series sort values once per load. Python's saved updater validates the exact envelope/header/map and projects the supplied canonical rows. Both readers require v3 without a v2 fallback. Search retains per-field NFKC/English lowercase substring matching; sorting retains the English numeric collator and numeric year comparison. There is no persistent report search index.

Typing waits for a 180 ms pause before filtering and sorting; clearing search applies immediately. Copy, sorting and page controls are disabled while that update is pending. The report retains the complete sorted match list, so page turns and Copy table do not repeat filtering/sorting or fetch metadata. A pending search does not render into a detached report. Only the current page's rows are mounted.

[Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) owns generation and recovery. Save changes canonical source and the editor's live view; the report continues to read its previous private metadata until Refresh Catalogue projects the supplied Work rows and removes explicit deletions, including affected member Works for a Series title change. Unselected rows retain their saved values. Unchanged selected rows cause no aggregate write; changed output still requires complete JSON serialization, without computing a whole-map hash. Missing/malformed saved metadata stops the updater without implicit full generation. The report metadata remains private and outside the Catalogue publication inventory.

For initial population, deliberate complete regeneration, schema conversion or repair, invoke the existing metadata owner explicitly:

```bash
python3 studio/services/catalogue/catalogue_works_metadata.py --write
```

Without Work selection this generates the complete private report using the same row projector as normal Refresh. It writes only `working/generated/catalogue/reports/catalogue-works/metadata.json`, with no queue/lifecycle changes, media production, document/Search build or Publish. The command's returned `count` and `projected_count` are operation diagnostics, separate from the saved header. The v3 conversion on 2026-10-10 used this maintenance path from empty queues. Changed-source Python/JavaScript lint, Python syntax and whitespace checks passed. The Python saved-file reader and actual browser normalizer in a direct Node diagnostic accepted 4,619 Works across 140 Series. Both queues stayed empty and lifecycle timestamps were preserved. No tests or browser interaction ran; mutation/deletion, unchanged-row writes and malformed/failure paths received source review only. Restart Local Studio and force-reload Docs Viewer to adopt the matching producer/reader. The local-only module requires no public projection or Publish.

The report module owns input validation, Work/Series search, five sortable columns, pagination, Work document links and Series labels, one six-column render, presentation-aware clipboard projection and unavailable or invalid states. Pager layout belongs to the existing local report stylesheet and reuses shared icon buttons. Editing remains in the [Catalogue Work Editor](Catalogue_Work_Editor.md) and its shared Series controls. There is no separate Catalogue Drafts workflow.

Work ID and title open the definitive subdocument in Working Catalogue. Its `doc_id` is the same five-digit Work ID, preserving leading zeroes. The report composes `?doc=<configured-report-host-id>&subdoc=<work-id>` through the shared route helper without reading a Catalogue document manifest or mapping file. A direct Catalogue destination loads its exact by-ID payload before the list manifest; a missing document fails at that destination without selecting another target. Regenerate owns repair of missing Catalogue documents.

Linked Catalogue documents have a separate freshness boundary: Refresh Catalogue supplies current generated Work JSON and records pending document updates; Catalogue Regenerate updates document titles and bound image-token bodies where needed and builds the pending documents. Each Build resolves image alt text, caption and selected metadata from the captured generated Work record. A Work Save does not rewrite those documents or this report's metadata; [Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) and [collection architecture](Sub_Scope_Index_Architecture.md#catalogue-work-records) own those operations.

Each Series name is displayed as plain text. Series remains a Catalogue grouping; document Subjects use Work, Folder or None. This report does not open Series in Media View or fetch their membership or Work images. Search, sorting and TSV output retain their existing values.

## Expanded Presentation

After its generated inputs and first complete render succeed, the module returns the exact live semantic table and toolbar through the optional `expandedPresentation` handle. The adapter places its expanded-view button immediately after Copy table, on the search row. The button is disabled when no Works are displayed, hides while expanded and returns with the embedded report; the existing presentation refresh subscription keeps its disabled state current. One frozen ordered column model supplies stable ids, labels, and `both` or `expanded` visibility; headers and body cells use the same six identities. Manage moves the existing report root into Content Detail, so search, sorting, current page, pager, rows, Work links, Copy table, event listeners, and route state remain on one report instance with no second data request or renderer.

Manage alone supplies accessible pointer and keyboard resize handles. One direct `colgroup` keeps headers and rows aligned through valid notified rerenders, while a mismatched header/body model fails closed. Widths exist only for the active expanded presentation: **Reset widths**, Back, or document navigation removes them, and reopening starts from the natural layout. Widened output scrolls inside the expanded viewport. Source, registry JSON, URLs, browser storage, canonical data, and generated payloads retain no width state.

Series labels in Expanded Report View remain plain text. Returning from Expanded Report View restores the embedded report with its search, sorting and current page retained; temporary expanded widths are released.

## Extension And Weak Spots

- The existing `test_module_uses_only_existing_studio_inputs_and_exact_catalogue_targets` in `docs-viewer/tests/python/test_catalogue_works_report_contract.py` still asserts retired canonical API reads and an old navigation fragment. It is stale and was not run or modified for this refactor; maintaining it requires a separate agreed test specification. Do not restore those product paths to satisfy the assertion.
- Recorded user review covers one Work title Save, expanded view, sorting, Work/Series links and improved search responsiveness. Detailed pager/clipboard interactions, other live mutation paths and failure scenarios remain unexercised; static/source review is not runtime coverage of those paths.
- Add a report column through Studio's generated metadata owner, with its stable id, label, `both` or `expanded` visibility, sorting participation and active TSV projection explicit.
- Keep curator-only context in the private metadata contract; it must not enter public Catalogue payloads.
- Keep the report search-required: empty search reveals no rows, and a failed current read never retains an older result.
- Search continues to match Work and Series only; an expanded-only value does not silently broaden that contract.
- Keep `catalogue_works` local-only. Public report metadata, loaders, data, and CSS do not expose it.
- Consider a persistent search index only after a demonstrated performance need; any future index belongs to Docs Viewer's explicit Search refresh with its own rules.
