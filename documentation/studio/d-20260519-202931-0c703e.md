# Catalogue Build And Lookup Refresh

## Save Completes Output

Ordinary Work editing completes through Save; shared Gallery and Series definition modals complete through OK or confirmed Delete. Work, Series and Gallery create/save, Work bulk edits, import and deletion share the output-completion owner in `studio/services/catalogue/catalogue_output_service.py`. Single, New and bulk Work saves also own Work Gallery membership. Studio Detail reads, mutations and editor UI are retired; bulk Work creation remains separate.

After the validated canonical transaction, that owner determines changed Works and Series. It completes required media, refreshes affected exact Work/Series/Gallery JSON and their discovery indexes, then refreshes private Studio lookups and returns current records and revisions. Detail folders and indexes are retired: ordinary source reads, generation and Save do not probe or recreate them. Work output includes Gallery memberships; a Work label change also refreshes its Gallery member rows. An unchanged Work Save can refresh output after its source media is repaired.

Canonical persistence and output completion are separate results. An output or lookup failure keeps the saved canonical change and reports the incomplete step and error. The editor also preserves a confirmed saved outcome if a later refresh fails. Fix the reported cause and use the ordinary owning operation again. If output generation was interrupted or previous membership output is missing, use complete JSON maintenance to reconcile former memberships as well. There is no automatic rollback or retry workflow.

## Generated Catalogue

The configured external output root must already be available at `$DOTLINEFORM_PROJECTS_BASE_DIR/catalogue/generated/`. Missing or escaping paths fail visibly without creating another tree.

`generate_work_pages.py` owns full payload projection and output reconciliation. It reads both canonical Gallery files, projects Gallery IDs/titles into each Work, and derives the inverse membership for individual Gallery files. `catalogue_output_selection.py` selects affected records: Work refresh includes its former/current Series and Galleries; Gallery refresh includes its former/current member Works, including removed members. Previous generated records supply invalidation targets only; current canonical sources determine every new payload. Gallery title changes therefore update embedded titles in member Work records, while Work labels update Gallery rows. Empty Galleries are emitted, and Gallery deletion removes the obsolete record and refreshes its former members.

The output service accepts a focused Gallery selection with `generate_catalogue_json(..., work_ids=(), gallery_ids=(...))`, using exact Gallery IDs without aliases. The existing Work Save caller continues to pass changed Work/Series IDs and gains Gallery refresh through the same owner. Omitting `work_ids` requests complete reconciliation, which also removes obsolete owned Work/Series/Gallery JSON and recognized obsolete thumbnails. All modes refresh the discovery indexes and shared media policy. This includes `galleries/galleries_index.json`, whose IDs/titles and member counts come from the same canonical inputs as the individual Gallery records. Gallery creation, rename, membership changes and deletion therefore update the lookup during focused or complete generation. Unchanged payloads retain their existing generated timestamp.

Work membership saves explicitly pass the union of the previous and selected Gallery IDs to that output owner, including when only membership changed. The single Work service read and save response carry a separate `gallery_ids` array; Work record revisions continue to describe Work metadata, while `expected_gallery_ids` guards membership replacement. The editor's `catalogue_galleries` service read projects the canonical ID/title registry directly; it creates no additional lookup file or editable reverse membership map.

Bulk replacement uses the existing `/bulk-save` route with one `gallery_ids` set and `expected_gallery_ids_by_work` covering exactly the selected Works, alongside their metadata revisions. All checks precede one canonical transaction. Gallery-only mutations write `galleries-by-work.json` once without normalizing or rewriting Work metadata. Omitting `gallery_ids` preserves memberships and allows ordinary Save completion to run again. The bulk response includes every selected Work and its saved memberships; output completion refreshes metadata revisions without discarding those memberships. The live Work search response also carries Gallery IDs for list display, without changing the persisted lookup format. The [Work editor](d-20260422-000000-45a776.md) owns intersection and replacement interaction.

Gallery definition operations use `/gallery/create`, `/gallery/save` and `/gallery/delete`. Create allocates the next numeric Gallery ID from the canonical registry; save and delete require the exact ID and definition revision supplied by `catalogue_gallery_record`. Delete additionally compares the complete confirmed `expected_member_work_ids` with current canonical members and rejects a changed set before writing. The definition and its membership removals share the existing source transaction; Work metadata in `works.json` remains unchanged. The response carries every affected canonical Work ID and the Gallery ID into completion, so output refresh does not depend on the current editor selection or a complete former generated member list. Definition-only Gallery operations refresh JSON/indexes and private lookups without Work media processing. Work membership Save retains its existing media/output behavior. Series deletion also explicitly rechecks that no Works belong to it.

[Catalogue Indexes And Payloads](/docs/?scope=studio&doc=d-20260519-202931-b05d27) describes the output shape. Generated Catalogue data is not a public acceptance decision. The producer does not write the frozen archive, old public pages, Recent, Catalogue Search or Docs output.

## JSON Maintenance

Use a complete JSON regeneration for deliberate maintenance:

```bash
python3 studio/services/catalogue/catalogue_json_build.py
python3 studio/services/catalogue/catalogue_json_build.py --write
```

The default previews changes. `--write` writes current JSON and reconciles obsolete owned files. Both report missing referenced thumbnails; an incomplete report exits 1 even when the JSON write succeeded.

This path uses current canonical records and existing media references/versions. It does not convert or upload primary images, copy thumbnails, promote media versions or refresh private Studio lookups. The initial thumbnail population was a one-off copy of existing thumbnails; ordinary Save now maintains affected output.

## Private Studio Lookups

Studio search/list files live under `studio/data/generated/catalogue-lookup/`; rich focused reads are service projections. `catalogue_lookup.py` owns serialization, and `catalogue_lookup_refresh.py` owns refresh. The focused Work service projection uses `studio_catalogue_work_record_v3`, with Work data, revision, resources and Series summary but no Detail sections. Detail lookup builders and invalidation paths are retired. Save completion performs a full private lookup refresh after media work so revisions include any promoted versions. This does not refresh Docs semantic lookups.

For a deliberate standalone complete export:

```bash
python3 studio/services/catalogue/export_catalogue_lookup.py
python3 studio/services/catalogue/export_catalogue_lookup.py --write
```

The exporter defaults to canonical Studio source and the private lookup directory. Its source/output overrides are for explicit controlled use.

## Media And Maintenance Boundaries

`catalogue_output_media.py` reuses source resolution, converters and the R2 transport. Source images retain the exact configured Work-media identity. Converted Details are ordinary Works. Staging is `catalogue/media-staging/`, while final Work thumbnails are `catalogue/generated/works/thumbs/`. Active media planning, thumbnail reconciliation, version finalization and R2 Catalogue operations accept Works only. Historical conversion tooling and the frozen public archive retain their separate boundaries. Gallery metadata/membership output generation does not process or upload media.

Save prepares the affected images and downloads, confirms complete primary variant sets, updates dimensions and media versions, and removes exact obsolete outputs. [Catalogue Media Pipeline Config](/docs/?scope=studio&doc=d-20260331-154730-b019e0) owns derivative policy; [Publish Media To R2](/docs/?scope=studio&doc=d-20260508-093841-3e27b1) owns remote comparison and complete-set version rules.

An unchanged download filename present in the same Work's previous canonical record and generated output can retain its existing R2 object when no local replacement is staged. Save verifies that exact remote object through R2 before completing generated JSON. A missing remote object or failed verification leaves canonical data saved and reports incomplete output. A new or changed download filename requires its staged local file; any staged replacement continues through the ordinary upload path. This lets a title or other metadata edit finish without requiring another local copy of an existing download. It adds no local-file discovery, automatic download or alternate staging root.

Focused writes still project the whole canonical corpus in memory and compare selected outputs by content version. Selecting a Work also considers current/former co-members of its affected Galleries; unchanged Work files are not rewritten. Large-collection Save latency has not been measured. Keep future performance work in these owners; do not introduce a second field planner or per-image whole-Catalogue refresh.
