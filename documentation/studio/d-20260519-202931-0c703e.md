# Catalogue Build And Lookup Refresh

## Save Completes Output

Ordinary Catalogue editing has one completion action: Save. Work and Series create/save, bulk edits, import and deletion share the output-completion owner in `studio/services/catalogue/catalogue_output_service.py`. Detail creation is retired; the Gallery editor and its eventual output trigger remain a later delivery.

After the validated canonical transaction, that owner determines changed Works and Series. It completes required media, refreshes affected exact Work/Series/Gallery JSON and all three existing discovery indexes, then refreshes private Studio lookups and returns current records and revisions. Work output includes Gallery memberships; a Work label change also refreshes its Gallery member rows. An unchanged Work Save can refresh output after its source media is repaired.

Canonical persistence and output completion are separate results. An output or lookup failure keeps the saved canonical change and reports the incomplete step and error. The editor also preserves a confirmed saved outcome if a later refresh fails. Fix the reported cause and use the ordinary owning operation again. If output generation was interrupted or previous membership output is missing, use complete JSON maintenance to reconcile former memberships as well. There is no automatic rollback or retry workflow.

## Generated Catalogue

The configured external output root must already be available at `$DOTLINEFORM_PROJECTS_BASE_DIR/catalogue/generated/`. Missing or escaping paths fail visibly without creating another tree.

`generate_work_pages.py` owns full payload projection and output reconciliation. It reads both canonical Gallery files, projects Gallery IDs/titles into each Work, and derives the inverse membership for individual Gallery files. `catalogue_output_selection.py` selects affected records: Work refresh includes its former/current Series and Galleries; Gallery refresh includes its former/current member Works, including removed members. Previous generated records supply invalidation targets only; current canonical sources determine every new payload. Gallery title changes therefore update embedded titles in member Work records, while Work labels update Gallery rows. Empty Galleries are emitted, and Gallery deletion removes the obsolete record and refreshes its former members.

The output service accepts a focused Gallery selection with `generate_catalogue_json(..., work_ids=(), gallery_ids=(...))`, using exact Gallery IDs without aliases. The existing Work Save caller continues to pass changed Work/Series IDs and gains Gallery refresh through the same owner. Omitting `work_ids` requests complete reconciliation, which also removes obsolete owned Work/Series/Gallery JSON and recognized obsolete thumbnails. All modes refresh the existing discovery indexes and shared media policy. Unchanged payloads retain their existing generated timestamp; no monolithic Gallery index is generated.

[Catalogue Indexes And Payloads](/docs/?scope=studio&doc=d-20260519-202931-b05d27) describes the output shape. Generated Catalogue data is not a public acceptance decision. The producer does not write the frozen archive, old public pages, Recent, Catalogue Search or Docs output.

## JSON Maintenance

Use a complete JSON regeneration for deliberate maintenance:

```bash
python3 studio/services/catalogue/catalogue_json_build.py
python3 studio/services/catalogue/catalogue_json_build.py --write
```

The default previews changes. `--write` writes current JSON and reconciles obsolete owned files. Both report missing referenced thumbnails; an incomplete report exits 1 even when the JSON write succeeded.

This path uses current canonical records and existing media references/versions. It does not convert or upload primary images, copy thumbnails, promote media versions or refresh private Studio lookups. The initial thumbnail population was a one-off copy of existing thumbnails; ordinary Save now maintains affected output.

## Private Studio Lookups

Studio search/list files live under `studio/data/generated/catalogue-lookup/`; rich focused reads are service projections. `catalogue_lookup.py` owns serialization, and `catalogue_lookup_refresh.py` owns refresh. Save completion performs a full private lookup refresh after media work so revisions include any promoted versions. This does not refresh Docs semantic lookups.

For a deliberate standalone complete export:

```bash
python3 studio/services/catalogue/export_catalogue_lookup.py
python3 studio/services/catalogue/export_catalogue_lookup.py --write
```

The exporter defaults to canonical Studio source and the private lookup directory. Its source/output overrides are for explicit controlled use.

## Media And Maintenance Boundaries

`catalogue_output_media.py` reuses source resolution, converters and the R2 transport. Source images retain the exact configured Work-media identity. Converted Details are ordinary Works. Staging is `catalogue/media-staging/`, while final Work thumbnails are `catalogue/generated/works/thumbs/`. Empty internal Detail maps and the retired Detail-thumbnail cleanup path remain during the staged consumer retirement. Gallery metadata/membership output generation does not process or upload media.

Save prepares the affected images and downloads, confirms complete primary variant sets, updates dimensions and media versions, and removes exact obsolete outputs. [Catalogue Media Pipeline Config](/docs/?scope=studio&doc=d-20260331-154730-b019e0) owns derivative policy; [Publish Media To R2](/docs/?scope=studio&doc=d-20260508-093841-3e27b1) owns remote comparison and complete-set version rules.

An unchanged download filename present in the same Work's previous canonical record and generated output can retain its existing R2 object when no local replacement is staged. Save verifies that exact remote object through R2 before completing generated JSON. A missing remote object or failed verification leaves canonical data saved and reports incomplete output. A new or changed download filename requires its staged local file; any staged replacement continues through the ordinary upload path. This lets a title or other metadata edit finish without requiring another local copy of an existing download. It adds no local-file discovery, automatic download or alternate staging root.

Focused writes still project the whole canonical corpus in memory and compare selected outputs by content version. Selecting a Work also considers current/former co-members of its affected Galleries; unchanged Work files are not rewritten. Large-collection Save latency has not been measured. Keep future performance work in these owners; do not introduce a second field planner or per-image whole-Catalogue refresh.
