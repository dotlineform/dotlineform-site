# Catalogue Work Editor

## What It Does

Use `/studio/catalogue-work/` to create, find, edit or delete canonical Works, including a batch from one project subfolder and images converted from former Details. Work downloads, links and project-media selection belong to this editor. The Detail browser and section-entry workflow are retired. The retired `provenance` and `artist` fields have no editor controls or create/save payload entries.

- `?work=<work_id>` opens one Work.
- `?series=<series_id>` selects the left-panel Series browser and lists its member Works, leaving the Work editor empty. Empty Series remain selectable; this entry does not open a definition modal or create a Work draft.
- `?mode=new` starts a new canonical record; optional `&series=<series_id>` preselects a Series.
- Work search opens one ID at a time, including a single result chosen through title search. Title and ID-prefix results sort by title using case-insensitive, numeric-aware collation, with Work ID breaking equal-title ties, before the 20-result limit. Ordering uses the already loaded browser records. Comma-separated IDs and numeric ranges are not accepted in the search or `work` URL parameter. Empty or malformed ID submissions close the popup without an instructional message. Select multiple Works in the displayed Series member list for bulk editing.

The URL tracks the displayed Series and open Work independently: when both `work` and a valid `series` are supplied, the Series selects the left-panel list and the Work opens in the editor. With only `work`, the browser initially displays that Work's saved Series. Committing a Series choice or creating a Series replaces the current URL's `series` value without navigation or an added browser-history entry; deleting the displayed Series removes it. Reload therefore restores the current displayed Series rather than the initial entry value. Browsing keeps the Work draft unchanged, and unsaved bulk selection is not encoded in the URL. Initial Series selection resolves against the loaded canonical registry; Series-only invalid or unknown IDs display an error. The browser owns this state and reuses loaded lookup data without an additional request. Series titles in Docs Viewer's [Series and Galleries](Reports.md) report open this entry in a new tab.

The list icon button to the right of the Work form's Series search shows the selected draft Series in the left-panel member list. It preserves the open Work and unsaved changes, uses the existing browser-owned Series selection and loaded lookup data, and is disabled while the form is busy/unavailable or has no selected Series. Browsing an unsaved assignment shows that Series's saved members; membership changes take effect on Save.

The [Catalogue Source Model](Catalogue_Source_Model.md) owns the data boundary. Ordinary Save completes the canonical edit and required local media; [Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) owns the separate generated-reader boundary.

Medium is one descriptive text field for materials, process and support. It saves as `medium`; the former `medium_caption` name and separate `medium_type` field are retired.

Medium remains optional unrestricted text and offers saved-value suggestions after two query characters in single, New, bulk and batch creation modes. Clicking its search input selects the current text for replacement. Matching is case-insensitive substring search over a browser-prepared vocabulary; results are alphabetical in the shared scrollable popup, with exact authored spellings preserved. Click a suggestion or use Arrow keys then Enter to select it. Tab keeps typed free text and moves to the next field; the clickable clear button is outside this field's Tab order. Escape closes the list without resetting text, and Enter without an active suggestion does not force the first result. No matching suggestion is required to save. Shared search-field clearing uses the ordinary draft input handler; bulk input remains an explicit replacement and retains existing mixed-value behavior.

The existing Work-search startup response (`studio_catalogue_lookup_work_search_v3`) supplies `medium_values`, a distinct list of nonempty saved strings projected from its already loaded canonical Work records. This is a response field, not another generated index or per-Work lookup field. [Candidate preparation and matching](../../studio/app/frontend/js/catalogue-work-medium-data.js) belong to the browser, and [the Medium field](../../studio/app/frontend/js/catalogue-work-medium.js) owns its popup/draft integration. Python performs no matching, authoring validation or additional filesystem read. The existing completion owner returns a replacement vocabulary for Work create/batch create, delete and Medium-changing single/bulk Save using its supplied completed Work map. Title/media-only and definition edits skip that projection; unchanged vocabulary remains in the mounted editor. The shared saved-response hook adopts replacements without a follow-up request. Saved choices therefore follow canonical edits without Refresh Catalogue. Typing performs no request, file read or generation.

## Catalogue Update Sequence

| Action | Completed result |
| --- | --- |
| Save | Canonical Work change, required prepared media in staging, exact updates selection and current editor display. |
| Refresh Catalogue | Selected Working metadata/media, cleared staging flags and true queue readiness; shared reader indexes update. |
| Regenerate in Docs | Catalogue source/document generation for refreshed entries; completed changes move into the publication queue. |
| Docs Publish | Each queued Work completes Preview and repository/R2 Deploy, then shared output publishes once. |

For deletion, start with Delete and continue through Refresh, Regenerate and Publish. After Save, the editor's image display reflects saved staged media; it does not show that Working, Preview or public output has been updated. [Catalogue Save And Refresh](Catalogue_Save_And_Refresh.md) owns the operational steps and updates queue; [Catalogue Deployment](Catalogue_Deployment.md) owns publication and its retained progress. Git commit/push and GitHub Actions deployment remain separate.

“Catalogue readers need Refresh before Docs Publish.” means that an affected Work has `refreshed: false` or a Gallery/Series/shared-output selection is pending in the updates queue. Empty Work maps can still require Refresh. A successful Refresh records its UTC completion time and forwards completed shared selections to publication; mutations preserve that time while queuing new effects. Definition-only changes with no affected Works use Save/Delete → Refresh → Publish. Changes that also affect Work documents require Regenerate before Publish. Status reads only the queue without Catalogue/configuration hashing or a separate receipt.
