# Retire Public Document Locations

## Requirements

Retire the public document-location builder and JSON, its unused shared picker/provider, and the legacy Catalogue document-URL projection and refresh. The user approved this cleanup after confirming that the UAC-1 pause protects an obsolete Catalogue schema. UAC-1 froze the old Catalogue into the archive; this cleanup does not resume that machinery or implement current Catalogue deployment.

Keep actual document navigation and link-authoring helpers, accepted document membership, Search content/build ownership, media deployment and the frozen archive intact. Retain publication-lineage support using exact accepted document IDs and configured report hosts; no workflows are currently configured. Historical tests remain unchanged.

## Deliverables And Process

Deploy Repo no longer produces or reads `document-locations.json`, computes legacy Catalogue document URLs, requires associations for that computation, or reports Catalogue as paused. Its response becomes `docs_deploy_repo_preview_v3` without `catalogue_document_urls`. Document counts come directly from accepted by-ID membership. Local subject association data retains its current owner and remains outside the public file projection.

Current Catalogue distribution remains an independent file projection from Studio-owned generated output into `site/assets/data/catalogue/`, creating the required directory structure and copying the selected public consumer files. [Catalogue Deployment](d-20260909-205938-3569d6.md) owns that pending requirement. No old Work/Series schema rewriting or Catalogue-to-document URL refresh is required by this retirement.
