# Delivery Sequence

## Complete Result

The legacy Catalogue remains available as an immutable archive, while current Catalogue content is presented through Analysis Docs Viewer. Catalogue remains the canonical data owner. Public consumers combine the accepted Analysis document set with current deployed Catalogue data, independently of when a consuming document was published.

[Publishing Workflow - Stage Structure And UI](/docs/?scope=studio&doc=d-20260906-160541-cf892c), including Content Alignment, is complete. The archive, canonical/editor simplification and Stage 5 Studio output are also complete. Further UAC 3 work waits for resolution of the possible minor Catalogue schema change.

The accepted Stage 3 findings remain useful evidence. Working document creation/editing/deletion and existing sub-scope report refresh are available; remaining Catalogue changes, semantic tokens and specialised editing tools belong to separate work.

[Concept](/docs/?scope=studio&doc=d-20260904-014334-f3dab5) records the Image View and many-document direction. Catalogue grouping, document subject, document parentage and token composition remain independent. Earlier assumptions about a unique Work document, automatic navigation or one document per record are not fixed requirements.

Bulk Catalogue-to-document migration is abandoned. [Projects](/docs/?scope=analysis&stage=working&doc=d-20260805-155400-4c341f) already contains the user's backlog for most Series; the unification must not generate another one. Stage 6 instead supplies a reusable batch New doc action for explicitly selected Works or Series. The unified `cat_id` proposal is also abandoned: retain explicit `series_id`, `work_id` and `detail_uid` subject fields.

The Studio Catalogue production pause is lifted. Ordinary Save completes affected generated data and required media; full JSON maintenance reuses existing media references. There is no adapter or synchronized old/new output. The archive remains outside active writes, while the Docs provider/publication switch and public deployment remain separate work.

### 6 — Batch New Docs For Selected Works Or Series

Build a batch New doc action that creates documents for selected Works or Series, inserting front matter and basic starter content automatically. This supports deliberate authoring alongside the existing Project docs backlog. It does not create a complete parallel document inventory or automatically create Details documents for every Work that has Details.

Decide before implementation:

- What front matter and starter content should each new document contain, including any subject-driven report, gallery or token?
- How are Works and Series found and selected for the batch?
- Where is the action available and where are documents created: `dotlineform`, `analysis`, or both?
- How are existing documents shown during selection so the action helps the current backlog without silently duplicating it? Multiple documents about the same entity remain valid.

**Gate:** selection, destination and starter content are agreed, and the action creates ordinary editable documents for the selected entities through the normal document workflow. Review and publication remain separate.

## Post-migration Follow-on

Work `00389` is the concrete example: the author had over 500 photos to publish and stored them as Details to avoid adding 500 Work records to `works.json`. The old site required a Work to anchor those Details, so `00389` was created for that purpose. Reconsider whether such a collection needs that Work anchor and how Works or Series without canonical images or thumbnails should appear. A blank thumbnail may be the desired presentation. This records an open design question, not a change to the current model or migration requirements.
