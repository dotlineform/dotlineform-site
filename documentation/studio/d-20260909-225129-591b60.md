# Semantic Token References Across Collections

## Outcome

The existing scope-level `generated/documents/semantic-tokens/index.json` includes semantic-token occurrences from the main collection and every configured sub-scope. The Analysis Working Semantic Tokens report shows their correct source-document titles and opens the exact documents.

Status: **complete, accepted and closed on 2026-09-12**. The user accepted the result and authorized closeout. This delivery is ready for manual archive; its parent feature remains active for other work.

## Current Behaviour

The current toolbar actions are:

- **Add Media View link:** inserts a Work text link that opens Media View.
- **Add Catalogue Image:** inserts a Work or Detail image that opens Media View.

These tokens render in main-collection and sub-scope documents. Both builder paths persist their collected occurrences in the shared scope-level index. The Analysis Working report resolves exact source titles, collection hosts and document links without a scope selector.

For Analysis Working, the existing index is under the configured Docs root at `scopes/analysis/working/generated/documents/semantic-tokens/index.json`. Keep that index as the token-usage store; do not introduce separate child indexes or another authoritative copy.

## Data And Update Rules

- Record tokens from documents in all configured collections of the selected scope/stage. Publication eligibility has no role in token usage: `publishable`, `draft` and Subject fields do not filter the occurrences. Tokens in a `publishable: false` document remain indexed.
- Preserve exact source identity: scope, sub-scope and `doc_id`, with an empty sub-scope for main-collection documents. Keep the selected stage in the dataset/read context and use it when resolving source-document links.
- Preserve the existing occurrence information: authored token, label, source range and repeated occurrences. Keep the Catalogue target and selected Detail identity intact; a Catalogue reference does not imply a document about that Work or Detail.
- On Document Save/Build, replace the current document's occurrences, including replacing them with an empty list when its last token is removed. Preserve the entries belonging to all other documents and collections.
- Remove a deleted document's contributions. A supported collection move must remove the old collection identity and write the new one without duplicate or stale entries.
- Main-collection builds must preserve child contributions, and child builds must preserve main-collection and sibling contributions. Reuse the occurrences already collected by rendering; do not add a whole-scope Markdown scan to an ordinary save.
- Complete the index update before Save/Build returns. This is a single-user system: use the existing synchronous write orchestration and preserve other collections during each sequential update. Do not introduce build-overlap mitigations.

Retain the existing token syntax, parsing, rendering and target-availability behaviour. Broken Links remains the separate diagnosis owner. This delivery adds no publication checks, eligibility transitions or recovery workflow.

## Implementation Boundary

Reuse the existing semantic-token occurrence collector, index writer and parent/child build paths. Extend the existing index only as needed for exact source collection identity and its reader. No new relationship subsystem or per-document token store is required.

Update the Semantic Tokens report and its data reader to include sub-scope documents with correct titles and links. The report is available only in Analysis Working, with no scope selector. Resolve child links through their actual collection and host in Working. Preserve the three-column layout and sorting. Add its local report host alongside Analysis Working's existing reports; retain the Studio report page as documentation linking to the new host.

Catalogue records are surfaced through Media View. This delivery creates no Catalogue reverse relationships, Catalogue-record writes or inferred document-to-document links.
