# Scope Links - Delivery

## Requirements

Provide one complete outcome: after the user runs **Rebuild docs and Search** for Analysis Working, a local **Links** report lists its recorded document-to-document links in two sortable columns, **from** and **to**. Each cell displays the document title and opens that exact document, including child documents in configured sub-scopes.

This delivery follows the completed [Doc Relationships](/docs/?scope=studio&doc=d-20260907-125101-d3bde6) implementation. It is complete, accepted and closed on 2026-09-10. The [Links report](/docs/?scope=analysis&stage=working&doc=d-20260910-214604-f9e841), sortable columns and final 🔄 Refresh placement are accepted; code review found no material issues. [Builder](/docs/?scope=studio&doc=d-20260423-000000-c9f3ea) and [Reports](/docs/?scope=studio&doc=d-20260513-105343-6de36b) own shipped behavior. This delivery is ready for manual archive; document-type icons remain a separate exercise.

The aggregate is `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/scopes/analysis/working/generated/documents/links.json`. Its only relationship inputs are the prepared `<doc_id>.json` files in the sibling `links-by-id/` directory. That directory already covers scope-level documents and the configured `concepts`, `moments`, `processing` and `works` collections; aggregation does not traverse their source trees or create separate collection indexes.

Use a version 1 envelope with `schema_version`, `scope`, `stage` and `documents`. Omit a prepared record only when both its incoming and outgoing lists are empty; include records with links in either direction. Copy each included record unchanged in deterministic file order, preserving exact targets, titles, hrefs, Subjects, occurrences and counts. This intentionally narrows the parent's earlier all-records proposal for this report while preserving the accepted per-document version 1 shape.

Document Build continues to own extraction, document existence, eligibility, both-end maintenance and counts. Aggregation reads and combines completed JSON, applying only the agreed empty-record omission; it does not derive relationships, inspect Markdown/front matter, resolve Subjects, reapply eligibility or repair missing files. Eligible drafts remain included. Existing exclusions for non-publishable documents, Folder subjects and missing targets remain entirely upstream.

### Report Rows And Navigation

Use one row per directed document pair: each record's `self` supplies **from**, and each `outgoing[].document` supplies **to**. Incoming entries are mirrors of these links and must not supply additional rows. Reciprocal authored links produce two rows, `A → B` and `B → A`. Repeated references from A to B produce one row; their occurrence details remain intact in JSON. Documents with incoming links only remain in the aggregate but add no report rows.

Use the prepared document titles and document hrefs, not authored occurrence labels or fragments. Keep distinct documents with identical titles distinct by exact `{scope, sub_scope, doc_id}`. Apply the existing same-scope Working navigation context to the supplied href without changing stored relationship data or losing a child's host/subdoc target. Both column headers toggle ascending/descending title sorting; initially sort by **from**, then **to**, with exact identity as the stable tie-breaker. Reuse existing table presentation; retain exactly the two requested columns.

Allow each document-title cell to receive a future icon prefix without changing its title sort key, exact target or link behavior. Preserve the prepared collection and Subject metadata for that later presentation choice. No icons, type-precedence rules or cross-report icon registry are selected or implemented here. Choosing consistent icons for concepts, Catalogue subjects and ordinary links across all reports and sub-scopes is a separate exercise; this delivery displays titles alone.

The report is local and read-only, hosted by an ordinary Analysis Working report document titled **Links**, excluded from publication and following the existing local-report conventions. It reads the saved aggregate once through the configured generated-data read boundary. The compact **🔄** Refresh button sits left of the links count on the same row. Opening or refreshing the report does not scan individual relationship files, build data or audit authored links. A valid aggregate with no outgoing links displays a normal empty state; missing or unreadable aggregate data displays an unavailable/error state with a rebuild instruction, not a misleading empty result.

### Refresh Boundary And Rebuild Integration

Refresh `links.json` at completion of a scope document rebuild, after all participating document and sub-scope builds have finished their relationship updates. Replace the aggregate from the directory's current contents so records removed upstream disappear on the next scope rebuild. A failed file read or JSON parse must fail aggregation visibly rather than silently publishing a partial result. Do not add relationship-semantic validation to this combining step.

An individual Save, watcher document build or single-document rebuild updates `links-by-id` through its current owner but leaves the aggregate at the last completed scope rebuild. Report refresh rereads that snapshot. The scope rebuild remains busy until its document work, aggregation and requested Search work have completed; only then may it report success and reload the current view.

SL.1 enables the existing **Rebuild docs and Search** control for Working and passes its exact stage through the management dispatcher, main collection, configured children and Search. The scope rebuild aggregates prepared records after successful document and Search work, then records the completed Build manifest. The real service operation is verified and the user has accepted the report workflow. Pre-publish remains unavailable through this action, and other publishing actions retain their separate boundaries.

### Agreed Decisions

| Decision | Agreed choice | Consequence |
| --- | --- | --- |
| What does “all the links” mean? | One row per directed document pair. | Compact two-column report; repeated occurrences remain available in JSON. One row per occurrence would repeat identical title pairs. |
| Collection coverage | Every prepared file in the scope/stage directory, except records with both link lists empty. | Includes every configured Working collection; no isolated-document records or collection filters. |
| Refresh timing | Scope rebuild only; report refresh rereads the saved snapshot. | Edits appear in the report after the next scope rebuild, even though the single-document Links view may already be current. |
| Working rebuild prerequisite | Enable the existing **Rebuild docs and Search** action for Analysis Working within this delivery. | SL.1 reuses the existing Search corpus and schema with explicit Working selection. |
| Rollout | Analysis Working only. | Other scopes, Pre-publish, Publish and public deployment remain separate deliveries. |
| Sorting | Both columns sort ascending/descending by document title. | Initial order is from, then to, with exact-identity tie-breaks. |
| Icon prefixes | Allow future cell prefixes; display no icons in this delivery. | Shared icon selection and type classification across reports/sub-scopes are a separate exercise. |

## Deliverables

- Scope-owned `generated/documents/links.json`, combining prepared per-document relationship records unchanged and omitting records with both lists empty.
- An awaited aggregation step within the Working scope rebuild and the bounded stage-aware support needed by the existing **Rebuild docs and Search** action.
- A local generated-data read and report loader using existing report/service owners.
- An Analysis Working **Links** report document with linked document titles in sortable **from** and **to** columns, allowing a future icon prefix independently of title sorting.
- Focused generator/service evidence, manual report review and current documentation in [Builder](/docs/?scope=studio&doc=d-20260423-000000-c9f3ea) and [Reports](/docs/?scope=studio&doc=d-20260513-105343-6de36b), covering their respective changed responsibilities.

## Process

1. Author or edit ordinary links in Analysis Working and wait for Save/Document Build to finish.
2. Run **Rebuild docs and Search** in Working and wait for the entire operation to complete. Document builds prepare the relationship files; scope aggregation combines their completed output.
3. Open **Links**, or reload its snapshot after a completed rebuild, to see all directed relationships.
4. Select either title to open the exact source or target document in the appropriate local Working context.
