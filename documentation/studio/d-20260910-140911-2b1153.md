# Links View design

**Links is a distinct presentation using the same hosting mechanism as Media View.** The shared Content Detail host provides the toolbar, lifecycle cleanup and **Back to document**, including scroll and focus restoration. Layout is selected per presentation: Links uses the normal document area, without an outer border, and retains the index panel in its existing state. Media, diagrams, tables and expanded reports use the expanded main area. The host is available to both public and Manage apps.

The design includes:

- A **Links** action 🔀 the doc toolbar for the displayed document, including the exact child document when viewing a sub-scope entry.
- A heading identifying that document, aligned vertically with the normal document title, followed by categorised links.
- Normal document width, no outer border, and the index panel available with its existing collapsed state respected.
- Ordinary document navigation when an entry is selected.
- **Back to document** returning to the invoking document.

The dedicated Links presentation adapter is implemented in the shared host. Media rendering and relationship rendering retain separate owners. The user accepted the proof and closed DR on 2026-09-10 after scope-wide rollout, code review and correction. [Links View](/docs/?scope=studio&doc=d-20260910-202325-53b5f9) is the durable reference for the shipped behavior. This mock-up is ready for manual archive.

The Links adapter reads the displayed document's separate `links-by-id/<doc_id>.json` relationship file. For Analysis Working, this is under `$DOTLINEFORM_PROJECTS_BASE_DIR/docs-viewer/scopes/analysis/working/generated/documents/links-by-id/`, resolved through scope configuration. The existing document `by-id` payload does not receive a relationship block. One relationship response supplies all entries and labels. The public-safe read path consumes configured static files without local services; public data preparation and activation remain separately owned.

The initial design proof used `links-by-id` files generated for representative test documents. After the user accepted that proof, DR-6 removed the document restriction. Normal Doc Build now maintains the accepted version 1 relationship files across every configured Analysis Working collection. The reference model and JSON serializer remain separate. [View Caching and History - Delivery](/docs/?scope=studio&doc=d-20260910-193232-e511cd) owns the separately agreed shared data-reuse and browser-history behavior.

- “all entries” currently means all relationships admitted by DR’s agreed rules. Non-publishable/Folder endpoints and missing targets are omitted; otherwise eligible drafts remain included in Working.

## View Layout

Links are shown in 3 sections:

- Concepts: these are links to docs which are sub-scope `analysis/concepts`
- Works: these are links to docs which contain a subject type field in front matter e.g. `work_id:`
- References: these are links to plain scope level docs

Design:

- If a section doesn't contain any links of that type, the section is hidden.
- Eventually the 'works' will cover all catalogue associations: series, works and work details (all included in the 'works' section)
- Combine incoming and outgoing relationships into one link per exact document identity. This view displays no direction arrows or direction labels. Incoming/outgoing distinctions remain in the generated data for other visualisations and reports.
- Sorting within each section is AZ, links do not have any special precedence over other links (this could be a future enhancement or for a different view/visualisation).
- Repeated authored links and reciprocal relationships share a single displayed entry. Deduplicate by `{scope, sub_scope, doc_id}`, so different documents with the same title remain distinct. Concepts classification takes precedence over a Work Subject, followed by scope-level References.
- Empty sections are hidden. A document with an empty relationship record displays “No links.” If its relationship file is absent, the view displays “Links data is not available for this document.”
- Inclusion of semantic-token references might be a future enhancement.
