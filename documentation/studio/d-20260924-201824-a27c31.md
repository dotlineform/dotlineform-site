# Preview Stage Consolidation

## Requirements

The user approved removing Pre-publish and renaming the accepted local Published snapshot to Preview. The local document consumer is Deploy Repo; its existing review gate and the separate GitHub Actions public deployment gate remain. Working owns authoring. One awaited Prepare Preview action produces a complete eligible, read-only snapshot for review. There are no compatibility aliases for retired local stages or routes.

## Deliverables

- Workspace schema v3 registers Working collections/media once and derives Preview configuration. Live storage is `working/source/`, `working/generated/` and `preview/`; temporary preparation inputs are removed after use.
- Preparation plans exact Working/configuration/Preview revisions, excludes draft and unpublishable subtrees and excluded collection hosts, builds captured inputs, validates the result and writes `preview-manifest.json` after byte verification.
- Local navigation, readers, capabilities and controls use Working and Preview. Deploy Repo consumes the exact reviewed Preview revision. Public payloads retain their separate `published` wire identity and existing destinations.
- The local snapshot conversion preserves document identity, content and preparation provenance. Browser bookmark and panel state for the old Published owner converts once to Preview; retired Pre-publish state is retained unused, without merging distinct owners.

## Process

Edit and rebuild in Working. Choose Prepare Preview, confirm the selected document count and wait for completion. Open Preview and review its documents. Choose Deploy Repo to inspect and apply its concrete repository/media changes. Commit/push and the manual public workflow are separate explicit actions.
