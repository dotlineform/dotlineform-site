# Docs Media Report Refactor

Status: implementation and static code review complete; manual report and Finder review pending.

The [Docs Media report](/docs/?stage=working&doc=d-20260812-212735-6d9cf3) now builds its rows in `docs-media-data.js` from generic `/docs/media-files` and `/docs/media-references` GET reads. `POST /docs/media-report` and `docs_media_report.py` are removed. [Media And Asset Handling](d-20260514-184303-7914e2.md) owns the current payload and media boundary.

## Responsibilities

| Owner | Responsibility |
| --- | --- |
| Front end | Join file records to document references, deduplicate document associations, construct document links from exact identities and configured hosts, order document lists, and build report rows. Own display exclusions, search, sorting, counts, refresh state and rendering. |
| Generic server data helpers | List files within configured media locations and return separate document-reference records with exact media and document identities. Supply data without report rows, presentation URLs or display ordering. |
| Shared reference extractor | Retain `source_media_references()` in `docs_media_inventory.py` for canonical source parsing, reused by the reference-read helper. Avoid duplicating the parser in JavaScript or downloading every source document to the browser. |
| Server file-action helper | Validate the exact media target, resolve an existing confined local file and reveal it in Finder. Keep filesystem paths and OS execution on the server. |

Preserve Working report coverage: configured ordinary ready-media and registered build sources, with references from ordinary and collection documents. Present unreferenced files retain a blank Documents cell; missing files produce no row. Build sources and generated outputs remain independent identities. Hide exact `.DS_Store` basenames in the report without changing the shared inventory or files on disk.

## Finder Helper Reuse

`docs_local_files.open_in_finder()` now owns the OS-opening step, platform check and dry-run suppression. Both `docs_local_links.py` and the new `docs_media_actions.py` call it after their existing validation; operation-specific error responses are retained.

The Docs action retains its exact `{stage, collection, role, media_type, identity}` request and `/docs/open-media-source` route. Projects confinement and Docs artifact confinement remain separate; neither is a fallback for the other. The browser supplies no absolute filesystem path.
