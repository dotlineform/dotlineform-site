# UAC 4 - Simplify Catalogue Data And Editors

## Requirements

Deliver canonical Catalogue records and Studio editors that support independent Series and Works, optional singular Work membership, and no Catalogue record publication state. Docs Publish retains the sole public acceptance decision, following [Publish workflow](/docs/?scope=studio&doc=d-20260905-141447-c33de1).

Removal of the fields described below will remove restrictions such as:

- A Work cannot be published unless it belongs to a published Series.
- A Series cannot be published without a primary Work and published members.
- The Series editor prevents removing its primary Work until another is selected.
- The Series editor prevents removing a Work’s last Series membership, directing you to unpublish or delete it instead.

Ordinary integrity checks remain: an assigned `series_id` must identify an existing Series, and record IDs must remain valid.

### Schema changes

- Replace Work `series_ids` with optional singular `series_id`. An ungrouped Work omits the field; empty Series remain valid.
- Remove `status` from `works.json` and `series.json`
- Remove `published_date` from `works.json` and `series.json`
- Remove `primary_work_id` from `series.json`
- Remove `series_type` from `series.json`

### UI and service changes

- Remove the editor/service actions and rules that use the removed fields. 
- Remove constraints whose only purpose is old-site publication or reciprocal navigation:
    - Allow empty Series and ungrouped Works.
    - Removing a Work from a Series clears its membership without requiring deletion, a replacement member or a publication action.
- Remove the catalogue draft works report and route `/studio/catalogue-status/`
- Retain exact IDs, Detail composite identity and per-Work aggregates, descriptive metadata, ordering, downloads, links, media references and necessary data/media checks. Catalogue membership, document subject, document parentage and token composition remain independent.

### Relationship with parent delivery

There is no demonstrated need for a wider consumer JSON redesign. The frozen archive, media objects, document sources, public presentation and publication workflow are outside this delivery's write boundary. Catalogue production workflows remain paused until Stage 5; controlled editor verification does not resume ordinary Catalogue use.

The result prepares Stage 5 to build the full external consumer output. The user authorized this delivery on 5 September after clarifying the schema and UI removals.

[Delivery Sequence](/docs/?scope=studio&doc=d-20260902-122221-1879db) records the accepted Stage 3 conclusions and completed cleanup. The starting data contains 1,935 Works, 139 Series and 142 Work Detail files. No drafts or multiple memberships remain; Work `00008` belongs to `105`, and `00214` to `103`. This was the pre-migration snapshot; Stage 4 has now replaced `series_ids` and removed the agreed fields while preserving every retained value.

## Deliverables

1. Migrated canonical Work/Series data, serializers, field definitions and validation using the agreed model, without old-field aliases or dual-format readers.
2. Matching Work and Series editors and services, including New, Save, membership changes, affected bulk operations and delete validation. Retained commands preserve revision checks and coherent multi-record writes.
3. Explicit Save and output behavior during the pause, with no old-site generation or hidden publication follow-through. Studio-owned read projections needed by the editors remain distinct from Stage 5's Docs consumer output.
4. Focused verification and updated durable source/editor documentation, plus a concrete Stage 5 handoff identifying remaining output and consumer dependencies.

## Process

Authors create and save ordinary canonical Works or Series. A Work has one selected Series or none. Removing a membership leaves an ungrouped Work; it does not delete the Work or require a publication-state change. Series membership editing continues to write the affected Work records coherently. Saving does not make a record public.

Stage 4 completed that editing behavior while preserving the Catalogue output pause. Save refreshes required private Studio lookups; Build and media output remain unavailable. Retargeting the producer, replacing the examples and switching Docs readers together belong to Stage 5.
