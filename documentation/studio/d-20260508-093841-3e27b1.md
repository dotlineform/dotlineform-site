# Publish Media To R2

## Transport Ownership

`studio/services/media/publish_media_to_r2.py` provides Catalogue remote comparison, upload and exact operator-requested deletion. It is a maintenance transport, not the normal Catalogue Save workflow or the owner of media versions.

Normal Save prepares local bytes and commits complete rendition sets with their dimensions and versions before Working JSON generation. [Catalogue Build And Lookup Refresh](d-20260519-202931-0c703e.md) owns that completion. Normal public distribution uses the Docs Preview plan/apply operation, labelled **Publish**, described in [Catalogue Deployment](d-20260909-205938-3569d6.md).

The CLI retains a separate `--scope docs` mode. Despite the command's historical name, that mode materializes one staged file into the local shared Docs assets; it does not publish it to R2. The domain selector is not a retired Docs scope identity.

## Catalogue Maintenance

The local upload source is the configured shared primary tree beneath `$DOTLINEFORM_DOCS_BASE_DIR/assets/works/primary/`. Original project images and Catalogue download staging retain their separate owners. Required widths and object naming derive from checked pipeline/site configuration:

```text
works/img/<work_id>-primary-<width>.webp
```

Preview one Work, then deliberately apply the reviewed maintenance operation:

```bash
python3 studio/services/media/publish_media_to_r2.py --scope catalogue --kind works --id 01007
python3 studio/services/media/publish_media_to_r2.py --scope catalogue --kind works --id 01007 --write
```

Changed remote objects require `--force`; matching bytes are skipped. Incomplete required variant groups are blocked unless the operator explicitly permits partial CLI transfer. No transfer, including a partial transfer, advances canonical versions or refreshes generated JSON. Retired Detail media has no active publisher kind.

Exact deletion requires `--delete --write` with one kind and ID; broad `--all` deletion is unavailable. This is an explicit maintenance capability only. Ordinary Save and Publish perform no automatic remote asset deletion.

## Versions Belong To Local Completion

Works carry positive canonical `media_version` values, used as primary URL cache tokens. Local preparation compares completed rendition bytes with existing local renditions. A difference in an existing rendition advances the Work version once; unchanged bytes and missing-rendition repair retain it. Prepared bytes, dimensions and versions use the Catalogue transaction owner together. Failed preparation does not promote an incomplete set.

Upload and copy operations preserve those versions. Do not infer a new content revision from a missing remote object, retransmission or deployment outcome. [Catalogue Media Pipeline Config](d-20260331-154730-b019e0.md) owns derivative policy.

## Docs Exact-File Materialization

The Docs mode reads one direct-child file from shared import staging and writes the configured Working ordinary or exact collection shared-media destination through `docs_media_storage.py`:

```bash
python3 studio/services/media/publish_media_to_r2.py --scope docs --docs-stage working --kind files --staged-filename document.pdf
python3 studio/services/media/publish_media_to_r2.py --scope docs --docs-stage working --kind files --staged-filename document.pdf --write
```

Use `--docs-collection <id>` for a configured collection. There is no `--docs-scope`, Docs `--all` or Docs remote-delete operation. Changed local bytes require `--force`. The command does not author a document link, prepare Preview or distribute public media; those remain with the [Docs media workflow](d-20260514-184303-7914e2.md).

## Credentials And Safety

Catalogue R2 operations load settings from `.env.local`, optional `--env-file` inputs and the configured environment. Missing variables are named; configured values and signed transport details remain private.

For credential rotation use the provider's current [Roll tokens instructions](https://developers.cloudflare.com/fundamentals/api/how-to/roll-token/). Update the corresponding local secrets and restart the owning service before verifying access. Never copy credentials into tracked documentation or reports.

The transport confines local inputs, rejects traversal/symlink escapes, defaults to dry-run, requires `--write` for mutation and compares size and ETag/MD5 before selecting remote changes. Reports contain non-secret identifiers and statuses. Run `--help` for the current options; normal public publication should use the reviewed Preview workflow rather than an ad hoc broad CLI upload.
