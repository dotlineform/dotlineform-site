# Catalogue Work Editor

## What It Does

Use `/studio/catalogue-work/` to create, find, edit or delete canonical Works. Work downloads, links, project-media selection and Detail-section management belong to this editor; individual Detail-record editing does not.

- `?work=<work_id>` opens one Work.
- `?mode=new` starts a new canonical record; optional `?series=<series_id>` preselects a Series.
- Explicit IDs, numeric ranges or a mixture open bulk edit mode.

The [Catalogue Source Model](/docs/?scope=studio&doc=d-20260519-000000-a0da45) owns the data and output boundaries. Ordinary Save completes affected external Catalogue output and required media.

## Create And Save

New mode shows the editable form and Save. The suggested Work ID can be replaced with any valid unused ID, including a deleted ID. Secondary controls appear after the first successful save.

Search uses the private Studio Work search projection. Opening a Work loads its exact canonical record, server-issued revision and related context from the local API. The source record remains the editable baseline.

Save validates the form and sends the changed record with its revision. The service rejects a stale revision, validates canonical integrity, writes through the source transaction owner, completes affected generated JSON/indexes and required media, then refreshes private Studio lookups. The editor reloads the focused projection with current revisions. If output or a later editor refresh fails, the saved canonical change remains complete and the message identifies the incomplete step.

A Work can belong to one Series or none. Selecting another Series reassigns it; removing the selected Series leaves it ungrouped. The Series chip opens its Studio editor. Membership does not assign a document subject, parent or destination.

There is no Work publication state, Publish/Unpublish action or Catalogue Drafts route. Save is the only ordinary completion action; there is no separate Build or media-publish control. It does not refresh Docs semantic lookups or publish documents. The local API must be available; browser edits are not queued for offline saving.

## Bulk Editing

Bulk mode performs one combined canonical transaction:

- Untouched fields preserve each Work's value.
- A touched empty field clears that field across the selection.
- Enter one Series ID to assign the selection, or clear the Series field to remove membership.
- Each selected Work supplies its own revision; a stale record rejects the combined save.
- Detail, download, link, media and delete controls are unavailable in bulk mode.

Bulk Save completes affected output and required media through the same service as single-Work Save, then refreshes private Studio lookups.

## Delete And Detail Sections

Work deletion uses a server preview and confirmation, then repeats validation and checks the Work revision before applying. It deletes the canonical Work and dependent Detail sections and records. It then removes exact obsolete media and reconciles generated records, indexes and former Series membership. Successful completion returns to the Work editor; an output error retains the deleted canonical state and reports incomplete cleanup.

Details remain a Work-owned aggregate:

- Sections own their title, direct media subfolder, ordering and Detail-sort policy.
- Creating a section adds the selected image records and their available dimensions to the Work's aggregate.
- Section Save uses the exact section revision.
- Deleting a section deletes its nested Details.
- Section mutations complete affected Work/Detail output and required media, then refresh private Studio lookups.

See [Catalogue Per-Work Detail Source](/docs/?scope=studio&doc=d-20260622-160612-b986f3) for aggregate identity and storage.

## Media And Runtime Ownership

The media picker resolves the Work's configured source, folder, optional direct subfolder and filename. The server validates paths without exposing absolute filesystem locations. Catalogue staging uses `catalogue/media-staging/` beneath the configured Projects base. Save prepares required media and maintains generated thumbnails under `catalogue/generated/`. The preview uses the configured remote primary URL and the saved Work's media version; an unavailable image is reported separately from missing preview configuration.

Browser modules under `studio/app/frontend/js/` divide the route into fields/form, selection, actions, record state, Detail sections and media picking. `catalogue-editor-service-client.js` owns transport; `studio_catalogue_api.py` dispatches to the focused services under `studio/services/catalogue/`. Field definitions and current code own the exact editable inventory.

The shared [Route Ready State](/docs/?scope=studio&doc=d-20260625-162242-b0b6c7) is exposed on `#catalogueWorkRoot`. The retained Catalogue smoke proves route/service boot; service tests protect mutations and UI acceptance remains manual.

[Catalogue Build And Lookup Refresh](/docs/?scope=studio&doc=d-20260519-202931-0c703e) owns output completion and failure handling after the canonical transaction. The editor combines single and bulk state with Detail and media context, so new responsibilities should use their existing focused owners.
