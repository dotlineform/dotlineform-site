# Catalogue Hosting And Storage Options

## Status And What Has Shipped

Proposed architecture decisions. None of the host/source/JSON migrations below has shipped.

Today Studio's [registered Work editor](../reference/Studio.md) owns browser authoring and canonical persistence through its existing service. The [five aggregate stores](../reference/Catalogue_Source_Model.md) remain under `studio/data/canonical/catalogue/`. Save completes canonical changes and selected staging; Refresh prepares Working data/media; Regenerate adopts Catalogue documents; one Docs Publish consumes finished selections. Public Catalogue JSON remains repository-hosted under `site/assets/data/catalogue/`; configured media uses its existing R2 destinations. [Current lifecycle](../reference/Catalogue_Save_And_Refresh.md)

Series–Gallery relevance and reader Related Links already operate on this boundary. Their remaining visual acceptance has its [own record](Related_Galleries.md); they do not need these migrations. The former standalone Studio Publish/publication-ledger proposal is superseded.

## Open Decisions

| Area | Candidate choices | Decision needed before delivery |
| --- | --- | --- |
| Local editor host | Keep Studio; host its existing editor inside local Docs; consider a separately scoped native editor | The earlier discussion preferred one local Docs host, with no approved implementation sequence. Agree mount/release, style containment and unsaved/busy navigation while reusing Catalogue operations. Public Docs remains read-only. |
| Canonical source layout | Keep aggregate Git records; move complete authoring records to exact by-ID files in an explicitly chosen source owner | Establish actual selected-I/O benefit, Gallery/membership and bulk-write authority, migration/history/recovery and derived-index/search work. Generated by-ID presentation is not complete canonical source. |
| Public Catalogue JSON | Keep tracked Pages output; consider R2 | Demonstrate the hosting need and define public URLs/CORS/cache, coherent Docs/JSON/media output, transfer verification and recovery. The current [workspace parser](../../docs-viewer/services/docs_workspace_config.py) accepts only repository JSON destinations, so this is not a config-only provider switch. |

These choices are independent. Moving a shell does not require moving canonical source or public JSON. The proposed by-ID source location under Docs Working is an ownership decision, not a consequence of an existing generated folder. Native Catalogue editing is separate from the [Docs Viewer App Roadmap](Docs_Viewer_App_Roadmap.md).

Keep one editable authority. A delivered migration must not substitute public fields for private project/storage inputs or add fallback reads/aliases to the former source. Browser filtering and pagination remain browser-owned; private Works-report data stays private. [Tradeoffs and rationale](../design/Catalogue_Hosting_And_Storage.md)

## Next Decision

Select one observed user/maintenance problem and the smallest complete change that addresses it. No new performance measurements or deployment constraint were established by this documentation review. If source I/O or repository size is the deciding factor, inspect that concrete operation before claiming a gain. Current Save/Refresh/Regenerate/Publish remains the operating model until a bounded migration is approved and delivered.
