# Rationalise Documentation

Make the repository docs quicker to use during development. Give current behaviour one maintained home, compile reusable design reasoning by domain, and keep completed delivery records when they preserve useful evidence. The Studio material was reviewed in bounded batches and the migration is complete. A batch is small enough to trace from a real question to the code or record that answers it. File count and word count help find overlap. Each retained passage should answer a question a developer could reasonably ask.

## What the documentation is for

> why does media view works page not have related links?

| Question behind the question | Where to look | What the docs should supply |
| --- | --- | --- |
| Has something broken, or have I missed a step? | `documentation/reference/` | What a Work in Media View currently shows, where its links come from, when they update, and what to check if expected links are missing. |
| Did we decide that Related Links did not make sense there? | `documentation/design/` | The decision, if recorded, with the relevant tradeoff. Compile the reasoning about Work Media View, Catalogue documents and other places where relationships are shown. |
| Did we run out of time and leave it as a follow-on? | `documentation/deliveries/` | What the completed delivery shipped, what it deferred, and the evidence that distinguishes the two. Link to an open item in `documentation/_working/` when there is one. |

The example starts a review. Establish current behaviour from its owner, look for an explicit decision, and record any remaining gap with the evidence available. `documentation/_working/` holds active and proposed work and writing in progress. This completed tracker now lives in Deliveries.

Processing is a separate project with its own documentation under [documentation/Processing](https://github.com/dotlineform/dotlineform-site/blob/abc409bdeeb8a33066b94e06d534e445af65a760/documentation/Processing/README.md), including its setup/design record. Its lifecycle is independent of the website documentation and release workflow.
