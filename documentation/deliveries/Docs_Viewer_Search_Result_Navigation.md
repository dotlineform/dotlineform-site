# Docs Viewer Search Result Navigation

Closed on 25 November 2026 after the user tested Manage and `site-preview` and approved closeout. [Current Search navigation](../reference/Reader_Discovery_And_Return.md#search-previous-and-next)

Open a document from **Index Search** in Public or Manage and review neighbouring matches using the same **Previous** and **Next** controls as a collection report. The controls follow the complete ranked document order, including matches beyond the first 50 shown in the Index. The first and last document have only the link that applies. Gallery rows continue to open in Media View, and document navigation steps past those rows. [Current Search and collection navigation](../reference/Reader_Discovery_And_Return.md#index-results-and-navigation)

Clearing Search leaves the displayed document open at its reading position and removes its Search links. Changing the query or scope also ends the old sequence. Selecting a document result starts a sequence from the current results, including when that document is already displayed. Collapsing the Index, including automatic collapse on Public mobile, keeps the search and its links active. **More** reveals rows from the same sequence. [Search controller](../../docs-viewer/runtime/js/shared/docs-viewer-search-controller.js) · [Public compact Index](../../docs-viewer/runtime/js/shared/docs-viewer-app-runtime.js#L190)

Browser Back restores the earlier document and its Search links when the invoking results are still active. After those results end, Back restores the document with its ordinary navigation. Direct, reloaded and new-tab URLs use the existing URL contract for the exact document and any Index query. Selecting a result in that session establishes its Search sequence. The delivery concerns Index Search in Public and Manage. Recent, Catalogue's own search and Book navigation keep their respective activation paths. [Browser history](../reference/Reader_Discovery_And_Return.md#browser-history) · [Reader URL construction](../../docs-viewer/runtime/js/shared/docs-viewer-router.js)

## Readiness Code Review

The pre-implementation review identified four areas to address. The implementation review records their resolution.

1. **Retained history can reintroduce an expired sequence.** The document controller captures `invokingSequence` in each retained view and restores it on Back. The route workflow separately keeps the current Index query during that restore. Removing the current footer alone would leave the saved sequence available to a caller. Validate Search lifetime at the shared footer projection point as well as removing the visible Search footer when its results end. This also covers a document load that finishes after Search changes. [Capture and restore](../../docs-viewer/runtime/js/shared/docs-viewer-document-controller.js#L19) · [Route restore](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L77)
2. **The same-target report branch could discard the supplied sequence.** Before the fix, `loadDoc` projected a supplied sequence, then restored a collection host with options that omitted it. The retained-document projector consequently received an empty sequence. The report path now carries the invoking sequence through restore. [Same-target routing](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L134) · [Retained document restoration](../../docs-viewer/runtime/js/shared/docs-viewer-document-controller.js#L89)
3. **Visibility and result identity have different lifetimes.** Compact Index collapse only changes disclosure. Search input and scope changes can clear or replace rows before the next ranked results are available. End the old sequence at the Search transition rather than waiting for asynchronous rendering. Keep **More**, scrolling and disclosure outside expiry. [Compact Index collapse](../../docs-viewer/runtime/js/shared/docs-viewer-app-runtime.js#L190) · [Search transitions](../../docs-viewer/runtime/js/shared/docs-viewer-search-controller.js#L398)
4. **Manage has two relevant link and refresh paths.** Normal and Alt-click links both look up the invoking sequence. Alt-click can enter Source for the already displayed target without calling `loadDoc`. Check that the Search invocation is retained when Source opens from that result and that navigating away from dirty Source still uses the existing confirmation. A Save or exact-document refresh renders a fresh payload with the previous invoking sequence, so it must use the same lifetime check as retained Back. [Link dispatch](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L256) · [Source entry](../../docs-viewer/runtime/js/management/docs-viewer-management.js#L260) · [Payload refresh](../../docs-viewer/runtime/js/shared/docs-viewer-document-controller.js#L456)

## Implementation Code Review

- Search builds one neighbour list on first activation from the loaded ranked matches and keys it by exact collection and document ID. **More** registers the newly rendered links against that list. The shared URL builder resolves each adjacent destination when it is displayed, and the route owner reads the selected document. The change introduces no new validation, fetches or persistence. [Search order and links](../../docs-viewer/runtime/js/shared/docs-viewer-search-controller.js#L127) · [Selected document open](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L95)
- Search expires the list when its inputs change or an owning Manage action replaces it. One lifetime check at footer projection covers retained Back, a pending document open and a refreshed payload. The check is required because those paths can carry an older sequence. Clearing Search reprojects the current footer in place and can restore the Book TOC's own order. Index disclosure and the history pair stay with their existing owners. [Footer projection](../../docs-viewer/runtime/js/shared/docs-viewer-document-controller.js#L27) · [Search refresh and deletion](../../docs-viewer/runtime/js/shared/docs-viewer-search-controller.js#L240)
- The same-target report path passes the supplied sequence through retained restore and captures the resulting view. Same-target Alt-click sets the sequence when Manage accepts the Source action. Existing link parsing, exact-target reads and dirty-Source confirmation still apply at the normal reader boundaries. A one-document sequence supplies zero links and leaves the footer landmark absent. [Same-target route](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L134) · [Source link dispatch](../../docs-viewer/runtime/js/shared/docs-viewer-route-workflow.js#L256) · [Footer](../../docs-viewer/runtime/js/shared/docs-viewer-collection-navigation.js#L41)
