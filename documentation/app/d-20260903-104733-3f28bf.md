# App v0

## Outcome

Before Docs Viewer work begins, the native Mac and iPad application becomes a coherent pre-1.0 product rather than a foundation demonstration presented as the whole application. It launches into an honest holding surface, gives the retained demonstration a proper About home, supplies real Help and application identity, preserves Python behind a reusable typed boundary, and produces a signed Release result that can be inspected and run.

This feature fills the visible and operational gaps already present in the application. It does not begin the Docs Viewer product, invent features for the holding page, or turn a personal native application into a distribution programme.

## Feature Rules

- Keep one shared Swift 6 target supporting native Mac and iPad only.
- Prefer native SwiftUI composition and standard platform commands for the shell, About, and navigation.
- Keep bundled page and WebKit mechanics contained rather than spreading them into the new main surface.
- Make the Python client reusable through typed request and response composition without exposing arbitrary remote function dispatch.
- Establish a development-signed Release boundary without adding App Store, TestFlight, notarisation, paid distribution, or public release work.
- Keep launch offline and make every cloud request an explicit user action.
- Update the durable owners as behavior becomes current.

## Delivery

1. [App v0.1](/docs/?scope=app&doc=d-20260903-104734-bae091) is the proposed complete delivery for the shell, About, Help, icon, product identity, reusable Python boundary, signed Release result, manual native review, and durable documentation transfer.

Add another App v0 delivery only if implementation or review exposes a second independently complete result that should not widen App v0.1. Later Docs Viewer work belongs to its own feature rather than an App v0 phase.

## Boundaries

This feature does not embed or migrate Docs Viewer, change canonical content or Catalogue data, create an editor, introduce a local repository clone on iPad, change the deployed Cloud Run service, send private content to Python, add a general plugin or action framework, create CI, deploy publicly, commit, push, or require a branch.

Work may continue on the current branch while the slice remains small and sequential. Reconsider isolation if implementation requires a deployed-service rename, substantial Xcode project restructuring, parallel work, or a recovery boundary that ordinary Git review no longer supplies clearly.

## Status

Proposed feature. Its shape is recorded, but implementation does not start until App v0.1 readiness is inspected and accepted.
