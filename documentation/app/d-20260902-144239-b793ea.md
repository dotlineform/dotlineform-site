# Delivery

## Complete Result

The first durable version of the dotlineform Swift application runs natively on the development Mac and connected iPad from one Multiplatform App target with no iPhone destination. Its retained About page displays **WORK ON THE DECAYED** and **䷑**, sends one explicit action from bundled JavaScript to Swift, invokes one provider-neutral Python operation deployed to Google Cloud Run through the Swift service boundary, and applies the validated response visibly in the page. The Xcode project, source structure, Mac/iPad builds, cloud deployment, focused tests, physical-device workflow, and development documentation are suitable foundations for the next real Docs Viewer feature.

## Requirements

- Treat the application project, shell, WebKit host, bridge, cloud-client boundary, workflow, and About page as retained product foundations rather than disposable proof code.
- Keep the visible behavior deliberately small so the new technology and workflow remain understandable.
- Build application code in one explicit boundary inside the `dotlineform-site` repository and document why that boundary owns it.
- Use one SwiftUI Multiplatform App target with native Mac and iPad supported destinations and no iPhone destination.
- Use SwiftUI and Apple frameworks by default, with no third-party Swift dependency unless an implementation step identifies a concrete need and pauses for review.
- Keep the WebKit bridge narrow and typed enough to evolve without allowing arbitrary page code to control application or cloud behavior.
- Make Swift, not JavaScript, own the HTTPS call and environment configuration.
- Deploy ordinary provider-neutral Python in a reproducible container to Google Cloud Run.
- Keep tracked configuration free of secrets, private paths, signing credentials, and machine-specific identities.
- Establish repeatable command-line build/test and cloud-deploy shapes alongside Xcode's interactive device workflow.
- Keep repository-wide App boundaries effective for tasks started at the repository root, and place exact Swift/Xcode commands and conventions in the accepted application-root instructions.
- Do not add an App-specific Codex configuration or setup layer without identifying the exact capability missing from the repository defaults and validating the smallest change in a fresh task.
- Select only evidence that protects the implemented boundary; use manual review for the About page presentation and interaction on the native Mac and physical iPad.

## Not In This Delivery

This delivery does not embed the real Docs Viewer runtime, open document scopes, edit Markdown, access iCloud, reproduce Manage mode, migrate JavaScript features, add Catalogue or Studio behavior, process private content, mutate canonical data, introduce a database, implement application accounts, build a generic cloud platform, add iPhone or additional Apple-platform support, configure TestFlight/App Store distribution, or require CI/macOS runners.

The delivery does not commit, push, create a pull request, publish an application, or activate a paid service without the explicit approval required for that operation.

## Process

Work one checkpoint at a time and stop at each gate for review. Preserve unrelated repository and external-document changes. Use the [Application Architecture And Development Conventions](/docs/?scope=app&doc=d-20260902-144236-7cf815), [Repository Boundary And Codex Instructions](/docs/?scope=app&doc=d-20260902-150055-edbbd9), [Build And Device Deployment](/docs/?scope=app&doc=d-20260902-144237-5bf6f5), [Cloud Python Runtime](/docs/?scope=app&doc=d-20260902-144238-a77d8b), and the currently applicable Studio [Development Checklist](/docs/?scope=studio&doc=d-20260523-190651-7157ec).

Each implementation checkpoint records its proportional verification budget after owner inspection and before adding tests or running broad checks. Unexpected scope, a required paid service, a new persistent data owner, a third-party Swift package, privileged application credentials, or a generic framework is a stop condition requiring review.
