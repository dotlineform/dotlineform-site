# v0.2 - Single Scope

The canonical runtime and native adapter render one controlled, accepted Published snapshot through a complete read-only document path on Mac and iPad.

- Accepted Published snapshot
- App is a read-only consumer from v0.2
- Consumption does not transfer snapshot ownership.
- Until v0.2 exists, there is no native adapter owner in code.

## Docs Viewer Enabling Work

Some Docs Viewer work must happen before a useful Swift integration can be completed, but it belongs inside the first native-reader slice rather than in an open-ended prerequisite refactor:

- define the host-neutral read operations from the actual Published payloads and routes;
- add the smallest native reader composition or entry point around the existing shared runtime;
- bundle the canonical runtime through an owned, deterministic build resource path rather than a manually maintained App copy;
- map current document URLs such as `/docs/doc?...` and Published media URLs such as `/docs/published/media/...` without changing semantic identity;
- validate exact scope, optional sub-scope, document, index, and media boundaries;
- prove one controlled Published snapshot end to end before adding external folder selection.

## The Adapter Boundary

The adapter is a small host boundary around viewer operations, not a general filesystem or networking abstraction. The opening contract should cover only the exact reads needed for a complete document path:

- open and validate one external scope manifest;
- load its collection and navigation indexes;
- load an exact document payload by scope, sub-scope, and document identity;
- load its Search index;
- resolve only media owned by that Published snapshot;
- report missing, invalid, or unauthorised data without silently falling back to another scope or path.

The public implementation maps these operations to configured public URLs. The native implementation may use a confined `WKURLSchemeHandler` or a typed message bridge; readiness work selects the smallest mechanism that preserves normal browser loading and error behavior. Swift validates the selected Published manifest, confines file access to the authorised snapshot, and maps the service-style URLs expected by the viewer to those files.

The viewer core must not know whether a payload arrived through HTTP or Swift. Do not expose a generic `readJSON(path)` API, arbitrary file access, inferred identity, or title and route fallbacks.

## Existing Foundations

The following foundations already exist:

- Canonical shared and public Docs Viewer runtime files live under `docs-viewer/`, with a deterministic tracked projection for the public site.
- Each configured scope has external canonical source, replaceable Generated output, and one accepted Published snapshot.
- Publish is the acceptance boundary. Direct consumers read Published output; they do not read source or Generated output.
- The JavaScript runtime already has shared reader behavior and separate public and Manage composition roots.
- The Swift application already provides the native project and a WebKit bridge on Mac and iPad.

These foundations mean the first native reader is an integration problem around an existing viewer and an existing accepted snapshot, not a request for a new generic core.

## Target Architecture

```text
configured scope source
  -> Build -> Generated
  -> Publish -> Published snapshot
                    |
canonical Docs Viewer runtime
  -> public composition + public adapter -> tracked site / public Analysis
  -> native reader composition + native adapter -> Swift host -> authorised Published snapshot
```

Both compositions use the same reader behavior and payload contracts. Each adapter supplies only the host-specific way to obtain those payloads. The public adapter uses configured static or HTTP URLs. The native adapter asks Swift for authorised local Published data through one explicit WebKit transport.

The native application reads one controlled scope first and later a user-selected external Published scope. It does not require a repository checkout, local HTTP server, Python process, network connection, or public deployment for ordinary reading.
